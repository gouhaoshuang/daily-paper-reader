## 摘要
移动智能体在诸如AndroidWorld等干净的在线基准测试中取得了令人瞩目的成果，但在实际部署中，由于环境变化和不完美的界面条件，其性能往往会急剧下降。在本工作中，我们提出了AndroidReality，一个基于扰动的框架，用于评估和提升移动智能体的鲁棒性。从马尔可夫决策过程（MDP）的角度出发，我们将真实世界的界面变异性组织成一个按三个轴（状态、转移和动作）划分的扰动分类体系。在该分类体系的指导下，我们在AndroidWorld之上构建了一个带有现实且可控扰动注入的扰动移动基准测试，从而能够系统地评估移动智能体的鲁棒性。我们的评估揭示了显著的鲁棒性差距和四类反复出现的错误，这促使我们提出一种简单的、无需训练的测试时内省恢复（TTIR）机制，以在扰动和干净设置下缓解这些失败。总之，这些结果将鲁棒性定位为移动智能体评估中缺失的一个维度，并确立了基准测试扰动作为压力测试和揭示移动智能体潜在弱点的有效工具。

## Abstract
Mobile agents have achieved promising results on clean online benchmarks such as AndroidWorld, yet their performance often degrades sharply in real-world deployment due to environmental variations and imperfect interface conditions. In this work, we introduce AndroidReality, a perturbation-based framework for evaluating and improving the robustness of mobile agents. Through a Markov Decision Process (MDP) perspective, we organize real-world interface variability into a principled taxonomy of perturbations along three axes: state, transition, and action. Guided by this taxonomy, we build a perturbed mobile benchmark on top of AndroidWorld with realistic and controllable perturbation injections, enabling systematic robustness evaluation of mobile agents. Our evaluation reveals substantial robustness gaps and four recurring error categories, motivating a simple training-free Test-Time Introspective Recovery (TTIR) mechanism that mitigates these failures on both perturbed and clean settings. Together, these results position robustness as a missing dimension in mobile agent evaluation and establish benchmark perturbation as an effective tool for both stress testing and surfacing latent weaknesses of mobile agents.

- **核心含义**：作者提出，鲁棒性（Robustness）是当前移动智能体评估中缺失的维度；需要系统性的扰动注入框架来压力测试智能体、揭示其潜在弱点，并为改进提供依据。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想：MDP 视角下的扰动分类

- 将移动交互建模为 MDP：`M = (S, A, T, R, γ)`，其中 S 为 UI 状态空间，A 为 GUI 动作空间，T 为环境转移动力学，R 为任务完成奖励。
- 真实部署被看作一族与干净基准共享任务语义、但在 MDP 不同组件上发生变化的**扰动 MDP 族**。鲁棒性 = 智能体在此扰动 MDP 族上的性能保持能力。
- 据此提出三类扰动：
  - **状态级扰动（State）**：修改观测表面（如字号、主题、DPI、方向、语言/日期格式、骨架屏），不改变底层任务进展。
  - **转移级扰动（Transition）**：修改环境动态 T，插入意外中间状态（如广告、同意书、权限对话框、安全弹窗、评分提示、通知、更新提示）。
  - **动作级扰动（Action）**：修改“意图动作→实际执行”的映射（如动作延迟、随机丢失、冻结、应用挂起、重置到主屏）。

### 2.2 扰动注入形式化

- 定义扰动算子：`P_{c,θ}` 将干净 MDP `M0` 转换为扰动 MDP `\tilde{M}_{c,θ}`，其中 c ∈ {State, Transition, Action}，θ 为扰动类型及配置。
- 交互公式：`s_{t+1} ~ \tilde{T}_θ(s_t, φ^A_θ(a_t))`，`\tilde{o}_{t+1} = φ^S_θ(s_{t+1})`，其中 `φ^A_θ` 扰动动作，`\tilde{T}_θ` 扰动转移，`φ^S_θ` 扰动观测。
- 扰动包装器作为 Android 模拟器与智能体之间的中间层，可灵活、可控地注入上述三类扰动，且保持任务语义与奖励定义不变。

### 2.3 评估指标

- 用干净环境成功率 `SR(M0)` 与扰动环境成功率 `SR(\tilde{M}_c)` 之差定义类别级性能下降：`Δ_c = SR(M0) − SR(\tilde{M}_c)`。
- 另报告步数开销：`Δ_step,c = T(\tilde{M}_c) − T(M0)`。

### 2.4 测试时内省恢复（TTIR）

- 基于错误分析发现的四类失败模式，设计训练无关、模型无关的 TTIR 模块，在每次动作前增加“诊断-恢复”步骤。
- 四组对应策略：
  1. **Stuck-loop detection → alternative-action recovery**：检测重复相同动作/思考（硬规则 N=3 或模型判断），恢复时引导选择不同目标或路径。
  2. **Action-effect verification → alternative-action recovery**：判断上一步动作预期效果是否在当前屏幕可见；若不可见，引导采用其他方式实现同一子目标。
  3. **Interference detection → dismiss-interference recovery**：检测弹窗/广告/通知等离任务干扰，恢复时只要求关闭干扰，禁止参与内容。
  4. **Task-alignment check → re-orientation recovery**：检测当前屏幕是否仍属于原任务路径；若偏离，恢复时仅返回任务上下文，不尝试完成任务本身。
- TTIR 的诊断器和恢复智能体复用主智能体的 VLM，无额外参数或训练数据。

## 6. 论文的主要结论与发现

1. **所有智能体在真实扰动下显著退化**：整体成功率绝对下降 13–36 点，且下降幅度跨越模型系列、规模、训练范式。大规模模型（如 GUI-Owl-32B）并未比小模型更鲁棒，说明单纯扩展规模不能解决鲁棒性缺口。
2. **状态级扰动造成最一致、最严重的退化**：字号、主题、DPI、方向等改变布局后，智能体常预测旧布局下的坐标，陷入“陈旧坐标卡死”循环。
3. **动作级扰动影响最小**：得益于智能体默认的“重试”行为，短时动作延迟/丢失被部分掩盖；但当动作丢失未被察觉时，会出现“静默动作失败”。
4. **转移级扰动跨模型差异最大**：有的智能体能干净地关闭弹窗，有的则深入参与干扰流程导致任务失败；即使成功关闭干扰，也常发生“目标记忆漂移”。
5. **四类重复错误模式**：
   - ① 陈旧坐标卡死（Stale-Coordinate Stuck）
   - ② 静默动作失败（Silent Action Failures）
   - ③ 分心参与干扰（Off-Task Engagement with Distractions）
   - ④ 干扰后目标记忆漂移（Goal Memory Drift After Distraction）
6. **TTIR 有效**：在扰动环境中失败任务数从 60 降至 50（相对减少 17%）；在干净环境中从 44 降至 35（相对减少 20%）。证明扰动暴露的错误模式并非扰动特有，而是当前智能体普遍存在的深层弱点。

## 7. 优点

- **理论框架严谨**：从 MDP 形式化导出扰动分类法，为鲁棒性评估提供了统一、可解释的基础，优于以往仅按“异常事件”列表处理的基准。
- **扰动设计全面且可控**：覆盖 24 种扰动、三类 MDP 组件，支持细粒度错误归因（如类别级 Δc、扰动级 Δc,θ）和步数开销分析。
- **评估流程公平可复现**：固定任务-扰动对、统一种子、共享环境，所有模型使用原始 prompt，确保模型无关比较。
- **错误分析深入**：人工标注失败轨迹并归纳出四类模式，且每类模式均有清晰的视觉图示和真实案例，理论上可指导后续改进方向。
- **TTIR 设计轻量有效**：无需训练、无需新参数，直接复用主模型 VLM，即插即用；同时证明了对干净环境也有收益，说明扰动测试能暴露更深层的缺陷。
- **直接回应现实部署问题**：将“鲁棒性”作为评估维度补入移动智能体研究，对社区具有启发意义。

## 8. 不足与局限

- **TTIR 验证范围窄**：仅在 GUI-Owl-7B 上测试 TTIR，未覆盖其他模型、尺度或训练范式，难以判断其普适性。
- **真实生态未覆盖**：所有实验基于 Android 模拟器，且扰动为人为注入；真实设备中的触控噪声、网络延迟波动、系统级随机性、多应用切换等可能产生模拟器无法复现的扰动，Robustness 结论存在外推限制。
- **扰动配置的主观性**：扰动的强度、时序、概率等参数由作者指定，未通过与真实用户数据的统计分析来校准，可能高估或低估实际风险。
- **缺失敏感性分析**：未系统探索扰动严重程度（如字号从 1.1 到 1.5、丢失概率从 0.05 到 0.2）对成功率的影响，因此无法判断智能体对扰动强度变化的响应曲线。
- **结果呈现不完整**：表 2 中 UI-TARS 系列只有 “Clean” 数据来自原论文，Perturbed 数值缺失（显示为减号），其他部分模型也仅有总体成功率而缺类别细项，影响横向比较的全面性。
- **未分析 TTIR 的额外代价**：TTIR 在每一步都要进行诊断，增加推理延迟和 token 消耗，论文未量化该额外开销与成功率收益之间的权衡。
- **未讨论失败分类的主观性**：四类错误模式由人工标注，缺乏标注一致性（如 Kappa 系数）报告，存在主观偏差风险。
- **无真实用户或设备测试**：未在真实手机、真实用户使用场景中验证 AndroidReality 扰动的生态效度，也缺少与真实崩溃/卡顿数据的对比。
