## 摘要
移动GUI代理在部署到源训练数据中未出现的应用时，其性能仍然较为脆弱。我们研究了在有限目标交互预算且无目标演示条件下，对新型应用的泛化问题。我们提出CoAdapt-GUI，一种测试时自适应（TTA）框架，该框架从代理自身的目标应用交互轨迹和奖励中，联合自适应结构化工作流上下文与策略。工作流上下文保留了可迁移的程序、失败模式和验证规则，同时排除了与应用绑定的源细节。这种分离使得可复用的工作流知识能够指导自适应，而无需迁移源界面状态。对于策略自适应，采用任务上下文匹配的组相对优化，在冻结的视觉-语言模型上更新LoRA适配器。在两个未见应用的评估中，CoAdapt-GUI在AndroidWorld-Generalization上达到45.0%的准确率，而报告的仅策略TTA基线为37.5%；同时将AndroidWorld Plus上的性能从38.6%提升至52.9%。这些结果表明，受迁移约束的工作流上下文能带来显著增益，且联合策略自适应进一步提高了保留集上的性能。

## Abstract
Mobile GUI agents remain brittle when deployed to applications absent from source training. We study novel-app generalization under a limited target interaction budget and without target demonstrations. We introduce CoAdapt-GUI, a test-time adaptation (TTA) framework that jointly adapts structured workflow context and policy from the agent's own target-app rollouts and rewards. The workflow context retains transferable procedures, failure modes, and verification rules while excluding app-bound source details. This separation allows reusable workflow knowledge to guide adaptation without transferring source-interface state. For policy adaptation, task-context-matched group-relative optimization updates a LoRA adapter on a frozen vision-language model. Across two unseen-app evaluations, CoAdapt-GUI reaches 45.0% on AndroidWorld-Generalization, compared with 37.5% for the reported Policy-Only TTA baseline, and raises AndroidWorld Plus performance from 38.6% to 52.9%. These results show that transfer-constrained workflow context provides substantial gains and that joint policy adaptation further improves held-out performance.

## 1. 论文的核心问题与整体含义

- **研究动机**：移动 GUI 智能体虽然在既有基准（如 AndroidWorld、AndroidLab）上表现出色，但在部署到**训练时未见过的新应用**时，性能显著下降。现有方法多在“熟悉界面”上泛化新任务实例，但面对全新应用时，既存在**界面级差异**（无法将动作正确映射到陌生 UI 元素），也存在**流程级差异**（缺乏正确完成任务所需的工作流和完成条件）。此时，仅更新策略或仅更新外部上下文都是不充分的。
- **核心问题**：如何在**没有目标应用演示**、**交互预算有限**、且**不能依赖任何测试集信号**的条件下，让移动 GUI 智能体在遇到新应用后，利用自身交互轨迹与任务奖励完成测试时自适应，从而提升在**未见应用**上的泛化能力。
- **整体含义**：论文提出 CoAdapt-GUI，一种将“显式工作流上下文”和“策略参数”作为两个互补的自适应状态、并在目标应用上**联合更新**的测试时自适应框架。其核心洞察是：跨应用迁移时，应只迁移可复用的流程知识（如何做、可能失败点、如何验证完成），而排除与应用绑定的界面细节（具体控件名、坐标、包名等）；策略更新则应在相同任务与上下文条件下进行相对比较，避免任务难度差异带来的噪声。

## 2. 论文提出的方法论

### 核心思想
- 将测试时行为分为两个可自适应状态：
  - **显式工作流状态 M_t**：包含适用条件、抽象流程、失败/恢复条件、完成检查，以结构化条目 `w = ⟨c, P, F, V⟩` 表示。
  - **参数策略状态 θ_t**：由视觉-语言模型（VLM）上的轻量 LoRA 适配器承载，VLM 主干冻结。
- 两个状态通过**目标应用自身的交互轨迹与奖励**联合更新，且互为“对方的数据来源”：当前工作流影响策略采样轨迹，当前策略生成的成败轨迹又用于后续工作流修订。

### 关键技术细节

#### 转移约束的工作流上下文
- 将源应用工作流拆分为：
  - **应用绑定状态 M_a^app**：屏幕转移有限状态机（FSM），包含具体屏幕、控件、资源标识符等，**不可跨应用迁移**。
  - **可迁移状态 M_a^tr**：与应用无关的抽象工作流条目，**可跨应用迁移**。
- 可迁移条目必须通过**资格检查（eligible）**：由模式验证器和 linter 拒绝包含应用名、包名、资源 ID、具体控件标签、坐标、任务实例值等内容。
- 源工作流条目按 Google Play 功能类别合并为**源工作流库 L_src**；目标应用仅能检索与其类别匹配的条目；若类别缺失（Category-Novel），则返回空先验而不是强加无关指导。

#### 联合上下文与策略自适应
两个通道复用同一批目标应用 rollout，但以不同频率更新：

1. **奖励引导的上下文更新**：
   - 维护一组 TrueSkill 评分的上下文变体，控制器在每轮选择已物化的变体，在匹配的任务和重置条件下收集 rollout，用任务奖励更新其评分。
   - 通过**冻结的反射器（reflector）** 对比成功与失败轨迹，向高评分父变体提出类型化修订，生成子变体；子变体必须通过模式、来源和 lint 检查后才能进入候选池，并且**不继承本轮奖励**，其效用只有在后续被采样评估时才确定。

2. **任务-上下文匹配的策略更新**：
   - 将轨迹按 `(任务 q, 上下文 κ)` 分组 `G(q,κ)`，仅在组内计算相对优势：`A_j = (r_j − r̄_G) / s_G`，其中 `s_G` 为 1（均值中心化）或组内标准差（标准化）。
   - 单元素组或奖励恒定组不产生有效梯度，被排除。
   - 对组内轨迹，先对其所有动作单元求平均对数概率 `ℓ_j(θ)`，再乘优势加权得到组相对策略目标（类 GRPO），并加冻结策略正则项 `βR(θ; π_anchor)`。
   - LoRA 在策略缓冲区达到阈值时最多更新一次，随后清空缓冲区；不使用陈旧策略的旧轨迹；VLM 主干始终冻结。

#### 算法流程概览
- 初始化：检索协议允许的源工作流上下文，目标侧状态置空，策略为源侧预训练初始。
- 循环至预算耗尽：选任务 → 选已物化上下文变体 → 收集匹配 rollout → 更新变体评分 → 从轨迹中提出并验证子修订 → 将轨迹加入策略缓冲区 → 若满足条件则更新 LoRA 并清空缓冲区。
- 结束后：从验证状态中挑选最高评分工作流，冻结上下文与策略，再进行保留集评估。

### 对比方法
- **Base Policy**：无任何 TTA，直接使用源侧初始策略。
- **Static Context Transfer**：仅提供冻结的源工作流上下文，不更新任何状态。
- **Policy-Only TTA**：保持工作流上下文固定，仅更新策略 LoRA（场景 1 为报告基线）。
- **Context-Only TTA**：保持策略固定，仅从目标 rollout 构建和修订工作流上下文。
- **CoAdapt-GUI**：同时更新工作流上下文与 LoRA 策略适配器。

## 6. 论文的主要结论与发现

- **联合自适应优于单通道自适应**：
  - 场景 1（新实例）中，CoAdapt-GUI 达到 **45.0%**，比报告 Policy-Only TTA 的 37.5% 高 7.5 点，比 Context-Only TTA 的 35.0% 高 10.0 点。
  - 场景 2（新模板）中，CoAdapt-GUI 将整体成功率从 Base 的 38.6% 提升至 **52.9%**（+14.3 点）；Context-Only TTA 达到 48.1%，Policy-Only TTA 仅 40.0%。
- **受迁移约束的工作流上下文收益显著**：即使不更新策略，Context-Only TTA 在两个场景中都超过静态上下文转移和 Base Policy；在 Category-Novel（无源工作流）条件下也能从 29.4% 提升至 31.4%（CoAdapt-GUI 则达 34.3%）。
- **策略更新在上下文进化后更有效**：上下文演化可为策略学习暴露此前不可见的成功信号（如 Chrome 示例中第 12 轮子变体首次获得非零奖励），从而改善策略梯度质量。
- **两类泛化（新实例 vs 新模板）均得到验证**：方法不仅适用于已见任务类型的新实例，也能泛化到完全未见的任务模板，且 Category-Novel 场景证明该机制不依赖源类别匹配。

## 7. 优点

- **清晰的状态分离**：将“可迁移工作流知识”与“应用绑定界面状态”严格分开，设计上避免源界面细节造成负迁移。
- **忠实于无监督 TTA 约束**：所有更新均来自代理自身交互与可执行奖励，无目标演示、无测试集泄漏；评估前冻结所有状态。
- **方法设计精细**：
  - 上下文变体采用 TrueSkill 评分，基于奖励的演化机制避免无条件信任模型生成的修订。
  - 策略优势仅在同任务、同上下文组内计算，有效控制任务难度与上下文差异的干扰。
  - 非退化组才参与策略更新，规避恒定奖励下的虚假梯度。
- **实验场景设计有说服力**：自建 AndroidWorld Plus 扩展了基准覆盖，并引入 Category-Shared / Category-Novel 作为源迁移的天然控制变量，直接检验迁移约束的有效性。
- **透明度较好**：附录提供了完整的模板清单、实现细节、参数表、验证合同和提示模板，可复现性强。

## 8. 不足与局限

- **评估范围有限**：全部基于 Android 模拟器环境（AndroidWorld 及扩展），未覆盖 iOS、Web、桌面等多平台场景；环境均为可重置模拟器，未涉及真实设备动态条件。
- **基准比较公平性存疑**：场景 1 中的关键基线（Policy-Only TTA）直接引用原文报告值，未在统一环境中复现；场景 2 的对比虽在相同环境内进行，但各配置独立运行会产生不同轨迹，论文也承认其差异并非“受控的 LoRA 单独贡献”。
- **统计报告不完整**：场景 2 未提供多次运行的方差或显著性检验；场景 1 只报告了少数配置的均值与标准差。
- **稀疏反馈下稳定性风险**：在奖励完全为 0 的早期回合，上下文演化与策略更新可能无法获得有效信号；虽然论文使用匹配种子与组相对优势缓解，但 20 轮 / 50 步的预算仍可能不足以稳定收敛。
