## 摘要
评估语言引导的移动智能体近期已从基于规则的方法转向基于模型的方法，以实现可扩展且自动化的评估。然而，现有的整体评估范式一次性处理整个轨迹，导致严重的上下文过载。此外，这些方法主要关注任务完成情况，而忽视了操作安全性。为解决这些局限性，我们提出了CRATE，一种新颖的两阶段VLM评判框架，用于自动化移动智能体评估，兼容开源和闭源模型。CRATE利用步骤级后果推理机制，独立提取任务相关的视觉线索，并推断每一步中受动作影响的状态变化。随后，通过轨迹级聚合对生成的步骤级文本证据进行综合，以提供基于证据的任务完成度评估。在此评估方案的基础上，我们进一步将CRATE扩展为CRATE-S，用于操作安全性评估。大量实验验证了CRATE和CRATE-S的有效性和稳健性。基于Qwen2.5-VL-72B-Instruct，CRATE在AndroidWorld上达到了0.833的F1分数（优于SPA-Bench 20%），而CRATE-S在MobileRisk上达到了0.697的F1分数，展现出与基准真实标签的高度一致性。代码可在 https://anonymous.4open.science/r/CRATE-D580 获取。

## Abstract
Evaluating language-guided mobile agents has recently shifted from rule-based to model-based approaches to achieve scalable and automated assessments. However, existing holistic evaluation paradigms process entire trajectories at once, leading to substantial context overload. Moreover, they primarily focus on task completion while overlooking operational safety. To address these limitations, we introduce CRATE, a novel two-stage VLM-as-judge framework for automated mobile agent evaluation that is compatible with both open- and closed-source models. Leveraging a step-level consequence reasoning mechanism, CRATE independently extracts task-relevant visual clues and infers action-conditioned state changes at each step. The resulting step-level textual evidence is then synthesized through trajectory-level aggregation to deliver an evidence-grounded evaluation of task completion. Building upon this evaluation scheme, we further extend CRATE to CRATE-S for operational safety assessment. Extensive experiments validate the effectiveness and robustness of both CRATE and CRATE-S. Powered by Qwen2.5-VL-72B-Instruct, CRATE achieves an F1-score of 0.833 on AndroidWorld (outperforming SPA-Bench by 20%), while CRATE-S reaches an F1-score of 0.697 on MobileRisk, demonstrating strong alignment with benchmark ground truths. Code is available at https://anonymous.4open.science/r/CRATE-D580.

## 2. 论文提出的方法论

### 2.1 核心思想

受人类审慎推理启发，将整体式评估解耦为两个阶段：
1. **步骤级后果推理**：对每一步独立进行"状态理解 → 状态转移建模 → 后果推断"，产生紧凑的文本证据；
2. **轨迹级聚合**：综合所有步骤证据进行全局判断，生成证据支撑的二元结论。

### 2.2 CRATE（任务完成度评估）

- **轨迹表示**：轨迹 T = (I, S, A)，其中 I 为任务文本描述，A = {a₁, a₂, ..., aₙ} 为动作序列，S = {s₀, s₁, ..., sₙ} 为截图序列（sᵢ 为执行 aᵢ 后的屏幕状态）。
- **步骤级后果推理**（式 1）：将轨迹分解为独立的 (sᵢ₋₁, aᵢ) 步骤对，连同任务描述 I 独立送入 VLM，生成结构化证据：
  - (cᵢ, eᵢ) = VLM(sᵢ₋₁, aᵢ, I | p_s)
  - cᵢ：与任务完成相关的视觉线索的文本描述；
  - eᵢ：推断的动作效果的文本描述。
- **关键设计**：利用 VLM 的内在世界模型能力，直接从"动作前屏幕 + 动作"推断动作后果，而非标准的 (sᵢ₋₁, aᵢ, sᵢ) 三元组，消除了冗余的跨状态计算；且每步独立评估天然支持批量推理加速。
- **轨迹级聚合**（式 2）：将全部步骤证据 {(cᵢ, eᵢ)}、任务描述 I 和最终截图 sₙ 一起送入 VLM，要求其先列出任务的全部必要条件，再逐条验证，最终输出二元判断 o ∈ {0, 1}：
  - o = VLM({(cᵢ, eᵢ)}ⁿᵢ₌₁, I, sₙ | p_t)
- **语义压缩本质**：步骤级推理过滤掉截图中的视觉噪声，使聚合阶段接收的是高密度、短上下文的因果链证据。

### 2.3 CRATE-S（操作安全评估）

- 采用与 CRATE 相同的两阶段流程，但有两点区别：
  1. **省略任务描述 I**：安全评估应该是任务无关的，优先关注操作安全而非指令安全；
  2. **增加步骤级风险标签**：步骤级推理额外输出二元风险标签 rᵢ ∈ {0, 1}，实现精确的风险步骤定位。
- **风险类别覆盖**：Agent 侧风险（破坏性操作、隐私泄露、有害内容生成与传播、资源滥用、法律合规问题、敏感操作过度自动化）+ 外部风险（提示注入、隐藏指令）。
- **轨迹级安全判断**：聚合所有步骤证据（不使用任务描述和最终截图），只要任一步骤存在明确安全风险即判为不安全，采用保守策略。
- **算法流程**（Algorithm 1）：循环对每步调用 VLM 生成 (cᵢ, eᵢ, rᵢ)，最后对 (C, E) 调用聚合 VLM 输出最终风险判断 o。

## 6. 论文的主要结论与发现

1. **两阶段方案有效**：将整体评估解耦为"步骤级后果推理 + 轨迹级聚合"可显著减轻上下文过载，使中等规模开源 VLM 也能达到甚至超越闭源大模型的评估精度。
2. **开源模型表现意外优于闭源**：除 SPA-Bench 外，Qwen2.5VL 作为评估器普遍优于 GPT-4o；GPT-4o 偏向保守（高精确率、低召回率），而 Qwen2.5VL 在 CRATE 框架下达到了更好的精确率-召回率平衡。
3. **降级分析的病理现象**：去除步骤级推理后，Qwen2.5VL 出现"过度乐观偏差"（Recall=1.000 但 Precision=0.480），说明长上下文直接推理是开源 VLM 失效的关键原因。
4. **安全评估无需任务描述**：CRATE-S 证明任务无关的安全评估范式可行，且步骤级风险定位比 OS-Sentinel 更精确。
5. **智能体排名一致性**：CRATE 评估的 8 个智能体的相对排名与 AndroidWorld 官方排行榜一致，验证了其作为通用评估工具的有效性。

## 7. 优点

- **方法设计层面**：
  - 创新性地将 VLM 世界模型能力用于"动作前状态 + 动作 → 后果"的推断，避免了对动作后截图的依赖，减少了跨状态冗余计算；
  - 步骤级推理本质上是"语义压缩器"，将视觉轨迹蒸馏为高密度文本证据，从根源上缓解上下文过载；
  - 完全免标注，无需人工设计任务特定规则或里程碑注释，支持新任务的无缝扩展；
  - 支持批量推理加速，且兼容开源/闭源模型，降低了评估成本；
  - 证据驱动、可解释：每个判断都有明确的步骤级证据支撑（案例研究表明 CRATE 能识别 SPA-Bench 忽略的数量约束）；
  - CRATE-S 同时提供轨迹级风险判断与步骤级风险定位，粒度更细；
  - 自建 CRATEBench 覆盖真实设备上的中文/国际流行应用，弥补了 AndroidWorld 与真实场景的差距。
- **实验设计层面**：双基准、双骨干、多基线、消融、案例、分层分析（难度、应用类别）多维度综合验证，结论较为扎实。

## 8. 不足与局限

- **场景覆盖有限**：仅在移动（手机）场景验证，未覆盖桌面 GUI、Web 浏览器等具有不同视觉层级结构的领域，泛化性有待验证。
- **评估模式受限**：仅支持事后（post-hoc）轨迹评估，尚未探索作为在线奖励模型或执行中实时反思模块的潜力。
- **依赖底层模型能力**：CRATE 的性能受限于现成 VLM 的世界模型和推理能力，未对专门优化做探索；VLM 自身可能存在的幻觉和偏见会传导到评估结果中。
- **安全评估验证不充分**：仅在 MobileRisk 一个安全基准上测试；安全评估中 GPT-4o 骨干下精确率偏低（0.576），存在一定的误报倾向，但论文未深入分析原因；步骤级定位得分（28.8）仍较低，说明精确的时序风险定位还远未解决。
- **资源信息缺失**：未披露算力消耗、推理成本、压缩率的具体量化数据，难以评估其实际部署成本。
- **其他潜在偏差**：CRATEBench 的成功轨迹仅 24 条，类别不平衡可能影响评估稳定性；自建基准的人工标注一致性未报告信度指标；Agent 能力基准测试中各智能体的超参、训练设置未统一披露，存在公平性隐患。
