## 摘要
基于LLM的智能体框架如今充当多步任务的个人助理。现有智能体框架（如OpenClaw）通常采用云智能体部署模式，使用闭源云LLM作为骨干模型，这可能会暴露用户私有信息并产生重复的LLM调用成本。本地智能体通过将前沿开源SLM部署在用户控制的设备上来解决这些部署问题，但其任务有效性仍远落后于云智能体。通过诊断分析，我们发现，采用前沿SLM骨干的本地智能体有效性受限，主要源于骨干模型规模有限所导致的环境知识缺失，包括环境规则和操作流程。为了以非参数化、上下文高效且无需专家编写的方式提供此类知识，我们提出了SkillSmith，一种云-本地智能体协作框架，该框架将技能作为上下文高效的知识载体，从云智能体任务探索中自动构建技能，并利用本地智能体执行反馈演进技能，以增强冻结的本地智能体。在每日智能体任务数据集AppWorld和WorkBench上的实验表明，自动生成的技能使采用Qwen3.6-27B（SLM）的本地智能体达到了与采用前沿LLM的云智能体相当的任务有效性，优于最强的非参数基线，将AppWorld-Normal上每个任务的平均动作数从36.1降至9.9，并且无需重新运行技能构建即可推广到其他SLM骨干模型。

## Abstract
LLM-based agent frameworks now act as personal assistants for multi-step tasks. Existing agent frameworks such as OpenClaw commonly follow the Cloud Agent depolyment mode using closed-source cloud LLMs as backbone model, which may expose private user information and incur repeated LLM-calling costs. Local Agents address these deployment concerns by depolying frontier open-source SLMs on user-controlled devices, but their task effectiveness still lags far behind Cloud Agents. Through diagnostic analysis, we reveal that the limited effectiveness of Local Agents with frontier SLM backbones mainly comes from missing environment knowledge caused by limited backbone model scale including environment rules and operation procedures. To supply such knowledge non-parametrically, context-efficiently, and without expert authoring, we present SkillSmith, a Cloud--Local Agent collaboration framework that uses Skill as a context-efficient knowledge carrier, automatic constructs Skill from Cloud Agent task exploration and evolves Skill using Local Agent execution feedback to enhance a frozen Local Agent. Experiments on daily agent task datasets AppWorld and WorkBench show that the automatically generated Skill enables the Local Agent with Qwen3.6-27B(SLM) to achieve task effectiveness comparable to Cloud Agents with frontier LLMs, outperform the strongest non-parametric baselines, reduce average actions per task from 36.1 to 9.9 on AppWorld-Normal, and generalize to other SLM backbone models without rerunning Skill construction.

### 2.2 方法论设计

**核心思想**：SkillSmith 是一个**云-本地智能体协作框架**，以 **Agent Skill**（S = (M, R, C)，其中 M 为主 Markdown 手册，R 为参考文件，C 为加载条件）作为上下文高效的知识载体，由云智能体自动构建初始 Skill，再由本地智能体执行反馈驱动迭代演进，最终增强**冻结的（frozen）本地智能体**，无需微调骨干模型。

**三个设计需求（R1–R3）**：
- **R1** 合适的知识载体，避免上下文低效（→ 采用 Skill 的渐进式披露机制）；
- **R2** 无需专家编写的自动高质量初始知识构建（→ 由云智能体替代人类专家）；
- **R3** 基于本地执行反馈的自动迭代演化，含验证与修正（→ 云智能体根据本地反馈驱动演进）。

**两个技术挑战**：
- **P1**：云智能体如何从代表性任务执行中构建高质量初始 Skill？→ 直接让云智能体凭任务描述编写 Skill 不可靠，因为任务描述低估了实际环境，可能产生幻觉规则或遗漏隐含流程。
- **P2**：如何基于本地智能体的执行反馈可靠地演进 Skill？→ 直接喂入失败轨迹和反馈效率低，失败具有歧义，跨长轨迹难以识别重复缺陷，无约束修订会导致 Skill 膨胀或使已成功任务回退。

### 2.3 系统架构与两阶段流程

**离线学习阶段**：
- **Skill 创建阶段（Skill Creation）**：
  1. **探索与反思（Explore and Reflect）**：云智能体（Claude Opus 4.7）执行代表性训练任务，结合评估器反馈，将每条轨迹总结为 Reflection Report（包含任务、压缩轨迹、评估结果、更高效路径、遇到的陷阱、使用的工具）；
  2. **创建初始 Skill（Create Initial Skill）**：通过三个云智能体角色完成——
     - **Cluster Agent**：按任务类型、应用、工具使用对 Reflection Reports 聚类，合并小簇，控制簇数 ≤10；
     - **Distill SubAgent**：对每个簇提取可复用信号（步骤序列、代码模板、陷阱与补救、簇特定规则、触发关键词、跨簇通用性判断）；
     - **Merge Agent**：根据提升规则（如步骤出现在 ≥N/2 簇则提升到主手册）合并为初始 Skill S₀，受长度预算 L_max 约束。
- **Skill 演化阶段（Skill Evolution）**（迭代 R 轮）：
  1. **执行与压缩（Execute and Compress）**：本地智能体（Qwen3.6-27B）使用当前 Skill 执行训练任务，将失败执行与评估器反馈压缩为 Failure Report；
  2. **演化 Skill（Evolve Skill）**：同样通过三个角色——Cluster Agent 对失败报告聚类；Analyze SubAgent 对照当前 Skill 进行失败归因（A：Skill/参考文件未加载；B：Skill 指令不完整/错误；C：粗心近似错误；其他：超出文本修复范围），并添加带优先级的修改备注；Merge Agent 合并修改、按优先级应用、超长时压缩。

**在线服务阶段**：冻结的本地智能体加载最终 Skill 运行，无云端 LLM 调用，用户数据全程本地。

### 2.4 公式化与算法流程

- **任务定义**：ξ = (D, y*)，其中 D 为任务指令，y* 为预期结果。
- **目标函数**：S* = argmax E_{ξ∼T}[r(S; ξ)]，在训练集上用经验通过率 J_{Dtrain}(S; Gs) 近似。
- **优化方式**：受 TextGrad 启发，将 LLM 生成的反馈视为类梯度信号，用云智能体 Gc 作为文本优化器：S₀ = Create(Gc, Dtrain)，Si = Evolve(Gc, Gs, Si−1, Dtrain)，迭代 R 轮，最终选择训练集通过率最高的 Skill 版本部署。
- **完整算法（Algorithm 1）**：创建阶段生成 S₀ → 执行并压缩获取失败报告 → 循环聚类、分析、合并、重新评估，保留最佳版本，若无失败则提前终止。

## 6. 主要结论与发现

- **根本原因**：本地智能体效果差距主要由 **SLM 骨干模型缺失环境知识**（环境规则和操作流程）导致，而非核心智能体能力不足；非参数化知识补充可修复大部分失败。
- **方法有效性**：SkillSmith 生成的 Skill 将 Qwen3.6-27B 本地智能体的通过率从 36.3%→78.6%（AppWorld-Normal）、28.1%→74.9%（AppWorld-Challenge）、51.1%→89.0%（WorkBench），绝对提升 37.9~48.2 个百分点。
- **媲美云代理**：与最强云代理的差距从 57.7/61.1/24.3 个百分点缩小至 15.4/14.3 个百分点，WorkBench 上甚至反超 13.6 个百分点。
- **优于所有非参数基线**：比每个数据集上最强的非参数基线高 11.3~26.2 个百分点；prompt-based 和 memory-based 方法在 WorkBench 上甚至略有退化，说明多轮演进反馈的价值。
- **效率提升**：AppWorld-Normal 平均动作数从 36.1 降至 9.9，累积上下文 token 从 450.7k 降至 200.6k。
- **成本效益**：SkillSmith 将成本从在线按任务付费转移为一次离线构建，约 560 个 AppWorld 任务后即比云代理更经济。
- **跨骨干泛化**：无需重新构建 Skill，同一 Skill 可提升 Qwen3.6-30B-A3B（+20.1/+30.8 点）和 Gemma-4-31B（+48.2/+7.8 点）的表现。
- **阶段贡献**：Skill Creation 是主导贡献（+30.0~+43.5 点），Skill Evolution 提供额外精细优化（+1.2~+12.3 点）；高质量初始 Skill 是后续演进的基础。
