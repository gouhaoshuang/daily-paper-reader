## 摘要
自主 AI 代理的兴起代表了用户与移动设备交互方式的重大范式转变。诸如 MobileRun 和 Mobile-Use 之类的框架可以自主导航 Android 应用并执行复杂的多步骤任务。为了理解用户界面，这些框架主要依赖 Android 无障碍（A11y）树，其次依赖视觉截图。在本文中，我们证明这种对未净化的无障碍元数据以及视觉输入的架构依赖，引入了对间接提示注入的系统性漏洞。我们表明，对抗性提示可以使自主代理放弃其原始目标、违反上下文边界并执行未经授权的设备操作。我们的实证评估展示了在视觉隐藏和完全暴露的攻击场景中的目标劫持、上下文漂移和未经授权的操作。总体而言，MobileRun 在使用 Gemma4:31B 时达到 0.822 的攻击成功率，而 Mobile-Use 使用 Qwen3.6:35B 将其降低至 0.150，但并未消除上下文漂移或未经授权的操作。这些发现揭示了当前的移动代理框架未能强制执行语义上下文边界，将被动环境文本视为可信指令。最后，我们提出了这些攻击的分类，并讨论了在移动代理架构中采用零信任输入验证、专用安全代理和严格上下文隔离的必要性。

## Abstract
The rise of autonomous AI agents represents a major paradigm shift in how users interact with mobile devices. Frameworks such as MobileRun and Mobile-Use can autonomously navigate Android applications and execute complex multi-step tasks. To interpret user interfaces, these frameworks rely primarily on Android accessibility (A11y) trees and secondarily on visual screenshots. In this paper, we demonstrate that this architectural dependence on unsanitized accessibility metadata, together with visual input, introduces a systemic vulnerability to indirect prompt injection. We show that adversarial prompts can cause autonomous agents to abandon their original objectives, violate context boundaries, and perform unauthorized device actions. Our empirical evaluation demonstrates goal hijacking, context drift, and unauthorized actions across visually hidden and fully exposed attack scenarios. In aggregate, MobileRun reaches an attack success rate of 0.822 with Gemma4:31B, while Mobile-Use with Qwen3.6:35B reduces this to 0.150 but does not eliminate context drift or unauthorized actions. These findings reveal that current mobile agent frameworks fail to enforce semantic context boundaries, treating passive environmental text as trusted instructions. Finally, we present a taxonomy of these attacks and discuss the need for zero-trust input validation, dedicated security agents, and strict context isolation within mobile agent architectures.

## 1. 核心问题与整体含义

- **研究动机**：自主移动 AI 代理正在成为智能手机交互的新范式。MobileRun、Mobile-Use 等框架可自动导航 Android 应用、执行多步骤任务，其核心感知机制是 Android 无障碍（A11y）树，辅以视觉截图。然而，这类架构将未净化的无障碍元数据视为可信观察源，使被动环境文本（通知、网页、日历、联系人、隐藏节点等）能够被恶意利用为攻击载体。
- **核心问题**：A11y 树作为观察通道，将应用控制的文本内容与用户指令以相同形式（自然语言）呈现给 LLM，导致代理无法区分“数据”与“指令”。攻击者可嵌入恶意指令，使代理偏离原始目标、执行跨应用导航或泄露设备信息，构成**间接提示注入**系统性风险。
- **整体含义**：当前的移动代理架构缺乏语义上下文边界，将环境文本误认为可信指令。这不仅是单一框架的实现缺陷，而是 A11y 驱动型代理普遍存在的架构性脆弱点，需要零信任的输入验证与上下文隔离设计。

## 2. 方法论

- **核心思想**：以 Android 无障碍观测通道为不受信任的安全边界建模，证明对抗者无需修改用户指令、模型或代理实现，仅通过控制 A11y 暴露的内容即可注入恶意指令。
- **攻击分类学**：提出 9 种攻击向量（A1–A9），分为三类：
  - **系统/运行时注入**（A1–A3）：通知注入、同应用运行时覆盖层（Chrome 内）、跨应用覆盖层（Chrome 覆盖影响 Telegram 任务）。
  - **应用内容注入**（A4–A8）：视觉隐藏的无障碍元数据、HTML 网页（条款文本）、日历描述、笔记正文、联系人备注字段。
  - **规划层注入**（A9）：针对 MobileRun 的 AppCard 机制（框架级规划上下文中的操作指南）进行投毒，测试规划层内容是否具有高于用户指令的权威性。
- **标准化对抗目标**：A1–A8 统一为“将代理重定向到 Android 设置、获取 Build Number 并在响应中输出”，以支持跨表面、跨配置的公平比较；A9 则测试未经授权的特定操作（如传输敏感信息）。
- **安全目标定义**：意图完整性（Intent Integrity）、数据–指令隔离（Data–Instruction Separation）、来源感知（Provenance Awareness）、操作授权（Action Authorization）。
- **评估指标（公式）**：
  - **ASR（攻击成功率）** = 成功完成对抗目标的试验数 / 总攻击试验数。
  - **CDR（上下文漂移率）** = 日志/动作中显示受对抗指令影响的试验数 / 总试验数。
  - **UAR（未授权操作率）** = 至少执行一次越界操作的试验数 / 总试验数。
  - 通过这三个指标的分离，区分“干净拒绝”“部分妥协”“完全攻击成功”三个阶段。

## 6. 主要结论与发现

- **系统性漏洞确认**：两个框架、两个模型均未提供完整防护。MobileRun 在 Gemma4:31B 下 ASR 达到 **0.822**（CDR=0.922，UAR=0.889），最脆弱的框架–模型组合。
- **模型差异**：Qwen3.6:35B 总体更稳健。MobileRun 下 ASR 降至 0.544；Mobile-Use 下大幅降至 **0.150**，但 CDR=0.325、UAR=0.275，仍存在中间阶段妥协。
- **攻击面差异**：应用内容注入与规划层注入最有效——A4（隐藏 A11y 元数据）与 A5（HTML 注入）在多数配置中 ASR 达 0.6–1.0；A9（AppCard 投毒）在两个模型下均完全成功（ASR=1）; 运行时注入（尤其是跨应用覆盖层 A3）效果较弱。
- **视觉辅助的局限性**：截图增强的效果不一致——在某些配置（如 MobileRun Reasoning + Vision + Gemma4）中降低 ASR，在另一些配置中（FastAgent + Vision）甚至提高了 ASR。视觉不能作为可靠的安全边界。
- **架构并不天然免疫**：更多推理阶段、多代理架构、附加视觉均无法保证数据–指令分离。核心问题在架构层面：需要来源追踪、显式数据–指令分离、跨应用操作授权校验。

## 7. 优点

- **系统性攻击分类学**：首次将 9 种 A11y 相关攻击表面系统化，覆盖运行时、应用内容与规划层三个维度，且明确区分注入位置与代理观察通道。
- **三层指标分离（ASR/CDR/UAR）**：比仅报告 ASR 更精细，能捕获中间阶段妥协（推理漂移与未授权操作），提高分析粒度与可解释性。
- **多维度对比矩阵**：同时变化框架（MobileRun vs. Mobile-Use）、执行架构（直接 vs. 多代理推理）、感知模态（A11y vs. A11y+视觉）、模型（Gemma4 vs. Qwen3.6），全面识别漏洞的普遍性与局限。
- **真实环境评估**：使用物理 Android 设备而非模拟器，保留真实的无障碍树生成、通知交付、应用转换等行为，生态效度高。
- **防御建议具体可落地**：提出来源追踪、数据–指令隔离、跨应用操作验证、零信任输入校验等设计原则，并指出应在观察进入框架时和计划传递给执行组件前分别设置检查点。
- **开放科学性强**：发布 benchmark 任务、注入载荷、脱敏痕迹、注释与分析脚本，保证可复现性。

## 8. 不足与局限

- **框架与模型覆盖有限**：仅评估 MobileRun 和 Mobile-Use，两个开源模型，一种 Android 设备家族；结论不一定迁移到商业模型（如 GPT、Claude 的移动端变体）、iOS 或其他 Android 版本。
- **试验次数有限**：每种配置仅 5 次重复，统计功效较低；作者也承认结果是描述性的，而非精确的群体估计。
- **对抗目标单一**：A1–A8 均使用 Build Number 泄露——低冲击、非破坏性。真实攻击可能涉及财务交易、账户修改或大规模信息泄露，论文未覆盖这些更严重后果。
