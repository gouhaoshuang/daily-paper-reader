## 摘要
随着设备端LLM代理演变为个人助手，移动操作系统已成为该范式的重要测试平台，使得严格的能力评估变得至关重要。然而，现有基准测试分为两类，每类都存在关键盲点：以GUI为中心的基准测试检验表层的屏幕操作，却忽视了后台工具使用和长程规划；而静态函数调用基准测试则依赖离线API匹配，与真实运行时约束脱节。为弥补这一差距，我们提出了\textbf{MobilePA-Bench}，一个交互式、有状态且以工具为中心的基准测试，用于评估移动规划代理的工具调用和规划能力。MobilePA-Bench运行在可执行的沙箱环境中，该沙箱维护实时应用数据库并返回结构化反馈，覆盖$13$个功能领域和$212$个真实移动工具。除了基础工具使用外，它从三个高级维度评估核心规划代理：\emph{(1)~子代理协作}——将复杂任务分解并委派给有能力子代理的专门工作；\emph{(2)~记忆使用}——调用存储的记忆、用户画像和过往偏好以解决隐含请求；以及\emph{(3)~技能使用}——调用预封装的复合技能，而非从零开始规划每一步。大量实验表明，当前前沿LLM在移动环境中仍不可靠：在严格工具排序、权限限制和意外运行时错误下，性能急剧下降。通过将交互式函数调用沙箱与基于证据的验证相结合，MobilePA-Bench既可作为实用的诊断基准，也可作为基于代理的强化学习的交互基础——加速可靠移动代理的开发。

## Abstract
As on-device LLM agents evolve into personal copilots, the mobile operating system has become a key testbed for this paradigm, making rigorous capability evaluation essential. Yet existing benchmarks fall into two camps, each with a critical blind spot: GUI-centric benchmarks test surface-level screen manipulation while overlooking background tool use and long-horizon planning, whereas static function-calling benchmarks rely on offline API matching that is detached from real runtime constraints. To close this gap, we present \textbf{MobilePA-Bench}, an interactive, stateful, and tool-centric benchmark for evaluating the tool-calling and planning abilities of mobile planning agents. MobilePA-Bench runs on an executable sandbox that maintains live application databases and returns structured feedback, spanning $13$ functional domains and $212$ realistic mobile tools. Beyond basic tool use, it evaluates a central planning agent along three advanced dimensions: \emph{(1)~Sub-agent Collaboration}---decomposing a complex task and delegating specialized work to capable sub-agents; \emph{(2)~Memory Usage}---recalling stored memories, user profiles, and past preferences to resolve implicit requests; and \emph{(3)~Skill Usage}---invoking pre-packaged composite skills instead of planning every step from scratch. Extensive experiments show that current frontier LLMs remain unreliable in mobile settings: performance drops sharply under strict tool ordering, permission limits, and unexpected runtime errors. By pairing an interactive function-calling sandbox with evidence-based verification, MobilePA-Bench serves as both a practical diagnostic benchmark and an interactive foundation for agentic reinforcement learning---accelerating the development of dependable mobile agents.

- 现有移动智能体基准存在两类关键盲区：
  - **GUI 中心基准**（如 AndroidWorld、OSWorld、MobiBench）只测试表面屏幕操作，忽视后台工具调用、长程规划和系统级执行效率。
  - **静态函数调用基准**（如 BFCL、DroidCall、AppBench、TAU-Bench）依赖离线 API 匹配，缺乏实时、有状态的环境反馈，无法反映真实运行时约束。
- 核心观点：真实移动任务（如多日旅行规划）必须同时依赖记忆检索、结构化 API 工具、多模态输入处理以及 GUI 子代理协作，这些能力在现有基准中无法被统一评估。
- 为此提出 MobilePA-Bench，一个“交互式、有状态、以工具为中心”的移动规划智能体基准，用于评估真实复杂任务中的工具调用与规划能力。

## 2. 论文提出的方法论

### 2.1 总体框架

- 将移动智能体形式化为“工具中心的编排回路”：中央规划智能体负责高层决策，直接调用结构化业务工具，或将专门任务路由给子代理；同时可检索用户记忆和加载可复用技能。
- 环境为有状态移动沙箱，包含领域数据库和运行时日志；每次工具调用会更新状态、返回结构化反馈，支持智能体动态调整计划。

### 2.2 核心技术设计

- **统一动作空间**：所有操作（直接工具、子代理入口、记忆工具、技能加载工具）都用结构化函数 schema 表示，便于 LLM 通过函数调用执行。
- **交互执行公式**：每一步智能体根据查询、历史和候选动作选择动作 \( a_t \)，沙箱执行后返回反馈 \( f_t \) 并更新状态 \( S_{t+1} \)，轮回直到智能体输出 Finish 或达到最大步数 \( T_{\max} \)。
- **技能动态动作空间扩展**：当智能体调用技能加载器 \( LoadSkill(s) \) 时，环境将对应的具体工具 schema 动态加入后续动作空间 \( A_{t+1} = A_t \cup G(s) \)。
- **有状态沙箱架构**：包含工具 schema、可执行工具代码、共享持久化数据库三层；工具执行时会验证参数、检查约束、更新数据库并记录操作日志，返回结构化反馈（状态、错误类型、载荷）。
- **内置环境摩擦**：在初始状态中注入缺失参数、权限阻止、实体歧义等障碍，迫使智能体根据运行时反馈进行错误恢复。

### 2.3 基于证据的验证机制

- 按照任务完成语义将查询分为三类，并为每类配置固定验证器：
  - **Bucket 1: Tool Call** — 对需要确定性、规范操作序列的任务，精确匹配工具名称、调用顺序、参数域及归一化值，不允许无关副作用调用。
  - **Bucket 2: State Change** — 对允许多种执行路径但最终状态唯一确定的任务，比较终态数据库差异，拒绝破坏性或无关写入。
  - **Bucket 3: Agent Behavior** — 对开放式或交互式任务（如子代理委派、澄清提问、推荐），评估是否调用合适的子代理以及后续用户交互是否合理。
- **能力门控**：
  - 记忆门：当任务需要检索特定记忆 ID 时，要求完整轨迹中确实取回了所有必要的记忆记录。
  - 技能门：要求智能体必须加载标注的目标技能，并且在该技能路径下完成后续任务。

### 2.4 总体评分

- 评分采用固定权重组合：

  \text{Score}_{\text{overall}} = 0.50 \times \text{Basic} + 0.10 \times \text{SubAgent} + 0.20 \times \text{Memory} + 0.20 \times \text{Skill}
  \]
- 全部任务计入分母，缺失或无效预测均视为失败，以支持诊断和统一比较。

## 3. 实验设计

### 3.1 数据集与 Benchmark

- **MobilePA-Bench** 包含 **1,705 个任务**，覆盖 **13 个功能领域**、**212 个真实移动工具**。
- 任务分布：
  - Basic Tool Use：1,040 个任务
  - Sub-agent Collaboration：89 个任务
  - Memory Usage：376 个任务（其中 188 个 DB-primary、188 个 API-primary；176 个单轮、200 个多轮）

## 6. 主要结论与发现

- 当前最强模型（Claude-Opus-5）总体加权得分仅为 **75.52%**，13 个模型中 7 个低于 70%，说明前沿 LLM 在移动环境中仍不够可靠。
- **基础工具使用**相对最好（最高 83.85%），但即使最强模型仍有 168/1040 任务失败。
- **子代理协作**和**记忆使用**是主要瓶颈：子代理最高 77.53%，记忆最高仅 64.63%。
- **技能使用**（最高 78.00%）普遍优于记忆使用，说明预制复合技能可以减少长程规划中的错误累积。
- 没有任何单一模型在所有维度上领先，说明“识别正确路径”不等于“可靠完成状态操作”。
- 错误会跨能力边界级联：多阶段任务中，单一维度的较小误差会累积为端到端显著失败。
- 当前规划智能体缺乏“校准的克制”和自适应的错误恢复能力，在遇到权限错误或歧义时容易过早幻觉式调用工具，而不是提问澄清或根据反馈调整策略。

## 7. 优点

- **统一评估框架**：首次在同一交互式状态化环境中同时评估基础工具调用、子代理协作、记忆使用和技能使用四个维度，弥补了 GUI 中心基准与静态函数调用基准之间的鸿沟。
- **真实的运行时反馈**：沙箱会执行工具、更新数据库、返回动态错误信息，能够测试智能体的实时错误恢复能力，优于静态字符串匹配。

- **轻量高吞吐设计**：避免视觉渲染开销，适合未来用于强化学习训练和快速大规模评测。
- **开源基础设施**：开放全部任务、评测数据和沙箱环境，有利于社区复现和扩展。
