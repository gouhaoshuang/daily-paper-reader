## 摘要
基于视觉语言模型（VLM）的GUI智能体有望从在线强化学习（RL）中显著受益。然而，其训练受到两个根本问题的制约：当前针对GUI智能体的数据合成方法依赖特定环境，难以生成多样化数据；而现有评估器要么可扩展性有限，要么提供不准确且不可靠的奖励信号。为克服这些挑战，我们提出GSAR（目标状态锚定奖励），一种支持可扩展任务生成并提供可靠奖励信号以实现稳定高效策略优化的RL奖励框架。我们的方法采用自进化数据合成，通过任务执行生成多个环境，并产生多样化的任务和目标状态。在此基础上，状态锚定机制自动标注成功目标状态中与任务相关的UI元素作为参考锚点。在RL训练过程中，这些参考锚点提供准确、可扩展的奖励信号，显著提升训练效率。大量评估表明，我们的框架在离线轨迹验证上达到90%以上的准确率，且性能最接近基于规则的方法。此外，使用我们奖励框架训练的智能体在AndroidWorld和自建基准上均表现出强大性能，为GUI智能体训练建立了一种可扩展的方法。

## Abstract
Vision-Language Models (VLMs) based GUI agents stand to benefit significantly from online reinforcement learning (RL). However, their training is bottlenecked by two fundamental issues: current data synthesis methods for GUI Agents rely on specific environments and struggle to generate diverse data, while existing evaluators either suffer from limited scalability or provide inaccurate and unreliable reward signals. To overcome these challenges, we introduce GSAR (Goal-State-Anchor Reward), a RL reward framework that supports scalable task generation and delivers reliable reward signals for stable and efficient policy optimization. Our approach features self-evolving data synthesis, which produces multiple environments through task execution and generates diverse tasks and goal states. Complementing this, a state-anchor mechanism automatically annotates task-relevant UI elements in successful goal states as reference anchors. During RL training, these reference anchors provide accurate, scalable reward signals that substantially enhance efficiency. Extensive evaluations demonstrate that our framework achieves over 90% accuracy on offline trajectory verification and performs closest to rule-based methods. Furthermore, agents trained using our reward framework exhibit strong performance on both AndroidWorld and our constructed benchmark, establishing a scalable approach for GUI agent training.

## 二、论文提出的方法论

GSAR框架包含两个核心阶段：

**（一）自进化数据合成（Self-Evolving Data Synthesis）**

核心思想：让任务分布、环境状态与轨迹数据通过持续与GUI环境交互而共同演化，模拟真实应用使用方式。

1. **模拟真实世界使用**：对每个应用先执行多轮任务，通过任务执行不断改变环境状态，使应用页面从初始的简单、信息匮乏逐步演化为丰富多样的状态。
2. **自动任务生成**：对应用进行随机探索得到轨迹 T=(s₀,a₀,s₁,a₁,...,sₙ)，再由VLM（GPT-4o）基于每步观测 sᵢ 生成候选任务集合 Qᵢ，并将对应环境 e 保存为初始状态，构成"任务-环境"对。
3. **轨迹收集与过滤**：用GPT-4o执行生成的任务获得轨迹数据，同时改变应用状态；采用OS-Genesis提出的过滤策略 F 剔除任务-轨迹不匹配样本，最终得到三元组 (q, e, τ)。
4. **从简单到复杂的任务演化**（Task Complexification）：对上一轮成功完成的任务，通过三种策略生成更复杂多样的新任务：
   - **继承（Inherit）**：从当前迭代的终端状态出发，生成后续续接任务；
   - **合并（Merge）**：在原始环境中将原任务与额外子任务合并成更复杂的工作流；
   - **改写（Rewrite）**：保持原任务结构不变，仅修改具体参数（如文件名、数值、文本内容等）生成变体。
5. 最大迭代次数T根据轨迹中独特页面数映射到1\u20136范围，控制演化深度。

**（二）状态锚定奖励机制（State-Anchor Reward）**

核心思想：显式提供"目标状态参考"作为任务完成的标准答案，弥补模型评估器缺乏任务显式参照的缺陷。

1. **目标状态获取**：从自进化合成阶段提取成功轨迹的最终截图 s_g = s_T 作为目标状态；对困难任务由人工执行获取可靠完成参考。
2. **自动奖励标注**：给定目标状态 s_g 及其可访问性树（a11y tree）A_g，先将元素索引叠加到屏幕上，用VLM识别与任务相关的元素索引 K_g = M(I(s_g, A_g), A_g)，再检索这些元素的包围盒并锚定到截图上生成目标状态锚定参考 G = A(s_g, {bbox(A_kg) | k∈K_g})，全程无需人工。
3. **训练奖励计算**：在每个时间步 t，评估器接收当前GUI状态 s_t、动作历史 τ₀:ₜ、目标状态锚定参考 G，输出二元任务完成判断：

   y_t = E(s_t, τ₀:ₜ, G)，r_t = 1 若 y_t=1，否则 r_t=0。

## 八、不足与局限

1. **成功判定的单路径假设**：仅将单一最终状态作为任务成功标准，未考虑同一任务可能存在多种等效的完成方式。
2. **问答类任务的奖励误判风险**：对提问类任务，可能在真正产出正确答案前就给予正确奖励。
3. **纯视觉判定的局限性**：对于无法完全通过视觉表达完成状态的任务（如删除操作），模型难以标注合理的任务相关元素，可能需要自然语言或其他模态补充描述。
4. **依赖较强VLM能力**：任务生成、执行、过滤、锚定标注均由GPT-4o完成，生成轨迹质量受限于执行模型能力；对无法自动完成的任务仍需人工执行获取目标状态，未完全消除人工依赖。
5. **在线实验规模有限**：自建基准仅86条查询、AndroidWorld训练子集仅42个任务，评估规模较小；论文未对训练步数更多、任务类型更丰富的场景进行验证。
6. **对OpenAI闭源模型的依赖**：数据合成依赖GPT-4o，存在潜在的API成本和可复现性问题；锚定标注质量也受单一模型能力制约。
7. **基准覆盖不均衡**：与OS-Genesis等同源数据方法对比时，生成分布相似可能导致一定程度评价偏差。
