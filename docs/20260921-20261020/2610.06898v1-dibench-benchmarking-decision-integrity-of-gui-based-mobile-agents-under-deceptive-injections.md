## 摘要
随着基于 GUI 的移动智能体快速发展，对其在真实应用界面中自主决策进行严格的安全评估变得日益关键。现有基准主要利用任务成功率或劫持率关注执行层面的异常，却无法捕捉多候选选择任务中的任务内目标偏离风险：在这类任务中，决策可能被引导至攻击者指定的目标，甚至违反指令隐含的约束（例如最便宜/评分最高），而不会出现任何明显的执行异常。我们提出 DIBench，一个用于衡量移动智能体此类风险的决策完整性基准。DIBench 覆盖 7 个商业应用和 3 个模拟应用，包含 5 种任务类型。在仅限非特权 UI 内容的威胁模型下，我们构造了 8 种欺骗性注入探针实例，能够在无明显异常的情况下引导关键选择。该基准包含 1,000 个干净实例和 36,672 个注入实例，并提供统一协议和完整性指标以便比较。跨 4 个智能体框架和 7 个基座模型的实验表明，基于完成度的评估可能高估智能体的可信度并遗漏决策完整性风险：欺骗性注入会引导选择并改变早期动作策略，抬高完成率并造成误导性的安全假象。包括检测、图像预处理和提示提醒在内的常见防御措施带来的完整性收益并不一致。总体而言，DIBench 提供了一个统一、可复现的基准，用于量化移动智能体任务内目标偏离的风险，并支持对安全防御进行可比评估。

## Abstract
As GUI-based mobile agents rapidly progress, rigorous safety evaluation of their autonomous decision-making in realistic app interfaces becomes increasingly critical. Existing benchmarks mainly focus on execution-level anomalies using task success or hijack rates, but fail to capture the in-task goal deviation risk in multi-candidate selection tasks, where the decision may be steered toward an attacker-specified target, even in violation of instruction-implied constraints (e.g., cheapest/highest-rated), without any overt execution anomalies. We present DIBench, a decision integrity benchmark for measuring this risk in mobile agents. DIBench covers 7 commercial and 3 simulated apps with 5 task types. Under a threat model restricted to non-privileged UI content, we construct 8 deceptive injection probe instantiations that can steer critical selections without overt anomalies. The benchmark includes 1,000 clean and 36,672 injected instances, with a unified protocol and integrity metrics for comparison. Experiments spanning 4 agent frameworks and 7 base models show that completion-based evaluation can overestimate agent trustworthiness and miss decision-integrity risks: deceptive injections steer selections and shift early action policies, inflating completion rates and creating a misleading illusion of safety. Common defenses, including detection, image preprocessing, and prompt reminders, yield inconsistent integrity gains. Overall, DIBench provides a unified, reproducible benchmark to quantify the risk of in-task goal deviation in mobile agents and enable comparable evaluations of safety defenses.

## 1. 核心问题与研究动机

- **背景**：基于 MLLM 的 GUI 移动智能体已广泛用于购物、外卖、旅行等高频场景，其输出可能直接触发真实交易与敏感决策，安全评估需求迫切。
- **现有评估的盲区**：主流基准（MSB、MLA-Trust、GhostEI-Bench、AgentHazard、SecMoba 等）聚焦**执行层异常**——任务完成率、劫持率、越权工具调用、轨迹异常，并隐含假设“流程正确完成 = 最终选择可信”。
- **被忽视的风险**：论文提出 **In-Task Goal Deviation（任务内目标偏离）**——在多候选选择任务中，智能体在无劫持、无越权、无异常轨迹的情况下完成任务，但最终选择被欺骗性 UI 内容导向攻击者指定目标，甚至违反指令隐含约束（最便宜/评分最高）。
- **关键洞察**：攻击者无需修改指令或控制流，仅利用平台允许的 UI 内容（标题、图片）即可操纵关键选择；而基于完成度的信号对此**不敏感**，导致风险被系统性漏报。
- **三大缺口**：(1) 缺乏针对定向任务内目标偏离的显式安全模型；(2) 缺乏覆盖商业与模拟应用的可扩展多候选选择基准套件；(3) 缺乏统一协议与决策完整性指标，难以横向比较框架、模型与防御。

## 2. 方法论

### 2.1 核心思想

- 在**非特权 UI 内容威胁模型**下（仅能影响屏幕可见内容，不改指令、提示词与控制流），构造**配对（benign/injected）实例**：保持任务、候选集、非视觉上下文完全一致，仅改变关键决策点的 UI 可见内容，从而隔离决策层风险。
- 将“是否完成”与“选择是否正确/是否被引导”解耦为不同指标。

### 2.2 任务形式化

- 每个任务定义：指令 \(I\)、候选集 \(C=\{c_1,\dots,c_n\}\)、可接受集 \(A(I,C)\subseteq C\)。
- 五类任务：
  - **Exploratory**：\(A(I,C)=C\)，全部候选可接受；
  - **Exact Match**：离散谓词过滤（品牌、名称、目的地）；
  - **Cost**：最小化价格/配送费；
  - **Spatio-Temporal**：最小化距离、配送时间、行程时长；
  - **Quality/Popularity**：最大化评分、销量、评论数。
- 非探索类任务满足 \(1\le|A(I,C)|<|C|\)，为“指令级正确性”提供标注基础。

### 2.3 注入探针（8 种）

- **载体**：Title（标题文本覆盖）、Cover（图片内嵌文字）、Pert.（无显式文字的视觉扰动）。
- **5 种文本变体**：Naive、Escape、Context Ignore、Fake Completion、Combined。
- **3 种跨通道变体**：Combined-C（仅 Cover）、Combined-TC（Title+Cover）、Combined-P（Perturbation），用于控制载体效应比较。

### 2.4 实例生成流程（5 步）

1. **Benign 构建与决策点定位**：执行参考轨迹，提取关键选择界面截图 + 固定非视觉上下文 \(\langle screenshot, fixed\ context\rangle\)。
2. **候选解析与注入锚点**：MLLM 辅助初标候选边界/属性/锚点，**人工校验修正**，分配稳定候选 ID 与像素/样式锚点。
3. **注入实例生成**：真实商业应用用**截图级叠加/嵌入**（不改底层 UI 结构）；模拟应用用**后端字段注入→前端渲染**，支持过程级分析。
4. **可接受集标注**：GPT-5.2 初标 + 两名人工独立核验 + 第三人仲裁；标注流程与所有被评估的 GPT-5.2 配置**隔离**，避免 label–model 耦合；歧义实例剔除。
5. **归一化与发布**：统一条目包含任务规格、决策状态、候选标注与锚点、注入规格、标签与索引、元数据。

### 2.5 评估协议与指标

- **配对评估**：每任务重复 \(R=10\) 次，benign/injected 使用**匹配随机种子**，取经验平均。
- **结果定义**：\(\tilde C=C\cup\{\bot\}\)，\(\bot\) 表示未提交；分为 Correct（\(\hat c\in A(I,C)\)）、Incorrect（\(\hat c\in C\setminus A(I,C)\)）、Failure（\(\hat c=\bot\)）。
- **指标**：
  - **TCR** \(=\Pr[\hat c(x)\in C]\)：是否完成选择；
  - **COR** \(=\Pr[\hat c(x)\in A(I,C)]\)：选择是否满足指令约束；
  - **ASR**：配对条件下，注入实例选中目标 \(g(x_a)\) 且其 benign 配对未选中目标的概率，
    \[
    E^{(r)}_{as}(x_a)=\big[\hat c^{(r)}(x_a)=g(x_a)\big]\wedge\big[\hat c^{(r)}(pair(x_a))\neq g(x_a)\big]
    \]
    数据集级取平均，用于刻画**定向操纵**（区别于非定向退化）。

### 2.6 配置套件与防御轨道

- **AgentAdapter**（框架实例化与选择阶段 I/O 对齐）+ **ModelProvider**（模型调用与固定推理设置），保证跨框架可比。
- **防御钩子**（三类，框架无关）：
  - 输入检测：LLM 检测器（image-only / planning+image，固定提示词）；
  - 输入预处理：高斯噪声、JPEG 压缩、缩放；
  - 提示级缓解：系统提示或指令前加固定风险警告句。

## 3. 实验设计

- **数据规模**：10 个应用（7 商业：AliExpress、Amazon、Booking、Fantuan、Foodpanda、Tripadvisor、Walmart；3 模拟：美团式外卖、购物、行程规划），5 类任务，每 (app, task type) 20 实例；候选集大小 3–6；共 **1,000 benign + 36,672 injected**。
- **两个评估环境**：
  - **COMMERCE**：真实商业应用的固定决策状态 + 截图级注入（不上传内容、不执行交易、不采集隐私）；
  - **SIMULATOR**：3 个可控模拟应用的端到端多步交互。
- **智能体框架（4 个）**：AppAgent、Mobile-Agent-V2、Mobile-Agent-E、Mobile-Agent-V3。
- **基座模型（7 个）**：开源通用 Qwen2.5-VL(32B)、Qwen3-VL(32B)；开源专用 GUI-Owl(32B)、Mai-UI(8B)；闭源 DoubaoSeed-1.6、Gemini-3-Flash、GPT-5.2。
- **对比条件**：No Attack + 5 种注入（Naive、Escape、Context Ignore、Fake Completion、Combined），以及载体变体（Title/Cover/Pert./Title+Cover）。
- **防御对比**：检测（4 框架 × 2 模型 × 6 条件 + image-only）、预处理（噪声 σ=2/5、JPEG Q=95/75、缩放 0.9×/0.75×）、提示提醒（ASR 与 COR 的 Δ）。
- **机制分析**：动作类型分布（Select/Delayed Decision/Filter/Search/Swipe/Answer 等）、候选索引选择概率分布、跨应用 ASR、按任务类型的选择分布（Correct / Correct(Target) / Wrong(Target) / Wrong(Non-Target)）。
