## 摘要
移动 GUI 智能体通过点击和滑动等 GUI 操作完成任务。这些操作可广泛适用于各类应用，但在到达导航界面时存在局限。一次深链接调用即可替代逐屏执行的一系列 GUI 操作。因此，我们引入混合交互：使用深链接进行直接导航，使用 GUI 操作完成其他屏幕内操作并在需要时回退。为实现这一点，我们通过静态分析发现候选深链接，在真实设备上验证它们，并描述其观测到的落地屏幕。该过程创建了一个经过验证且有依据的深链接目录，将每个可用深链接与其落地屏幕描述配对。利用该目录，我们提出 GUI-Hopper，它在真实设备上的商业应用中提升了任务成功率，进一步证明了混合交互的优势。

## Abstract
Mobile GUI agents complete tasks using GUI actions like taps and swipes. These actions are broadly applicable across applications, but reaching a navigation interface. A single deeplink call can replace a sequence of screen-by-screen GUI actions. We therefore introduce hybrid interaction, using deeplinks for direct navigation and GUI actions for other on-screen operations and fallback. To enable this, we discover candidate deeplinks through static analysis, validate them on real devices, and describe their observed landing screens. This process creates a verified and grounded deeplink catalog that pairs each working deeplink with a description of its landing screen. Using this catalog, we introduce GUI-Hopper, a improves task success in commercial applications on real devices, further demonstrating the benefits of hybrid interaction.

## 1. 核心问题与研究背景

- **研究对象**：移动端 GUI 智能体（Mobile GUI Agents），即通过“看屏幕—点按/滑动”来操作手机应用完成任务的智能体。
- **核心痛点**：
  - 点击、滑动等 GUI 动作**通用性强**，可跨应用复用，不依赖应用内部接口；
  - 但在**导航类需求**上效率极低——要到达某个功能页，往往需要逐屏点击、经过多层菜单，路径长、步数多，每一步都可能出错，误差会累积。
- **关键观察**：应用原生的 **deeplink（深链接）** 一次调用即可直达目标页面，等价于替代一长串逐屏 GUI 操作。

## 2. 方法论

### 2.1 核心思想
构建一个**经过验证且有依据（verified and grounded）的 deeplink 目录**，把“可用 deeplink”与“其落地屏幕的描述”配对；智能体在决策时可将 deeplink 作为一种高层动作调用，并与常规 GUI 动作混合使用。

### 2.2 关键技术流程（文字化描述）

1. **候选 deeplink 发现（静态分析）**
   - 对应用安装包做静态分析，提取其中声明的深链接入口信息（如 scheme / host / path、intent filter 等路由声明），得到候选 deeplink 集合。
   - 该步骤成本低、可批量，但产出的是“候选”，存在声明了却不可用、需要参数、受权限限制等情况。

2. **真机验证（validation）**
   - 在真实设备上逐条实际触发候选 deeplink，剔除无法打开、崩溃、跳转到无关页面的条目。
   - 只保留“真实可用”的链接，保证目录的可靠性。

3. **落地屏幕描述（grounding）**
   - 对每条验证通过的 deeplink，记录并描述其实际落地界面（页面类型、可见内容/功能），形成“链接 ↔ 落地页语义”的对应关系。
   - 这一步是让智能体能够**判断某条 deeplink 是否服务于当前任务**的前提，避免盲目跳转。

4. **目录构建**
   - 输出结构化目录：每条记录 = 可用 deeplink + 落地屏幕描述（可能还含参数、所属应用等元信息）。

5. **GUI-Hopper 智能体（混合决策与执行）**
   - 给定任务与当前屏幕，智能体在两类动作间选择：
     - **deeplink 动作**：依据目录检索/匹配候选链接，直接跳转到目标页面；
     - **GUI 动作**：点击、滑动、输入等，用于页面内操作与细粒度交互。
   - **兜底机制**：当 deeplink 不可用、跳转结果不符合预期或任务需要页面内操作时，回退到 GUI 动作序列。
   - 由于目录已附带落地页描述，跳转后智能体可对“是否到达预期界面”进行校验，从而决定继续执行还是回退。

## 6. 主要结论与发现

- **混合交互有效**：将应用原生 deeplink 与 GUI 动作结合，可在真实设备的商业应用上**提升任务成功率**。
- **deeplink 可被系统化获取**：通过“静态分析发现 → 真机验证 → 落地页描述”的流水线，能够构建**可验证、可接地**的 deeplink 目录，说明该资源具备工程可行性。
- **兜底设计是必要的**：deeplink 并不能覆盖全部操作，仍需 GUI 动作完成页面内交互并在失败时回退，二者是互补而非替代关系。
- **动作空间层面的增强是一条有效路径**：相比只优化模型能力，为智能体提供更高层的“跳转”原语，能直接压缩导航路径、减少累积误差。

## 7. 优点（亮点）

- **问题选择精准**：抓住“GUI 动作通用但导航低效”这一结构性矛盾，用 deeplink 做互补，动机清晰且有说服力。
- **动作空间创新而非模型堆叠**：不依赖更大模型，而是扩展智能体可调用的动作类型，具有较强的可迁移性与低成本特性。
- **“验证 + 接地”双保险**：不仅挖掘链接，还在真机验证可用性，并为落地页生成描述，缓解了 LLM 智能体“幻觉调用不存在接口”以及“跳转后不知道自己在哪”的两类典型失败。
- **兜底机制务实**：保留 GUI 动作作为 fallback，避免因 deeplink 覆盖率不足而导致整体性能下降，工程上更稳健。
- **真实商业应用 + 真机评测**：相比沙盒环境，更接近实际部署条件，结论的外部效度更高。
- **产出可复用资产**：deeplink 目录本身可作为基础设施，供其他移动智能体工作复用。

## 8. 不足与局限

- **覆盖率天花板**：静态分析只能发现应用**主动声明**的 deeplink，未暴露或需复杂参数/登录态的深层页面无法覆盖，混合交互的收益受目录规模限制。
- **维护成本与时效性**：应用版本更新会导致链接失效、路由变更、落地页改版，目录需要持续重建与重验证，长期运行成本未在可见材料中讨论。
- **状态与权限依赖**：deeplink 跳转常依赖登录状态、地区、账号权限；未登录或权限不足时的行为（是否静默失败、是否跳到首页）会影响智能体判断。
- **语义鸿沟风险**：落地页描述若由模型生成，可能不准确或过于粗略，导致链接与任务的匹配错误；描述质量对最终性能的影响需要消融验证。
- **可能“跳过”必要的上下文**：直接跳转可能绕过用户本应确认的中间步骤，在需要多步确认或状态累积的任务上未必适用，也存在一定的安全/隐私考量（如绕过引导页、直达敏感页面）。
- **实验信息不透明（基于现有材料）**：应用与任务集规模、基线设置、重复次数、方差、显著性均未知；若任务集与目录构建所用的应用/页面高度重叠，存在乐观偏差风险。

- **平台局限**：方法与应用包静态分析、intent 机制强相关，向 iOS 或跨平台场景的迁移性未在可见材料中说明。
