## 摘要
视觉语言模型（VLM）已成为自主移动 GUI 智能体的常见基础，但大多数现有系统在几乎每个交互步骤都依赖 VLM 同时进行规划与动作定位，导致显著的延迟和模型服务成本。我们提出 Jev-Mobile，将该范式转变为低频 VLM 规划与高频轻量执行：VLM 指定局部目标，可访问性树定义结构化的可执行动作空间，而 Jev 作为一种快速的类型化决策模型，在该空间内反复选择动作。该设计允许在单次 VLM 决策下执行多个 GUI 动作，减少昂贵的 VLM 推理，同时保持自适应交互。在完整的 AndroidWorld 任务套件上，Jev-Mobile 达到 79% 的任务成功率，而 SeeAct-V 为 78%，逐步式 VLM 基线为 84%。在成功轨迹中，相对于逐步式 VLM，其平均端到端执行时间降低 32.7%，平均模型 API 成本降低 73.4%。这些结果表明，将高层 VLM 推理与低层动作执行解耦，可在保持有竞争力的任务性能的同时显著提升移动 GUI 智能体的效率。

## Abstract
Vision-language models (VLMs) have become a common foundation for autonomous mobile GUI agents, but most existing systems rely on the VLM for both planning and action grounding at nearly every interaction step, leading to substantial latency and model-serving cost. We introduce Jev-Mobile, which shifts this paradigm to low-frequency VLM planning and high-frequency lightweight execution: the VLM specifies local goals, the accessibility tree defines a structured executable action space, and Jev, a fast typed decision model, repeatedly selects actions within this space. This design allows multiple GUI actions to be executed under a single VLM decision, reducing expensive VLM inference while preserving adaptive interaction. On the full AndroidWorld task suite, Jev-Mobile achieves 79% task success, compared with 78% for SeeAct-V and 84% for a Step-wise VLM baseline. Among successful trajectories, it reduces mean end-to-end execution time by 32.7% and mean model API cost by 73.4% relative to Step-wise VLM. These results show that decoupling high-level VLM reasoning from low-level action execution can substantially improve mobile GUI agent efficiency while maintaining competitive task performance.

# Jev-Mobile 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：视觉语言模型（VLM）已成为自主移动 GUI 智能体的主流基础，但绝大多数系统在**几乎每一个交互步**都让 VLM 同时完成“高层规划”和“底层动作落地（grounding）”。
- **问题**：这种“每步一次大模型推理”的范式带来两方面代价：
  - **延迟高**：端到端执行时间被昂贵的 VLM 推理拖长；
  - **成本高**：模型服务（API）费用随步数线性增长。
- **核心研究问题**：能否将“高层推理”与“低层动作执行”解耦——由 VLM 只在低频给出**局部目标**，再由一个快速、轻量的**类型化决策模型（Jev）**在同一目标下连续执行多步 GUI 动作？
- **整体含义**：论文主张把 VLM 的角色从“逐步决策者”收缩为“任务解释者 + 局部目标设定者”，而把逐屏动作选择交给一个受约束的决策服务，从而在保持竞争性成功率的同时大幅降低时间与成本。

## 2. 方法论

### 2.1 核心思想：低频规划 + 高频执行

- **VLM（规划者）**：读取任务指令、当前截图与可访问性树、以及“按局部目标分组的真实动作历史”，一次调用输出：
  - 决策类型 $d_k \in \{\text{delegate}, \text{finish}, \text{blocked}\}$；
  - 局部目标 $g_k$（仅 delegate 时）；
  - 可选的精确文本值 $v_k$（如从笔记中复制的会议时间字符串）。
- **Jev（执行者）**：在 $g_k$ 下反复从候选集中选择动作，可连续执行多个原子动作而**不触发新的 VLM 调用**；返回 `DONE` 交还控制权，或返回 `BLOCKED` 请求重新解释。
- **关键约束**：VLM **不生成**“委托后总结（post-delegation summary）”，避免模型自述引入幻觉；VLM 只看到程序记录的、真实提交给设备的动作历史。

### 2.2 关键技术细节

- **观测定义**：$o_t = (I_t, T_t, z_t)$，即截图、可访问性树、可观测设备上下文。Jev 只接收文本树、局部目标、本委托内的动作历史与候选描述，**不看截图**。
- **候选集构建**：$C_t = f(T_t, z_t, v_k)$ 为确定性程序枚举：
  - 遍历原始树节点（含 clickable 父节点）；
  - 仅对“可见、可用、边界有效”的节点按显式 flag 生成 click / long-press / scroll / focus；
  - $v_k$ 中显式给出的文本可对聚焦输入框生成 input 动作；
  - 按可观测设备状态补充 Back、Home、Enter、Open app；
  - 每个候选绑定“局部 ID + 动作 + 节点/区域 + 参数”，标签取首个可用文本属性加节点索引。
- **落地保证（re-observation）**：执行前用**新鲜观测**校验候选；执行一个动作后立即重新观测并重建 $C_{t+1}$，旧 ID 与坐标全部失效，避免界面变化后“看似相同的节点”被静默错绑。
- **类型化决策**：每次 Jev 请求是一个**类型化选择**，候选 ID、`DONE`、`BLOCKED` 映射到描述；适配器在执行前校验类型与 ID。
- **事件账本**：每步记录所选 ID、实际动作参数、执行状态、前后观测 ID、确定性变化描述；交接时只传当前截图/树 + 分组动作历史，超长时用“目标 + 步数 + 交接原因”压缩并记录被省略的组。
- **预算与失败处理**：墙钟时间、动作数、调用数、等待、重试共享一个 episode 预算；非法输出、过期 ID、溢出、API 错误均计入账本；非幂等动作的模糊响应触发检查而非盲目重发。
- **无训练**：不训练新模型、不做层级修复、不做语义字段绑定、不引入学习型路由器或跨任务记忆。

### 2.3 一个说明性例子（非实测结果）

- 任务：把笔记中的会议时间复制进 Calendar。
- VLM 负责读懂笔记并给出**精确时间字符串**；Jev 负责在后续多个界面上选择字段、按钮、Save 等候选。
- 若笔记只以图片形式存在，或所需控件不在树中，Jev 返回 `BLOCKED`；当前版本**无法**从图像合成坐标动作。

## 3. 实验设计

- **Benchmark**：完整 **AndroidWorld** 任务套件，使用其任务初始化与终端评估器；隐藏任务状态与终端奖励不进入任何在线模型提示。
- **对比系统（仅 3 个）**：
  1. **Step-wise VLM**：共享的通用 VLM 在每一步从当前观测与交互历史中选择动作；
  2. **SeeAct-V**：同一通用 VLM 做逐步决策，另用 **UI-TARS-1.5-7B** 做视觉落地（替代原论文的 UGround，论文明确披露该替换）；
  3. **Jev-Mobile**：VLM 设定局部目标 + Jev 在当前树候选内连续选择，交接模式为 “jev action history”，无生成式总结。
- **模型配置**：所有通用 VLM 角色统一使用 **Qwen3.8-Max**（OpenRouter ID `qwen/qwen3.8-max-0902`）；Jev 与 UI-TARS 为专用执行模型。
- **指标**：
  - 全任务成功率 $\mathrm{SR} = |D|^{-1}\sum_{i\in D} S_i$；
  - 成功轨迹上的平均总在线时间（含规划、执行模型请求、设备交互、等待、重试）；
  - 成功轨迹上的平均执行模型时间；
  - **执行器成本**（成功轨迹上的队列总和，非单轨迹价格）；
  - **平均每成功轨迹模型 API 成本**（所有模型角色费用的平均）。

- **实验组数**：仅**一组主实验**——在完整 AndroidWorld 上对比 3 个系统；**没有消融实验**，没有多 benchmark，没有多随机种子/方差报告，没有统计显著性检验。

- **公平性方面**：

## 7. 优点

- **范式清晰且有实用价值**：把“贵的推理”和“快的选择”分离，直接命中移动智能体部署中的延迟与成本痛点。
- **动作空间结构化、可验证**：候选由可访问性树**确定性生成**，每个候选绑定具体观测；“执行前校验 + 执行后重观测”从机制上抑制了界面变化导致的错绑，比自由生成坐标更可控。
- **拒绝生成式中间产物**：不产生“委托后总结”，只回传真实提交的动作历史，减少幻觉与信息失真。
- **零训练、易复现**：无需新数据、新模型或层级修复，工程上可直接替换现有 VLM 智能体的执行层。
- **失败归因清晰**：显式区分 **coverage（有无可接受候选）/ selection（Jev 是否选对）/ handoff（控制权是否恰当交还）** 三类失败，比单一成功率更有诊断价值。
- **表述克制、披露充分**：主动说明 SeeAct-V 的落地器替换、结果刻画的是完整系统而非 Jev 的孤立效应、以及成功轨迹条件统计的口径。

## 8. 不足与局限

- **基准单一**：仅在 AndroidWorld 上评测，未覆盖 Web（DOM 结构、页面动态差异大），结论外推性受限。
- **强依赖可访问性树**：视觉上可见但树中缺失的目标无法转为可执行候选；当前版本**没有坐标生成的视觉回退**，这是结构性天花板。
- **输入限制**：当前输入路径仅支持可打印 ASCII 文本，非 ASCII 输入被拒绝，限制了多语言场景。
- **长历史压缩有损**：动作历史超限时被“目标 + 步数 + 原因”替换，可能丢失关键上下文。
- **消融缺失**：未做“Jev vs 小 VLM 在同一委托工作流中”的对照，也未做候选构建方式、交接粒度、预算设置等消融，无法定位收益来源。
- **统计严谨性不足**：未报告任务实例数、成功轨迹样本量、方差或多随机种子，79% 与 78% 的差异缺乏显著性支撑。
- **成本/时间口径偏差**：仅在成功轨迹上统计，忽略失败轨迹开销，可能系统性低估低成功率方案的真实代价。
- **公平性隐忧**：三系统观测/动作接口不同，SeeAct-V 使用替代落地器，比较更接近“系统级”而非“组件级”。
- **外部效度**：单一 VLM 后端（Qwen3.8-Max）、单一作者、Jev 服务的规模与部署细节未公开，复现与迁移存在不确定性。
