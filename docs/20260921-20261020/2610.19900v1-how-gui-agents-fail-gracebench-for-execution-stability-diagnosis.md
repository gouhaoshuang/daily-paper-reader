## 摘要
随着GUI智能体越来越多地被部署用于移动任务自动化，其可靠性不仅取决于最终任务结果，还取决于它们是否通过稳定的交互轨迹达成这些结果。在自动化工作流中，不必要的动作、绕路和执行错误会给收集到的数据增加噪声、引入不可逆的副作用或削弱信任，即使智能体最终完成了任务。因此，系统性地诊断执行稳定性十分重要，包括智能体是否偏离可行路径、进入循环、停滞不前，或从不稳定动作中恢复。然而，现有基准主要评估最终任务成功或少量中间里程碑，导致步骤级执行行为仍不清晰。为弥补这一空白，我们提出GraceBench，一个在线评估框架，它将移动应用的可达交互空间表示为UI转移图（UTGs），为步骤级执行诊断提供结构化参考。为支持动态UI观察与图状态之间的可靠对齐，GraceBench在此图对齐表示上使用基于视频锚定的轨迹评估，通过偏离率、循环负担率和恢复能力等指标，在最终成功之外评估过程稳定性。GraceBench包含跨越10个应用的169个任务，并构建了10个UTGs，包含2,909个规范GUI状态和3,116个观测转移。在3,718条轨迹上，GraceBench表明结果分数会掩盖执行不稳定性：GPT-5.6 Sol取得最高成功率（SR），但恢复能力最低，51.24%的成功运行仍包含偏离或循环，并且具有相同成功率（SR）和完成率（CR）的轨迹在恢复行为上可能差异显著。代码和数据将在 https://iaie-physicalai.github.io/GraceBench 发布。

## Abstract
As GUI agents are increasingly deployed for mobile task automation, their reliability depends not only on final task outcomes, but also on whether they reach these outcomes through stable interaction trajectories. In automation workflows, unnecessary actions, detours, and execution errors can add noise to collected data, introduce irreversible side effects, or undermine trust, even when the agent eventually completes the task. It is therefore important to systematically diagnose the execution stability, including whether an agent deviates from a feasible path, enters a loop, becomes stagnant, or recovers from unstable actions. Existing benchmarks, however, primarily assess final task success or a small set of intermediate milestones, leaving step-level execution behavior unclear. To bridge this gap, we introduce GraceBench, an online evaluation framework that represents the reachable interaction space of mobile applications as UI Transition Graphs (UTGs), providing a structural reference for step-level execution diagnosis. To support reliable alignment between dynamic UI observations and graph states, GraceBench uses video-grounded trajectory evaluation over this graph-aligned representation, assessing process stability beyond final success with metrics such as deviation rate, loop burden rate, and recovery ability. GraceBench contains 169 tasks spanning 10 applications and constructs 10 UTGs with 2,909 canonical GUI states and 3,116 observed transitions. Across 3,718 trajectories, GraceBench shows that outcome scores hide execution instability: GPT-5.6 Sol achieves the highest success rate (SR) but the lowest recovery ability, 51.24% of successful runs still contain a deviation or loop, and trajectories with the same success rate (SR) and completion rate (CR) can differ substantially in recovery behavior. Code and data will be released on https://iaie-physicalai.github.io/GraceBench.

- **核心问题**：智能体的可靠性不仅取决于**是否最终完成任务**，还取决于**是否通过稳定的交互轨迹达成**。但现有基准存在明显盲区：
  - 以 AndroidWorld 为代表的在线基准只检查**最终状态是否满足目标**；
  - A3、SPA-Bench、ProBench 等过程感知基准引入中间里程碑/子任务，但仍属**粗粒度语义检查点**，隐含假设任务近似线性；

- **研究含义**：需要一种**步骤级、结构化**的诊断手段，判断智能体是否偏离可行路径（deviation）、陷入循环（loop）、停滞（stagnation），以及能否从错误中恢复（recovery），从而支撑更可靠的 GUI 智能体部署与优化。

## 2. 方法论

### 2.1 核心思想
- 将移动应用的**可达交互空间**建模为 **UI 转移图（UTG）**：节点 = 可视觉验证的 GUI 状态，有向边 = 可执行动作转移 `e=(v_i, a, v_j)`。
- 每个任务定义为 UTG 的**任务特定子图** `G_τ ⊆ G`（含多条合法路径，排除无关绕路），将智能体真实执行轨迹**映射回该子图**，实现步骤级诊断。
- 由于移动 UI 动态变化（加载、弹窗、动画、内容刷新），采用**视频锚定的轨迹评估**，用与动作时间戳同步的录屏证据对齐观察与图状态。

### 2.2 关键技术流程

**（A）UTG 构建（智能体驱动探索 + 人工审核）**
- 智能体通过 ADB 观察截图与 UI 层级，识别可交互元素、选择动作并执行；外部 harness 负责证据采集、动作执行、图序列化、风险门控与一致性检查。
- 状态签名：截图哈希 + 结构哈希（Activity、节点数、可点击数、前 18 个稳定控件），结合语义状态名与加权匹配规则去重合并。
- 候选动作打分：`s_tap(c) = 8·I_clickable + 5·I_labeled + 6·Σ I[k∈label] − 12·I_risk`；待探索边按 `s_plan` 排序（含滑动、优先级、风险惩罚等）。
- **安全边界**：支付、下单、充值、授权、发布等高风险操作被标记为边界状态（defer），不执行副作用确认。
- 探索后经人工审核、裁剪、剪枝、去重，得到最终 UTG。

**（B）任务整理**
- 选取**可视觉验证、完成语义稳定**的终端节点作为任务目标；
- 提取任务子图 `G_τ=(V_τ, E_τ)`，包含替代合法路径；
- 每个任务生成**两种指令变体**：简洁指令（用户级目标）与详细指令（沿一条人工验证的可行路径给出步骤级操作），用于分离“规划歧义”与“底层执行稳定性”。

**（C）视频锚定轨迹评估（四阶段）**
1. 按动作时间戳将整段录屏切分为步骤级视频片段；
2. 检索任务子图作为参考结构；
3. 视频评估器分析局部转移 `(o_t, a_t, o_{t+1})`，将前后观察映射为图状态：
   - `v̂_t = v_i`（若 `o_t` 匹配 `v_i ∈ V`），否则 `v̂_t = v_out`（图外状态）；
   - 图对齐转移：`(o_t, a_t, o_{t+1}) → (v̂_t, a_t, v̂_{t+1})`；
4. 为每步打上四类标签之一：
   - **on path**：沿 `G_τ` 合法转移；
   - **stagnation**：无有意义状态变化；
   - **deviation**：离开任务子图或进入 `v_out`；
   - **recovery**：从 off-path 状态返回合法状态/转移。
- 得到诊断轨迹 `T' = [(v̂_1,a_1,v̂_2,ℓ_1), …, (v̂_T,a_T,v̂_{T+1},ℓ_T)]`。

### 2.3 评估指标
- **SR**：任务成功率（沿用冻结的逐轨迹评估摘要标签）；
- **CR**：已完成必需转移数 / 必需转移总数 `|E_req|`；
- **DR**：偏差标签步数 / 可评分步数（排除 WAIT、COMPLETE）；
- **LBR**：循环覆盖步数 / 决策步数（含 WAIT，不含 COMPLETE），仅在发生循环的轨迹上聚合；
- **RSR**：成功恢复次数 / 偏差事件数；
- **ARL**：成功恢复的平均步数（`t_rec − t_dev`）；
- **RA**：每个恢复机会贡献 `c_i = 1/max(1, latency_i)`（恢复）或 0（未恢复），再按机会数取平均，综合恢复成功率与速度。

## 6. 主要结论与发现

- **失败与不稳定高度相关**：失败轨迹的 DR 显著更高（详细 0.3067 vs 0.0889；简洁 0.3618 vs 0.1412），循环发生率更高（0.6525 vs 0.2066；0.6520 vs 0.2748），LBR 更高，RA 更低。
- **成功掩盖不稳定**：1,294 条成功轨迹中 **51.24%（663/1,294）至少含一次偏差或循环**；详细指令下 36.78% 含偏差、20.66% 含循环，简洁指令下升至 46.11% 与 27.48%；另有 126 条成功轨迹 DR 为 0 但仍含循环。
- **高 SR ≠ 高稳定性**：GPT-5.6 Sol 在两种条件下 SR 最高（0.6391），但**恢复能力（RA）最低**（详细 0.4454，简洁 0.4525）；GLM-5

- **高 SR ≠ 高稳定性**：GPT-5.6 Sol 在两种条件下 SR 最高（0.6391），但**恢复能力（RA）最低**（详细 0.4454，简洁 0.4525）；GLM-5.3-Flash 等模型虽然 SR 略逊，却在 DR、LBR 与 RA 上表现更均衡。这说明**模型排名高度依赖所选指标**：若只看成功率，会系统性高估“靠反复试错撞到终点”的模型，低估“路径干净但偶有失手”的模型。论文据此主张，模型选型应同时报告结果指标与过程指标，而非单一 SR 排序。
- **指令粒度是可分离的失败来源**：详细指令（给出步骤级路径）在总体上提升了 SR，并显著压低偏差率与循环发生率，但改善幅度因模型而异——对规划能力弱、易在开放目标下“猜路径”的模型帮助更大，对底层执行本就不稳的模型改善有限。这一对比支持了作者的假设：**“规划歧义”与“执行稳定性”是两类可分别诊断、分别干预的失败模式**。
- **恢复的及时性比“是否恢复”更有判别力**：成功轨迹中，偏差发生后往往能在较少步数内回到合法路径；而失败轨迹更多表现为“偏差后长时间滞留于图外状态”或“反复进入同一循环”。RA（同时编码恢复成功率与恢复时延）因此比单纯的恢复率更能区分模型，这也解释了为何高 SR 模型的 RA 反而可能偏低——它们可能依赖更多次“迟到的恢复”。
- **过程指标具有独立的信息价值**：在分组预测消融中，DR、LBR、RA 在控制步骤数与执行时长后，仍对任务成败具有增量解释力。也就是说，过程信号并非结果信号的冗余代理，而是提供了结果标签无法覆盖的可靠性维度。
- **结论对任务划分与场景组成稳健**：在 1,000 次分层重采样下，模型间的相对排序保持较高秩相关；留一模型、留一场景的敏感性分析中，主要结论方向不变，说明发现并非由个别任务或个别应用驱动。
- **自动标签与人工判断总体一致**：约 10% 轨迹的盲审显示，自动过程标签与人工参考在多数转移上一致，分歧主要集中于**动态 UI（加载态、动画、内容刷新）造成的状态匹配歧义**，以及 `v_out`（图外状态）边界判定。这既验证了视频锚定评估的可用性，也指出了其误差来源。

## 7. 局限性与需要注意的问题

- **UTG 构建成本高**：依赖智能体探索加人工审核裁剪，10 个应用即产生 2,909 个规范状态；扩展到大规模应用生态时，构建与维护成本会成为瓶颈，论文未给出自动化审核的可行路径。
- **评估器本身是模型**：视频评估阶段依赖模型将观察映射到图状态，其判读误差会传导到所有过程指标；虽然有审计背书，但审计样本仅约 10%，长尾场景的标签质量仍不确定。
- **环境单一**：全部实验在物理 Android 设备、固定分辨率与固定动作预算（15 步）下完成；跨设备、跨系统版本、跨语言/地区的泛化性未被检验。两个 GUI 专用模型还在独立主机采集，存在环境混杂的可能。
- **安全门控带来的路径截断**：支付、下单、授权等高风险动作被标记为边界状态而不执行副作用确认，这可能使部分任务的合法路径被人为缩短，从而影响 CR 与 DR 的可比性。
- **统计上的谨慎边界**：部分场景级分析样本量小、属探索性且未做多重检验校正；结果控制配对中的模型对并非独立样本，作者已声明区间按任务聚类计算，读者不应将其解读为独立模型间的显著性检验。
- **复现性信息缺口**：未报告硬件配置与完整算力开销，且 GUI 专用模型的视频/截图原始文件未纳入分析包，削弱了端到端复现的可能。

## 8. 总体评价与启示

- **核心贡献**：把“智能体可靠性”从模糊的工程直觉，操作化为**可测量、可分解、可归因**的一组步骤级指标（DR / LBR / RSR / ARL / RA），并以 UTG 提供结构化的参照系；其价值不止于一张排行榜，而在于提供了一套**失败归因语言**。
- **方法论意义**：视频锚定的轨迹评估绕开了“只比对终态截图”的信息损失，使循环、停滞、偏离与恢复这些此前被隐藏的行为第一次成为一等公民；任务特定子图的设计也避免了对“唯一正确路径”的过度假设。
- **实践启示**：对部署方而言，SR 达标并不等于可上线，**成功轨迹中过半含偏差或循环**这一发现提示需要引入过程级监控与早期预警；对模型开发者而言，恢复能力（尤其恢复时延）应作为独立优化目标，而非成功的副产品。
- **可拓展方向**：UTG 构建的自动化、跨设备一致性校验、将过程指标用于在线智能体的实时干预（如在检测到循环时触发重规划），以及把该框架迁移到 Web/桌面等非移动 GUI 场景。
