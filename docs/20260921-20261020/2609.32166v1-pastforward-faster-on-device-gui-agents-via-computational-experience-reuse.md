## 摘要
在边缘设备上运行 GUI 智能体可使敏感屏幕内容与交互历史保留在本地，但在每个动作步进行推理的计算开销使部署面临挑战。现有的 GUI 智能体系统要么在每个动作步执行完整的视觉语言模型（VLM）推理，要么复用与先前任务匹配的粗粒度知识。然而，动态的移动环境与用户任务使得在不进行额外微调或任务特定离线探索的情况下，难以充分利用先前的任务执行经验。为应对这一挑战，我们提出 PastForward，该系统通过对日常任务执行过程中积累的计算经验进行经过验证的细粒度复用，来加速 GUI 智能体。在解码过程中，PastForward 检索先前的输出序列作为设备自适应的多 token 提议，并在单次 VLM 前向传播中对其加以验证。在动作步之间，它利用先前的 GUI 状态转移，在设备执行当前动作的同时启动下一步推理，仅当预测屏幕与观测屏幕一致时保留早期计算，并将可复用的 KV 状态向前传递。我们在基于真实移动使用模式构建的 AndroidWorld 工作负载上，使用多种 VLM 骨干模型，在服务器与边缘平台上对 PastForward 进行了评估。在设备端，PastForward 在保持任务成功率的同时，实现了 1.63–2.36× 的动作步延迟加速。

## Abstract
Running GUI agents on edge devices can keep sensitive screens and interaction histories local, but the computational cost of inference at every action step makes deployment challenging. Existing GUI agent systems either perform full vision-language model (VLM) inference at each action step or reuse coarse-grained knowledge matched to prior tasks. However, dynamic mobile environments and user tasks make it difficult to fully utilize prior task executions without additional fine-tuning or task-specific offline exploration. To address this challenge, we present PastForward, a system that accelerates GUI agents through validated, fine-grained reuse of computational experience accumulated during ordinary task execution. During decoding, PastForward retrieves prior output sequences as device-adaptive multi-token proposals and verifies them in a single VLM forward pass. Across action steps, it uses prior GUI transitions to begin next-step inference while the device executes the current action, retains the early computation only when the predicted screen matches the observed screen, and carries reusable KV states forward. We evaluate PastForward on AndroidWorld workloads derived from real mobile usage patterns using multiple VLM backbones across server and edge platforms. On device, PastForward achieves action-step latency speedups of 1.63-2.36$\times$ while maintaining task success rates.

## 二、方法论

### 2.1 核心思想
把日常任务执行中自然积累的执行记录视为**“计算经验”**，以“先提议、后由当前 VLM 或观测屏幕验证”的方式复用，且**只在被验证有效时复用**；无需离线探索、无需微调、不改动 VLM 骨干与智能体策略。

### 2.2 三大机制

**（1）Experience-Guided Adaptive Decoding（经验引导的自适应解码，§3.2）**
- **解码经验记忆 M_dec**：以解码器最后一层隐状态 h_i（同时条件化于多模态 prompt 与前缀 y_<i）为索引键，而非 token 本身（token 身份有歧义）。
- **存储结构**：每条记录为 (h_i, p_i, b_i)，p_i 为 token 在共享数组中的位置，b_i 为**输出序列边界**；提议长度 ℓ 只能访问 p_i+1 … min(p_i+ℓ, b_i)，防止跨入下一动作步的输出。
- **上下文兼容检索**：查询为 (h_i, y_i)；先按“存储 token 与 y_i 相同且 p_j < b_j”过滤，再做余弦相似度排序取最高（相似度 s_d）；无可用条目则退化为普通 greedy 单步。
- **单次前向验证**：一次 VLM 前向同时计算提案各位置及提案后一位的预测；取最长匹配前缀 ℓ_acc，接受该前缀并追加第一个不匹配处的模型预测（或全匹配时追加提案后一位），即一次迭代前进 **ℓ_acc + 1** 个 token。最后追加的 token 必由当前 VLM 生成，故**输出与 greedy 解码完全一致（论文称零精度损失）**。每个迭代后把新 token 及其上下文写回 M_dec。
- **运行时自适应长度控制器**：最小化估计延迟
  - `L*_d = argmin_{0≤ℓ≤ℓmax} T̂(ℓ) / (Â(ℓ, s_d) + 1)`
  - T̂(ℓ)：在线 log-quadratic 拟合的“验证延迟 vs 提案长度”；Â(ℓ, s_d)：在线 logistic 回归估计的期望接受 token 数（首 token 接受概率 × 后续条件延续概率）；+1 为每轮必得的 greedy token；ℓmax=64，并偶尔探索相邻长度。

**（2）Early Inference via Next-Screen Prediction（下一屏预测的提前推理，§3.3）**
- **交互经验记忆 M_int**：每条记录 `(φ(S_j), σ(a_j), h^a_j, S_{j+1})`，含**直接索引**（φ 为 64-bit 感知哈希 pHash，σ 为动作类型+决定效果的参数，坐标量化到网格）与**潜索引**（h^a_j = 工具调用 token 位置集合 I_{a_j} 上隐状态的均值池化，余弦阈值 0.98）。
- **检索流程**：先用 (φ(S_t), σ(a_t)) 精确查直接索引；未命中则以 h^a_t 查潜索引；仍无则跳过提前推理。命中则取 S_{j*+1} 作为候选下一屏。
- **提前推理与验证**：候选屏只替换下一步输入中的屏幕分量，在 A2O 间隔内启动下一步 VLM 推理；其 KV cache、解码记忆、控制器状态全部隔离。观测到 S_{t+1} 后比较应用内容，一致则采用，不一致则丢弃并回滚（重算）。**验证前不发送任何动作**，故不改变决策、无精度损失。

**（3）Cross-Step State Carryover（跨步状态承接，§3.4）**
- **提示前缀 KV 复用**：对相邻步 prompt 的最长公共前缀直接复用 KV。
- **滚动图像 KV 复用**：多截图窗口滑动时图像移到新位置，超出可复用前缀；用 RoPE 旋转调整缓存的 key：
  - `K̃_{m'} = R(m') · R(m)^{-1} · K̃_m`，value 状态原样复用。
  - 因因果上下文已变（左侧可能有被逐出的截图），该方法**是近似的**，仅用于保留截图；新屏幕、变化文本与其余后缀正常计算。

### 2.3 实现要点
- 隐状态经固定随机投影映射为 **256 维 int8 键**；ℓmax=64；M_int 用 64-bit pHash + 动作签名的哈希表，潜检索余弦阈值 0.98。
- 截图以 PNG 存盘（记录保存文件路径与内容哈希），Early Inference 在后台 worker 中运行；prefill 使用连续 BF16 cache 支持两类承接。
- 集成方式为通用推理 runtime，保留各智能体原有 prompt 构造、图像处理、输出解析与动作接口。
