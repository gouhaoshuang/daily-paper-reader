## 摘要
移动设备上的大语言模型（LLM）可作为智能体调用外部软件工具来完成复杂任务，但支持端侧移动智能体AI的主要挑战在于移动设备上LLM工具调用的长延迟。具体而言，解码阶段是这种长延迟的主要来源，但其受内存带宽而非计算能力限制，因而难以在移动处理器上加速。为解决这一限制，本文提出SchemaWeaver，一种新的端侧移动智能体AI技术，在LLM工具调用的解码阶段实施模式引导的并行解码，通过每次解码轮次产生多个token来降低延迟。SchemaWeaver可通用地应用于移动设备上的LLM推理引擎，无需任何训练工作或对LLM进行更改；我们在主流移动SoC和LLM系列上的实验结果表明，与有竞争力的基线相比，SchemaWeaver可将LLM工具调用延迟最多降低3.9倍。

## Abstract
Large language models (LLMs) on mobile devices can act as agents that call external software tools to complete complex tasks, but the major challenge of supporting on-device mobile agentic AI with LLMs is the long latency of LLM tool calling on mobile devices. In particular, the decode phase is the main contributor of such long latency, but is hard to speed up on mobile processors as it is bound by memory bandwidth rather than compute power. To address this limitation, in this paper we present SchemaWeaver, a new on-device mobile agentic AI technique that enforces schema-guided parallel decoding in the decode phase of LLM tool calling, to reduce its latency by producing multiple tokens in each decode pass. SchemaWeaver can be generically applied to the LLM inference engine on mobile devices without involving any training efforts or changes on LLMs, and our experiment results on major mobile SoCs and LLM families show that SchemaWeaver can reduce the LLM tool calling latency by up to 3.9 times, compared to the competitive baselines.

## 1. 核心问题与研究动机

- **背景**：移动设备上的 LLM 智能体可通过调用外部软件工具完成复杂任务，主流移动 OS 已提供 Android AppFunctions、iOS App Intents 等原生工具接口，MCP 也成为常用工具调用协议。端侧 1B–3B 量化模型已具备一定工具调用能力，且能保护用户数据隐私。
- **核心问题**：端侧 LLM 工具调用的**延迟过长**，其中解码阶段是主要贡献者，最高占工具调用墙钟时间的 **81%**。
- **瓶颈本质**：移动端解码受**内存带宽**而非算力限制。每个 decode pass 只生成 1 个 token，却需反复从内存加载全部模型权重；移动 SoC 的共享内存架构使 GPU/NPU 也难以显著缓解。实验显示，OnePlus 12R 上 CPU 解码吞吐仅 **22.6 tokens/s**，而 prefill 达 **145.7 tokens/s**。
- **现有方法不足**：
  - **推测解码**：小 draft 模型仍逐 token 解码、同样受带宽限制；74% 猜测正确仅换来 31% 加速，手机上甚至因验证 pass 和 draft 权重读取而变慢。
  - **约束解码**：仅保证格式合法，不减少 decode pass 数。
  - **Jump-forward 解码**：可跳过固定 token，但参数值仍需逐 token 串行解码，整体受 decode pass 数约束。
- **关键洞察**：工具 schema 固定了工具调用中除参数值以外的几乎所有字符，参数值的位置在解码前即可确定。因此可**并行解码所有参数值**，固定部分用 prefill 一次完成。BFCL 分析显示，工具调用中 **54–63%** 的 token 是固定内容。
- **整体定位**：首个无需训练、无需修改 LLM、可通用集成到移动端推理引擎的端侧 LLM 工具调用加速系统设计。

## 2. 方法论

### 2.1 核心思想

利用工具 schema 提供的结构信息，将工具调用拆分为：

- **固定部分**（工具名、参数名、标点、格式 token）→ 一次 prefill 处理；
- **可变部分**（各参数值）→ 多个 token 序列在同一 decode pass 中**批量并行解码**；
- 解码完成后将并行结果**重组写回**为单一序列，并重建 KV cache；
- 可选参数在必需参数解码后串行决定，并通过**暂定调用（provisional call）**与工具执行重叠以隐藏延迟。
