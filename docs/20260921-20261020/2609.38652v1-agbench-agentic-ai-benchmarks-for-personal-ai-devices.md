## 摘要
智能体 AI 系统日益依赖云托管的大语言模型进行规划、工具使用和迭代执行，这引发了对 API 成本和数据暴露的担忧。个人 AI 设备的进步使智能体能够在本地执行，但设备上的有限资源可能影响任务成功率和性能。现有基准不足以系统刻画跨设备、工作负载和部署架构的这些权衡。我们提出 AgBench，一个基准套件和开放工件，用于在个人设备上可复现地评估智能体 AI。使用 AgBench，我们评估智能体工作负载下的本地、混合和云端执行，考察任务成功率、延迟、云 API 成本和数据暴露。我们的结果基于超过 162.07 百万个数据点，表明个人 AI 设备可以在本地完成许多智能体任务，但仅本地执行通常比仅云端执行具有更低的任务成功率和更长的完成时间，尤其是在并发增加时。仅本地执行消除了云模型 API 成本以及向云智能体暴露敏感信息。混合执行可以提高任务成功率，但其云成本和数据暴露取决于智能体如何划分工作和共享信息。没有单一架构在任务成功率、有效吞吐量、云成本和数据暴露方面都表现最佳；部署选择应反映预期工作负载和设备能力。AgBench 可在 https://anonymous.4open.science/r/AgBench-2777 获取。

## Abstract
Agentic AI systems increasingly rely on cloud-hosted large language models for planning, tool use, and iterative execution, raising concerns about API cost and data exposure. Advances in personal AI devices enable agents to execute locally, but limited resources on device may affect task success and performance. Existing benchmarks are inadequate for systematically characterizing these trade-offs across devices, workloads, and deployment architectures. We present AgBench, a benchmark suite and open artifacts for reproducible evaluation of agentic AI on personal devices. Using AgBench, we evaluate local, hybrid, and cloud execution across agentic workloads, examining task success, latency, cloud API cost, and data exposure. Our results, drawn from over 162.07 million data points, show that personal AI devices can complete many agent tasks locally, but local-only execution generally has lower task success and longer completion times than cloud-only execution, especially as concurrency increases. Local-only execution eliminates cloud model API costs and sensitive-information exposure to cloud agents. Hybrid execution can improve task success, but its cloud cost and data exposure depend on how agents divide work and share information. No single architecture performs best across task success, goodput, cloud cost, and data exposure; deployment choices should reflect the intended workload and device capabilities. AgBench is available at https://anonymous.4open.science/r/AgBench-2777.

## 1. 核心问题与研究动机

- **背景趋势**：智能体 AI（Agentic AI）系统通常依赖云端大语言模型完成规划、工具调用、结果评估与迭代执行。此类系统已在软件工程、办公生产力、个人助理等场景快速普及。
- **核心矛盾**：
  - 云端执行带来 **API 成本**与**敏感数据暴露**风险；
  - 个人 AI 设备（如 RTX 5090 工作站、NVIDIA DGX Spark、AMD Ryzen AI Halo 等）具备本地运行智能体的算力，但资源受限可能影响任务成功率与执行性能；
  - 混合架构（设备—云协同）理论上可折中，但其实际收益不明确。
- **研究缺口**：现有基准分为两类——能力型基准（GAIA、TUA-Bench、Terminal-Bench 等）主要测“能不能完成任务”；系统型基准（XPerf、OSWorld-Human、AgentSysBench 等）主要测“执行性能与瓶颈”。**尚无基准系统刻画智能体从云端迁移到个人设备时，跨设备、负载、部署架构的多维权衡**。
- **核心研究问题**：**个人 AI 设备是否已准备好承载智能体 AI？** 具体拆解为四个问题：
  - Q1：从云到本地，任务成功率受何影响？
  - Q2：本地执行是否拖慢智能体工作流？
  - Q3：本地执行能否降低云 API 成本？
  - Q4：本地执行能减少多少云端数据暴露？
- **整体含义**：论文试图为“智能体部署架构选择”提供可复现的实证依据，而非单纯追求任务能力上限。

## 2. 方法论

### 2.1 核心思想

AgBench 将**任务能力评估**与**系统执行测量**统一到一个基准框架中：在受控的设备、部署架构与并发配置下运行统一任务套件，同时采集任务结果、模型/工具交互、云模型使用量、云数据传输与系统资源利用，从四个维度刻画权衡：**任务成功、执行性能、云 API 成本、云数据暴露**。

### 2.2 基准工作流（四步）

1. **任务构建**：构建覆盖多样用户活动与系统需求的 60 个任务，每项任务包含人类可读指令、隔离执行环境、任务专用验证器。
2. **配置控制**：每个配置指定“设备 + 部署架构 + 并发级别”；本地设备资源用于本地模型推理与工具执行，架构决定推理位置与智能体协作方式。
3. **迭代执行**：智能体反复调用工具、检查结果，直到任务完成或终止；任务在隔离 Docker 容器中运行，但共享 CPU、GPU、内存、存储 I/O 与本地模型服务，以刻画资源竞争。
4. **测量采集**：记录任务结果、模型与工具交互、智能体间通信、云模型使用与数据传输、系统资源利用率；由任务专用验证器判定成功。

### 2.3 任务套件

- **规模与来源**：60 个任务，取自 GAIA、TUA-Bench、Terminal-Bench 2，适配为 AgBench 格式但保留原始目标。
- **八类任务及数量**：
  - 本地文件分析：12
  - 信息检索：10
  - 计算与工具使用：8
  - 办公生产力：8
  - 多媒体处理：4
  - 科学与工程计算：4
  - 系统与软件操作：2
  - 复杂终端问题求解：12
- **资源画像**：按 CPU 时间、峰值内存、磁盘读写划分为 CPU-heavy、Memory-heavy、I/O-heavy、Mixed、Low footprint。
- **筛选标准**：固定输入、可复现环境、可程序化验证；排除需人工交互或主观评估的任务。

### 2.4 执行配置

- **两台个人 AI 设备**：
  - **RTX 5090 工作站**：Intel Core Ultra 9 285K（24 核/24 线程）+ NVIDIA GeForce RTX 5090（独立 GPU，32 GB 专用显存）+ 128 GB 系统内存。
  - **AMD Ryzen AI Max+ 395 紧凑系统**：16 核/32 线程 + 集成 Radeon 8060S（96 GB 统一内存分配给 GPU，系统可见约 30.5 GB）+ 128 GB 统一内存。
  - 二者分别代表**独立 GPU + 专用显存**与**集成 GPU + 统一内存**两种设计。
- **并发级别**：1、2、4、8，即最多同时执行 C 个任务。
- **四种部署架构**（任务环境与工具执行始终在本地设备）：
  - **LO（Local-Only）**：本地智能体完成规划与工具调用，模型推理全本地。
  - **CO（Cloud-Only）**：云智能体规划，模型推理经云 API，工具执行仍在本地。
  - **HCL（Hybrid Cloud-Led）**：云智能体主导任务，按需将子任务委派给本地智能体；本地执行后返回结果。
  - **HLL（Hybrid Local-Led）**：本地智能体主导任务，遇到推理困难时咨询云智能体；云返回建议后本地继续执行。
- **推理配置**：
  - 本地：Qwen3.8-27B，UD-Q6_K_L 6-bit 量化，llama.cpp（commit 0b5be7e4），RTX 5090 用 CUDA 12.8.1、Max+ 395 用 Vulkan；启用 Flash Attention、8-bit KV cache、MTP 投机解码（最多 2 个 draft token）；每设备最多 8 个并发模型调用；上下文窗口 65,536 token，单次输出上限 8,192 token。
  - 云端：DeepSeek V4 Flash，高推理强度；上下文窗口 1,000,000 token，单次输出上限 384,000 token。
- **智能体循环**：基于 Pi Coding Agent v0.84.1 实现；系统提示固定；混合架构额外增加协调提示，规定委派/咨询、信息交换与继续执行方式。

### 2.5 指标与计算方式

- **主指标**：
  - **任务成功率**：通过任务专用验证器的任务比例。
  - **完成时间**：任务开始到终止的墙钟时间；为公平比较，主表仅统计“四种架构均成功完成”的任务，保证同一 n。
  - **Goodput（有效吞吐）
