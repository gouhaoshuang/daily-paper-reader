ABSTRACT
While frontier vision-language models demonstrate strong capabilities in user in-
terface (UI) navigation, their high inference costs prohibit everyday use. Con-
versely, smaller models trained via supervised fine-tuning (SFT) or offline rein-
forcement learning often memorize static trajectories, leading to brittle execution
and an inability to recover from errors. To address these limitations, we propose
a novel online reinforcement learning framework that trains UI navigation agents
directly on live iOS applications. Our framework decouples the agent into two
specialized components: a Planning agent and a UI Grounding model. We rely on
an LLM-as-a-Judge to provide comprehensive reward signals, combining dense,
step-level feedback to evaluate intermediate progress with a terminal reward for
overall task completion. To effectively leverage this dual reward structure, we
optimize the agent using Proximal Policy Optimization (PPO) with step-level
advantage estimation. Furthermore, we introduce GiGPPO, a novel neighbor-
conditioned value estimation method that improves critic stability by leveraging
reward signals from visually similar states across concurrent trajectories. To sup-
port this online training paradigm at scale, we introduce an efficient infrastructure
that orchestrates hundreds of concurrent virtual iOS devices. Evaluations on rigor-
ous benchmarks, including UINavBench, iOSWorld, and AndroidWorld, demon-
strate that our online RL trained agents substantially outperform both SFT and
terminal-only RL baselines while accelerating training convergence. Notably, our
8B RL agents achieve nearly a sevenfold improvement over the SFT baseline in
out-of-distribution generalization to Android environments, while outperforming
Gemini-3.5-Flash and tying with Gemini-3.1-Pro on real iOS applications.

INTRODUCTION
UI Navigation agents, which are AI systems designed to perceive graphical user interfaces and au-
tonomously execute sequences of actions to achieve user-specified goals, are gaining traction in
both industry and academia. Their applications range from automatically completing tasks for users
(Qin et al., 2025a; Gu et al., 2025) to A/B testing (Lu et al., 2026). While frontier models can be
quite proficient at UI Navigation (Jang et al., 2026; Agrawal et al., 2025), they are expensive, often
costing several dollars per task (EasyClaw Research, 2026), making them impractically expensive
for frequent, everyday use. As a result, there has been a surge in interest for training small models
for proficient UI navigation (Yang et al., 2025; Chai et al., 2026). However, current training meth-
ods suffer from significant weaknesses. Supervised Fine-tuning (SFT) tends to memorize training

trajectories rather than learn generalizable strategies, resulting in brittle execution that struggles to
recover from errors (Zhou et al., 2025b; Bai et al., 2024; Qi et al., 2024; Yan et al., 2025). Existing
Reinforcement Learning (RL) approaches largely rely on single-step RL that mirrors these same
SFT limitations (Yang et al., 2025; Yan et al., 2025) or rely on only a terminal reward at the end of a
trajectory, providing a weak, sparse signal (Bai et al., 2024; Wang et al., 2025; Qi et al., 2024; Zhou
et al., 2025a).
To address these challenges, we propose a novel framework, trained at a large scale on real iOS
applications, that decouples the agent into two specialized components: a Planning Agent and
a UI Grounding Model. Rather than training a single model to jointly handle planning and spa-
tial localization, our architecture allows each component to be optimized for its specific objective.
The Planning Agent observes the screen, maintains a history of past actions, and utilizes Chain-of-
Thought reasoning to produce both an immediate step and a long-term plan. The immediate step
is then passed to the Grounding Model, which translates it into a precise action and correspond-
ing coordinates for on-device execution. Additionally, the Planning Agent’s action space includes
an ASK USER primitive to handle underspecified tasks by requesting user preference specifica-
tions. Because grounding is a largely deterministic mapping problem effectively solved via SFT,
this decoupling allows us to reserve computationally expensive RL for the Planning Agent, where
open-ended reasoning and adaptation provide the most benefit.
We optimize the Planning Agent in an online RL setting, centered on a robust LLM-as-a-Judge
reward mechanism. To overcome the sparsity of terminal-only feedback, we combine two com-
plementary signals. A Dense Reward evaluates whether each individual step makes meaningful
progress while penalizing hallucinations and unproductive loops. A Terminal Reward assesses over-
all task completion. This dense, step-level feedback provides a rich signal throughout the trajectory,
giving the model useful feedback even when terminal success is rare under the current policy. It
further encourages exploration and explicitly teaches the agent to recover from unexpected states
rather than failing when it deviates from a golden path. To effectively leverage this dense reward
structure, we optimize the agent using Proximal Policy Optimization (PPO) with step-level Gener-
alized Advantage Estimation (GAE). To prevent the agent from artificially prolonging trajectories
to exploit step-level rewards, we use an asymmetric discounting strategy in our reward function that
balances local process supervision with discounted dense rewards, combined with a terminal reward
for successful task completion. Furthermore, we introduce GiGPPO, a novel neighbor-conditioned
value estimation method that improves critic stability by incorporating reward signals from visually
similar states across concurrent trajectories.
Because online RL requires continuous interaction with real UI environments, we built a highly
scalable device management system to support this training paradigm. By orchestrating a large pool
of cloud-hosted iOS devices and utilizing rapid virtual machine snapshots, our infrastructure en-
ables hundreds of parallel live trajectories. This allows the agent to generate fresh rollouts across
concurrent environment instances without bottlenecking on sequential device interactions. To our
knowledge, this work represents the first time UI navigation agents have been trained at-scale en-
tirely on live iOS devices interacting with real iOS applications.
We evaluated our trained agent system on public benchmarks, including UINavBench and iOS-
World, as well as AndroidWorld to test out-of-distribution performance. Our experiments demon-
strate that our 8B online RL agents substantially improve upon the SFT baseline. Most notably,
the RL agents achieve nearly a sevenfold higher success rate than the SFT baseline on Android-
World, proving that our framework successfully teaches generalizable navigation strategies rather
than simply memorizing iOS-specific trajectories. Furthermore, both our dense reward formulation
and GiGPPO accelerate training convergence, and on UINavBench, a rigorous benchmark of real
iOS applications, our RL agents outperform Qwen3.8-27B and Gemini-3.5-Flash while tying with
Gemini-3.1-Pro. In summary, our key contributions are as follows:
• Online RL planning-grounding framework on Live iOS: We propose a decoupled
planning-and-grounding architecture trained at scale entirely on live iOS devices, utiliz-
ing LLM-as-a-Judge to provide both dense and terminal rewards.
• Asymmetric Reward Discounting and GiGPPO: We identify and resolve reward hacking
in step-level RL by introducing an asymmetric discounting strategy that balances local
process supervision with undiscounted terminal task completion. We also introduce a novel

RELATED WORK
2.1
UI NAVIGATION AGENTS
The rise of vision-language models (VLMs) has produced a wave of research on UI navigation
agents. Early agents simply prompted a frontier VLM with no training (Zhang et al., 2025); SeeAct-
V (Zheng et al., 2024) improved on this by pairing a zero-shot frontier planner with a separately
trained visual grounding model, but left the planner itself untouched. Running a frontier model on
every step is expensive and slow, which has pushed the field toward smaller VLMs that may fit on-
device (Yang et al., 2025), but a small model cannot rely on a frontier model’s zero-shot competence,
so it has to be trained. One training approach is supervised fine-tuning (SFT) on human or model-
collected demonstrations (Yang et al., 2025; Chai et al., 2026). SFT training is mostly on successful
trajectories, so it learns to imitate the next action along a path that is already going right rather than
a generalizable strategy; it rarely sees what an error looks like or what to do once one occurs, and
tends to memorize training trajectories rather than adapt to states outside them, resulting in poor
error recovery and weak generalization to out-of-distribution apps and tasks (Zhou et al., 2025b;
Agrawal et al., 2025; Qi et al., 2024; Yan et al., 2025).
To address the limitations of SFT, researchers have started exploring RL methods. However, many of
these approaches mirror SFT’s limitations through single-step RL that rewards similarity to golden
traces (Yang et al., 2025; Yan et al., 2025), or by relying on offline human corrections. For exam-
ple, UI-TARS (Qin et al., 2025b) fine-tunes on human-relabeled “reflection” pairs via DPO rather
than learning recovery through live interaction. For online training methods, several systems use an
independent judge (such as a VLM) to evaluate trajectories without needing reference traces (Bai
et al., 2024; Wang et al., 2025; Qi et al., 2024; Zhou et al., 2025a). However, these approaches
provide a terminal reward at the end of the trajectory, which provides a sparse training signal and
does not give the agent credit for intermediate steps that make real progress toward a goal it ulti-
mately fails to finish. While some of these training frameworks add dense signals like hand-coded
repetition penalties (Zhou et al., 2025a), they still lack a mechanism to reward partial success. Sim-
ilarly, Qwen-UI-Agent (Zhou et al., 2026) trains an end-to-end agent across approximately 10,000
concurrent environments (mobile (Android), web, and desktop). Its multistage pipeline includes
offline RL training targeting per-step action accuracy with a set of hand-curated action failure types.
However, this per-step accuracy focuses on localized checks (e.g., grounding accuracy and action
repetition) rather than assessing genuine progress toward the goal. This offline phase is followed
by online training using only terminal rewards. In contrast, our framework provides both dense
progress evaluation and terminal task-completion rewards within a single online RL stage, using an
LLM-as-a-Judge without requiring manually curated error taxonomies or pattern-specific training
data. Across this line of work, group-relative methods have become the default: GRPO or a close
variant is used by Yang et al. (2025), Yan et al. (2025), Zhou et al. (2025a), Zhou et al. (2026), and
Tang et al. (2026). A consequence is that no prior GUI-agent system learns a value function for step-
level credit assignment; dense signals, where present, are aggregated into trajectory-level returns or
into subgroup averages over repeated states. Our framework instead trains a critic that consumes the
dense channel directly, which is what makes the asymmetric discounting of Section 3.5 possible.
Concurrent with our work, ClawGUI-RL (Tang et al., 2026) combines a terminal outcome reward
with a dense step-level reward from a Process Reward Model. It trains a single end-to-end policy for
both planning and grounding using GiGPO on Android emulators at a scale of 64 concurrent envi-
ronments. We differ in three key respects. First, we decouple a specialized RL-trained planner from
a frozen SFT grounder rather than training end-to-end. Second, while GiGPO forms a step-level
baseline by averaging returns of exactly recurring states, which degenerate into singletons in our
setting, we route this cross-trajectory signal through a learned value function (Section 3.5). Third,

2.2
UI NAVIGATION BENCHMARKS
Early UI agent benchmarks evaluated models offline on static screenshot–action pairs (Deng et al.,
2023; Li et al., 2020), which cannot assess sequential decision-making or error recovery. The field
has since shifted toward live-environment evaluation: MiniWob++ (Liu et al., 2018) and WebArena
(Zhou et al., 2023) require agents to act in real browser sessions, OSWorld (Xie et al., 2024) eval-
uates desktop tasks across multiple operating systems, and AndroidWorld (Rawles et al., 2024)
and MobileWorld (Kong et al., 2026) target Android apps with programmatic state verification
to measure task success. iOS evaluation has been comparatively underserved until recently, with
UINavBench (Agrawal et al., 2025) and iOSWorld (Jang et al., 2026) introducing live-device evalu-
ation with VLM-based success judges. While most of these benchmarks focus on single-app tasks,
AndroidWorld, UINavBench, and iOSWorld include workflows that require planning across multi-
ple applications.

UI NAVIGATION AGENT SYSTEM AND TRAINING
3.1
PROBLEM FORMULATION
We treat UI navigation as a sequential decision process. Given a natural-language task instruction
g (e.g., “Search for a pair of shoes and add it to cart”), an agent repeatedly observes the current
screen and executes a single action, continuing until the task is complete. At each step t, the agent
observes the current state, which consists of the current screenshot st and a running summary of
its past actions. The agent then outputs one action at from a fixed set of primitives: TAP, SWIPE,
TEXT ENTRY, NAVIGATE HOME, LONG PRESS, ASK USER, and TASK COMPLETE.
The ASK USER action allows the agent to request preference-related clarification for underspecified
parts of a task. In the shoe search example, the agent might ask the user what type of shoes to search
for and which specific option from the search results to add to the cart. Executing at transitions
the environment to a new state, in a way that depends on the app that the agent does not control
directly. Because the instruction states only the final goal rather than the steps to reach it, the agent
must determine its own sequence of screen-specific actions and dynamically revise this sequence
whenever the environment deviates from expectations. An episode ends when the agent selects
TASK COMPLETE or reaches the maximum step limit.
3.2
ARCHITECTURE
To produce at, the agent must determine what to do on the current screen (planning) and identify the
exact x,y-coordinates to execute the planned action (grounding). Unlike prior work that combines
both functions into a single model, we decouple the agent into two separate models for planning and
grounding. Figure 1 illustrates the agent architecture as well as the training setup.
4


At each step, the Planning Agent outputs a plan for the current screenshot, preceded by chain-
of-thought (CoT) reasoning (Wei et al., 2022). The agent also outputs a remaining plan (a set of
high-level goals required to finish the task), which is similarly preceded by its own CoT reasoning.
The inputs to the Planning Agent include the task instruction, the current screenshot, a history of
previous step plans with their reasoning, and the remaining plan from the prior step.
The current step plan is then passed to the Grounding Model, which maps it to one of the ac-
tion primitives and the specific x,y-coordinates on the screen to execute on device. We decouple
these components because planning and grounding represent fundamentally different challenges,
and splitting them maximizes model performance in both aspects. Grounding requires precise spa-
tial understanding to map a specific intent to UI coordinates, a task that can be trained highly ef-
fectively with SFT (et al., 2025; Lin et al., 2025). Planning, conversely, is an open-ended task that
requires understanding the overall goal, tracking completed actions, adapting to dynamic changes
in the UI, and recovering from errors when unexpected states arise. This open-ended reasoning and
need for continuous adaptation make RL a highly suitable training method for the Planning Agent.
By separating the two, we can reserve computationally expensive RL for the planning phase where
it provides the most benefit. Appendix A.3 compares the performance of the Planning Agent when
paired with different Grounding Models.
Virtual device environment. The agent operates on cloud-hosted iOS virtual machine devices that
are provisioned through cloud-based service, which also handles device lifecycle management and
automatic retirement of degraded sessions. Devices are driven over a VNC session via a typed action
interface (e.g., tap, swipe, type, long press, home, wait) that mirrors physical-device behavior. Each
device is configured once with the necessary apps installed and signed in with an Apple ID. This
verified ready state is then captured as a virtual machine snapshot, which the device can be reverted
to at any time through the cloud-based service. Episodes end by rolling back to the snapshot rather
than tearing the session down, which reduces restart latency to roughly 10 seconds. This combi-
nation of on-device fidelity and rapid snapshot-based reuse is necessary for our online RL training
with high throughput. During training, our system is able to run 512 trajectories simultaneously,
each with its own independent device and agent-environment loop.
3.3
SFT WARM START
Before RL, we warm-start the Planning Agent from Qwen3-VL-8B-Instruct (Bai et al., 2025) us-
ing supervised fine-tuning on human-annotated task trajectories. The training data are drawn from
three separate datasets. Two are collected in-house: one covering first-party iOS apps and another
covering third-party iOS apps. Each pairs a task goal with a human-executed sequence of screens
and the corresponding actions taken. The third is the public GUIOdyssey dataset (Lu et al., 2025).
Although it consists of Android apps, we include it specifically for its multi-app trajectories (tasks
requiring navigation across several apps). This addresses a gap in our iOS datasets, which only
contain single-app tasks and lack app-switching behavior.
None of the three datasets natively record reasoning. They provide only the goal, the sequence of
screens, and the current plan at each step, lacking both CoT reasoning and long-term plans. To
produce the reasoning and remaining-plan targets that the Planning Agent is designed to output
(Section 3.2), we use Gemini (Google, 2025) to generate the chain-of-thought reasoning consistent
with each step plan, as well as the plan for the remaining steps and its corresponding reasoning.
3.4
ONLINE REINFORCEMENT LEARNING SETUP
To overcome the limitations of offline training on static datasets seen in prior work, we optimize the
Planning Agent using online RL training. This approach employs an LLM-as-a-Judge as a fast and
robust method to generate real-time rewards that adapt to the dynamic UI environment. During train-
ing, the agent continuously interacts with live virtual iOS devices to generate fresh rollouts. This
active interaction allows the model to experience the direct consequences of its actions, navigate un-
expected screen states, and learn robust error recovery strategies using online reinforcement learning
algorithms, specifically Proximal Policy Optimization (PPO) and our novel neighbor-conditioned
variant, GiGPPO. Rewards are computed at both the step and trajectory levels, and all trajectories
collected at a step are batched into a single synchronous on-policy update. For ASK USER steps
5


that require user input, we use Gemini-3.5-Flash to provide realistic user responses. We use this
simulated user during both RL training and the benchmark evaluations in Section 4.
Training Data For online RL training, we randomly sampled tasks and apps from the existing iOS
datasets used during SFT. Because the multi-app tasks in GUIOdyssey are on Android, they could
not be directly executed in our iOS environment. To address this, we synthetically generated multi-
app iOS tasks using a two-stage pipeline to ensure diversity. First, we prompted Gemini to identify
logical pairs of iOS apps for cross-app workflows. For example, pairing Weather and Calendar
enables tasks like finding a day with clear weather to schedule an outdoor event. Second, for each
identified app pair, we generated a diverse set of multi-app tasks, using single-app examples from
our iOS datasets as in-context references to guide the generation process. To ensure realism and
feasibility of the generated tasks, one author manually verified each one, making corrections as
needed.
Reward Design Studies have shown that LLM-as-a-judge is an effective way to provide RL rewards
during training (Zhou et al., 2025a; Qi et al., 2024; Wang et al., 2025; Zhou et al., 2025b). We use
this approach as an efficient and robust way to supply live rewards during online training. To ensure
sufficient signal, we provide both dense and terminal rewards, and design each reward judge to
handle a variety of scenarios. Because our LLM-as-a-judge reward requires no ground-truth action
sequence, it generalizes to any app/task pair rather than only those with human-annotated golden
traces and enables RL training directly on the synthetic multi-app tasks.
Since the dense reward judge is called at every step, we use Gemini-3.5-Flash. Given the task,
action history (with the corresponding dense judge results), current plan, reasoning, and before/after
screenshots, the judge returns one of three outcomes: success, fail, or overcomplete. To achieve a
success, the before/after screenshots must show progress towards completing the overall task, and
agent’s reasoning and action must both align with the visual state of the UI; accidental progress
from hallucinated reasoning is penalized as a failure. The judge also penalizes unproductive loops
by checking for repeated failed actions. The overcomplete label penalizes the agent for continuing
to act after the task is already satisfied, teaching the policy to recognize task completion. Finally,
a separate dense judge evaluates ASK USER actions, using only the current screenshot to verify
whether the requested information is genuinely underdetermined at that step.
Similar to Zhou et al. (2025b), our terminal judge evaluates task success using the trajectory’s final
three screenshots. However, we additionally provide the full action history, along with prior dense-
judge verdicts. The judge outputs one of three outcomes: success, fail, or blocked complete. The
blocked complete label rewards trajectories that correctly execute all steps up to an unavoidable
external barrier, such as a paywall or CAPTCHA, preventing the agent from being penalized for
unactionable states. We use Gemini-3.1-Pro for the terminal judge.
3.5
ONLINE REINFORCEMENT LEARNING OPTIMIZATION
While GRPO is effective for trajectory-level optimization and is commonly used to train UI Naviga-
tion Agents (Yan et al., 2025; Zhou et al., 2025a; 2026), it is less suited to exploit rich intermediate
supervision: dense rewards must be aggregated with the terminal reward before computing a group-
relative advantage, obscuring their temporal structure. Alternatively, one can estimate a separate
GRPO advantage at each state by sampling multiple candidate actions, as in Verifiable Process Re-
wards (VPR) (Yuan et al., 2026), but this requires multiple additional samples per state and does not
naturally incorporate the eventual task outcome into the local advantage. We instead use Proximal
Policy Optimization (PPO), whose critic can directly exploit dense rewards. Recently, StepSearch
(Zheng et al., 2025) combined step-wise and terminal rewards using PPO with Generalized Advan-
tage Estimation (GAE) and an undiscounted return (γ = 1). In our setting, however, this requires
the critic at each state to predict the expected cumulative contribution of potentially distant future
dense rewards which is a difficult task for the critic.
Reward Discounting Furthermore, as observed in the run detailed in Appendix A.2, an undis-
counted return can lead to reward hacking. With a discount factor of γ = 1, every future dense
reward is valued equally to an immediate one, removing the agent’s incentive to complete the task
efficiently. Because dense credit accrues at each step up to the maximum step budget, the undis-
counted return is maximized simply by taking more steps that appear locally correct. Consequently,
the agent learns to artificially prolong trajectories to collect positive dense rewards at each step rather

combines local process supervision with an optimization signal that remains anchored to the actual
evaluation objective: successful task completion.
Neighbor-conditioned value estimation (GiGPPO) GRPO estimates the value of the states along
a trajectory by comparison with the other trajectories sampled for the same task, but the comparison
is trajectory-level: returns are aggregated before the advantage is formed, so dense rewards collapse
into a single scalar and their temporal structure is lost. GiGPO (Feng et al., 2025) refines this idea by
exploiting repeated states, collecting states that recur across the trajectories of a task into subgroups
and estimating the value of a state as the average reward within its subgroup, which yields a step-
level baseline without a critic. In our setting, however, an identical screen almost never recurs:
with G = 4 or G = 8 rollouts per task, subgroups defined by exact state equality are essentially
singletons, while relaxing equality to screen proximity would average over states that are merely
similar and pass that bias directly into the critic’s value estimates.
To address this, alongside our PPO implementation, we introduce and evaluate an alternative
method: GiGPPO, which retains the underlying intuition that the reward observed at a similar state
in a sibling trajectory is informative about the value of the current state, but route it through the critic
rather than through averaging. Each state is paired with the state whose 64-bit perceptual hash lies
closest in Hamming distance among the sibling trajectories of the same task; we call this state its
neighbor. A small multi-layer perceptron then predicts V π(st) from the hidden embeddings of the
state and of its neighbor, the neighbor’s return (its discounted dense sum plus undiscounted terminal
reward), and the Hamming distance between the two screens, the last of which lets the critic cali-
brate how far the neighbor’s reward should be trusted: at distance zero the two states are the same
screen and that reward is nearly a direct observation of the quantity being predicted, whereas at large
distance the screens differ and its contribution should be discounted. The state’s own reward is never
an input, so the regression target cannot leak. Conditioning on the neighbor in this way gives the
critic strictly more information than standard PPO, where V π(st) must be inferred from st alone.
Reward structure For the PPO and GiGPPO runs, we utilize a dual-channel reward structure. The
dense channel scores each step and is discounted at γdense = 0.5: +1.0 for a judged success, 0.0 for
a judged fail or an ungroundable plan, −1.0 for an empty plan or a generation truncated at the length
limit, and −2.0 for acting after the task is already complete (i.e., overcomplete). The terminal chan-
nel is paid once and carried undiscounted to every step, gated on what the agent declared: +2.0 for
completing the task and declaring Task Complete, +0.5 for encountering blocked complete, −0.75
for exhausting the step budget, −1.0 for a false completion claim, and −2.0 for ending on un-
parseable or empty output. Since the dense return is bounded by 1/(1 −γdense) = 2.0, a trajectory
that succeeds at every step earns exactly one terminal success worth of dense credit, so neither chan-
nel dominates. Ordinary failure is left unpunished to keep exploration cheap, but unusable output
7


is charged at terminal scale, since a single discounted dense charge cannot outweigh a guaranteed
terminal cell of zero and an unusable action scored at zero is gradient-equivalent to a genuine one
while being cheaper to emit.
Trajectories lost to infrastructure rather than behavior, such as an application that never renders, a
failed app installation, a dropped device connection, or an exceeded generation deadline, are masked
instead of penalized: they enter neither the policy gradient nor the critic regression, cannot serve as
neighbors, and are excluded from the statistics used to whiten advantages, which matters because
their zero reward values would deflate the standard deviation and inflate every genuine advantage.
Remaining optimization and hyperparameter details are given in Appendix A.1.
Critic Training For both the standard PPO and GiGPPO runs, the value model (i.e., critic) is ini-
tialized from the supervised fine-tuning checkpoint with a fresh scalar value head. We found that
training the critic and the policy jointly from the start is highly unstable. Because the initial value
estimates are uninformative, the resulting advantages are dominated by value error rather than ac-
tual reward signals, causing the policy to take large, disruptive early updates. To mitigate this, we
warm start the critic for 15 steps. During this initial phase, the policy is held frozen while rollouts
are collected, and the value function is regressed directly onto the observed returns. Only after this
warm-up period do we begin joint training. Furthermore, the critic uses a learning rate of 1 × 10−4,
which is two orders of magnitude larger than the policy’s learning rate of 1×10−6. This discrepancy
is intentional. The value function must rapidly track a moving target and is ultimately discarded at
the end of training, so it can afford to update quickly. In contrast, the policy is the final artifact being
preserved and must be updated deliberately slowly to avoid destroying its supervised fine-tuning
initialization.

EXPERIMENTS
4.1
BENCHMARKS
Because our training focused primarily on iOS apps, we evaluated our agents on two public iOS
benchmarks: UINavBench (Agrawal et al., 2025) and iOSWorld Jang et al. (2026). UINavBench
consists of 116 tasks of varying difficulty across 36 real iOS apps staged with user data. iOSWorld
comprises 133 tasks across 26 synthetic iOS apps, all staged with data reflecting a single user per-
sona. Both benchmarks include a mix of single-app and multi-app tasks. Additionally, iOSWorld
features 46 tasks specifically designed to test the agent’s personalization capabilities, requiring the
agent to discover and act upon the user persona’s underlying preferences. For both benchmarks, task
success is evaluated using a Vision-Language Model (VLM) that verifies whether a specific set of
requirements is met by the agent’s output trajectory. To assess the generalizability of our iOS-trained
agent, we also evaluate it on out-of-distribution Android apps using the AndroidWorld benchmark
(Rawles et al., 2024), which consists of 116 tasks across 20 real applications.
4.2
UI GROUNDING MODELS
For grounding, we utilized an internal 3B dense pretrained model finetuned on a large human-
annotated dataset that maps step-level instructions to action primitives and precise x,y-coordinates
on real iOS screenshots. This model achieves over 90% accuracy on its held-out test set. However,
because it supports only directional swipes (e.g., “swipe up”) rather than precise location-based
swiping, we route all swipe instructions to Gemini-3.5-Flash, which has demonstrated strong UI
grounding capabilities (Jang et al., 2026) and supports location-based swiping. We ran the RL
training using this grounding setup, but experimented with various grounding configurations on the
benchmarks in Appendix A.3. We report the task success rates with the optimal grounding configu-
ration for each benchmark in Table 1.

and Step 336, respectively. Because UINavBench runs on real iOS apps and most closely matches
the RL training environment, this accelerated learning under GiGPPO can likely be attributed to the
critic effectively leveraging signals from visually similar UI screens for value estimation.

which achieved more than double the success rate of the SFT baseline (9.8% vs. 4.5%). One rea-

deviate from the real iOS apps our agents were trained on. Another factor is the greater complexity
of the benchmark’s tasks, which include user personalization workflows (e.g., “find my most fre-
quently ordered restaurant and item, then reorder my usual”) and multi-app tasks spanning more

than two apps; both categories account for the majority of the benchmark and are out-of-distribution

datasets remain scarce. Similarly, UI-TARS’s strong performance on AndroidWorld is attributed to

5
CONCLUSION
In this work, we presented a novel online reinforcement learning framework that trains UI navigation
agents directly on live iOS applications to overcome the brittleness of supervised fine-tuning and the
high inference costs of frontier models. By decoupling the agent into a specialized RL-trained plan-
ner and a frozen SFT grounder, we efficiently focused open-ended reasoning capabilities where they
are most needed. To provide rich learning signals, we utilized an LLM-as-a-Judge to supply both
dense, step-level feedback and terminal task-completion rewards. We optimized this dual reward
structure using Proximal Policy Optimization (PPO) with a novel asymmetric discounting strat-
egy to prevent reward hacking, and introduced GiGPPO, a neighbor-conditioned value estimation
method that stabilizes the critic using visually similar states across concurrent trajectories. Evalu-
ations across UINavBench, iOSWorld, and AndroidWorld demonstrate that our online RL agents
substantially outperform the SFT baseline, while our dense reward formulation and GiGPPO sig-
nificantly accelerate training convergence compared to terminal-only rewards. Notably, on real iOS
applications, our 8B RL agents surpass multiple frontier models and match Gemini-3.1-Pro, while
achieving nearly a sevenfold improvement over the SFT baseline in out-of-distribution generaliza-
tion to Android environments. Ultimately, this work provides a highly effective pathway toward
robust, generalizable, and economically viable UI navigation agents.

APPENDIX
A.1
PPO TRAINING DETAILS
The Planning Agent is initialized from the same 8B vision-language supervised fine-tuning check-
point used in Appendix A.2, and the critic from that checkpoint with a fresh value head. The policy’s
vision tower is frozen; the critic is adapted with LoRA of rank 32 and α = 64, excluding the visual
modules, beneath the neighbor-conditioned network, whose projection and hidden widths are 128
and 512 and which adds about 0.9M trainable parameters. Each step draws 16 tasks and samples
G = 8 trajectories per task, giving 128 trajectories, with episodes capped at 30 agent steps, prompts
at 12288 tokens and generations at 700 new tokens per step; rollouts are sampled at temperature 1.0
and evaluation rollouts at temperature 0.7 with 5 samples per task. Advantages use step-level GAE
with γ = λ = 1 and a dense discount γdense = 1/2. The objective is a dual-clipped surrogate with
ϵlow = 0.18, ϵhigh = 0.22 and c = 3, together with a KL penalty of 0.01 to the frozen supervised
fine-tuning reference; value updates are clipped at 0.5. The policy takes two optimizer steps per
batch, using a mini-batch of 8 tasks over one epoch, with AdamW at a learning rate of 1 × 10−6,
while the critic takes one at 1 × 10−4; both use a weight decay of 0.01, no warmup, and gradient-
norm clipping at 1.0. The critic is trained alone for the first 15 steps, with the policy frozen, so that
advantages are not dominated by value error while its predictions are still uninformative. Training
runs under FSDP on 8 GPUs, with rollouts produced by 16 generator shards each driving up to 32
concurrent virtual iOS devices.
A.2
GRPO
We initialize the Planning Agent from the 8B vision-language supervised fine-tuning checkpoint
described in Section 3.2 and optimize it using Group Relative Policy Optimization (GRPO). No
value network is trained; advantages are computed directly from the relative returns within each
group of rollouts sampled for the same task. At every training step, we draw 32 tasks and sample
G = 4 trajectories per task, yielding 128 trajectories per step, and each episode is capped at 30
agent steps. Returns are undiscounted (γ = 1, λ = 1). Optimization uses AdamW with a constant
learning rate of 1 × 10−6, β = (0.9, 0.999), a weight decay of 0.01, and gradient-norm clipping
at 1.0. Rollouts are generated at a temperature of 1.0 and top-p of 1.0, with a maximum of 700
new tokens per step and an 8192-token context. Evaluation rollouts use a temperature of 0.7 and 5
samples per task. Training ran for a single pass over the task set using FSDP (Fully Sharded Data
Parallel) for the policy and reference models, supported by the scalable pool of virtual iOS devices.
Reward The reward follows the dense-plus-terminal decomposition outlined in Section 3.4, with
the per-step judge returning +1 for a success and the terminal judge returning +10 for a success
and +5 for a blocked completion. A trajectory’s return is therefore the sum of its per-step rewards
plus its terminal reward, and lies within [0, 40]. Crucially, every reward in this run is non-negative.
A step whose plan is judged a failure, whose reasoning is hallucinated, or whose plan cannot be
grounded on the current screen receives exactly 0 rather than a penalty. The same is true of a
trajectory that exhausts the 30-step budget without completing the task or that keeps acting after
the task is already finished. Two consequences follow directly from this design. First, nothing in
the objective explicitly discourages unproductive behavior. Because accumulated dense credit is
bounded by the step limit of 30, while a terminal success contributes only 10, a long trajectory
that collects partial credit can out-earn a short trajectory that actually completes the task. Second,
because failure is indistinguishable from inaction at 0 reward, the relative advantage within a GRPO
group is determined largely by how much dense credit each rollout happened to accumulate rather
than by whether the task was completed. Most importantly, a wrong action is never punished in this
experiment. An action that the dense judge rejects, one whose stated reasoning does not match the
screen, and one that cannot be grounded at all are all worth the same as no action, which is zero.
The policy therefore receives no gradient signal that distinguishes a harmful step from a neutral one,
and the only way to change the return is to accumulate more positive credit. Section 3.5 replaces
this with a reward in which wrong actions and unsuccessful terminations are explicitly negative.

A.3
GROUNDING EXPERIMENTS
To determine the optimal grounding setup for each benchmark, we evaluated three different config-
urations paired with the SFT baseline planning model: (1) the internal 3B dense model alone, (2)
the RL training setup (where the 3B model handles all actions except swipes, which are routed to
Gemini-3.5-Flash), and (3) Gemini-3.5-Flash alone. The results are presented in Table 2.
The RL training setup achieved the best performance on UINavBench. This aligns with expectations,
as the 3B dense model was trained on real iOS screenshots that match the apps in this benchmark.
Furthermore, routing swipes to Gemini-3.5-Flash successfully addresses the 3B model’s limitation
to direction-only swipes, enabling the location-based swiping required by certain UINavBench tasks.
Gemini-3.5-Flash proved to be the optimal grounding model for iOSWorld. Because iOSWorld con-
sists of synthetic iOS apps, its visual features deviate from the training distribution of the 3B model.
Following this logic, since AndroidWorld consists entirely of Android applications, its interfaces de-
viate even further from the 3B model’s training data. As a result, we conclude that Gemini-3.5-Flash
is also the best grounding model for AndroidWorld.
