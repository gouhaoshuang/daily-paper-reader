## 摘要
GUI 记忆应保留过去动作的结果并学习可复用操作。这在长时程工作流中很困难，因为智能体必须跨应用使用信息，且有用操作与失败尝试交织在一起。我们提出任务推进记忆（TAM），它将任务推进定义为经校验的任务进展，并支持持续的任务执行和学习可复用操作。在执行过程中，任务推进状态表示经校验的任务进展如何改变剩余目标，使智能体能够跨应用基于先前成果继续推进。在每个任务之后，推进监督识别并抽象出产生经校验局部结果的交互。所学操作保留所需输入、预期结果与验证条件之间的关系。这保留了来自成功任务和失败任务的局部成功操作。在 MobileWorld 仅 GUI 任务上，仅任务推进状态就将成功率从 12.0% 提升到 28.2%。完整 TAM 相较于最强评估基线在任务成功率上取得 17.6% 的相对提升，并将每个已解决任务的生命周期 token 数降低 38.7%。在 SPA-Bench 上，TAM 在单应用英文 Level 3 设置中取得最先进的任务成功率。

## Abstract
GUI memory should preserve the results of past actions and learn reusable operations. This is difficult in long-horizon workflows, where agents must use information across applications and useful operations are interleaved with failed attempts. We introduce Task Advancement Memory (TAM), which defines task advancement as verified task progress, and supports ongoing task execution and learns reusable operations. During execution, Task Advancement State represents how verified task progress changes the remaining goals, allowing the agent to build on earlier achievements across applications. After each task, advancement supervision identifies and abstracts the interactions that produced a verified local result. The learned operations preserve the relation between required inputs, expected outcomes, and verification conditions. This retains locally successful operations from both successful and failed tasks. On MobileWorld GUI-only tasks, Advancement State alone raises success from 12.0% to 28.2%. Full TAM achieves a 17.6% relative gain in task success over the strongest evaluated baseline and reduces lifecycle tokens per solved task by 38.7%. On SPA-Bench, TAM achieves state-of-the-art task success in the single-app English Level 3 setting.

## 1. 核心问题与研究动机

- **背景**：GUI 智能体需要在跨屏幕、跨应用的长时程工作流中完成任务。例如，智能体在日历中确认会议事件后，还要利用已读到的会议详情去通知参与者。
- **核心痛点**：
  - 长交互历史中，**已完成的工作与失败尝试、有效动作与绕路交织**，智能体难以判断"任务推进到哪一步、还剩什么"。
  - 现有**动作日志式记忆**只记录"点了保存"，却不确认结果是否真的发生，导致智能体反复检查或重复操作。
  - 现有**轨迹/工作流记忆**绑定历史动作序列，界面变化后难以适配；且任务的最终成败对中间操作反馈不完整——**失败任务可能包含有用的局部成功，成功任务也可能包含无效尝试**。
- **整体含义**：论文主张 GUI 记忆应以"任务推进"为中心：记忆应表示**已完成工作如何改变剩余任务**，并从中抽象出**可复用的操作能力**，而非简单堆叠交互记录。

## 2. 方法论：Task Advancement Memory（TAM）

### 2.1 核心思想
- 将**任务推进（Task Advancement）**定义为"经 GUI 观测校验的任务进展"：此前未满足的需求被确认满足（获得所需信息或达成所需结果）。
- 任务推进有两个用途：
  - **作为状态（State）**：在线执行时，用已验证进展缩减剩余任务，指导跨应用执行。
  - **作为监督（Supervision）**：任务结束后，从产生局部验证结果的交互中抽象出可复用操作。

### 2.2 关键技术细节

- **任务编译（Task Compilation）**：LLM 将自然语言指令编译为需求图 `Q = (V, EQ)`。节点 `V` 为需求（信息获取或结果达成），边 `EQ` 为依赖关系。每个需求 `q` 包含：
  - 依赖集 `Rq`（为其提供输入的需求）
  - 证据规则 `Vq`（如何识别结果）
  - 可选分支条件 `γq`（何时需要该需求）
- **推进判定公式**：
  - `Adv(q) = 1[(z⁻q, z⁺q) = (U, E)] · Vq(ξ)`
  - 即需求状态从 UNRESOLVED（U）变为 ESTABLISHED（E），且观测 ξ 通过证据校验 `Vq`。
- **状态更新（两阶段）**：
  - `S̄t = Robs(St, ot)`：从当前观测建立可见信息与对象绑定。
  - `St+1 = Reff(S̄t, ot+1; Vt)`：用动作后的观测校验结果效果。区分"草稿—尝试—确认"三种情形（如输入文本是草稿、点击保存是尝试、出现确认提示才算保存成功）。
- **任务约简与推进前沿（Advancement Frontier）**：
  - `Ft = {q ∈ Ut : Rq ⊆ Kt, St |= γq}`
  - 已完成需求移出待办视图，其结果保留在状态中供后续需求消费；前沿是输入已齐备、分支条件成立的未完成需求集合。
- **证据缓存（Evidence Cache）**：保存与任务事实绑定的源图像/裁剪，当源屏幕离开近期上下文时可召回，且标记为历史证据；当前控件坐标仍来自实时屏幕。
- **推进监督与操作抽象**：
  - 每个推进记录一个候选交互片段；任务结束时 LLM 审阅者结合后续证据（确认或反证）判断局部结果是否成立，并筛选真正贡献的步骤。
  - 学习到的**推进操作**：`κ = ⟨Rκ, ∆κ, Vκ, Bκ, Γκ, Aκ⟩`，分别对应入口需求、预期推进、验证条件、对象角色、适用条件、经审阅的 GUI 实现（动作序列 + 界面条件）。
  - 抽象时用**对象角色替换实例值**，但保持输入、结果与验证目标指向同一对象（如事件详情与创建确认必须指同一事件）。
  - 操作图 `G` 将语义操作与多个 GUI 实现关联，兼容样本合并描述但保留各自路线。
- **操作复用**：分离两个问题——(1) 该操作能否由现有输入提供所需结果（语义匹配）；(2) 当前界面是否支持记录的 GUI 路线（兼容性与可靠性检查）。选择采用双轴 ϵ-Pareto（需求覆盖 + 执行支持），最多保留两个候选；路线不可用时仍可提供语义指导（输入、预期结果、验证线索）。
- **可靠性平滑**：`rj = (sj + αj) / (sj + fj + αj + βj)`，j ∈ {sem, gui}，用正负证据计数与平滑伪计数估计语义/路线可靠性，阈值可随经验校准。

### 2.3 算法流程（Algorithm 1 概要）
1. 编译需求图 Q，初始化状态 S、缓存 E、历史 H、轨迹 T、候选片段 B。
2. 循环：观测 o → 更新 S → 记录新推进片段 → 读取剩余工作 → 检索前沿相关证据与操作 → 组装记忆上下文 C → 基座策略采样动作 a → 执行得 o′ → 更新 S → 记录片段 → 追加轨迹。
3. 任务结束：用 T 审阅 B，保留有支持的片段，抽象入口输入与结果，合并入操作图 G。

## 6. 主要结论与发现

- **MobileWorld**：TAM 成功率 34.2%，比最强基线 ConAct（29.1%）高 5.1 个百分点，相对提升 17.6%；比无记忆 backbone（12.0%）高 22.2 个百分点。
- **任务推进状态的独立贡献最大**：仅启用 State 即把成功率从 12.0% 提升到 28.2%；加入 Operator Graph 后达 32.5%，完整 TAM 达 34.2%。
- **跨应用收益更显著**：多应用任务上相对 ConAct 提升 8.1 个百分点，单应用仅 1.8 个百分点，契合方法设计目标。
- **效率优势**：EQA@50 最高（29.2%），平均 20.6 轮；LTS 0.771M，比 ConAct（1.257M）低 38.7%，接近最便宜的 AWM（0.720M）但成功率远高。
- **SPA-Bench**：57.0% 成功率，超过 GUI-explorer 的 53.7%，为该设置下报告的最高结果。
- **机制发现**：
  - 信息识别与目标使用覆盖率均为对比方法中最高。
  - 状态可用性 77.8% vs 扁平状态 55.6%；正确目标使用 77.8% vs 66.7%。
  - 审阅将保留片段长度中位数从源轨迹的 20% 压缩到 7.7%，监督信号更聚焦局部操作。
  - 信息在状态中保留 10 步后仍达 95.1%，远高于当前 XML/近期文本的 57.6%。
  - 74.8% 含验证局部结果的失败执行贡献了可保留学习材料。

## 7. 优点

- **视角统一**：用"任务推进"一个概念同时贯通在线执行（State）与离线学习（Supervision），概念简洁、解释力强。
- **语义与实现解耦**：操作 = 语义契约（输入/结果/验证）+ 多个 GUI 实现，界面变化时仍可复用语义指导，设计优雅。
- **重视失败经验**：显式从失败任务中提取局部成功，弥补"仅从成功轨迹学习"的覆盖不足。
- **即插即用、低成本**：不重训策略，仅替换记忆上下文；上下文占用小（状态与指导中位仅占 5.7% 文本），LTS 显著低于同类记忆方法。
- **实验较扎实**：统一 backbone/预算的公平对比、组件消融、细粒度机制诊断（字段级、操作级、片段级）层次分明，且对下界与不可比因素有明确披露。

- **评测覆盖有限**

## 9. 对后续研究的启示

- **"推进"作为记忆的第一等公民**：把记忆从"动作日志"重构为"已验证的需求状态"，为长时程 GUI 任务提供了一种可解释、可裁剪、可监督的中间表示，这一思路可迁移到 Web Agent、具身操作与软件工程 Agent 的任务状态建模。
- **执行与学习共用同一表征**：State 与 Supervision 共享"推进"语义，使在线推理产物天然成为离线学习素材，避免了"执行用一套记忆、学习用另一套轨迹"的割裂，值得作为 Agent 记忆系统的通用设计原则。
- **语义契约 + 多实现的操作抽象**：将"能做什么（输入/结果/验证）"与"怎么做（界面路线）"解耦，为界面漂移下的技能复用提供了可行路径；未来可引入版本化路线与自动修复（路线失效时由 Agent 重新探索并回填）。
- **失败即数据**：显式承认"失败任务含局部成功"，并设计审阅机制筛选贡献步骤，为提升数据利用效率提供了新角度；后续可研究审阅者的不确定性建模与主动复核。
- **可继续推进的方向**：需求图的自动纠错与增量修订、跨任务的操作图共享与冲突消解、记忆的隐私保护与遗忘机制、以及在更强/更弱 backbone 上的能力边界刻画。

## 10. 总体评价

论文以"任务推进"统一了 GUI Agent 的记忆状态与学习监督，问题定位准确（长交互中"做到哪、还剩什么"的失配），方法设计简洁且工程可落地（不重训、上下文占用低、LTS 显著下降），实验在统一 backbone 与预算下呈现了清晰的组件贡献分解与跨应用收益，机制分析细致且对不可比因素与下界有诚实披露。主要短板在于评测规模与场景覆盖、统计严谨性、超参数敏感性以及成本与隐私维度的报告不足。总体而言，这是一篇概念贡献明确、实证较扎实的工作，其"推进中心"的记忆范式有望成为 GUI/长时程 Agent 记忆设计的参考基线。
