## 摘要
设备端LLM推理面临响应延迟、硬件资源有限和用户隐私的三难困境。全云推理提供强大的计算能力，但暴露用户提示和对话数据，而独立设备端推理对于大多数消费类和嵌入式边缘设备不可行。本文提出了一种基于端点认证的KV缓存的隐私为中心的边云协同LLM推理框架。本地端点处理输入预处理、嵌入计算、自适应特征优化、KV缓存认证、推测性解码和低维模型头计算，而云端负责认证解码器推理、KV缓存管理、令牌验证和高维词汇投影。端点融合部分输出，应用语言自适应掩码并采样目标令牌。所有传输数据和截断的logits均经量化并使用AES-GCM加密以保护隐私，核心轻量级模块、草稿参数和缓存访问策略保留在本地以避免泄露。该框架通过优化的流式传输、批处理和量化ONNX部署，支持包括纯CPU、GPU配备和嵌入式设备在内的异构设备。评估表明，与基线分割推理相比，该框架将每令牌延迟降低高达46.1%，下行链路负载降低高达67.4%，同时保持与全云推理相当的性能。

## Abstract
On-device LLM inference faces a trilemma of response latency, limited hardware resources and user privacy. Full cloud inference delivers strong computing power but exposes user prompts and dialogue data, while standalone on-device inference is unfeasible for most consumer and embedded edge devices. This paper presents a privacy-centric edge-cloud collaborative LLM inference framework built on endpoint-authenticated KV cache. Local endpoints handle input preprocessing, embedding computation, adaptive feature optimization, KV cache authentication, speculative decoding and low-dimensional model head calculation, while the cloud conducts authenticated decoder inference, KV cache management, token verification and high-dimensional vocabulary projection. Endpoints fuse partial outputs, apply language-adaptive masking and sample target tokens. All transmitted data and truncated logits are quantized and AES-GCM encrypted for privacy, with core lightweight modules, draft parameters and cache access policies kept local to avoid leakage. The framework supports heterogeneous devices including CPU-only, GPU-equipped and embedded devices via optimized streaming, batching and quantized ONNX deployment. Evaluations demonstrate that the framework reduces per-token latency by up to 46.1\% and downlink payloads by up to 67.4\% over baseline split inference, retaining comparable performance to full cloud inference.

## 2. 论文提出的方法论

### 2.1 核心思想
- **端点掌控敏感决策**：端点保持隐私敏感操作（如缓存授权、语言识别、局部推理）在本地，云端只执行授权的解码器推理。
- **分割逻辑**：将模型推理按功能和隐私等级分割，云端处理计算密集但信息量较低的深层变换，端点处理轻量但隐私敏感的部分。
- **多层保护**：结合传输层加密（AES-GCM）、端点本地LoRA模块、缓存授权策略，形成系统级防护。

### 2.2 关键技术细节

1. **端点控制KV缓存授权**：端点生成控制元组 `c = (flag_Cache, L_Cache, dtype, ℓ)`，明确指示云端是否使用历史KV缓存以及允许使用的缓存长度。云端根据授权决定是否访问已有缓存。

2. **设备自适应特征准备**：根据端点硬件能力调整初始特征张量：
   - **纯CPU**：按列分块 `h0 = concat(h0^(1), ..., h0^(Nb))`，流式传输以重叠解密与本地计算。
   - **GPU**：通过张量并行、模型切片和本地批处理加速。
   - **边缘设备**：导出为ONNX模型，通过ONNX Runtime执行，可选量化。

3. **分布式词汇投影**：
   - 将隐藏维度 `D` 分割为 `Dend`（端点侧）和 `Dcloud`（云端侧），对应的LM-head权重矩阵也分割。
   - 端点计算 `zend = h_end * W_end`，云端计算 `zcloud = h_cloud * W_cloud + b`。
   - 端点通过加法 `z = zend + zcloud` 恢复完整logits。
   - 支持**语言自适应词汇子集**：云端仅返回指定语言子集 `Vℓ` 的logits，端点对其他维度赋 `-∞`，大幅减少下行通信。

4. **端点推测解码与云端验证**：
   - 端点使用轻量草稿模块 `g_φ` 提出 `N` 个未来令牌，云端以目标模型验证。
   - 接受令牌直接提交，拒绝则从最后一个接受位置重算。
   - 草稿长度 `N` 设备自适应（GPU用5，边缘用2）。

5. **传输保护与隐藏状态保护**：
   - **AES-GCM** 加密量化后的张量载荷，保护网络传输。
   - **端点本地LoRA模块**：轻量模块的LoRA权重保留在端点，不传输至云端，增加反演难度。
   - **缓存授权**：端点显式控制是否、以及多少历史缓存可被云端使用。

6. **算法流程（Algorithm 1）**：
   - 端点预处理输入，生成嵌入、语言标识和控制元组 → 云端进行授权解码 → 返回隐藏状态 → 端点计算局部logits并生成草稿令牌 → 云端验证并更新KV缓存 → 循环直至终止。

## 7. 优点

- **隐私与性能的统一设计**：将隐私控制作为一等目标，通过缓存授权、分割投影、本地LoRA等机制系统性降低暴露，而非事后增加加密。

- **组件化、可配置**：端点分割维度、草稿长度、缓存授权等均可按场景调整，提供清晰的trade-off控制。
