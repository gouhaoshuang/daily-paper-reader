## 摘要
大语言模型（LLM）智能体已从生成响应扩展到执行多步任务，通过调用工具、观察结果并迭代决定下一步动作。大多数智能体系统运行在桌面或服务器上，支持工具使用和任务自动化。移动设备也是重要的智能体环境，因为它们广泛可用且包含用户数据、传感器和日常应用。现有的移动智能体主要通过图形用户界面（GUI）操作（如点击、滑动和输入）来操控智能手机，这通常形成长且依赖界面的序列，无法直接访问设备能力，并使执行边界难以定义。我们提出PalmClaw，一个开源的智能体框架，原生运行在手机上，并直接在设备上管理会话、记忆、技能、工具和智能体循环。PalmClaw将设备能力暴露为具有明确参数、结构化结果和清晰定义执行边界的设备工具。这种设计使智能体能够直接使用移动能力，同时保持每个动作明确可控。实验表明，与最强基线相比，任务成功率相对提高11.5%，完成时间减少94.9%，设置负担更低，并通过痕迹说明了执行边界的应用方式。代码可在https://github.com/ModalityDance/PalmClaw获取。

## Abstract
Large Language Model (LLM) agents have moved beyond generating responses to executing multi-step tasks by calling tools, observing the results, and iteratively deciding the next action. Most agent systems run on desktops or servers, which support tool use and task automation. Mobile devices are also important agent environments because they are widely accessible and contain users' data, sensors, and daily-use applications. Existing mobile agents mainly operate smartphones through graphical user interface (GUI) actions such as tapping, swiping, and typing, which often form long, interface-dependent sequences, cannot directly access device capabilities, and make execution boundaries difficult to define. We present \textbf{PalmClaw}, an open-source agent framework that runs natively on mobile phones and manages the sessions, memory, skills, tools, and agent loop directly on the device. PalmClaw exposes device capabilities as device tools with explicit arguments, structured results, and clearly defined execution boundaries. This design enables agents to use mobile capabilities directly while keeping each action explicit and controlled. Experiments show an 11.5\% relative improvement in task success and a 94.9\% reduction in completion time over the strongest baseline, with lower setup burden and traces illustrating how execution boundaries are applied. Code is available at https://github.com/ModalityDance/PalmClaw.

- **核心问题**：现有的移动端大语言模型智能体主要依赖图形用户界面（GUI）操作（如点击、滑动、输入）来操控手机，存在三大局限性：

- **整体含义**：作者主张移动智能体不应仅停留在“屏幕操控”层面，而应原生运行在移动设备上，通过结构化的“设备工具”直接调用手机能力，从而提升任务完成效率、降低对外部计算资源的依赖，并增强执行的可控性与安全性。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：将移动设备能力抽象为具有**显式参数、结构化结果和工具特定执行边界**的*设备工具*，并将整个智能体框架（会话管理、记忆、技能、工具注册、代理循环）原生运行在手机端，而非依赖桌面或云服务器。

- **关键技术细节**：
  - **智能体组件**（均在设备端维护）：
    - **会话**：管理来自本地消息、远程通道消息、定时唤醒任务的持续交互，每个会话包含对话历史、工具痕迹、附件及专属工作区。
    - **记忆**：两层持久记忆——跨会话的共享长期记忆和每个会话的摘要记忆；支持智能体通过工具读写或检索历史。
    - **技能**：可复用的任务指令（SKILL.md 文件），支持始终激活和按需匹配加载，避免全量上下文负载。
    - **设备工具**：每个工具包含模型端规范（名称、描述、JSON 参数模式）和设备端函数（调用移动服务或应用管理操作），通过注册表管理。
  - **代理执行流程**：
    1. **上下文组装**：从系统指令、运行时上下文（时间、时区、工作区路径）、长期记忆、技能、对话历史、工具规范六个来源构建上下文。
    2. **代理循环**：反复进行“上下文→LLM调用→执行工具→返回结果”的迭代，直到无工具调用或达到轮次上限。
    3. **工具执行三检**（执行前校验）：
       - **Schema**：验证必要参数、类型和范围；
       - **权限**：检查设备授权或用户确认（缺失则触发系统权限请求或设置引导）；
       - **工作区**：解析文件路径，拒绝越界（其他会话工作区、未授权的全局路径），外部写入需用户确认。

## 3. 实验设计

- **数据集/场景**：

  - **AssistantBench**：19 个开发集子任务（Web 信息查询任务，使用官方准确率指标）。
- **基准方法**：
  - **ApkClaw**：Android 原生应用，通过 GUI 操作（点击、滑动、输入）控制手机。
  - **MobileClaw**：手机端客户端+外部 Python 运行时，通过截屏/ GUI 动作控制。
  - **ClawMobile**：在 Termux 终端中运行，结合 Phone API、Shell 命令和 GUI 控制。
  - 此外部署对比中增加了桌面框架 **OpenClaw**。
- **实验配置**：

  - 轮次限制：PalmClaw 最多 30 轮（AssistantBench），GUI 基线最多 100 轮。
- **评价指标**：任务成功率（MobileTask）、准确率（AssistantBench）、平均动作数、总 Token 数、完成时间；以及部署步骤和时间的对比、执行边界案例分析。

## 6. 论文的主要结论与发现

- **任务完成效果**：在 MobileTask 上，PalmClaw 任务成功率达到 97.1%，相对最强基线 ApkClaw（87.1%）提升 11.5%；平均完成时间仅 17.7 秒，相比 ApkClaw（348.8 秒）降低 **94.9%**；动作数和 Token 数也大幅减少。

- **执行边界**：通过两个典型案例（日历权限、工作区边界）展示了工具执行前的 Schema-权限-工作区三层校验机制，有效阻止了未授权操作，并要求用户明确授权或提供手动操作指引。

## 7. 优点

- **原生设备端设计**：将智能体组件全量运行在手机上，摆脱了对桌面/服务器端的依赖，降低了部署门槛，适合更多用户。
- **设备工具抽象**：将设备能力封装为带明确参数和结构化结果的工具，避免了冗长、脆弱的 GUI 动作序列，显著提升效率（时间减少 94.9%）。
- **明确的执行边界**：通过注册、参数验证、权限检查、工作区隔离等多层控制，使每个工具调用均受控，提高了安全性和可解释性。
- **开源与可扩展**：框架开源（AGPLv3），支持内置和用户安装的技能、工具，易于定制。
- **用户体验友好**：支持通过手机应用程序直接交互，无需额外硬件或命令行配置。

- **实验覆盖范围有限**：
