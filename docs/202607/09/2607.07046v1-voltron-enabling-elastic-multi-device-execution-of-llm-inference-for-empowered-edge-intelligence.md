## 摘要
大型语言模型（LLM）因其在生成式任务中的卓越能力而广泛用于智能服务。通常，基于LLM的服务在集中式数据中心处理用户的推理请求。然而，这种集中式执行对最终用户存在局限性，例如通信开销导致的响应延迟增加以及隐私泄露风险。为缓解上述局限，越来越多的工作推动在用户端设备本地执行LLM推理。然而，单个边缘设备有限的资源限制了对LLM可达精度的要求。为克服该问题，我们首先提出利用边缘可用的多个用户端设备进行LLM推理，从而支持更大模型的执行。具体而言，我们提出了Voltron，一种新颖的设备端LLM推理框架，可弹性利用多个用户端设备执行LLM推理，同时适应多样化的真实边缘环境。在我们的评估中，Voltron相比可在单个边缘设备上执行的最先进的LLM，实现了高达16.5%的精度提升，并满足用户QoS需求。

## Abstract
Large language models (LLMs) are widely used in intelligent services due to their remarkable capability in generative tasks. Typically, LLM-based services process the inference requests of the users in a centralized data center. Unfortunately, such centralized execution has limitations for end-users, such as increased response latency with communication overhead and privacy leakage risk. To alleviate the aforementioned limitations, there have been increasing pushes to execute LLM inference locally on user-end devices. However, the limited resources of a single edge device impose restrictions on achievable accuracy of LLMs. To overcome the issue, we first propose to leverage multiple user-end devices available at the edge for LLM inference, enabling the execution of larger models. Specifically, we propose Voltron, a novel on-device LLM inference framework that elastically utilizes multiple user-end devices for LLM inference execution while adapting to diverse real-world edge environments. In our evaluation, Voltron achieves up to 16.5% higher accuracy than state-of-the-art LLMs that can be executed on a single edge device, satisfying user QoS requirements.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 核心思想
Voltron是一个弹性多设备LLM推理框架，能够在每次对话开始时根据当前执行环境（设备计算/内存能力、模型架构、精度配置、网络状况、推理阶段等）动态确定每层的并行策略（MP或TP）和精度设置，并在推理过程中持续监控环境变化（如KV缓存增长、无线信号波动），实时调整执行策略，从而在满足QoS约束下最大化精度。

### 关键技术细节
- **模型执行计划（Model Execution Plan）**：
  - **层级混合并行（Layer-wise Hybrid Parallelism）**：对每一层，分别评估模型并行（MP）和张量并行（TP）的执行时间（通过回归模型预测计算时间，基于传输数据大小和网络带宽估计通信时间），选择更快的策略。MP将连续层子集分配给设备；TP将每层切片分发到所有设备。分配时考虑设备性能（避免慢设备成为瓶颈）和内存预算（防止OOM）。
  - **重要性感知混合精度（Importance-aware Mixed Precision）**：离线阶段为每层计算重要性分数（基于逐通道剪枝导致的困惑度变化），在线阶段利用二分搜索在精度-延迟-内存空间中高效确定最优混合精度配置（FP16/INT8/INT4），优先保护重要层的精度。
  - 对预填充阶段和解码阶段分别探索执行策略，因为两者计算特性差异大。

- **弹性模型执行（Elastic Model Execution）**：
  - **计算缩放（Computation Scaling）**：当KV缓存增大或设备断开导致内存紧张时，先进行精度缩放（重新运行执行计划模块，逐token调整层精度）；若仍不足则采用重要性感知的逐片剪枝（按重要性升序剪除分片）。通过I/O与计算重叠的机制隐藏层/分片替换的开销。
  - **通信缩放（Communication Scaling）**：当无线信号减弱导致通信开销过大时，对需要跨设备传输的激活值进行重要性感知的量化（先降精度，必要时剪枝传输激活及对应分片），以减少传输数据量，满足QoS。

- **能量优化（可选）**：当优先节能时，通过计算缩放创造延迟裕量，再利用DVFS降低处理器电压频率，实现高精度下显著节能（最高降低59%能耗）。
