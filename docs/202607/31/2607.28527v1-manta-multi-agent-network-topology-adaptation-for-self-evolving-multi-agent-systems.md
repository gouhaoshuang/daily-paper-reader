## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题的求解能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出了 MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自演化。在执行前，MANTA 从先前的结构经验中初始化一个任务条件化的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界的结构更新。这些更新可以修改智能体角色、通信链接、执行顺序、信息可见性和验证路径，同时保留任务接口和智能体预算。我们在五个基准上对 MANTA 与代表性的单智能体和多智能体基线进行了评估，涵盖了信息检索、工具使用、规划、工作流执行和数学推理。MANTA 取得了平均分 74.0 的最高分，比最强基线高出 5.8 个百分点，并在 PlanCraft 上取得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作本身的架构。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

- **核心问题**：多智能体系统能否在**执行任务的过程中（测试时）自动改进自身的通信拓扑**？即是否可以根据当前任务和实时观察到的协作轨迹，动态调整智能体角色、通信链接、执行顺序、信息可见性和验证路径，而无需改变模型权重。
- **整体含义**：提出“拓扑级自我改进”（topology-level self-improvement）这一新维度，将自我演进从输出、提示、推理轨迹、记忆、工具等层面提升到**协作架构本身**。这一思想借鉴生物系统对环境压力的持续适应，为多智能体系统在真实复杂场景中的在线自适应提供了新路径。

## 2. 提出的方法论：核心思想与关键技术

### 2.1 核心思想

MANTA（Multi-Agent Network Topology Adaptation）通过**两层层级结构**实现拓扑自演化：

- **目标多智能体系统层**：负责实际执行任务，进行推理、工具调用、消息交换。
- **编排层**：由确定性代码与三个LLM组件（拓扑规划器、轨迹审计器、技能反思器）协同，负责拓扑的规划、监控、修复与经验累积。

基本流程：

1. **执行前**：基于长期经验初始化一个任务条件化的拓扑；
2. **执行中**：每一轮协作后，轨迹审计器扫描协作过程，若发现可观察的过程异常（不判断答案正确性），则控制器允许执行**一次有界的结构修复**（最多一次变异，每次变异≤3个操作）；
3. **修复后**：在修订后的拓扑上运行最后一轮，然后通过投票和证据综合产生最终答案；
4. **跨运行记忆**：短期剧本记录当前运行内的拓扑/审计/修复历史；长期剧本跨运行累积可复用的拓扑选择经验，由技能反思器周期性重写（仅基于过程信号，不接触基准答案或ground truth）。

### 2.2 拓扑表示

- **版本化与验证**的拓扑规范，定义了智能体结构角色（协调者、工人、验证者、辩手、投票者等）和阶段角色（worker/critic）。
- 支持**嵌套模式组**（如星形、链式、辩论、投票等），允许一个智能体作为子组的中心并综合其报告；还可以额外添加直接通信边。
- 上下文策略控制智能体的信息可见性（可读消息、发送者、证据范围等），由代码强制实施。
- 执行前会校验成员关系、循环、角色、预算等；无效提案被拒绝。

### 2.3 编排循环

1. **任务条件化规划**：拓扑规划器接收任务与经验记忆，输出紧凑计划（交互模式、agent数量、可选验证器/嵌套组），确定性代码将其扩展为完整拓扑并验证。
2. **回合执行**：按组结构递归执行；agent通过结构化中继包（含答案、证据、置信度、未解决问题）通信；共享上下文控制器强制执行可见性策略；相同工具调用去重；证据账本以追加方式记录声明与证据。
3. **轨迹审计与修复**：审计器扫描结构化工件（工具记录、中继包、置信度、未解决问题、证据可见性），输出过程风险标志（如过度承诺、过早共识、重复状态变更等），不查看基准答案。若有中/高严重度可修复标志，则运行被标记；规划器生成一个修复变异（最多三个操作），确定性代码校验后应用；无效提案回退到保守修复编译器或跳过。
4. **双时间尺度记忆**：短期剧本记录本运行内每轮拓扑、审计发现和修复决策；长期剧本存储通用原则，规划器在初始规划和修复时使用，并每隔N次运行被技能反思器更新。

### 2.5 Agent Harness 与上下文管理

- 所有任务智能体共享一个阶段执行契约（结构性系统提示、角色子句、工具使用契约等），强制指令优先级。

## 6. 主要结论与发现

- **主结果**：MANTA在5个基准上的平均分**74.0**，比最强基线（ADAS 68.2）高出**5.8个百分点**，并在PlanCraft上取得最佳结果；且在所有基准上都优于Single Agent。
- **消融**：任务条件化初始拓扑规划贡献最大（去掉后从71.7降至57.5）；执行时修复次之（降至60.8）；长期剧本带来额外小幅提升（67.5/66.7）。
- **变异预算**：首个变异机会带来最大增益，额外变异（2~3次）继续提升覆盖率，说明有界修复能扩展任务覆盖。
- **经验迁移**：长期剧本可在同域和跨域（PlanCraft↔WorkBench）间转移，平均提升3.3分；而AFlow、AgentSquare、MASS等工作流结构迁移多为负效果。
- **令牌效率**：MANTA是评估的MAS系统中总体token消耗最低的，元级操作仅占约12%的推理预算，说明轻量级规划/修复开销可控。
- **拓扑修复模式**：修复不只是增加智能体——更多是重连通信边、串行化执行、插入验证角色等结构变化。案例显示，修复能解决过载分支、缺失验证、过早共识、重复写入等具体问题。
- **审计信号**：无修复标志的运行正确率（83.2%）显著高于有标志的运行（62.5%），说明过程信号与答案可靠性相关；但干净轨迹不等于正确，可能一致认同错误答案。

## 7. 优点

- **问题新颖**：明确提出“拓扑级自我改进”概念，将MAS研究从离线优化扩展到在线自适应。

- **过程信号使用**：审计器不依赖ground truth，使用纯过程信号，现实适用性强；通过确定性分类与开放式审计结合提高鲁棒性。
- **实验扎实**：主实验+消融+预算分析+迁移实验+案例研究+审计统计，多角度验证方法有效性和可解释性。

- **深刻的修复洞见**：案例展示出“变结构”比“变规模”更重要，为多智能体系统设计提供新视角。

## 8. 不足与局限

- **实验规模受限**：每基准仅30个问题，3次重复，统计噪声大；需要更大基准或更多问题验证。
- **单一模型**：仅用Gemma 4，未测试Gemini、GPT、Llama等其他骨干，泛化性未知。
- **算力细节缺失**：未报告硬件配置、时间和成本，难以复现和比较实际开销。
- **公平性存疑**：自适应设计基线（AFlow等）的搜索预算“尽可能匹配”但未给出详细说明；静态MAS的agent角色与MANTA相同但可能未做最优配置。
- **审计代理局限**：审计器本身是LLM，可能产生误报/漏报；论文也承认过程信号与答案正确性不完全对齐。
- **修复条件有限**：每运行只允许一次修复，最多3个操作；复杂任务可能需要更多自适应迭代。
- **应用范围**：面向信息检索/工具/规划类任务，未覆盖真实机器人、多轮交互、多模态等场景；长期剧本的跨域迁移仅在两个规划类基准上验证，更广泛迁移性需进一步测试。
- **潜在偏差**：过程信号标签由系统自生成，可能存在自我确认偏差；修复效果分析是观察性的，未做严格的配对反事实实验。
