## 摘要
我们提出了OrchNAS，一个能量感知的、个性化的联邦边缘智能框架，它利用神经架构搜索服务为异构边缘环境自动设计服务自适应模型。该框架在服务器端的NAS服务上编排架构搜索过程，使边缘服务能在设备级的能量、计算和内存约束下推导出个性化架构。我们引入了一种能量感知的全局架构搜索机制，该机制跨异构服务学习一个紧凑的全局表示。我们开发了一种能量高效的架构选择机制，通过渐进式、贪婪、能量感知的剪枝策略，使每个服务能推导出满足其资源约束的个性化子网。我们提出了一种能量高效的个性化模型优化方案，在保持全局表示的同时更新服务自适应参数，其中原始-对偶优化机制在架构适应过程中强制执行严格的能量预算。在真实世界和基准数据集上的实验证明了所提方法的有效性。

## Abstract
We propose OrchNAS, an energy-aware, personalised, federated edge intelligence framework that leverages a Neural Architecture Search Service to automatically design service-adaptive models for heterogeneous edge environments. The framework orchestrates the architecture search process on a server-side NAS service, enabling edge services to derive personalised architectures under device-level energy, computation, and memory constraints. We introduce an energy-aware global architecture search mechanism that learns a compact global representation across heterogeneous services. We develop an energy-efficient architecture selection mechanism that enables each service to derive a personalised subnet that satisfies its resource constraints via a progressive, greedy, energy-aware pruning strategy. We propose an energy-efficient personalised model optimisation scheme that updates service-adaptive parameters while preserving global representations, where a primal-dual optimisation mechanism enforces strict energy budgets during architecture adaptation. Experiments on real-world and benchmark datasets demonstrate the effectiveness of the proposed approach.

## 1. 核心问题与整体含义（研究动机和背景）

- **研究背景**：边缘计算与联邦学习（FL）结合形成“联邦学习即服务（FLaaS）”，使异构边缘设备（智能手机、IoT传感器、自动驾驶车辆）协同训练模型，同时保护数据隐私。然而，设备间的**统计异质性（非IID数据）**导致全局模型收敛困难，性能下降。
- **核心问题**：个性化联邦学习（PFL）虽能通过本地微调提升性能，但带来**高能耗**问题。现有PFL方法依赖手动设计模型架构，缺乏自动化，且大多忽略设备级能量约束。现有NAS方法（如SPIDER、FEDPNAS、PEACHES）虽能搜索个性化架构，但搜索过程本身昂贵，且未显式考虑能量消耗。
- **整体含义**：需要一种**能量感知、自动化的个性化NAS框架**，能在异构边缘设备上平衡模型精度与能耗，实现可扩展的联邦边缘智能。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- **框架**：OrchNAS（Orchestrated NAS），将NAS过程卸载到云端**NAS服务**上，服务器端进行全局架构搜索，客户端根据自身资源约束获取个性化子网，并采用**原始-对偶优化**强制执行能量预算。

### 关键技术细节
1. **能量感知的全局架构搜索**：
   - 基于**One-Shot NAS**：构建超级网络（DAG），候选架构共享权重，避免从头训练。
   - 服务器通过**进化变异**更新候选池，生成新架构。
   - 每个客户端`k`评估候选架构`a`：估计每轮训练能量`Ê_tk(a) = α_k * FLOPs(a) * T_tk`，并计算能量感知分数`S_tk(a) = ValAcc_tk(a) - λ * Ê_tk(a)`（λ>0为权衡系数）。
   - 服务器选择全局最优架构：`a_t = argmax_{a∈A_b} Σ p_k * S_tk(a)`，并广播给参与客户端。
2. **能量高效的架构选择（渐进式贪婪剪枝）**：
   - 每个客户端检查当前子网是否满足动态资源约束（能量预算B、计算容量C、内存M）。
   - 若不满足，执行**渐进式贪婪能量感知剪枝**：对每条边上的每个操作，计算移除后的精度下降ΔAcc和能量减少ΔE，按分数`Score(o)= ΔAcc - β*ΔE`升序排序，依次移除分数最低的操作（即能耗高、精度损失小的操作），直到满足约束。
3. **能量高效的个性化模型优化**：
   - 固定全局参数，更新个性化参数`v_k`，使用近端项`(μ/2)||v_k - w_global||²`保持与全局知识一致。
   - 采用**原始-对偶优化**处理能量约束：
     - **原始更新**：通过剪枝最小化拉格朗日函数`L = F_k + η(E_k - B_k)`（η为对偶变量）。
     - **对偶更新**：η_{t+1} = [η_t + ρ(E_k(a_k) - B_k)]⁺，若能量超支则增大惩罚系数。
   - 理论上保证平均能量约束违反量不超过O(ρ)。

### 算法流程（Algorithm 1）
- 初始化全局参数、候选池、各服务个性化参数、子网、对偶变量。
- 每轮：NAS服务生成候选并通过进化变异更新；并行评估；选择全局架构；客户端本地SGD更新全局参数；剪枝得到个性化子网；更新个性化参数；更新对偶变量；上传全局参数至服务器加权平均。
