## 摘要
大型语言模型（LLM）多智能体系统越来越不仅依赖于单个智能体的推理方式，也依赖于智能体之间的连接方式。本文介绍了QueenBee规划器，这是一个将智能体间通信拓扑视为可检索且自我改进的设计技能的框架。工作智能体池、任务适配器和评分函数保持固定；仅有一个外部LLM规划器学习生成时间通信有向无环图（DAG），指定谁在哪个轮次向谁发送信息、谁合并消息以及谁输出最终答案。执行轨迹被提炼为基于证据的设计规则，包含三种操作：“保留”、“修改”和“避免”。为了防止自我进化将偶然的成功或看似合理但错误的解释转化为策略，QueenBee使用了保留接受门、方差感知信用、动机级归因、迁移信任、洞察证伪和结构去重。我们在Count-Frequency聚合和Silo-Bench风格的分布式协调任务上评估了该方法。在固定工作智能体的情况下，自我进化的图生成产生的通信结构优于固定拓扑和冷生成。在CF全测试设置中，最佳生成图将RMSE从最强固定拓扑的12.53降低到7.87，同时减少了消息、模型调用和Token成本；Silo风格的结果显示出相对于冷启动和固定拓扑基线的相同改进方向。这些结果表明，多智能体系统可以学习可重用的架构设计知识，而不仅仅是记忆任务答案。

## Abstract
Large language model (LLM) multi-agent systems increasingly depend not only on how individual agents reason, but also on how agents are connected. This paper introduces QueenBee Planner, a framework that treats inter-agent communication topology as a retrievable and self-improving design skill. A pool of worker agents, the task adapter, and the scoring function are frozen; only an outer LLM planner learns to generate temporal communication DAGs specifying who sends information to whom, in which round, who merges messages, and who emits the final answer. Execution traces are distilled into evidence-backed design rules with three actions: \emph{Preserve}, \emph{Modify}, and \emph{Avoid}. To prevent self-evolution from turning lucky runs or plausible but false explanations into policy, QueenBee uses held-out acceptance gates, variance-aware credit, motif-level attribution, transfer trust, insight falsification, and structural deduplication. We evaluate the method on Count-Frequency aggregation and Silo-Bench-style distributed coordination tasks. With fixed workers, self-evolved graph generation produces communication structures that improve over fixed topologies and cold generation. In the CF fulltest setting, the best generated graph reduces RMSE from 12.53 for the strongest fixed topology to 7.87 while also reducing messages, model calls, and token cost; Silo-style results show the same direction of improvement over cold and fixed-topology baselines. These results suggest that multi-agent systems can learn reusable architectural design knowledge rather than merely memorizing task answers.

## 2. 论文提出的方法论

### 2.1 核心思想

- **规划器-工作者分离**：冻结工作者池（包括角色、提示、解析）、任务适配器和评分函数；仅让**外层LLM规划器**学习如何生成时序通信有向无环图（temporal DAG）。学习对象不是任务答案，也不是工作者的推理能力，而是规划器生成拓扑的能力。
- **技能库**：将执行经验蒸馏为证据支持的设计规则，分为三种动作：
  - **保留（Preserve）**：直接保存已验证的高效结构作为可执行骨架。
  - **修改（Modify）**：保留核心信息流，但调整边、汇点或轮次指令以适应类似但不完全相同的任务。
  - **避免（Avoid）**：记录导致失败的结构，作为未来生成的负约束。

### 2.2 关键技术细节

- **时序通信DAG生成**：规划器生成一个结构化描述 \(G = (N, T, E, h, I, R)\)，其中：
  - \(N\)：工作者数量
  - \(T\)：通信轮数
  - \(E \subseteq [N] \times [N] \times [T]\)：有向时序边
  - \(h\)：最终答案持有者
  - \(I\)：接收端指令集
  - \(R\)：合并规则（如何将新消息与旧信念融合）
  - 执行语义：同一轮内边同步传递，接收者使用上一轮结束时的出箱消息。
- **可行性约束**：轮数上限 \(T_{\text{max}}\)、总边数上限 \(M\)、每轮每个工作者最大扇入 \(\beta\)，确保可执行且成本受控。
- **动机级信用分配**：将完整生成的图拆解为8个手部结构特征（如通信步数、总消息数、最大扇入、是否存在审计边等），每个证据行将其损失分配给激活的动机。动机的信用估计使用样本数惩罚（\(\tilde{L}_k = \bar{L}_k + \kappa_m / \sqrt{n_k}\)），避免小样本幸运噪声。
- **自我进化循环**：
  1. 从技能库检索相关技能 → 生成候选DAG（受可行性约束） → 通过动机和探针先验排序 → 执行 → 蒸馏证据 → 候选更新。
  2. 候选更新必须通过**保留验证门**：在保留案例/种子上比较新旧技能库的生成器性能，只有统计显著提升才被接受。
  3. 额外的保护机制：方差感知信用（用 \(\bar{L} + \kappa_s \sigma/\sqrt{n}\) 评估风险）、迁移信任（技能不能自动转移到无证据的新任务）、洞察证伪（LLM提出的自然语言见解需通过验证）、结构去重（用等价哈希合并同构图）。

## 3. 实验设计

- **任务与数据集**：
  - **Count-Frequency (CF)**：全局数组频率计数。数组分片给8个工作者，精确可验证答案（RMSE、精确匹配）。使用数组长度1024，值域0-9，种子101-104。
  - **Silo-Bench风格**：分布式协调任务，智能体处于信息孤岛，需合作恢复全局答案。评估集含6个保留案例（难度桶I、II、III各2个），每例4个种子（401-404），共24个配对实例。
- **基准方法**：
  - **固定拓扑**：树、mesh-star、单peer指数DAG星型等。
  - **冷生成（Cold free-DAG）**：规划器无技能库时从头生成图。
  - **自进化生成**：使用进化后的技能库生成图，评估最佳图和轮均值。
- **对比模型**：DeepSeek-V4-Flash、DeepSeek-V3、Qwen3.5-Flash、Qwen3.5-Plus、GPT-4o、MiMo-V2-Flash等。
- **评估指标**：CF任务：RMSE、精确匹配、消息数、模型调用数、Token成本。Silo任务：精确匹配（EM）。
- **关键对比结果**：
  - CF全测试（DeepSeek-V4-Flash）：固定拓扑最佳RMSE 12.53，冷生成16.63，自进化最佳图7.87（降低37.2%），同时消息减少74.2%，模型调用减少54.5%，Token成本减少59.6%。

## 6. 主要结论与发现

1. **通信拓扑可作为可学技能**：通过规划器-工作者分离，系统可以学习到如何生成更好的通信DAG，且改进源自拓扑设计而非工作者推理能力变化。
2. **自进化图显著优于固定拓扑和冷生成**：在CF任务上RMSE降低最多37.2%，同时通信和Token成本大幅下降；Silo任务上自进化达到0.539 EM，超越每种案例最优固定拓扑（0.417）。
3. **进化过程中技能库积累可重复使用的设计知识**：如低扇入聚合、审计边、阶段约简等结构模式被保留，而链式、密集网格等模式被避免。
4. **防止噪声进化的机制有效**：保留验证门、方差信用等确保了只有跨保留集稳定的设计规则才进入长期记忆。
