## 摘要
移动GUI智能体通常是经过微调的7B规模视觉语言模型（VLM），它们将每个动作生成为文本。然而，这些VLM逐词元解码每个动作，甚至对候选动作打分的智能体也要将大型语言模型或VLM保持在循环中，导致速度慢且内存需求高。为解决这些问题，我们提出GUI-JEPA，据我们所知，这是首个基于联合嵌入预测架构（JEPA）的无解码器GUI智能体策略，它在预训练于未标注GUI截图的JEPA编码器潜空间中选择动作。其以动作和区域为条件的潜预测器将屏幕潜表示转换为每个候选动作对应的一个潜表示，使轻量级头能够在一次批处理中根据指令为所有候选动作打分，而无需解码任何词元。我们进一步表明，打分器依赖这一潜通路，且预测器是为决策本身训练的：随机初始化的预测器与在屏幕动态上预训练的预测器表现一样好。在AndroidControl上，GUI-JEPA在同一GPU上比我们用相同输入微调的Qwen2.5-VL-7B智能体快2.8-4.0倍，同时以6%的参数达到其分布内准确率的86-92%。代码见 https://github.com/bcwang-sjtu/GUI-JEPA

## Abstract
Mobile GUI agents are typically fine-tuned 7B-scale vision-language models (VLMs) that generate each action as text. However, these VLMs decode every action token by token, and even agents that score candidate actions keep a large language model or VLM in the loop, making them slow and memory-hungry. To address these issues, we propose GUI-JEPA, to our knowledge the first decoder-free GUI agent policy built on a Joint-Embedding Predictive Architecture (JEPA), which selects actions in the latent space of a JEPA encoder pretrained on unlabelled GUI screenshots. Its action- and region-conditioned latent predictor turns the screen latent into one latent per candidate action, letting lightweight heads score all candidates against the instruction in a single batched pass, without decoding a token. We further show that the scorer relies on this latent pathway and that the predictor is trained for the decision itself: a randomly initialised predictor does just as well as one pretrained on screen dynamics. On AndroidControl, GUI-JEPA is 2.8-4.0x faster on the same GPU than a Qwen2.5-VL-7B agent we fine-tune with the same inputs, while reaching 86-92% of its in-distribution accuracy with 6% of its parameters. Code is available at https://github.com/bcwang-sjtu/GUI-JEPA

# GUI-JEPA 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：当前移动 GUI 智能体的主流范式是微调 7B 级视觉语言模型（VLM），将每一步动作序列化为文本（如 JSON），再逐 token 解码。这种"生成式"策略在真实设备上代价高昂：论文实测 Qwen2.5-VL-7B（LoRA 微调）在单张 NVIDIA H20 上每步需 207 ms（vLLM）或 507 ms（HF），而 8B 级智能体在实机 benchmark 上平均每步 2.6–10.6 秒。
- **关键观察**：
  - 在 GUI 接地任务中，VLM 的目标元素在 prefill 阶段就已基本确定，解码只是在细化坐标；把解码放在决策关键路径上会让智能体"正确但迟到"。
  - 已有的候选评分型智能体（如 V-Droid、LiMAC、Jev-Mobile）虽避免完整生成，但仍把 LLM/VLM 保留在循环中，速度与显存开销依旧。
  - JEPA 在 GUI 领域此前只用于理解用户意图（UI-JEPA）、验证状态转移（LGWM）或作为训练正则（MIRAGE），尚无工作把 JEPA 本身作为选择动作的策略。
- **核心问题**：能否让 GUI 智能体完全不解码 token，而是在 JEPA 的潜空间中直接对候选动作打分并选择？论文给出肯定回答，并提出 **GUI-JEPA**——据称首个基于 JEPA 的无解码器 GUI 智能体策略。

## 2. 方法论

### 2.1 核心思想
将动作选择从"解码生成"转为"潜空间候选评分"：用冻结的、在无标签 GUI 截图上预训练的 JEPA 编码器把屏幕编码一次，再用一个动作与区域条件化的残差预测器为每个候选动作生成一个"候选条件化潜表示"，最后由轻量头在**单次批量前向**中完成打分与 argmax，全程不生成任何 token、像素或代码。

### 2.2 关键技术细节与流程

- **候选构造**：从 accessibility tree（a11y）枚举可见的可点击/长按/可编辑/可滚动节点（按面积取最小 80 个），每个节点产生一个 click 候选，可编辑节点额外产生 input_text 候选；再加入固定全局动作集（4 个滚动方向、back、home、wait、open_app）。每个候选携带 16 维动作向量 $a_c$（类型 one-hot + 坐标或滚动方向）及 ROI。
- **JEPA 编码器（303M，冻结）**：ViT-L/16，ImageNet 初始化后在 189K 张无标签移动/桌面截图上以 I-JEPA 式目标预训练 2 epoch——学生看到随机遮挡一半 patch 的截图，在遮挡位置回归 EMA 教师在全图上的 token（smooth-L1 + stop-gradient）。预训练后冻结并缓存 196 个 patch token，策略训练不再跑骨干。
- **残差潜预测器（39.9M）**：将 $a_c$ 与候选 ROI 池化特征 $u_c$ 经 MLP 注入一个学习查询 token，3 层 Transformer 在 196 个 patch token 与查询上注意力，输出
  $$\tilde{z}_c^t = z^t + \Delta(z^t, a_c, u_c)$$
  残差形式保留当前屏幕内容，只表达候选特定变化，避免重合成整幅潜表示导致细节丢失。
- **结构头（2.1M）**：对 $\tilde{z}_c^t$ 做 ROI 池化与全屏池化，与条件向量（冻结 CLIP 文本嵌入 + 历史）的 MLP 表示做带学习尺度的余弦相似度，加类型偏置：
  $$s_{\text{lat}}(c) = \kappa \cos(\text{MLP}_v(v_c), \text{MLP}_t(\text{cond})) + b_{\text{type}(c)}$$
  关键约束：该头**唯一的候选相关视觉输入**就是 $\tilde{z}_c^t$，训练无法绕过 JEPA 潜通路。
- **MiniLM 文本匹配器（33M）**：交叉编码器，打分目标+文本动作历史与元素文本的匹配度，与结构头分数在外部相加：$s(c) = s_{\text{lat}}(c) + s_{\text{text}}(c)$。结构头负责动作类型与全局动作仲裁，文本匹配器承担大部分点击接地。
- **两个后置文本 ranker（stage 3，在固定基策略上训练）**：
  - **span ranker（22.7M，MiniLM-L6）**：从目标中抽取 span 作为 input_text 参数；
  - **click reranker（33.5M，MiniLM-L12）**：仅在基策略 argmax 为 click 且置信度超阈值时，对点击候选做 listwise 重排。
- **训练目标**：在 AndroidControl 13,594 个 episode（74,714 步）上用候选上的 listwise 交叉熵，对非 click 步加权 1.5、click 步加权 1，以抵消 click 占比过高；AdamW，6 epoch，3 个种子，一个模型同时服务 AC-Low 与 AC-High。总参数 0.50B，其中 366M 冻结（编码器 + CLIP 文本编码器），约 132M 可训练。

## 3. 实验设计

- **数据集 / Benchmark**：AndroidControl 的四个官方子集——IDD（721 episodes）、app_unseen（631）、task_unseen（803）、category_unseen（700）；以完整测试集（1,543 episodes / 8,444 步）和 OOD union（full test 减 IDD，4,586 步）为主要证据单位；另有 137-episode 验证集用于选择 reranker 的变体、权重与门控。设置分 AC-Low（步指令条件）与 AC-High（episode 目标条件），均提供 ground-truth 动作历史。
