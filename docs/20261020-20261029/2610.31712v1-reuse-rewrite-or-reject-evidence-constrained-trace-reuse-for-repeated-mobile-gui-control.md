## 摘要
移动GUI智能体经常执行具有相似交互流程的重复任务。复用先前执行可以减少冗余的LLM推理和执行开销，但用户指令和执行环境的变化可能使先前成功的动作失效。我们将这些变化系统地归纳为六种代表性类别，并观察到此类变化并不一定使整个流程失效：当针对当前任务上下文和界面状态进行验证时，单个转换仍可保持可复用性。基于这一洞见，我们提出图-文本模板用于选择性执行轨迹复用。图捕获UI状态和动作转换，而文本编码任务意图、流程结构以及用于可变内容的带类型槽位。一个记录-模板-回放框架从已验证的执行中构建模板，并利用当前指令和实时UI状态来复用、调整或丢弃单个转换。给定一条执行轨迹，我们的框架在AndroidWorld的五个基础智能体上将LLM推理token消耗平均降低约80%，大多数智能体相比仅使用LLM执行实现至少1.5倍加速。在Android和HarmonyOS的真实设备评估中，我们的框架实现了70.7-79.8%的动作复用率，同时在大多数评估配置中保持超过2倍的执行加速。

## Abstract
Mobile GUI agents frequently perform repetitive tasks with similar interaction procedures. Reusing previous executions can reduce redundant LLM inference and execution overhead, but variations in user instructions and execution environments may invalidate previously successful actions. We systematically characterize these variations into six representative categories and observe that such changes do not necessarily invalidate entire procedures: individual transitions can remain reusable when validated against the current task context and interface state. Based on this insight, we propose graph-text templates for selective execution-trace reuse. The graph captures UI states and action transitions, while the text encodes task intent, procedural structure, and typed slots for variable content. A record-template-replay framework constructs templates from verified executions and leverages the current instruction and live UI state to reuse, adapt, or discard individual transitions. Given an execution trace, our framework reduces LLM inference token consumption by approximately 80% on average across five base agents on AndroidWorld, with most agents achieving at least 1.5-fold execution speedup over LLM-only execution. In real-device evaluations on Android and HarmonyOS, our framework achieves action reuse ratios of 70.7-79.8% while maintaining over 2-fold execution speedup in most evaluated configurations.

## 1. 核心问题与整体含义

- **研究动机**：移动 GUI 智能体经常重复执行流程相似的任务（如“加购一杯奶茶”“设 10 分钟计时器”）。若每一步都调用 LLM，会持续支付重复决策的推理成本与用户等待时间；复用历史执行轨迹是自然的加速途径。
- **核心矛盾**：历史成功动作在两类变化下可能失效——**环境变化**（应用状态、界面布局、弹窗打断）与**指令变化**（参数值、实体对象、措辞表达）。直接整段回放脚本因此不可靠。
- **关键观察**：变化通常不会让整条流程失效，而是使**个别转移（transition）** 失效；只要针对当前指令与实时界面逐一验证，其余转移仍可复用。
- **问题形式化**：把“何时可复用经验”转化为对每个候选转移的三选一决策——**REUSE（复用）/ REWRITE（改写）/ REJECT（拒绝并回退）**，并给出证据约束。
- **整体含义**：为“经验驱动加速”提供了从“脚本级回放”到“转移级、证据约束的选择性复用”的转变，兼顾效率与正确性。

## 2. 方法论

### 2.1 核心思想
- 采用 **record–template–replay（记录–模板–回放）** 三段式框架，将“记忆形成”与“记忆使用”分离。
- 用 **图–文本模板（graph–text template）** 同时表达两类信息：图刻画 UI 状态与动作转移（怎么改动了具体界面），文本刻画任务意图、流程结构与类型化槽位（想达成什么）。
- 复用粒度是**单步转移**而非整条轨迹；每次只准入一个转移，执行一次并验证，失败即交还基础智能体（base agent）回退。

### 2.2 六类变化分类（设计依据）
- 环境变化：背景状态变化、布局与工作流变化、模态打断。
- 指令变化：参数变化、实体替换、目标表达（改写）变化。
- 对应策略：状态重检查/目标已满足检测、语义重定位与路径拒绝、阻断性弹窗识别；槽位重绑定、实体重接地、跨改写的过程检索。

### 2.3 关键技术细节
- **记录阶段**：正常执行任务的同时，保存每步动作前后的可观察状态（截图 + UI XML）、动作与目标、流程步骤、类型化值、进度/完成信号；失败终态不作为成功示范存储，截断前缀须有显式边界与状态证据。
- **转移契约**（式 1）：
  - \(e = (v_i, a, v_j, z)\)，\(z = (g, k, s, r, \phi^-, \phi^+)\)
  - \(v_i, v_j\) 为前后 UI 状态；\(a\) 为动作；\(g\) 为流程意图；\(k\) 为类型化槽位；\(s\) 为目标选择器；\(r\) 为风险等级；\(\phi^-/\phi^+\) 为动作前/后所需证据（前置条件与预期效果）。
- **模板抽取**：合并兼容的状态与动作，冲突条件保留为独立分支；缺证据、目标不可接地、终态失败的转移被排除；可变内容（数量、时间、金额、实体）暴露为槽位，稳定导航与流程结构保留为可复用边。
- **三层检索**：文本流程匹配意图/槽位/进度 → UI 图检索匹配当前状态并排序候选边 → 当前 UI 接地（目标可见且唯一、无阻断浮层、风险可控）。
- **准入检查三组**：A 上下文对齐（任务/UI 匹配、锚点可见唯一）；B 输入契约（槽位合法、前置条件成立）；C 安全与可观测（风险有界、后置条件可测）。
- **决策规则**：全部匹配 → REUSE 原样执行；仅需重绑定输入/锚点且保持意图 → REWRITE；不安全或无匹配 → REJECT，不执行任何 GUI 动作，直接回退策略 \(\pi_F\)。
- **执行与恢复**：准入边先刷新前置证据（并检查目标是否已满足，避免重复/逆向动作），执行一次，再做语义后检查；后检查失败则在本 episode 内封禁该边并回退，回退后重新观察、重新对齐，后续转移重新检查。
- **安全约束**：高风险实体/值需更强证据，不能仅凭偏好静默填充；歧义引用直接拒绝；权限、登录、支付等弹窗视为阻断态。

### 2.4 评估指标公式
- 复用率：\(r_{\text{task}}=\frac{1}{M}\sum_i R_i/N_i\)（任务等权），\(r_{\text{step}}=\sum_i R_i/\sum_i N_i\)（步等权）。
- LLM 调用削减：\(d_{\text{LLM}} = 1-\frac{(1-r_{\text{step}})N_1+C_{\text{extra}}}{N_0}\)；token 削减：\(d_{\text{tok}} = 1-K_1/K_0\)。
- 加速比：\(S=\frac{1}{|P|}\sum_{i\in P} T_{0,i}/T_{1,i}\)（仅统计双方均成功的配对）。
- 作者明确指出：复用率不能直接替代 LLM 步数削减或 token 削减，端到端加速还受 UI 结构获取、等待、验证与恢复影响。

## 3. 实验设计

- **Benchmark 1：AndroidWorld**（116 任务、20 个 Android 应用，参数化初始化 + 程序化结果校验）。5 个基础智能体：GUI-Owl-7B、MAI-UI-8B、GELab-Zero-4B-preview、AutoGLM-Phone-9B-Multilingual、UI-TARS-1.5-7B；各自用其 LLM-only 成功执行构建模板，记录任务与回放任务相似但部分存在参数/细节差异。

- **三类代表条件**：背景状态变化（指令不变、状态变）、参数变化（熟悉流程内改值）、改写指令（意图不变、措辞变）；其余三类（布局/工作流、模态打断、实体替换）仅作定性讨论。
- **消融设置（累积式 C0→C3）**：仅回放 → +状态重检查/TOCTOU 感知（背景态）、+参数泛化（参数）、+应用级语义检索（改写）→ +目标保持/指令–结果一致性/软任务匹配 → 全配置（含基础模型回退与语义路由）。
- **对比方法**：主要做**系统内消融 + PreAct 作为外部参考**（PreAct 报告 15 任务子集上 73.3% 热启动成功率）。SkillDroid、EchoPath、EAM 无公开实现；MobiMem、MobiAgent、AgentRR 无法复现其记录–回放协议；MobileGPT 使用自定义 80 任务基准。因此作者明确将外部结果仅作上下文参考，未做严格同协议横向对比。

## 6. 主要结论与发现

- **可行性**：给定一条已验证执行记录，转移级选择性复用可显著减少重复模型决策。AndroidWorld 上 5 个智能体复用率 82.0–87.5%，token 降低 78.0–89.6%，LLM 步数降低 71.1–79.8%，加速 1.2–1.9×。
- **真机效果更强**：背景状态变化、参数变化、改写指令三种条件下复用率 70.7–79.8%，加速 1.8–3.9×（多数配置超过 2×）；全配置相对“仅回放”在成功率上提升 35–50 个百分点，全配置成功率达 92.0–98.0%。
- **加速受限的机理**：AndroidWorld 协议在动作前后反复获取 UI 结构，该部分可占总执行时间约 40.02%，压缩了“省掉 LLM 调用”能带来的收益；真机实现优化并降低了 UI 结构获取频率，因此加速更明显。
- **消融结论**：状态重检查/目标保持、参数泛化 + 指令–结果一致性、应用级语义检索 + 软任务匹配，各自对对应变化条件有实质贡献；三者共同构成“复用–改写–拒绝”的完整证据链。
- **总体判断**：保留可复用流程结构 + 逐动作按当前条件重评估，是把历史执行转化为“更少模型决策、更快执行”的有效路径；拒绝与回退机制是保证不因复用而降低成功率的关键。

## 7. 优点

- **粒度选择合理**：以“带已验证结果的转移”为记忆单元，避免整脚本回放的脆弱性，也避免纯经验检索的不可执行性。
- **表示互补**：图（可执行结构、状态条件、选择器）+ 文本（意图、流程、类型化槽位）分工清晰，兼顾语义检索与 UI 接地。
- **证据约束贯穿全流程**：准入前三组检查、执行前后 \(\phi^-/\phi^+\) 校验、失败封禁

与回退，使“复用”始终处于可验证、可撤销的状态，正确性不被效率目标绑架。
- **回退设计克制**：REJECT 时不执行任何 GUI 动作，直接交还基础智能体，避免“半复用”造成的状态污染；失败边仅在当前 episode 内封禁，不污染长期记忆。
- **对“目标已满足”的显式处理**：执行前检查目标是否已达成，可避免重复加购、重复计时等常见回放错误，这一细节体现了对真实使用场景的理解。
- **指标交代细致**：区分任务等权与步等权复用率、明确零动作完成的处理、只在双方均成功的配对任务上计算加速比，并主动指出复用率不能等同于 LLM 步数或 token 削减，态度诚实。
- **消融设计有针对性**：每个累积配置对应一类变化，能较清楚地归因各机制的作用，而非笼统地“全开 vs 全关”。
- **工程可落地性**：不训练模型、基于现成智能体、以转移为单位的增量式复用，较易嵌入现有移动智能体系统。

## 8. 局限与不足

- **离线成本未计量**：记录、模板抽取、图–文本对齐的构建开销及其摊销未被纳入效率评估，而这一成本在真实部署中可能相当可观，尤其当任务重复频率不高时，复用收益可能被构建成本抵消。
- **依赖“已有成功记录”**：方法的前提是存在一条已验证的成功轨迹；对新任务、新应用或基础智能体本身失败的任务，框架无法提供加速，成功率上限受基础智能体约束（AndroidWorld 上的派生乘积指标即为体现）。
- **覆盖变化类型不全**：六类变化中仅三类（背景状态、参数、改写）做了定量评估，布局/工作流变化、模态打断、实体替换仅定性讨论；组合变化（如参数变化叠加弹窗打断）完全未覆盖，而这恰是真实场景的常态。
- **真机评估的判定主观性**：依赖旁站人工判定成功/失败，未报告与自动验证器的一致性（如 Cohen's κ），跨设备、跨应用的细粒度结果也未给出。
- **外部对比薄弱**：仅 PreAct 一个 15 任务子集的参考数字，其余方法因无公开实现或协议不同而未做同协议对比，因此“优于现有经验复用方法”的结论证据不足。
- **统计严谨性缺失**：未报告置信区间、显著性检验或多次运行的方差；LLM 智能体本身存在随机性，单次运行结果可能波动，加速比与成功率的稳定性未知。
- **任务集代表性有限**：真机任务为“贴近实用场景的设计任务”，非按应用分层的平衡基准，应用级成功率缺失，难以判断方法在长尾应用上的表现。
- **失败恢复的深度有限**：后检查失败仅封禁当前边并回退，未讨论回退后如何避免在同一 episode 内反复尝试相似失效边，也未分析多次回退对总时延的影响。
- **安全边界的处理偏保守**：高风险场景要求更强证据、歧义直接拒绝，这在正确性上是合理的，但可能显著降低高风险任务上的复用率，论文未量化这一权衡。

## 9. 启发与可借鉴点

- **“转移级复用 + 证据约束”是可迁移的范式**：不仅适用于移动 GUI，也可推广到 Web 自动化、RPA、桌面智能体等“有状态、有副作用”的顺序决策场景；核心是把“经验”表示为带前置/后置条件的可验证契约，而非可执行脚本。
- **图–文本双表示的分工值得借鉴**：图负责“能不能执行、在哪执行”，文本负责“为什么执行、执行什么”，二者互补可同时缓解语义检索的模糊性与 UI 接地的脆弱性。
- **REUSE/REWRITE/REJECT 三态决策**：比“复用/不复用”二态更贴近现实——多数变化只需局部改写而非整体放弃，而明确拒绝出口是保证不劣化的安全阀。
- **TOCTOU 意识**：执行前刷新前置证据、执行后做语义后检查，这一“检查–执行–再检查”的循环对任何依赖缓存或历史状态的系统都有参考价值。
- **评估口径的自我约束**：主动区分复用率与真实成本削减、只在配对成功任务上比较加速比，这种“不夸大”的度量方式值得在系统类论文中推广。
- **对“目标已满足”的检测**：是一个成本低、收益高的实用技巧，可独立于本框架被其他回放系统采用。

## 10. 可复现性与开放性问题

- 论文未明确说明是否开源代码、模板数据集与真机任务集；AndroidWorld 为公开基准，但模板构建流程、图–文本抽取规则、证据字段的具体判定阈值若未公开，复现难度较大。
- 关键超参（如风险等级划分标准、锚点唯一性判定、软任务匹配的相似度阈值）的取值与敏感性未报告。
- 记录阶段的“截断前缀须有显式边界与状态证据”这一规则的具体实现方式未详述，影响他人复现部分成功轨迹的复用能力。
- 开放问题：如何在复用率与构建成本之间做在线权衡（例如按任务重复频率决定是否建模板）；如何在组合变化下维持证据链完整；如何把人类反馈纳入高风险场景的证据强度估计。

## 11. 总体评价

- 论文抓住了一个真实且被低估的成本来源——重复相似任务的逐步 LLM 决策开销，并给出了一个**粒度恰当、证据闭环、可回退**的解决方案。其最大贡献不在于某个单点技术，而在于把“经验复用”从“脚本回放”重构为“带前置/后置条件的转移级准入决策”，并用 REJECT 出口守住了正确性底线。
- 实验在“多基础模型 + 多设备 + 多变化条件 + 累积消融”上做了较扎实的组合式验证，真机结果（1.8–3.9× 加速、全配置 92.0–98.0% 成功率）具有说服力；对 AndroidWorld 加速幅度受限的机理解释（UI 结构获取占约 40% 时间）也显示作者对系统瓶颈有清醒认识。
- 主要短板在于：离线构建成本未计量、变化类型与组合变化覆盖不全、外部对比与统计严谨性不足、真机判定存在主观性。这些不影响核心论点的成立，但限制了结论的强度与推广范围。
- 综合判断：这是一项**工程价值明确、方法论有迁移性、评估态度诚实但证据强度中等**的系统性工作；适合作为“经验驱动智能体加速”方向的基础参考，其“转移契约 + 三态决策 + 证据校验”的设计可直接被后续工作继承与扩展。
