## 摘要
GUI智能体旨在通过交互移动界面来自动化复杂的用户任务，但在长时程场景中，有效的决策需要复用先验经验，而非仅依赖环境观测。现有的基于记忆的方法通常将经验存储在单动作级别或完整轨迹级别。单步动作往往过于细粒度，难以承载有意义的语义，因为单个动作的成功并不必然意味着向总体目标推进。相反，完整轨迹往往过于粗粒度，且难以在不同任务间复用。我们提出一种子目标感知的记忆图，将过去轨迹蒸馏为子目标级别的结构化、可复用证据。我们将子目标定义为共享单一意图的连续动作，这一粒度使面向任务的进展具有意义。为减少冗余并支持跨任务复用，我们将子目标经验组织为图中的节点，其中相关记忆可基于环境观测进行合并、扩展和检索。在SPA-Bench上，我们的方法相较基线将成功率提高了11.11%。

## Abstract
GUI agents aim to automate complex user tasks by interacting with mobile interfaces, but ef- fective decision-making in long-horizon set- tings requires reusing prior experience rather than relying solely on the environment ob- servations. Existing memory-based methods typically store experience either at the single- action level or as entire trajectories. Single- step actions are often too fine-grained to carry meaningful semantics, since the success of an individual action does not necessarily imply progress towards the overall goal. In contrast, whole trajectories are often too coarse-grained and difficult to reuse across different tasks. We propose a subgoal-aware memory graph that distils past trajectories into structured, reusable evidence at the level of subgoals. We define a subgoal as consecutive actions shar- ing a single intent, the granularity at which progress toward the task becomes meaning- ful. To reduce redundancy and support cross- task reuse, we organise subgoal experiences as nodes in a graph, where related memories can be merged, extended, and retrieved based on the environment observation. On SPA-Bench, our method improves success rate by 11.11% over the baseline.

# 论文总结：Subgoal-aware Memory Graph for GUI Agent

## 1. 核心问题与研究背景

- **应用背景**：GUI 智能体通过点击、滑动、输入等操作自动完成移动端复杂任务（如购物下单、设置闹钟、系统设置导航）。在 SPA-Bench 等基准中，单个任务常需跨多个界面执行 30 步以上操作，属典型长时程任务。
- **核心矛盾**：长时程场景下仅依赖当前环境观测不足——许多子目标在不同任务、不同 App 间反复出现，若无经验复用，智能体必须反复“从零探索”相同工作流。
- **现有记忆方案的粒度缺陷**（论文的核心批评点）：
  - **单步动作级**（如 GUI-Explorer 的 (observation, action, outcome) 三元组）：过细，局部“成功”不等于向总目标推进，且记忆迅速累积冗余条目、缺乏可复用结构。
  - **完整轨迹级**（如 HyMEM 的轨迹嵌入图、EchoTrail-GUI 检索整条成功 episode）：过粗，与特定任务的路径强绑定，对“共享中间步骤但具体细节分叉”的任务几乎不可复用。
- **论文主张**：应取二者之间的**中间抽象层级——子目标（subgoal）**，即“共享单一意图的连续动作序列”。图 1 用同一子目标成功/失败的对比说明：只有在子目标粒度上，“是否取得进展”才可见，而单动作粒度无法区分。
- **整体含义**：该工作属于“冻结 LLM + 上下文注入记忆”的路线，不更新模型权重，而是通过构造可增量扩展、可跨任务复用的结构化经验库来提升决策质量。

## 2. 方法论

### 2.1 核心思想

将历史轨迹“蒸馏”为子目标级证据，并以**有向图**组织：**节点 = 视觉相似 GUI 状态的聚类**，**边 = 子目标转移**（携带意图、效果、行为模式、成功标签）。检索时以当前截图为查询，返回相似状态出发的历史子目标作为提示。

### 2.2 子目标抽取与标注（Subgoal Extraction）

- **输入**：轨迹 $\tau=(s_0,a_0,s_1,\dots,a_{n-1},s_n)$，语料 $T=\{\tau_1,\dots,\tau_m\}$。
- **分割**：由 LLM 读取完整动作序列，输出分段边界，每段对应一个连贯子意图（如“打开搜索栏并提交查询”“把选中的墨镜加入购物车”）。
- **视觉锚点压缩**：仅保留每段的首、末两张截图作为 $s_{from}, s_{to}$，丢弃中间帧（边界状态已足以支撑检索）。
- **元数据元组**：$g=\langle s_{from},s_{to};\ \text{text},\text{effect},\text{behaviour},\text{success}\rangle$
  - `text`：子目标意图的自然语言摘要；
  - `effect`：由首末截图对比得到的视觉变化描述；
  - `behaviour`：底层动作序列的简洁概括，突出主导交互模式；
  - `success ∈ {yes, no, uncertain}`：由 LLM 裁判在子目标级给出的成功标签。

### 2.3 子目标感知记忆图构建（三阶段流程）

1. **环境状态合并（节点级）**：对每张边界截图计算图像嵌入，与已有记忆节点比较；若最近节点满足 $\cos(s,m_j)\ge\tau$ 则并入该节点，否则新建节点。每个节点维护其成员截图集合与**滑动平均嵌入**用于后续匹配。作用：让经验跨轨迹累积而非碎片化。
2. **有向子目标边**：每个子目标成为从其源节点到目标节点的有向边，边上存储意图、视觉效果、成功标签、行为模式。**关键设计：成功与失败尝试都保留**，使检索既能模仿成功也可规避已知失败。
3. **构建期去重**：仅当两条出边**同时满足**——指向同一目标节点、成功标签相同、意图文本嵌入余弦相似度 $>\theta$——才判为重复并丢弃后写入者；目标/结果/意图任一不同则作为独立证据保留。

### 2.4 记忆检索

- 每个决策步以当前截图 $s_q$ 为查询，与各节点嵌入做余弦相似度比较，取 **top-$k$** 最近节点（实验中 $k=1$）。
- 收集这些节点的**全部出边**（成功与失败均返回，各带结果标签），格式化为简短 memory block 追加到智能体提示中。
- 超参：视觉阈值 $\tau=0.9$、文本阈值 $\theta=0.9$；图像与文本嵌入均由 Qwen3-VL-Embedding-8B 计算。

## 3. 实验设计

- **基准/场景**：SPA-Bench 的**英文单 App、level-3 划分**（作者称其为更难层级）；运行于通过 ADB 控制的云端 Android 手机实例。剔除少数无法在云手机运行的 App 后，**最终评测仅 13 个任务**。
- **基座模型**：Qwen3-VL-8B-Instruct（记忆构建与检索的嵌入用 Qwen3-VL-Embedding-8B）。
- **评价指标**：per-attempt 成功率（SR），三次独立运行取平均。
- **对比方法**（表 1，均为同一骨干与设置下的内部变体）：

|---|---|

- **实验规模**：主结果 1 张表（5 个配置），每配置 3 次运行；本质上是“1 个基准 × 1 个划分 × 1 个骨干 × 13 个任务”的小规模评测。

## 6. 主要结论与发现

- 在相同骨干下，子目标图记忆将成功率从 34.19% 提升至 45.30%，论文表述为“相对基线提升 11.11%”（按表内数值实为 **+11.11 个百分点**；若按相对提升计算约为 +32.5%，两种口径需区分）。
- **粒度结论**：动作级（38.46%）与任务级（36.75%）记忆相对基线收益有限；子目标粒度收益最大，支持“中间抽象层级最适配长时程 GUI 任务”的核心假设。
- **结构结论**：去掉图结构、改为扁平子目标存储后 SR 降至 30.77%（甚至低于无记忆基线），说明收益并非仅来自“存了子目标”，而主要来自**跨轨迹共享视觉状态节点 + 去重**带来的记忆压缩与检索精度。
- 检索同时提供成功与失败子目标，被认为有助于规避已知失败模式并模仿成功行为。

## 7. 优点

- **问题定位清晰**：对“单步过细、整轨迹过粗”的诊断具体且有例证（图 1 的成功/失败同子目标对比），子目标粒度是有说服力的中间解。
- **表示设计优雅**：以“边界截图 + 语义标注”替代完整动作序列，既压缩存储又保留可检索的视觉锚点；节点合并 + 滑动平均嵌入使记忆可**增量扩展**而非重建。
- **保留负经验**：显式存储失败子目标并带结果标签，比只存成功轨迹更贴近试错式交互的实际需求。
- **去重规则保守合理**：要求“同目标 + 同结果 + 同意图”三条件同时满足，避免误合并语义不同的证据。
- **工程可行性好**：不微调模型、检索延迟约 0.5 s，具备实际部署的性价比；同时给出了构建成本量级。
- **消融设计有针对性**：Flat 变体有效隔离了“图结构”这一关键贡献，而非仅报告总体提升。

## 8. 不足与局限

- **状态离散化假设**（作者自述）：方法假定 GUI 环境可近似为离散状态空间、截图能聚类为紧凑节点。该假设在布局稳定的 App 上成立，但在视频播放器、动画/连续变化界面中，视觉相似度是语义等价性的**噪声代理**，节点合并可能错误。
- **评测覆盖过窄**：仅 13 个任务、单一基准的单一划分（英文单 App level-3），且剔除了部分 App，存在选择偏差；结论向多 App 跨应用、跨语言、Web 端的外推能力未验证。
- **缺少外部基线**：未与现有记忆型 GUI 智能体方法同条件对比，“优于现有方法”的论断证据不足。
- **统计可靠性**：无方差/置信区间/显著性检验；"11.11%" 的表述在“百分点”与“相对提升”之间存在口径模糊，易被误读。
- **超参与敏感性未探明**：$\tau=\theta=0.9$、$k=1$ 均为固定设定；top-1 单节点检索在视觉近邻噪声较大时风险高，缺少 $k$ 与阈值的消融。
- **标注质量依赖 LLM**：子目标分割与 success 标签均由 LLM 生成，错误会沿图结构传播并被去重机制“固化”；论文未报告标注一致性或人工校验结果。
- **失败经验的双刃性未量化**：检索返回失败子目标是否真的被模型正确利用（而非误导），缺少行为层面的分析。
- **成本信息不完整**：仅给 4 GPU-hours 与 0.5 s 延迟，缺 GPU 型号/数量、轨迹采集与标注开销，复现与规模化评估受限。
