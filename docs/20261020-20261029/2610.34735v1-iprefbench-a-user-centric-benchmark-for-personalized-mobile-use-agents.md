## 摘要
一个真正了解用户并能代表用户行动的智能体，一直是 AI 助手长期以来的承诺。计算机使用智能体通过能够在各类应用中执行完全指定的任务，使这一承诺触手可及。然而，真实世界中的用户请求往往指定不足。为了针对特定用户正确行动，智能体必须从用户的活动历史中推断某些缺失信息，并询问只有用户才能提供的其他信息，同时不做无根据的假设，也不以不必要的问题给用户增加负担。我们提出 iPrefBench，一个用于评估个人移动使用智能体在可执行 iOS 环境中、与交互式模拟用户交互时“推断与询问”能力的基准。iPrefBench 基于一个具有 3,051 条历史活动事件的一致人物画像，包含跨 26 个应用的 130 个指定不足的用户任务。每个被省略的、依赖用户的需求，在构造上要么可从历史中推断，要么只能通过询问获得。iPrefBench 从两方面评估个性化移动智能体：智能体是否为用户正确完成任务（即个性化任务完成），以及是否在必要时寻求用户输入（即用户-智能体交互）。对 7 个前沿智能体的评估揭示了执行与个性化之间的显著差距。智能体取得较高的动作完成分数（最高 91.6%），但完整任务成功率较低（最高 47.7%），因为个性化落后。它们在仅能通过询问获得的信息上尤其吃力，未能请求足够多的必要信息。我们的发现凸显了个性化智能体在知道该推断什么以及何时询问方面所面临的挑战。我们希望 iPrefBench 能成为一个有价值的测试平台，用于构建了解其用户并与用户协同工作的智能体。

## Abstract
An agent that truly knows and acts on behalf of its user has been a long-standing promise of AI assistants. Computer-use agents bring this promise within reach by capably executing fully specified tasks across apps. However, real-world user requests are often underspecified. To act correctly for the particular user, an agent must infer some missing information from the user's activity history and ask for other information that only the user can provide, without making unsupported assumptions or burdening the user with unnecessary questions. We present iPrefBench, a benchmark for evaluating the infer and ask capabilities of personal mobile-use agents in an executable iOS environment with an interactive simulated user. Grounded in a coherent persona with 3,051 past activity events, iPrefBench comprises 130 underspecified user tasks across 26 apps. Each omitted user-dependent requirement is, by construction, either history-inferable or ask-only. iPrefBench evaluates personalized mobile agents on both whether agents complete tasks correctly for the user (i.e., personalized task completion) and whether they seek user input when necessary (i.e., user-agent interaction). Evaluation of 7 frontier agents reveals a substantial gap between execution and personalization. Agents achieve high action completion scores (up to 91.6%) but low full task success (up to 47.7%) because personalization lags behind. They especially struggle with ask-only information, failing to request enough necessary information. Our findings highlight a challenge for personalized agents in knowing what to infer and when to ask. We hope that iPrefBench can serve as a valuable testbed for building agents that know their user and work with them.

# iPrefBench 论文结构化总结

## 1. 核心问题与研究动机

- **背景**：计算机使用智能体（CUA）已能在桌面、移动、Web 等环境中执行**完全指定**的任务，长程 GUI 操作能力快速提升。
- **核心矛盾**：真实用户请求普遍**欠明确（underspecified）**。例如用户说“帮我订明天常去的那家餐厅”，并未给出餐厅名、时间、人数。
- **真正个性化的两个信息来源**：
  - **推断（infer）**：从用户活动历史中恢复稳定偏好与习惯（如“常去的餐厅”）；
  - **询问（ask）**：只有用户当下才知道的信息（如本次聚餐的时间与人数）。
- **两种失败模式**：静默做出无根据假设（偏离真实意图）vs. 对历史中已可推断的信息反复提问（丧失自主性、增加用户负担）。
- **现有基准的缺口**：
  - 常规 CUA 基准（OSWorld、AndroidWorld、WebArena 等）任务完全指定，无用户历史、无澄清；
  - 个性化基准（PersonalWAB、Persona2Web、PersonalAlign、Fingertip 等）只给历史、无人可问；
  - 交互式基准（τ-bench、IN3、UserBench、AmbigSWE 等）只给模拟用户、无历史，因而**无法判定某个问题是否必要**；
  - VitaBench 2.0、KnowU-Bench 同时具备两者，但**未显式区分每个缺失信息的来源**，无法评估“交互必要性”。
- **论文定位**：提出 iPrefBench，首次在移动（iOS）环境中同时提供**有据可依的用户历史**与**交互式模拟用户**，并对每个缺失信息标注唯一来源（可推断 / 仅可询问），从而同时评测“个性化任务完成”与“必要性感知的用户-智能体交互”。

## 2. 方法论

### 2.1 核心思想
对每个任务 $t$，令 $U_t$ 为指令未指定的、依赖用户的信息集合；每个 $u \in U_t$ 都有唯一预期值与唯一来源：
- **可推断信息** $u \in U_t^{\text{infer}}$：可由历史 $H$ 中的主导模式或稳定事实恢复；
- **仅可询问信息** $u \in U_t^{\text{ask}}$：$H$ 中不存在，只能通过 `ask_user` 获得。

该划分对应真实私人助理的认知边界：稳定偏好会在历史中留痕，而当下情境细节不会。

### 2.2 环境构建
- **可执行 iOS 模拟器**（基于 iOSWorld）：26 个 mock 应用，覆盖餐饮、办公、消息、购物支付、出行、娱乐、健康等 7 大类，应用间数据互联。
- **动作空间**：`tap_xy`、`type`、`swipe`、`home`、`wait`、`stop`，外加新增的 `ask_user`（自然语言提问 → 模拟用户回复作为观测）。
- **用户活动历史 $H$**：将种子应用数据用 LLM 转写为**按时间排序的自然语言事件流**，共 3,051 条；作为智能体**唯一的先验上下文**。跨应用聚合使偏好可跨应用推断。
- **用户画像 $P$**：从种子数据抽取的结构化画像，13 个维度、92 条条目，每条附证据指针；**对智能体隐藏**，仅用于模拟用户与评测。
- **模拟用户**：以 Claude Sonnet 5 扮演人物 Jordan Avery，输入为 $P$、任务级隐藏上下文（ask-only 的预期值）与情境补充；被严格指令为**只回答被问到的内容、不主动泄露**，以保证测的是智能体自身的“识别缺失”能力。
- **任务级环境控制**：数据覆盖（如商品缺货）、日志追加（改变历史以体现偏好漂移）、画像覆盖（同步更新模拟用户与判分依据）。

### 2.3 任务设计
- 130 个欠明确任务；单个任务可含多个可推断与仅询问需求，常需跨多条历史事件整合证据或跨应用迁移偏好。
- **三类扰动任务**（提升真实性、防止“历史即规范”）：
  1. **指令扰动**（11 个）：当前指令显式违背历史主导模式，须以指令优先；
  2. **偏好扰动**（10 个）：近期行为显示偏好已漂移，须识别趋势而非取历史众数；
  3. **环境扰动**（13 个）：偏好选项不可用，须识别、告知用户并按替代偏好行动或停止。
- **三阶段构建流水线**：编码智能体生成 188 个候选 → 8 名人工评审逐条核验来源、修订种子数据、去重与多样化 → 2 名验证专家在模拟器中实跑校验可行性与评分标准。最终保留 130 个任务，每个任务经**两轮人工审核**。

### 2.4 评测指标
**(a) 个性化任务完成**：任务级 rubric 分两类标准，由 LLM judge 依据轨迹（截图+动作+最终答案）、用户画像、隐藏上下文、运行时钟逐条判 pass/fail：
- **动作完成标准**：所需操作是否被执行（与用户相关取值无关）；
- **个性化标准**：每个用户相关决策是否匹配预期值，并标注来源（可推断/仅询问）。
- 指标：动作完成分、个性化分（可再按来源拆分）为各类标准满足比例的任务级宏平均；**任务成功（SR）要求全部标准通过**。

**(b) 用户-智能体交互**（基于 Grice 合作原则“信息量恰如所需”）：
- judge 将 `ask_user` 消息**分解为多条独立信息请求**（重复请求计多次，同一决策的候选选项计一次），再语义匹配到 ask-only 需求：$\phi_t(q) \in U_t^{\text{ask}} \cup \{\bot\}$；
- 已获取的 ask-only 需求集合 $E_t = \{u \in U_t^{\text{ask}} \mid \exists q \in Q_t, \phi_t(q)=u\}$；
- $\text{Recall} = \sum_t |E_t| / \sum_t |U_t^{\text{ask}}|$（是否问全）；
- $\text{Precision} = \sum_t |E_t| / \sum_t |Q_t|$（问的是否都是必要的、非重复的），两者均为**微平均**。
- 另设**格式层质量**：specificity、answerability、option provision 三项。

## 3. 实验设计

- **基准**：iPrefBench 本身（130 任务 / 26 应用 / 3,051 事件 / 13 维画像），所有对比方法在同一 harness、同一提示、同一模拟用户与 judge 下运行。
- **评测对象（7 个前沿模型）**：Claude Opus 5、Claude Sonnet 5、Gemini 3.1 Pro、Gemini 3.7 Flash、Kimi K3、Qwen3.8-27B、Qwen3.8-Flash-Next。
- **被排除的方法**：专用 GUI 智能体（UI-TARS-1.5-7B、GUI-Owl-1.5-32B）因上下文窗口无法容纳完整历史；MAI-UI-8B 虽可容纳但动作频繁解析失败（动作完成仅 16.9%），会混淆“执行失败”与“个性化失败”，故未纳入主表。
- **设置**：每 episode 使用全新种子模拟器；默认向智能体提供**完整历史**（以隔离检索/导航能力的干扰）；最多 50 步，`stop` 或超步即结束；模拟用户与 judge 均为 Claude Sonnet 5。
- **实验组**：
  1. 主实验（7 模型 × 130 任务）；
  2. 三类扰动子集分析（指令/偏好/环境）；
  3. 人工错误分析（Claude Sonnet 5 的 79 条与 Qwen3.8-27B 的 96 条失败轨迹，四类错误标注）；
  4. 消融一：**显式前置澄清阶段**（Sonnet 5、Qwen3.8-27B）；
  5. 消融二：**历史暴露量**（0 / 20 / 50 / 100 / 500 / 1k / 全量，两个模型）；
  6. 评测可靠性：模拟用户人工校验（89 组问答）、judge 与人类在 100 条轨迹上的一致性、跨 judge（Gemini 3.7 Flash）复评、消息格式质量评分。

## 5. 实验数量与充分性

**规模**：主实验约 910 个 episode（7×130）；两组消融各 2 模型 × 130 任务；历史暴露实验 7 档 × 2 模型；扰动子集分析 3×7；错误分析手工标注 175 条失败轨迹；评测验证含 100 条人工标注轨迹与 89 组问答。

**充分与客观之处**：
- 同一 harness / 提示 / 环境，跨闭源与开源、不同规模模型，横向可比；
- 指标拆解到位：动作完成 vs. 个性化、可推断 vs. 仅询问、recall vs. precision，能定位失败环节；
- 人工错误分析区分“未识别决策”与“识别但解错”，比单一分数更有解释力；
- 评测可靠性做了三重验证：模拟用户行为校验（96.6% 合规）、judge 与人类一致性（准则级 95.7%、κ=0.89；任务级 97.0%、κ=0.94）、跨 judge 一致性（≥95.9%），显著降低单一 judge 的偏差风险；
- 扰动子集与历史暴露消融构成了有针对性的因果性探索。

**仍显不足之处**：
- **单一人物画像**（Jordan Avery），无法评估跨用户泛化，模型可能对该画像过拟合；
- 扰动任务各仅 10–13 个，子集结论的统计功效有限；
- 消融仅覆盖 2 个模型，且前置澄清只测了一种提示形式
