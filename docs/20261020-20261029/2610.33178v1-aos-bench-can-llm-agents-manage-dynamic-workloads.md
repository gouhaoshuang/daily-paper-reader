## 摘要
编码智能体正从一次处理一个请求，转变为持续为用户的连续工作流提供服务的常驻助手：构建、数据处理作业和缺陷修复可能同时待在同一台机器上。这样的智能体必须决定何时接受新任务、如何委派与重叠任务，以及如何保持在机器的 CPU 和内存限制之内。现有基准无法衡量这一点，因为它们孤立地评估每个任务。我们提出 AOS-Bench，它将智能体系统作为工作负载管理器来评估：经过验证的任务随时间到达，必须在共享的 CPU 和内存限制下交付；而相同任务逐个运行则作为每个系统的参考。在五组模型—执行框架组合上，孤立任务成功率并不能均匀地迁移。在重负载下，每个系统都损失 13 至 23 个百分点。在中等负载下，各系统在孤立成功率上相差 11 个百分点，但在连续任务流成功率上相差 26 个百分点；两个在孤立场景中仅相差 0.6 个百分点的系统，分别完成了相同任务的 54% 和 68%。执行策略干预表明，这一差距在很大程度上源于任务接收：串行调度导致 73% 的重负载任务无人承接。然而，更复杂的管理未必有帮助。固定并发度为 2 在中等和重负载下均与最佳智能体管理策略相差不超过 4 个百分点；并且在所有策略下，任务等待期间 CPU 使用率中位数始终低于已配置核心数的 30%。这些结果将工作负载管理确定为智能体的一项独立能力，并将 AOS-Bench 作为衡量该能力的一种方法。

## Abstract
Coding agents are moving from handling one request at a time to serving as persistent assistants to which users hand a stream of work: a build, a data-processing job and a bug fix may all be pending on the same machine at once. Such an agent must decide when to take on new tasks, how to delegate and overlap them, and how to stay within the machine's CPU and memory. Existing benchmarks cannot measure this, because they evaluate each task in isolation. We introduce \benchname{}, which evaluates an agent system as a workload manager: verified tasks arrive over time and must be delivered under shared CPU and memory limits, and the same tasks run one at a time serve as a per-system reference.   Across five model--harness pairs, isolated task success does not carry over evenly. On heavy workloads every system loses 13 to 23 points. On medium workloads, systems span 11 points in isolated success but 26 points in stream success, and two systems 0.6 points apart in isolation deliver 54\% and 68\% of the same tasks. Execution-policy interventions trace much of this gap to task intake: serial dispatch leaves 73\% of heavy-workload tasks unclaimed. Yet more elaborate management does not necessarily help. A fixed concurrency of two comes within four points of the best agent-managed policy on both medium and heavy workloads, and under every policy median CPU use stays below 30\% of the provisioned cores while tasks wait. These results identify workload management as a distinct capability for agents, and \benchname{} as a way to measure it.
