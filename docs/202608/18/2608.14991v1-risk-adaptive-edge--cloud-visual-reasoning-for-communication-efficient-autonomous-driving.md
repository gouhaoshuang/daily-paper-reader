## 摘要
云端托管的视觉语言模型（VLM）比小型车载模型具有更强的上下文推理能力，但频繁的视觉上传会增加通信开销，并为战术决策带来网络和推理延迟。我们提出了一种风险自适应的边缘-云架构，其中车载交通评估决定何时请求云端推理。车载VLM和轻量级检测器捕捉时变交通状况和路径相关危险，以进行保守的本地响应和选择性的云端访问。云端模型提供战术建议，而验证、车辆控制和自动紧急制动仍保留在本地。在CARLA实验中，我们的方法匹配了周期性云端访问的任务成功率，同时将云端请求减少了54.1%，并记录了更少的自动紧急制动（AEB）激活次数。在延迟道路施工的消融实验中，语义事件在预定审核之前触发了请求。在三种模拟网络配置下，该方法继续减少云端流量，尽管车道变更比周期性访问花费了更长时间。因此，在这些实验中，车载交通评估可作为选择性VLM推理的实用触发条件。

## Abstract
Cloud-hosted vision-language models (VLMs) offer greater contextual reasoning capabilities than smaller onboard models, but frequent visual uploads increase communication overhead and add network and inference latency to tactical decisions. We present a risk-adaptive edge-cloud architecture in which onboard traffic assessment determines when cloud reasoning is requested. An onboard VLM and a lightweight detector capture temporal traffic conditions and path-relative hazards for conservative local response and selective cloud access. The cloud model provides tactical advice, while validation, vehicle control, and automatic emergency braking remain local. In CARLA experiments, our method matched the task success rate of periodic cloud access while reducing cloud requests by 54.1% and recording fewer automatic emergency braking (AEB) activations. In a delayed-roadwork ablation, semantic events triggered requests before the next scheduled audit. Across three emulated network profiles, the method continued to reduce cloud traffic, although lane changes took longer than with periodic access. Onboard traffic assessment therefore served as a practical trigger for selective VLM inference in these experiments.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 自动驾驶需要在有限车载资源下同时满足**及时本地响应**和**深度上下文推理**的需求，但这两者之间存在根本性矛盾：
  - 车载计算**延迟低、依赖少**，但模型容量和能耗受限；
  - 云端计算可运行**大规模视觉语言模型（VLM）**，推理能力强，但频繁上传视觉数据会带来**通信开销、网络延迟和推理时延**，可能错过决策窗口。
- 现有边缘计算和V2X系统虽已研究设备-云端协同推理，但多聚焦于模型切分、早停或观测上传，**忽略了“何时请求云推理”与“本地控制权边界”的耦合问题**：
  - 哪些决策必须留在本地？
  - 云端建议如何被验证和采纳？
  - 紧急情况下紧急制动如何独立于学习模型运行？
- 论文针对上述问题提出**风险自适应（Risk-Adaptive）边缘-云架构**，核心思路是：**用结构化车载语义评估交通风险，作为是否调用云端VLM的触发器**，从而实现通信效率与任务安全性的兼顾。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想
- 构建非对称边缘-云系统：**车载端持续运行语义感知与保守控制**，**云端仅在必要时提供战术建议**。
- 本地模型不直接控制车辆，云端模型也不直接输出执行命令；**执行权、验证权、紧急干预权全部保留在本地确定性模块**。

### 2.2 关键技术细节

#### 车载语义证据提取
- 收集前摄像头时序帧序列 \( C_t = \{ I^{front}_{t-k\Delta t} \}_{k=0}^{N-1} \)。
- 车载VLM（Qwen3-VL-4B）将视频剪辑映射为结构化观测 \( z_t = f_{edge}(C_t) \)。
- 观测字段包括：路径清空度、危险类别、屏幕横向位置、相对运动、接近程度、路径阻塞、模型置信度、可见证据等。
- 轻量检测器YOLO11n提供路人的边界框，并将其底部中心与规划车道投影 \(\Gamma_t\) 比较，判断是否与路径相关。

#### 本地语义策略
- 将联合证据映射为本地动作 \( r_t = \pi_{edge}(z_t, B_t, \Gamma_t) \in \{ proceed, slow, stop \} \)。
- 若出现接近、穿越、邻近或阻塞的路径内危险，则执行 `stop`；若冲突不确定，则执行 `slow`。
- 视觉停止后，需要连续三次清晰观察才能解除停止状态（语义锁存）。

#### 云端请求调度策略
- 定义紧急度 \( U_t \in \{0,1,2,3\} \) 分别对应无危险、谨慎、停止、车道阻塞。
- 请求指示 \( q_t \) 的触发条件为：
  - 启动时；
  - 紧急度上升时（\( U_t > U_{t-1} \)）；
  - 持续危险且距上次请求 ≥3 秒；
  - 距上次请求 ≥10 秒（审计备份）。
- 周期访问策略（Periodic-cloud）则固定每约3秒请求一次，不使用语义触发。
- 云端请求内容：左/前/右三视角JPEG图、车速与加速度、新鲜车载语义证据（可选）、当前可执行的换道集合。
- 云端返回战术建议：\( a_t = (m_t, v^*_t, p_t, \ell_t, e_t) \)，包括推荐操作、目标速度、置信度、有效时长和解释。

#### 本地验证与执行
- 云端建议必须通过三重校验：**置信度≥0.60**、**新鲜度**（非换道建议≤2秒，换道建议≤5秒）、**几何可行性**（目标车道存在、同向、前向≥20m、后向≥10m）。
- 换道建议被采纳后，由纯追踪控制器和比例速度控制器执行。
- 自动紧急制动（AEB）独立于所有学习模型，当 \( g_t \le 5m \) 或 \( 0 \le TTC_t \le 1.5s \) 时触发全制动。

## 3. 实验设计：数据集 / 场景、基准、对比方法

### 3.1 仿真环境
- 使用 **CARLA 0.9.15**，地图为 **Town04**，车辆为 **Tesla Model 3**。
- 每轮30秒，10Hz控制频率，巡航速度11 m/s，摄像头分辨率640×360，水平视角90°。

### 3.2 场景设置
- 四个驾驶场景：
  1. **Clear road**：无障碍道路，测试是否产生不必要干预；
  2. **Adjacent-lane vehicle**：邻道车辆，测试路径接地的正确性；
  3. **Static in-lane obstacle**：车道内静态障碍，测试保守的纵向停车；
  4. **Roadwork merge**：道路施工合流，需要战术换道。
- 另设**延迟道路施工（delayed roadwork）**场景，施工点在第5秒后显现，用于消融实验。

### 3.3 对比方法
- **Edge-only**：仅使用车载语义感知与本地控制，不请求云端。
- **Periodic-cloud**：不使用车载VLM，固定每约3秒请求云端。
- **Audit-only**：仅使用Risk-adaptive的车载语义，但移除语义事件触发请求，只保留启动和10秒审计。
- **Risk-adaptive**：完整方法，含语义触发、冷却、审计。

### 3.4 评估指标
- 任务成功率、严格成功率（排除AEB激活）、AEB激活次数、碰撞次数；
- 云端请求次数、图像负载（MB）、消耗token数；
- 车道变换完成时间、最晚AEB触发时间等。

## 6. 论文的主要结论与发现

- **RQ1**：
  - Periodic-cloud和Risk-adaptive均完成40/40任务，Edge-only完成30/40（全部失败在道路施工换道）。
  - Risk-adaptive相比Periodic-cloud，云端请求减少 **54.1%**，图像负载减少 **51.9%**，token减少 **51.2%**；
  - Risk-adaptive严格成功率更高（35/40 vs 29/40），AEB激活更少（5 vs 11）。
- **RQ2**：
  - 语义事件触发机制可在下次审计之前提前发起云端请求；
  - Risk-adaptive完成任务5/5，Audit-only 4/5，Periodic-cloud 3/5；
  - 多数情况下Risk-adaptive的换道完成时间比Audit-only提前（平均3.86秒）。
- **RQ3**：
  - 在三种网络配置（Normal、Moderate、Severe）下，Risk-adaptive均比Periodic-cloud减少约 **41%–48%** 的请求和负载；
  - 但Risk-adaptive的车道变换完成时间平均长 **1.92–3.67秒**；
  - 两者总任务成功率均为47/60，但Risk-adaptive严格成功更多（38 vs 32），AEB激活更少（12 vs 28）；
  - 失败模式不同：Periodic-cloud失败多为未完成换道并触发AEB；Risk-adaptive失败多为已执行换道但未在30秒内通过施工区，因为道路施工语义锁存未及时清除。
- 总体结论：**结构化车载交通语义可作为选择性地请求云端VLM推理的有效触发器**，在保持任务完成率的同时显著降低通信成本，但以较慢的战术响应为代价。

## 7. 优点

- **权责划分清晰**：本地执行、云端建议、AEB独立三层隔离，避免学习模型直接控制执行器，增加安全性。
- **触发机制合理**：结合时序语义和路径接地，能识别“该请求的时刻”而非固定轮询，具有可解释性。
- **评估指标丰富**：不仅看任务成功率，还分析严格成功、AEB激活、通信量、负载、token、时序等，较全面。

- **通信节省效果显著**：在多个场景中稳定减少约一半的云端请求，验证了核心价值。

## 8. 不足与局限

- **实验条件局限**：
  - 仅使用CARLA单一地图、单一车型、固定30秒运行时长；
  - 场景过于简单（无行人、信号灯、密集交通、恶劣天气、定位噪声、非结构化道路）。
- **统计充分性不足**：
  - RQ2仅5个样本，无法支撑推广；
  - RQ3与RQ2有数据复用，且网络影响与模型随机性未隔离；
  - 置信区间宽，且未做非劣效检验。
- **安全结论局限**：
  - AEB使用CARLA真值计算，属于实验性保护而非可部署感知系统；
  - 更少AEB激活不能直接解释为更安全，因为可能只是任务未完成但未触发紧急制动。
- **资源度量不完整**：
  - 只统计云端通信和token，未考虑边缘计算成本、能耗、经济开销、网络认证延迟等。
- **模型与部署假设**：
  - 车载VLM（Qwen3-VL-4B）和云端GPT-5-mini的输出均为不可校准的置信度，阈值设定较主观；
  - 车道投影、可行性检查依赖模拟器几何，离真实传感器部署有差距。
