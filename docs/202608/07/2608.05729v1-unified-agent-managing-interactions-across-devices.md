## 摘要
随着能力的迅速提升，AI智能体可以从在单个应用内运行，发展到跨用户设备随时间行动。然而，现有智能体系统在此场景下仍显不足。这是因为观测分散在不同设备和时间点上，但主流系统并未围绕这一事实进行设计：将设备视为工具的单一智能体缺乏对所有设备跨时间的有效状态管理，而多智能体系统虽协调各智能体，却无法维护跨设备、跨时间请求所需的紧凑携带状态。我们认为，智能体应维护一种有效设计的状态，将交互证据、已陈述事实和当前请求以紧凑、可操作的形式组织起来，以便根据当前观测决定下一步行动。为了比较状态设计，我们构建了一个跨设备与时间的用户-智能体交互基准。我们将这一原则实例化为统一智能体（Unified Agent），这是一种有状态智能体，能够跨设备和时间携带交互证据，并结合当前观测进行行动。在默认设置下，它显著优于我们对四种已发表设计的改编版本。在多模态大语言模型（MLLM）家族、能力和推理努力程度的变化中，它始终领先于所有对比系统，表明状态设计的优势在不同MLLM设置下具有鲁棒性。我们的代码和数据将在GitHub上公开提供。

## Abstract
As capabilities rapidly increase, AI agents can move from running inside one app to acting across a user's devices over time. Yet existing agent systems still fall short in this scenario. This is because observations are scattered across devices and moments, but mainstream systems are not designed around this fact: a single agent that treats devices as tools lacks effective state management for all devices across time, and multi-agent systems coordinate across agents but do not maintain the compact carried state a cross-device, cross-time request needs. We argue that the agent should maintain an effectively designed state that organizes engagement evidence, stated facts, and the standing request in a compact, action-ready form for deciding its action given the current observation. To compare state designs, we construct a benchmark of user-agent interaction across devices and time. We instantiate this principle in Unified Agent, a stateful agent that carries interaction evidence across devices and moments and uses it with the current observation to act. In the default setting, it significantly outperforms our adaptations of four published designs. Across changes in multimodal large language model (MLLM) family, capability, and reasoning effort, it remains ahead of all compared systems, demonstrating that the state-design advantage is robust across MLLM settings. Our code and data will be publicly available on GitHub.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：随着AI智能体能力的快速提升，其应用场景正从单一应用内的操作扩展到跨用户多个设备的持续性任务。例如，用户可能在不同设备上进行比较、查找信息，稍后在不指明设备的情况下提出请求（如“帮我预订我之前在看的餐厅”）。
- **核心问题**：现有智能体系统在面对跨设备、跨时间的交互时存在根本性缺陷。观测信息分散在不同设备和时间点上，而主流系统并未围绕这一事实进行设计：
  - **单智能体系统**：将设备视为工具，但缺乏跨时间的有效状态管理，每个请求都被当作全新请求处理，早期语境一旦消失便无法利用。
  - **多智能体系统**：虽能协调多个智能体，但缺乏统一的跨设备状态，无法处理依赖分散在多个设备与时刻的信息的请求。
- **核心论点**：智能体应维护一种**有效设计的紧凑携带状态（compact carried state）**，将**交互参与证据（engagement evidence）、已陈述事实（stated facts）和当前请求（standing request）** 组织成可操作的形式，以支持在当前观测下做出正确决策。这种状态设计是跨设备智能体能否成功的关键因素。

### 2. 论文提出的方法论（核心思想、关键技术细节、公式或算法流程）

- **核心思想**：提出 **Unified Agent（统一智能体）** 框架，一个跨设备和时间的有状态智能体。它通过维护一个紧凑、可操作的状态来整合历史交互证据，并结合当前观测进行决策，从而解决单次观测信息不足的问题。
- **状态表示**：在每个时刻 *t*，智能体携带状态 *Sₜ* = (*Cₜ*, *Pₜ*, *Kₜ*, *rₜ*)，其中：
  - ***Cₜ***：编码参与证据，包括非空参与观测计数 *mₜ* 以及各设备参与次数 *litₜ(d)*。
  - ***Pₜ***：保留被注意设备的线索（渲染基准中为指向动作，真实照片为手部接触设备）。
  - ***Kₜ***：存储已陈述事实，按“设备-主题”配对（设备已知时）或仅按主题存储。
  - ***rₜ***：存储最新的行动请求（standing request）。
- **状态更新（折叠）公式**：*Sₜ* = *U*(*Sₜ₋₁*, *Oₜ*) —— 在每个时刻，将当前观测 *Oₜ* 折叠进前一个状态，更新参与证据、记录新事实、更新当前请求，同时保留早期证据。
- **行动决策公式**：*aₜ* = *D*(*Sₜ*, *Oₜ*) —— 智能体同时读取更新后的状态和当前观测来做出行动决策。这样做的好处是：当前观测提供即时信息，而状态提供历史证据，使早期交互线索在视觉线索消失后仍能影响决策。
- **六个任务框架（Observe–Think–Act）**：将每个交互时刻组织为六个子任务：
  1. **检测用户和设备**（感知任务）；
  2. **识别参与设备**（Eng）；
  3. **推断用户意图**（Int）；
  4. **回忆相关信息**（Inf）；
  5. **选择响应设备**（Rsp）；
  6. **决定下一步行动**（Nxt）。
- **设备与智能体的分工**：智能体通过共享决策接口用语言指定哪些设备应响应以及如何操作，各设备使用制造商设计的原生控件执行指令。这种分离使一个智能体能够服务异构设备，同时保持设备对自身执行的责任。

### 3. 实验设计（数据集/场景、基准、对比方法）

  - **每个片段**：12 帧，包含初始场景建立、早期交互建立参与关系和上下文、后期设备未指定的请求和回忆问题。

  - **已发表基线**：Mem0（记忆系统）、MM-DST（多模态对话状态跟踪）、Mixture-of-Agents（多智能体混合）、Debate-or-vote（多智能体辩论投票）。
