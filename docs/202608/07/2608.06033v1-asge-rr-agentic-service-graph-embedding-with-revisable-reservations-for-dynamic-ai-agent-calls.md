## 摘要
AI智能体工作流通常涉及对分布在网络中的模型、存储和工具的远程调用。随着执行的推进，这些依赖调用共同形成一个智能体服务图（ASG）。与传统服务请求不同，许多依赖调用仅在运行时才显现。因此，将资源分配给当前可见的调用可能会消耗后续高价值工作流调用所需的容量。我们将这一挑战表述为智能体服务图嵌入（ASGE），这是一个在线网络控制问题，在容量、成本和截止时间约束下，将运行时显现的工作流调用映射到服务副本和网络路径。我们提出了ASGE-RR，一种具有可修订预留的在线ASGE控制器。ASGE-RR在强制约束的同时，为可能的未来调用保护容量。ASGE-RR根据预测的工作流延续来评估候选的副本-路径映射，并在新的执行信息可用时更新预留。我们使用OpenHands和GPT Researcher工作流对ASGE-RR进行了评估，这些工作流使用gpt-5.6-luna执行，并在两个互补的实验环境（受控Docker测试平台和WAN测试平台）中重放。调查表明，所有被评估的AI智能体任务都至少暴露了一个可在连接建立前被引导的运行时显现依赖调用。利用这一控制点，尽管实验环境规模较小，ASGE-RR已经显示出显著潜力：在WAN测试平台上，它比具有相同信息的滚动时域控制器和当前调用转向控制器多完成（最多）10%的工作流价值。结果表明，运行时显现的工作流结构创造了一个新的网络控制机会：为可能的未来调用保护资源，使更多AI智能体工作流能够按时完成。

## Abstract
AI-agent workflows often involve remote calls to models, memory stores, and tools distributed across a network. As execution progresses, these dependency calls collectively form an agentic service graph (ASG). Unlike traditional service requests, many dependency calls are revealed only at runtime. Consequently, allocating resources to a currently visible call may consume capacity later needed by a call from a higher-value workflow. We formulate this challenge as Agentic Service Graph Embedding (ASGE), an online network-control problem that maps runtime-revealed workflow calls to service replicas and network paths under capacity, cost and deadline constraints. We present ASGE-RR, an online ASGE controller with revisable reservations. ASGE-RR protects capacity for likely future calls while enforcing the constraints. ASGE-RR evaluates candidate replica-and-path mappings against predicted workflow continuations and updates reservations as new execution information becomes available.   We evaluate ASGE-RR using OpenHands and GPT Researcher workflows executed with gpt-5.6-luna and replayed over in two complementary experimental environments, a controlled Docker testbed and a WAN testbed. The investigation shows that all the evaluated AI-agent tasks expose at least one runtime-revealed dependency call that can be steered before connection establishment. Exploiting this control point, even though the experimental environments are small-scale, ASGE-RR already demonstrates noticeable potential: It completes (up to) 10% more workflow value than a same-information rolling-horizon controller and a current-call steering controller on the WAN testbed. The results suggest that runtime-revealed workflow structure creates a new network control opportunity: protecting resources for likely future calls allows more AI-agent workflows to finish in time.

## 2. 方法论：核心思想、关键技术细节与算法

### 核心思想
- 提出 **ASGE-RR（ASGE with Revisable Reservations，具有可修订预留的ASGE控制器）**：通过"可修订预留"机制，为**可能的未来调用**保护容量，并在新的工作流信息出现时**动态更新预留**，从而将部分未来结构知识转化为准入保护，且**不违反硬容量约束**。

### 关键技术细节

1. **四步决策流程**（在每次调用释放事件时）：
   - **生成可行动作**：枚举所有符合策略的副本-路径映射（含等待动作 γ_wait）
   - **预测工作流延续（后缀）**：用历史轨迹学习概率权重，保留高概率后缀，若覆盖不足则回退为短视策略
   - **计算可修订预留**：基于加权分位数，在每个资源-时间槽位上预留未来调用所需容量
   - **选择动作**：综合完成时间、资源成本和稀缺性评分，选取最优动作

2. **容量日历（Capacity Calendar）**：以时间槽为单位跟踪已承诺负载、预留负载和剩余可用容量；每次事件时更新，保证硬分配不超容量。

3. **预测与量化**：
   - 使用加权分位数汇总未来需求：R_rτ,jl(γ) = Q_{1-ε}({v_rσ,jl(γ)})，ε 为资源预留尾部水平
   - 完成时间估计：Ĉ_β(γ) = Q_{1-β}({Ĉ_σ(γ)})，β 为完成时间尾部水平
   - 预留优先级：π(γ) = ν_r · p_on(γ) / max{ε_t, A_r + L_r − t_τ}，随价值、按时概率、紧急性升高

4. **可行性测试**：资源可行性（u + R + R_其他 ≤ S）和截止时间可行性（Ĉ ≤ A_r + L_r）；若被其他工作流的预留阻塞，则按优先级由低到高释放预留。

5. **动作评分**：score(γ) = 归一化完成时间 + λ_K · 归一化成本 + λ_R · 稀缺性项，综合短视性能与未来灵活性。

6. **安全保证**：**定理1**——只要初始日历可行且实际需求在声明范围内，ASGE-RR 的每次提交都满足容量与策略约束，**与预测精度无关**。复杂度为 O(P_path + T_dR_cZHWB²[L + log(WB)])。

## 3. 实验设计：数据集/场景、基准与对比方法

- **重放机制**：先在线执行录制调用序列和精确字节数，再冻结成确定性工作负载在两种环境下重放，确保不同控制器面对完全相同的应用行为——隔离网络策略效果

### 实验环境一：受控 Docker 测试床
- 9个角色分离容器（网关、控制器、收发中继、两个副本、事件记录器）

  1. 中度竞争
  2. 高竞争
  3. 仅服务竞争
  4. 仅路径竞争
  5. 充裕容量
  6. 单一合法映射
  7. 预测失误（预留资源但调用未出现）
- 每种条件20次配对执行、2种控制器执行顺序、10次重复，主实验加反序实验共 **560次运行**

### 实验环境二：WAN 测试床（5台VM）

- **3种条件**：中度竞争、饱和、充裕容量
- 20个评估块（每个评估任务一个块）、两种控制器执行顺序、配对设计

### 对比基准
1. **滚动时域控制器（Rolling-horizon）**：使用相同预测和测量，在调用出现时重新优化优先级加权完成目标，但在事件之间释放预测保护（消融对比：保留的预留是否有额外收益）
2. **CATS风格控制器**：逐个处理当前调用、选择预期最早完成映射（代表已有计算感知流量转向方法，对比：工作流感知是否优于强当前调用转向）
- **完整信息基准**：非因果式基准，假设未来调用和实际服务时间已知，通过混合整数规划求得最优配置

## 6. 主要结论与发现

1. **控制点存在且普遍**：所有20个评估任务都至少暴露一个可在连接建立前由控制器绑定的运行时揭示调用（Wilson 95%区间0.839–1.000）；调用水平上，94/124个调用可绑定（OpenHands 75/87，GPT Researcher 19/37）。
2. **可操作性时间窗口充分**：实测显示，从早期响应完成（2.910s）到下一个调用出现（60.3ms后），控制器可在8.1ms内完成副本/路径绑定，网关0.03ms后打开连接——控制器决策速度远快于网络传输（5.0s vs 5.8–6.0ms）。
3. **预留机制有效**：在中度和高竞争下，ASGE-RR比无预留控制器分别降低工作流释放到返回延迟 **1.45s和4.31s**；服务队列和路径瓶颈均可创造预留机会（分别降低1.53s和0.87s）；在充裕容量或单一合法映射下无收益（符合预期）；预测失误会产生0.46s代价。
4. **WAN环境下的价值提升**：在中度竞争下，ASGE-RR比滚动时域多完成 **8.75个百分点**（95%CI：1.25–17.5）的工作流价值，比CATS多完成 **10个百分点**（95%CI：1.25–20.0）；增益集中在4个OpenHands块 + 1个GPT Researcher块，在14个块中持平（其中1个GPT Researcher块有损失）。在饱和条件下，由于两个执行顺序差异大，差异未通过统计显著性检验。
5. **理论保证**：无论预测准确与否，ASGE-RR 的提交动作始终满足容量与策略约束（定理1）。
6. **核心结论**：运行时揭示的工作流结构创造了一个新的网络控制机会——保护未来可能调用的资源，能够显著提升工作流按时完成率，网络控制应当面向演化中的工作流依赖关系优化，而非孤立地优化每个调用。

## 7. 优点（方法与实验亮点）

- **问题定义新颖**：将AI智能体的运行时依赖调用与网络资源的在线嵌入问题形式化为ASGE，区别于传统SFC/VNE假设的"请求已知"设定，开辟新问题空间。
- **方法设计精巧**：可修订预留以软状态（soft state）形式保护容量但不消耗容量——预测错误只会降低效率，不会违反硬容量约束；通过概率后缀和加权分位数实现预测；预留仲裁机制优先让高价值、紧迫的工作流占用资源；覆盖不足时自动回退为短视策略，保证鲁棒性。
- **安全保证清晰**：定理1为在线控制器的可靠性提供了理论支撑。
- **实验方法论严谨**：重放机制隔离网络控制与AI智能体行为差异，保证对比公平；配对设计 + 顺序反转控制混淆变量；独立检验器验证结果；同时用受控Docker环境和真实WAN环境互补验证。
- **真实性**：直接用主流开源AI智能体运行时（OpenHands、GPT Researcher）的实际工作流，不是合成流量，保证问题真实存在。
- **多维度评估**：同时报告完成价值、完成时间、资源成本三个量，以及时序分解（控制延迟 vs 网络延迟 vs 服务时间），透明展示系统运行细节。

## 8. 不足与局限

- **实验覆盖有限**：仅测试了2种AI智能体运行时和28个公共任务，未覆盖不同领域的智能体类型（如业务自动化、机器人控制、多模态智能体等）；WAN测试床仅有5台VM、2条路径、2个副本，没有大规模生产级验证。
- **统计功效有限**：20个评估块的样本量偏小，WAN结果中多个置信区间跨零（如饱和条件下 −2.5–5.0 个百分点），实验结论主要基于中度竞争条件，普适性有待更大样本验证。
- **预测依赖性**：ASGE-RR依赖历史痕迹预测工作流延续，需要与评估集不相交的轨迹数据；对未见过的新任务/新模型版本，预测质量可能下降，论文未讨论冷启动或模型变化下的适用性。
- **复杂度风险**：算法复杂度为 O(T_dR_cZHWB²[L + log(WB)])，在大规模生产环境（大量同时工作流、大量节点、更多候选路径）中，计算开销可能成为瓶颈，论文未在更大规模环境中测量实际运行时间。
- **基准未量化**：论文定义了完整信息基准，但在评估部分未报告ASGE-RR与完整信息最优解之间的差距，缺少"最优性缺口"分析。
- **假设简化**：忽略排队时延，使用服务时长上界和路径容量预定模型，对真实网络中TCP拥塞、链路状态波动等动态效应未建模。
- **限制条件**：协议层面假设依赖调用的副本是"等价的"、请求和响应路径均可由控制器选择；在现有专有智能体平台的封闭生态中，这种控制面开放程度可能不现实。
