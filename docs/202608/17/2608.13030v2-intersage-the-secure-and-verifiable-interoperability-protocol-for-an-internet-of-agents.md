## 摘要
新兴的智能体互联网使由大语言模型驱动的智能体能够跨组织边界发现对等节点、调用工具和委派任务。现有协议越来越多地定义了智能体如何交换消息，但没有定义智能体如何证明其身份、授权、宣传的能力或委派后的责任归属。我们提出InterSAGE，这是一个原生信任协议套件，与通信协议并行提供缺失的安全基座，而不是取代通信协议。InterSAGE包含四层：持久身份、发现、信任协商和问责。其四个核心原语是：(1) 智能体身份卡，绑定开发者、代码包、运营者和部署上下文；(2) 使用绑定DID的可验证凭证清单进行能力感知发现；(3) 信任协商，结合单调能力衰减与两级访问控制；(4) 由内核中介的加密审计跟踪，将使用、委派和执行痕迹与智能体身份绑定，无需共识账本。InterSAGE旨在补充MCP、A2A、ANP和AG-UI，使通信协议能够独立演进，同时保持信任语义显式、可移植且可验证。我们将InterSAGE与涵盖智能体协议、去中心化身份、OAuth/OIDC扩展、零信任治理、委派和审计架构的50多项工作进行了比较。我们表明，此前没有任何架构能够将持久身份、能力感知发现、信任协商和问责作为一个统一四层信任基座，共同支撑安全智能体互操作。

## Abstract
The emerging Internet of Agents enables LLM-powered agents to discover peers, invoke tools, and delegate tasks across organizational boundaries. Existing protocols increasingly define how agents exchange messages, but not how an agent proves its identity, authorization, advertised capabilities, or accountability after delegation. We present InterSAGE, a trust-native protocol suite that supplies this missing security substrate alongside, rather than in place of, communication protocols. InterSAGE comprises four layers: Persistent Identity, Discovery, Trust Negotiation, and Accountability. Its four core primitives are: (1) Agent Identity Cards that bind developer, code package, operator, and deployment context; (2) capability-aware discovery using DID-bound Verifiable Credential manifests; (3) trust negotiation combining monotonic capability attenuation with two-tier access control; and (4) kernel-mediated cryptographic audit trails that bind usage, delegation, and execution traces to agent identity without a consensus ledger. InterSAGE is designed to complement MCP, A2A, ANP, and AG-UI, allowing communication protocols to evolve independently while keeping trust semantics explicit, portable, and verifiable. We compare InterSAGE with more than 50 efforts spanning agent protocols, decentralized identity, OAuth/OIDC extensions, zero-trust governance, delegation, and audit architectures. We show that no prior architecture jointly enforces persistent identity, capability-aware discovery, trust negotiation, and accountability as a unified four-layer trust substrate for secure agent interoperability.

### 1. 核心问题与整体含义（研究动机与背景）

- **背景**：LLM 驱动的自主智能体正从单体应用走向跨组织协作的"智能体互联网"（Internet of Agents，IoA）。工业界已涌现出大量通信协议（如 MCP、A2A、ANP、AG-UI、ACP），但这些协议主要解决"智能体如何通信"（消息格式、任务生命周期、工具调用），而非"智能体凭什么可信"。
- **核心问题**：在智能体跨组织边界协作时，缺乏一个安全基座来回答四个关键问题：**智能体是谁**（身份）、**它能做什么**（能力）、**它被授权做什么**（委托边界）、**它做了什么**（问责）。现有协议无法证明智能体的身份真实性、能力真伪、授权范围，以及委派后行为的不可抵赖性。

- **威胁模型**：论文系统梳理了六类智能体特有威胁——身份伪造（T1）、能力升级（T2）、委托滥用（T3）、跨域信任崩溃（T4）、支付与使用欺诈（T5）、行为抵赖（T6），并指出其结构性成因在于现有协议缺乏绑定、单调衰减、共享信任锚与签名审计。

### 2. 方法论：InterSAGE 协议套件

论文提出 **InterSAGE**，一个四层信任原生协议套件，沿用了作者此前 BlockA2A 工作的安全理念而摒弃了区块链依赖。五个设计原则：信任作为绑定层而非附加件（P1）、补充而非替代现有协议（P2）、通用密码学原语无基础设施锁定（P3）、默认拒绝且收敛于严格（P4）、结构保证优于策略保证（P5）。

**四层架构与核心原语：**

- **Layer 0 — 持久身份（Agent Identity）**：核心原语为**智能体身份卡（AIC）**，由全球智能体注册处（GAR）签名：
  ```
  AIC = Sign_GAR(DID_agent ∥ K_pub ∥ S_max)
  ```
  四维身份绑定——开发者（Ed25519 签名密钥）、代码包（SHA-256 摘要）、运营者（OIDC 验证）、部署上下文（租户/环境）——每个维度由不同方控制、独立验证。私钥永不离开隔离信任边界，提供三级密钥保护（OS文件隔离 → OS 钥匙串 → TEE 安全区）。

- **Layer 1 — 能力感知发现（Discovery）**：将技能（skill）和工具（tool）表示为 **DID 绑定的可验证凭证（VC）清单**，各自由技能分发者/工具提供者签发，经 GAR 背书。发现时执行四步校验：供应链验证（发行者签名）→ 主体绑定（credentialSubject.id 必须匹配展现者 DID）→ 权限对齐（perms_required ⊆ S_max）→ 新鲜度（未过期/未吊销）。发现由此从目录查寻变为建立信任的安全原语。

- **Layer 2 — 信任协商（Trust Negotiation）**：互认证采用挑战-响应协议（32 字节 nonce、60 秒 TTL、Ed25519 签名），会话能力边界为双方能力交集 `S_session = S_policy ∩ (S_A_max ∩ S_B_max)`。委托采用 **AIC 委托链**，保证：单调衰减、租户隔离、深度约束、级联吊销、有效期封顶、环路抵抗。访问控制为**两级模型**——基础设施层（密码学验证，内核强制）与应川层（声明式策略，可选），互不干扰、独立失败。

- **Layer 3 — 问责（Accountability）**：每个操作生成由内核私钥签名的**追踪条目**，通过 `prev_hash` 链接形成防篡改哈希链。代币使用记录绑定智能体 DID 与会话，可将成本沿委托链追溯到人类运营者。提供最小支付原语框架（广而告之价格 → 协商 → 计量 → 结算），与 Google AP2 互补而非竞争。

**核心安全保证**：单调能力衰减链（开发者声明 → 运营者选择 → GAR 签发 → 运行时交集）确保每一阶段只能收窄权限，任何放宽都需要伪造签名——最不特权原则是"结构性"的而非依赖策略引擎正确配置。

### 6. 主要结论与发现

1. **诊断结论**：现有智能体协议和零信任覆盖层都将最不特权视为"运行时策略问题"而非"凭据结构问题"——策略引擎误配置或证明器被攻破即可静默扩大权限边界。
2. **设计主张**：InterSAGE 将单调能力衰减作为签发时签入凭据的结构性不变式，策略层只能收窄而非放宽；两级访问控制使密码学验证与应用策略在独立路径上故障关闭。
3. **联合覆盖是核心贡献**：每个单独原语在先前工作中都有前驱（DID/SPIFFE 之于 AIC、UCAN/Biscuit 之于衰减、AgentMesh 之于两级直觉、AgentRFC 之于原则形式化、BlockA2A 之于统一信任），但**没有任何单一架构将这四层联合实现为统一信任基座**。
4. **互补性而非竞争性**：InterSAGE 嵌入现有通信协议而非取代之——MCP 调用携带 AIC 能力边界、ANP 发现响应携带清单 VC、A2A 交互携带会话令牌、AG-UI 事件流附加签名执行痕迹。
5. **去基础设施依赖**：通过内核中介密码学实现与共识账本相当的防篡改能力，使信任基座可部署于云端、边缘和隔离环境。

### 8. 不足与局限

- **缺乏经验验证**：没有原型实现、性能数据或真实部署证据。安全性仅靠概念论证支撑，未经过形式化验证（TLA+/ProVerif）或红队攻防检验。
- **GAR 信任锚风险**：GAR 与 CA 有相同的单点信任问题——根密钥被窃即系统性崩溃；跨 GAR 联邦协议尚未设计；作为全球级基础设施的可扩展性缺乏实证。
- **冷启动/网络效应问题**：InterSAGE 价值随采用率增长，早期部署面临"先有鸡还是先有蛋"困境；尽管提出了 L0 可独立采用的思路，但全栈价值仍需生态协同。
- **核心技术权衡未被充分讨论**：内核信任假设意味着部署者仍需信任内核实现（如 DeepKernel）；"应用层无法访问私钥"在安全性上有利，但也限制了应用层可实现的灵活签名逻辑。
- **语义标签治理缺失**：L1 的开放语义标签词汇表缺乏治理机制，可能碎片化或被恶意利用（尽管作者声称"无执行权重"）。
- **认知安全边界**：提示注入使智能体在授权范围内做出恶意行为，被划为"LLM 级认知失败"而非协议缺陷——这个边界是否可接受存在争议，在真实攻击中捕获和归因"授权内的恶意行为"仍困难。
- **支付原语过于简略**：L3 支付仅提供了身份与计量基础设施，未涉及争议解决、服务质量保证和微支付效率等关键问题，实际部署尚需大量补充。
