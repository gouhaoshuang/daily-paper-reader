## 摘要
在当今快节奏的环境中，快速访问、理解并基于数据采取行动的能力不再是可选项，而是必需的。然而，大多数组织仍然数据丰富但洞察贫乏，受限于查询、解释和说明企业级信息的复杂性。我们提出了Polaris，一个由监督者主导的多智能体框架，用于对话式企业分析，弥合了这一差距。Polaris引入了动态任务协调（DTC），这是一种决策理论驱动的编排层，将智能体任务分配建模为自适应二分匹配，实现了跨查询、可视化和推理等专门智能体的实时协调、恢复和优化。通过将DTC与推理优先、ReAct风格的智能体相结合，Polaris将自然语言查询转化为连贯的分析工作流，不仅能检索和可视化数据，还能解释潜在的“原因”。在结构化企业数据集上的评估显示了高语义保真度和答案相关性，凸显了多智能体编排在规模化提供可信赖的端到端商业智能方面的潜力。

## Abstract
In today's fast-paced environment, the ability to swiftly access, understand, and act on data is no longer optional; it is essential. Yet most organizations remain data-rich but insight-poor, constrained by the complexity of querying, interpreting, and explaining enterprise-scale information. We present Polaris, a supervisor-led multi-agent framework for conversational enterprise analytics that bridges this gap. Polaris introduces Dynamic Task Coordination (DTC), a decision-theoretic orchestration layer that models agent-task assignment as adaptive bipartite matching, enabling real-time coordination, recovery, and optimization across specialized agents for querying, visualization, and reasoning. By coupling DTC with reason-first, ReAct-style agents, Polaris transforms natural-language queries into coherent analytical workflows that not only retrieve and visualize data but also explain the underlying "why." Evaluation on structured enterprise datasets demonstrates high semantic fidelity and answer relevancy, underscoring the potential of multi-agent orchestration to deliver trustworthy, end-to-end business intelligence at scale.

## 2. 论文提出的方法论：核心思想、关键技术细节与流程

- **整体架构**：Polaris 是一个由监督者（Supervisor）主导的多智能体系统。系统通过与用户对话，逐步拆解自然语言请求，利用由 DTC 编排的多个专业智能体完成**数据查询、可视化、因果解释和报告生成**的完整分析流程。
- **核心创新——动态任务协调（DTC）**：
  - DTC 是一个决策理论驱动的在线编排层，将智能体–任务分配建模为**自适应二分图匹配**问题：
    - 设图 G = ( A ∪ T, E )，其中每个智能体 a ∈ A 有能力向量 θ_a，每个任务 t ∈ T 有描述符 τ_t。
    - 边权重（效用函数）综合考虑能力契合度、既往可靠性与成本惩罚：
      - U(a, t | s) = α·sim(θ_a, τ_t) + β·q(a, t) − γ·c(a, t)
      - 其中 q(a, t) 表示由执行反馈（诊断追踪、错误信息、延迟）更新的经验可靠性，c(a, t) 表示成本，s 为系统状态。
    - 全局最优匹配为：
      - M* = arg max_{M∈M} Σ_{(a,t)∈M} U(a, t | s)
      - 其中 M 为在优先级、容量和工具/数据可用性约束下的可行匹配集合。
  - **闭环自适应机制**：执行反馈持续更新 q(a, t) 及智能体能力向量 θ 的置信度，使系统能够实时进行不确定感知的重规划、抢占和回滚，实现约束满足、负载均衡与能力感知分配。
- **智能体间协同模式**：
  - 所有智能体采用 **reason-first ReAct 范式**（推理 + 行动），在工具选择与执行之前先进行情境化推理，通过“思考–行动–观察”循环自适应地规划多步工作流，而非直接生成工具调用。
- **四大专家智能体**：
  - **监督者智能体（Supervisor Agent）**：负责解析意图、维护跨会话上下文、按约束条件近似求解 Eq. 1 来分配任务、分解歧义请求。遇到模式不匹配或字段缺失时，触发恢复协议并保持对话连续性。
  - **查询专家（Query Expert）**：将领域特定的自然语言转为 SQL++ 查询。流程包括：模式推断与语义标注（借助 SQL++ INFER 命令并对字段做语义消歧，如将“amount”解析为“total sales amount”）→ 输入规范化（扩展模糊用户提示）→ NL-to-SQL++ 翻译（ReAct 推理）→ 数据质量检查与自适应恢复（检测空值列、模式错配、结果过大时自动聚合）。
  - **图表专家（Charting Expert）**：基于检索数据的结构与语义，结合规则启发式与 ReAct 框架动态生成可视化代码（Seaborn/Plotly），在 Python REPL 中执行，根据栈追踪自动纠错或更换图表类型。
  - **推理专家（Reasoning Expert）**：挖掘潜在模式、识别因果关系，结合数据库领域特定知识生成富解释性的叙述。
  - **报告专家（Report Expert）**：汇总查询结果、嵌入可视化、记录方法论并补充元数据，生成结构化报告。

## 3. 实验设计：数据集 / 场景 / Benchmark / 对比方法

- **数据集**：使用 Airbnb listings 数据集（纽约租赁房产的结构化元数据），来源为 Kaggle 公开数据集。
- **基准构造（Golden Dataset）**：采用合成数据生成器构造了包含 **40 个“查询–答案对”** 的金标准数据集。每个实例包含：
  1. 自然语言查询
  2. 由数据集推导出的参考答案
  3. 用于生成答案的参考上下文（Ground Truth）
  4. NL2SQL++ 管道生成的检索上下文
  5. 最终智能体回复
- **评估指标**（三个，均基于 GPT-4o 的嵌入计算）：
  - **语义相似度（Semantic Similarity）**：检索上下文与参考上下文的嵌入余弦相似度。
  - **上下文精度（Context Precision）**：检索上下文中相关部分的比例（即检索到的相关集合与总检索集合的比值）。
  - **答案相关性（Answer Relevancy）**：生成答案与查询、检索上下文之间的加权相似度，公式为 λ·sim(e(a), e(q)) + (1−λ)·sim(e(a), e(C_r))，λ 平衡查询对齐与上下文忠实度。

- **覆盖完整的分析链路**：从查询生成到可视化再到解释性报告，系统设计覆盖了商业智能分析的全流程，具有较强的工程完整性。
- **智能错误恢复与自适应**：通过诊断反馈自动纠正可视化代码、针对大结果集自适应聚合等设计，贴合真实企业数据的脏乱特性，实用性较强。
- **多模态输出的一致性保障**：监督者通过集中化状态协调确保查询结果、图表与叙述保持语义一致，回应了企业场景下对输出可信度的核心需求。
