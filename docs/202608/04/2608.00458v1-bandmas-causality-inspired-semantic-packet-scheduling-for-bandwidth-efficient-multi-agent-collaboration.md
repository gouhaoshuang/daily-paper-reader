## 摘要
基于LLM的多智能体系统通过跨专业智能体交换消息，基于聚合信息做出决策。转发每个生成的消息增加了应用层流量。然而，这为智能体处理引入了大量输入令牌，可能提高推理延迟和计算开销。现有方法试图通过修剪智能体或丢弃冗余消息来解决上述问题。然而，这种智能体级或消息级优化导致最终决策的证据支持不足，或仍包含冗余消息传输。为了应对这些挑战，我们提出BANDMAS，一个多智能体协作框架，将智能体间通信建模为面向任务流量，通过受因果关系启发的回放评估实现高效传输。具体而言，我们通过分析语义特征（如证据和请求）将消息分解为若干数据包。系统仅在这些预测的回放贡献超过其资源成本时才传输这些数据包。因此，BANDMAS能够在遵守带宽、延迟、截止时间和接收者上下文约束的同时，自适应调度通信数据包。在SciFact、HotpotQA和FanOutQA上的冻结Qwen3-4B流量上，我们的框架在选定上限下将应用层字节减少53.2%至77.3%，并在所有三个工作负载的受限方法中取得最高平均任务指标。

## Abstract
LLM-based multi-agent systems make decisions based on the aggregated information via exchanging messages across specialized agents. Forwarding every generated message among agents increases application-layer traffic. Yet, it introduces tremendous input tokens for agent processing, potentially raising inference latency and computational overhead. Existing approaches attempt to address the above issues by pruning agents or discarding redundant messages. Nevertheless, such agent-level or message-level optimization results in insufficient evidence supporting for final decisions or still containing redundant message transmissions. To address these challenges, we propose BANDMAS, a multi-agent collaboration framework that models inter-agent communications as task-oriented traffic, which enables efficient transmission via causality-inspired replay valuation. Specifically, we decompose messages into several data packets by analyzing their semantic features such as evidence and requests. The system only transmits these packets if their predicted replay-derived contribution exceeds their resource cost. Consequently, BANDMAS is able to adaptively schedule communication packets while adhering to bandwidth, latency, deadline, and receiver context constraints. On frozen Qwen3-4B traffic across SciFact, HotpotQA, and FanOutQA, our framework reduces application-layer bytes by 53.2\% to 77.3\% at selected caps and attains the highest mean task metric among constrained methods on all three workloads.

## BANDMAS：受因果关系启发的语义数据包调度，用于带宽高效的多智能体协作

### 1. 核心问题与整体含义（研究动机与背景）

**问题背景：**

基于大语言模型（LLM）的多智能体系统依赖多个专业化智能体之间交换自然语言消息来完成复杂任务。在证据密集型工作流中，reader/专家智能体分别阅读不同文档、追踪或遥测流，下游 verifier/answerer 智能体整合各方发现生成最终输出。

**核心矛盾：**

- 若转发每个生成的完整消息，应用层流量剧增，同时接收端输入上下文膨胀，导致推理延迟和计算开销上升；
- 但若直接丢弃整个消息或修剪智能体，又可能丢失必要的支撑证据；
- 现有方法（agent级剪枝、message级丢弃、提示压缩等）粒度太粗——要么损害决策质量，要么仍残留冗余传输；
- 消息长度与语义相似度都无法回答关键问题：**这段内容是否真正提升任务效用？**

**核心挑战：** 在接收端生成最终输出之前，区分有用内容与冗余内容，同时保持证据链完整和相关声明间的依赖关系。

**BANDMAS 的核心立场：** 将智能体间生成的文本视为具有不同任务价值的应用层流量，而非不可分割的完整对话历史，从而在细粒度上实现通信控制。

### 2. 方法论：核心思想、技术细节、公式与算法流程

**整体架构：** BANDMAS 是接收端通信控制框架，在"消息生成之后、接收端推理之前"介入。它不改变智能体角色、不重写生成内容、不改变协作拓扑，仅决定哪些完整的语义数据包记录穿越接收边界。

**核心概念——语义数据包：**

- 将每条消息分解为多个带类型标记的语义数据包：Claim（声明）、Evidence（证据）、Uncertainty（不确定性）、Request（请求）；
- 每个数据包记录消息标识、路由、语义类型、时间戳、来源、段序、依赖元数据、语义跨度及负载；
- 数据包是应用层记录，不是物理网络包；通过紧凑 UTF-8 JSONL 序列化器计量真实字节成本。

**因果启发的回放价值评估（RCE）：**

对每个数据包 pᵢ，定义两种对比情境下的贡献：

- 充分性（Sufficiency）：Δsuf(pᵢ) = U(Fx({pᵢ}), x) − U(Fx(∅), x)——该数据包单独存在时带来的效用增益；
- 必要性（Necessity）：Δnec(pᵢ) = U(Fx(Px), x) − U(Fx(Px\{pᵢ}), x)——从完整上下文中移除该数据包造成的效用损失；
- RCE：Δ(pᵢ) = ½[Δsuf(pᵢ) + Δnec(pᵢ)]。

正/零/负 RCE 分别表示该数据包在给定上下文中是有帮助的、冗余的、有害的。这一标签是上下文依赖的、受因果启发的画像标签，而非无约束的因果效应或在线结果信号。

**离线/在线分离：**

- 离线：在 profile/validation 划分上执行受控回放，计算 RCE 标签，训练冻结的预测器；
- 在线：使用冻结的预测器和预接收资源观测做出调度决策，严禁使用金标签、接收端输出、评估分数或最终测试 RCE。

**分裂安全预测器（Split-Safe Predictor）：**

- 特征集仅包含：数据包类型、路由、词汇标记、序列化大小、轮次位置；排除接收端输出及任何由任务/证据分数计算的特征；
- 采用经验贝叶斯式收缩估计（shrinkage strength α=6）：
  bμg = (n_g/(n_g+α))·Δ̄g + (α/(n_g+α))·πg
- 特征层级从全局 RCE 均值出发，依次形成类型/路由先验，并细化为类型-路由、词汇标记、数据包大小、轮次等特征单元。

**调度策略：**

- **静态 BANDMAS：** 按冻结分数排序，贪心接纳每个完整记录（只要序列化批次不超过硬性字节上限）；
- **自适应 BANDMAS：** 额外加入截止时间、积压、上下文和价格检查。资源价格更新：
  λ_{k,t+1} = max(0, λ_{k,t} + η_k(u_{k,t}/C_{k,t} − 1))
- 净价值公式：
  g_t(p) = s_h(p) − λ_b,t·(c_wire(p)/C_b) − λ_ℓ,t·(c_link,t(p)/C_ℓ) − λ_q,t·(c_ctx(p)/C_q)
- 无论何种模式，都必须保留完整的序列化批次记账（即每次候选后重新精确计算字节数，而非简单加总负载字符），以捕捉数据包封装的共享开销。

**两种打分策略：**

- scausal(p) = bΔ(p)：纯预测 RCE；
- shybrid(p) = λ₁·Norm_x(bΔ(p)) + λ₂·q_sem(p)：RCE 与语义先验的加权（默认 λ₁=0.75，λ₂=0.25）。

### 7. 优点

- **细粒度语义数据包化：** 将消息分解为 Claim/Evidence/Uncertainty/Request 类型化数据包，在"整条消息"与"任意 token 截断"之间提供了恰当粒度，既保留语义完整性和可追溯性，又实现更精细的准入决策；
- **因果启发的价值信号：** 充分性+必要性双重对比互补了彼此的缺陷（必要性在可替换数据包下失效，充分性低估组合价值），RCE 为调度提供了消息长度和语义相似度无法提供的任务价值信号；
- **严格的离线/在线边界（no-outcome-leakage）：** 预测器仅使用预设的预输出特征，在线决策不接触金标签或最终测试 RCE，具备可审计的部署边界；
- **精确的资源记账：** 使用紧凑序列化批次的精确字节计数（而非负载字符加总），捕捉了数据包封装开销、共享批次字段和转义效果，比简单相加更真实；
- **静态/自适应双模式：** 自适应模式通过已完成服务观测更新资源价格，清晰刻画了"饱和前静态排序已足够、饱和后价格调整降低尾部延迟"的可控延迟-效用权衡；
- **统计严谨性：** 任务聚类推断、配对符号翻转检验、Holm 校正，以及将任务而非数据包作为推断单元；
- **可迁移性验证：** 跨两个模型世代（Qwen3-4B、Qwen2.5-7B）和三个不同通信结构的数据集验证；
- **效用-成本分离报告：** 任务指标与证据指标分开报告，避免训练目标掩盖"牺牲支持证据换取任务正确"的假象。

### 8. 不足与局限

- **RCE 的因果范围有限：** RCE 仅在冻结消息、固定接收端效用和两个声明上下文中定义；不识别无约束的自适应智能体效应（如消息内容随调度改变而产生的连锁反应），也忽略高阶数据包交互；
- **三个种子统计效力有限：** 对某些交叉策略差异（如 FanOutQA 上 causal 与 hybrid 的区别）不足以做出强声明；作者也将部分比较限定为"描述性排序"；
- **基线复现偏差风险：** AgentPrune 和 SafeSieve 是协议匹配的复现（适配到统一数据包协议），而非原生代码的直接执行，可能与原实现存在行为差异；
- **缺少真实网络条件的验证：** 实验在受控无损耗链路上进行；未覆盖传输头、重传、加密、实际网络拥塞等因素；字节节省仅适用于紧凑应用层记录；
- **模型覆盖有限：** 仅两个 Qwen 模型世代；迁移检查不包含 FanOutQA，也未做配对显著性检验；Qwen 之外的模型家族（如 GPT、Llama、Gemini）未验证；
- **离线回放计算成本未被量化：** RCE 画像需要大量受控接收端调用（每数据包至少两次完整回放），论文未报告这部分的总计算开销，可能影响实际部署决策；
- **GPU 测量局限：** 持续 Ollama 分配使内存增量无法提供信息，GPU 遥测仅是工件而非数据包级 KV 证据；接收端延迟是预热后的测量，不代表真实网络延迟；
- **失效模式与安全边界未探索：** 产生无效流量（如 JSON 解析失败的恶意或格式错误输出）的智能体不在范围内，针对无线流量预测的投毒攻击等安全威胁也未讨论；
- **无绝对性能保证：** 论文明确承认"无法保证在所有运行场景中都降低延迟"；在重负载下效用必然受损，部署需选择截止时间或效用目标而非期望无条件改进。
