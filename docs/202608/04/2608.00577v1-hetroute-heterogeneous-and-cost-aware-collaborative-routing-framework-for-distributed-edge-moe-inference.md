## 摘要
混合专家（MoE）模型已成为大规模AI服务的主流架构，但在地理分布式的异构边缘服务器上部署它们仍然具有挑战性。当一个token的Top-k激活专家分布在多台服务器上时，最优路由取决于跨服务器链路带宽、异构GPU计算能力、GPU-CPU专家加载延迟、瞬时队列积压以及副本级量化质量损失。现有的分布式推理和MoE服务方法分别处理这些因素，并未提供用于在线多服务器协同路由的统一框架。本文提出了HetRoute，一种面向分布式边缘MoE推理的异构成本感知协同路由框架。HetRoute引入了一个统一的每分配成本模型，明确捕获四个成本组成部分：跨服务器传输、GPU-CPU卸载、带队列的GPU计算以及量化引起的质量惩罚。在模型指导下，离线阶段通过一个路由成本耦合的部署算法确定专家服务器放置、GPU-CPU驻留和副本精度，而在线阶段则将Top-k激活专家集作为一个整体进行路由，通过精确枚举或束搜索最小化瓶颈层成本。理论分析建立了回退可行性、参与服务器数量的界限、小候选域上的逐层最优性以及在线计算复杂度。在异构10服务器边缘测试平台上对三个MoE模型的轨迹驱动评估表明，与代表性基线相比，HetRoute将平均推理延迟降低高达59.0%，P99延迟降低高达58.0%，削减跨服务器流量高达72.1%，实现2.13倍的吞吐量提升，同时将质量下降保持在配置预算内。

## Abstract
Mixture-of-Experts (MoE) models have become a dominant architecture for large-scale AI services, yet deploying them over geo-distributed heterogeneous edge servers remains challenging. When the Top-k activated experts of a token are spread across multiple servers, the optimal routing depends jointly on cross-server link bandwidth, heterogeneous GPU computing capability, GPU-CPU expert loading delay, instantaneous queueing backlog, and replica-level quantization quality loss. Existing distributed inference and MoE serving methods address these factors separately and do not provide a unified framework for online multi-server collaborative routing. In this paper, we propose HetRoute, a heterogeneous-cost-aware collaborative routing framework for distributed edge MoE inference. HetRoute introduces a unified per-assignment cost model that explicitly captures four cost components: cross-server transmission, GPU-CPU offloading, GPU computation with queueing, and quantization-induced quality penalty. Guided by this model, the offline stage determines expert server placement, GPU-CPU residency, and replica precision through a routing-cost-coupled deployment algorithm, while the online stage routes the Top-k activated expert set as a whole by minimizing the bottleneck layer cost via exact enumeration or beam search. Theoretical analysis establishes fallback feasibility, a bound on the number of participating servers, per-layer optimality for small candidate domains, and online computational complexity. Trace-driven evaluation on three MoE models over a heterogeneous 10-server edge testbed shows that HetRoute reduces average inference latency by up to 59.0% and P99 latency by up to 58.0%, cuts cross-server traffic by up to 72.1%, and achieves 2.13x throughput improvement compared with representative baselines, while keeping quality degradation within the configured budget.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：混合专家（Mixture-of-Experts, MoE）模型已成为大规模AI服务的主流架构。MoE 通过 Top-k 稀疏路由机制，每个 token 仅激活少量专家，这一特性与资源受限的边缘智能场景天然契合，使得在分布式边缘服务器上部署 MoE 模型成为可能。
- **核心问题**：当一个 token 的 Top-k 激活专家分布在多台异构边缘服务器上时，最优协同路由决策联合依赖于以下多个动态因素：
  - 跨服务器链路带宽的异构性；
  - GPU 计算能力的差异性；
  - GPU-CPU 之间的专家加载延迟（本地 CPU 驻留的"冷专家"可能比远端 GPU 驻留的"热专家"更慢）；
  - 瞬时服务器队列积压状态；
  - 副本级量化精度导致的质量损失差异。
- **现有方法不足**：已有分布式推理（如 EdgeShard、Petals）主要面向密集模型按层切分；MoE 服务系统（如 MoE-Infinity、Prism）分别优化专家缓存、放置或卸载，但缺乏统一框架来联合建模上述多因素，未能在在线状态下进行多服务器协同路由。同时，per-expert 贪心选择忽视了多个激活专家之间通过 fan-out/fan-in 产生的耦合。
- **关键洞见**："本地优先"路由假设在分布式边缘 MoE 场景下不再成立——远端 GPU 驻留的热专家可能比本地 CPU 驻留的冷专家执行更快，因此需要一个统一、异构、成本感知的协同路由框架。

## 2. 论文提出的方法论

### 2.1 核心思想
提出 **HetRoute**，一个离线-在线两阶段协同优化的异构成本感知路由框架。核心是建立统一的**每分配（per-assignment）成本模型**，将部署、驻留、精度选择与在线路由决策耦合起来。

### 2.2 统一异构成本模型（公式9）
对目标专家 E 通过副本 E' 在服务器 n 上执行的单分支成本，包含四项并加权衡系数 λ：

\[
C_{i,l}(E, E', n) = \underbrace{\frac{d_{in}}{B_{link}(\theta_{i,l}, n)} \mathbb{1}[n \ne \theta_{i,l}]}_{\text{跨服务器传输}} + \underbrace{\frac{(1-y_{E',n}) \cdot w_{E'}}{\beta_n}}_{\text{GPU-CPU 卸载}} + \underbrace{\frac{w_{E'} + Q_n(t)}{F_n}}_{\text{带队列的 GPU 计算}} + \underbrace{\lambda_q \left( q_{E',n} + Q_{sub}(E, E') \right)}_{\text{量化与替代执行质量惩罚}}
\]

- **传输项**：仅当执行服务器与 token 当前所在服务器不同时产生。
- **卸载项**：仅当副本驻留在 CPU 内存（y=0）时需要加载到 GPU。
- **计算项**：包含 GPU 计算负载与当前队列积压（刻画瞬时拥塞）。
- **质量惩罚**：包含该副本的量化损失和替代执行（substitute execution）带来的质量损失。

### 2.3 层级瓶颈延迟模型（公式10）
由于 k 个激活专家在各自服务器上并行执行，层延迟由最慢分支决定，包括 fan-out 传输、并行计算、fan-in 聚合三个阶段，以 max 操作聚合。

### 2.4 离线阶段：路由成本耦合的部署算法（Algorithm 1）
- **目标**：确定专家放置 X、GPU/CPU 驻留 Y、每副本量化精度 c。
- **Stage 1（GPU 驻留分配）**：基于校准流量模拟在线路由，计算路由概率加权的驻留收益 \(g_{E,n}\)，贪心分配 GPU 内存。
- **Stage 2（冗余复制）**：基于统一成本计算边际复制收益 \(b_{E,n}\)（预期成本降低 − 内存价格），反复插入最高收益副本，直到预算耗尽或收益为负。
- **Stage 3（驻留重优化）**：全局重新优化 GPU 驻留，加入"边际收益递减保护"，防止同一专家的第二份 GPU 副本挤占其他高价值专家。

### 2.5 在线阶段：集合级协同路由（Algorithm 2）
- **精确优先替代策略**：优先使用精确副本，仅当所有精确候选违反质量或稳定性守卫时才激活替代候选集合。
- **两重在线守卫**：硬性质量守卫（累积质量退化 ≤ 预算）和常规稳定性守卫（窗口负载不超过容量）。
- **集合级路由决策**：路由针对的是完整 Top-k 专家集合，而非逐个专家独立决策。通过最小化瓶颈层成本（公式10）完成分配：
  - 候选域小（≤R̄）时用精确枚举；
  - 候选域大时用束搜索（beam search）+ 1-exchange 局部搜索。
- **支配性快速路径**：当所有专家在当前服务器均 GPU 驻留且本地明显最优时，直接本地执行，但这不是无条件"本地优先"。
- **紧急回退机制**：若正常路径无可行解，每个专家被分配到由约束 (c.4) 保证的**全精度精确副本**，质量守卫永不放松，但稳定性守卫可放松，以队列延迟换取可行性与质量安全。
- **自适应成本权重**：通过投影反馈规则（公式21）动态调整各成本分量的权重，惩罚当前系统瓶颈。

### 2.6 理论性质
- **Property 1（回退可行性）**：算法总能终止，且不违反质量预算。
- **Property 2（参与服务器上界）**：每 token-layer 的参与服务器数量 ≤ k。
- **Property 3（小域最优性）**：候选域足够小时精确枚举保证逐层全局最优。
- **Property 5（在线复杂度）**：路由复杂度为 O(LkR̄B)（束搜索）或 O(LR̄^k)（精确枚举），与服务器总数 N 无关。

## 6. 论文的主要结论与发现

- 在 Mixtral-8x7B 上，HetRoute 相比 EdgeShard 将**平均延迟降低 59.0%**（156 ms vs 381 ms），相比 Prism 降低 28.1%。
- **P99 尾延迟降至 286 ms**，相比 EdgeShard 降低 58.0%，相比 Prism 降低 33.2%。
- **跨服务器流量仅为 1.24 GB/千 token**，相比 EdgeShard 减少 72.1%，相比 Prism 减少 24.8%。
- **吞吐量达 1490 token/s**，是 EdgeShard 的 2.13 倍、Prism 的 1.35 倍。
- **CPU 卸载率降至 14%**（MoE-Infinity 为 42%，Prism 为 31%）。
- 执行类型分解显示：46% 本地 GPU 精确执行 + 24% 远程 GPU 精确执行，替代执行仅占 14%，紧急回退仅 2%——说明 HetRoute 主要通过将执行组合转向 GPU 驻留精确副本来降低延迟。
- 质量损失受控：WikiText-103 困惑度从 5.32 增至 5.39，SQuAD F1 从 86.7 降至 86.1，GSM8K 准确率从 56.8% 降至 56.0%，均在预算内。
- Top-k 越大，集合级路由的优势越明显（k=4 时延迟降低 29.8%）；k=1 时与贪心方法几乎一致，验证了方法的理论一致性。
- 冗余部署存在收益饱和点（内存预算比 2.0 后增益急剧减小）。
- 高负载（80 req/s）下，HetRoute 的 SLA 满足率仍达 73%，显著优于 Prism（51%）和 EdgeShard（21%）。

## 7. 优点

- **统一成本模型的创新性**：首次将跨服务器传输、GPU-CPU 卸载、带队列的 GPU 计算、量化质量损失纳入同一数学框架，突破了"本地优先"的传统假设，能准确捕捉"远端 GPU 热专家优于本地 CPU 冷专家"的关键场景。
- **集合级路由而非逐专家贪心**：将 Top-k 专家作为整体优化瓶颈层成本，显式建模 fan-out/fan-in 耦合，避免局部最优而全局劣质的组合；理论上证明了贪心是集合路由的特例（当无分支交互时），体现了方法的普适性。
- **离线-在线协同设计的闭环**：离线部署的每一项收益度量均以在线统一成本的期望形式定义（路由概率加权驻留、统一成本驱动复制），消除了传统两阶段方法"离线与在线脱节"的问题。
- **严格的质量安全保障**：通过全精度精确副本不变式（c.4），保证紧急回退永远零质量损失，以延迟换取可行性而非以质量换取可行性；质量守卫在任何情况下不放松。
- **理论分析扎实**：覆盖可行性、结构性质（参与服务器上界）、最优性范围、复杂度四个方面，且复杂度与服务器总数无关，可扩展性强。
- **实验设计全面**：多模型、多数据集、多基线、多维度消融，结论呈现的方式也比较完整（延迟分布、行为分解、预算敏感性、负载鲁棒性均有覆盖）。

## 8. 不足与局限

- **未披露完整算力/硬件明细**：论文未给出具体 GPU 型号与数量、实验运行时长等信息，虽然 10 台验证平台有一定规模的保证，但对于工程复现仍有信息缺口。
- **测试规模有限**：仅 10 台边缘服务器；真实边缘系统可能包含数十至数百节点，更大规模下的路由效率与可扩展性（特别是 beam search 在大域中的表现）尚未验证。
- **网络拓扑单一**：实验使用普通互联网链路但未考虑具体的真实拓扑结构（如多跳中继可达性）；现实中部分服务器对之间也许没有直接链路，论文未讨论多跳路由场景。
- **质量评估范围相对有限**：困惑度、F1 和准确率对量化/替代的质量退化敏感性有限，未涉及生成类任务（如对话、翻译）的主观质量或指令跟随能力评测。
- **未报告统计显著性**：未提供多次独立运行的标准差/置信区间，难以判断实验中核心指标差异的统计可靠性。
- **模型覆盖有限**：三个模型中最大为 Mixtral-8x7B，未覆盖当前更大规模的 MoE 模型（如数百 B 参数级），也未考虑 MoE 与 attention 等密集组件的交互效应对路由的影响。
- **离线校准依赖静态流量假设**：论文在结论中承认未处理时变专家激活分布；若用户请求分布发生概念漂移，离线优化得到的部署可能过时。
- **未考虑多租户/多模型共存**：实际边缘系统可能同时服务多个 MoE 模型，资源竞争与部署耦合在论文中未涉及；P0 问题中也未讨论 SLA 差异化或多优先级流量。
