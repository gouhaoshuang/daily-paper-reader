## 摘要
在移动机器人上部署数十亿参数的视觉-语言-动作（VLA）策略会产生系统冲突：语义推理受益于云GPU，而闭环控制必须在存在网络延迟和抖动的情况下进行本地响应。现有的层次化和异步策略提高了吞吐量，但其慢路径表示仍可能过期到达，或需要显式的调度和延迟提示。我们提出了CloudEdgeVLA，一种将时间错位视为表示学习问题的云-边策略。云VLA将延迟的观测编码为缓慢变化的任务特征，而轻量级边缘头将最新的可用云特征与当前本地视觉相结合。在训练期间，当前帧和随机延迟帧在新鲜路径和陈旧路径中与相同的当前动作目标配对。该目标鼓励云表示保留任务级信息，同时边缘路径提供状态敏感的修正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口下保持63.8%至78.0%的成功率，而VLASH最多达到6.4%，所评估的单路径基线最多为3.0%。通过在控制回路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，在这种部署中，云模型可以不断增长，而边缘计算保持轻量和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心冲突**：将数十亿参数的视觉-语言-动作（VLA）模型部署到移动机器人上存在系统性矛盾——云端的 GPU 擅长语义推理（理解任务）、边缘端则需要低延迟的闭环控制（执行动作），但网络延迟和抖动使二者难以协调。
- **现有方案不足**：已有分层/异步策略（如 MResT、DP-VLA、HiRT、SmolVLA、VLASH 等）虽通过快慢系统分离提升吞吐量，但慢路径（云端）返回的表示可能已经过期，且常依赖显式调度、定时/频率对齐或延迟提示才能工作；动作分块（action chunking）方法在开环执行期间假设环境静止，进一步累积陈旧性误差。
- **核心命题**：CloudEdgeVLA 将**时间错位（temporal misalignment）**视为一个表示学习问题：云端负责编码"做什么"（缓慢变化的、不依赖精确时刻的任务特征），边缘端利用当前实时视觉负责"现在怎么做"（状态敏感的控制修正），从而**无需阻塞同步或显式延迟信息**即可容忍网络延迟。论文借此论证：延迟容忍可以是一种**可学习得到的接口属性**，而不仅仅是一个推理调度问题。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 总体架构（三组件，时间角色不对称）

1. **云侧 VLA 骨干（fθ，System 2，延迟不敏感）**
   - 参数量大（基于 7B OpenVLA），用 LoRA 适配，完全运行在云端。
   - 输入：观测 o 与语言指令 ℓ → 输出规划表示 h = fθ(o, ℓ) ∈ R^(L×D)。
   - 设计目标：特征编码任务目标、操作策略、物体语义，而非精准的"何时执行"。

2. **边缘视觉编码器（vψ，System 1 感知，延迟敏感）**
   - 轻量级视觉编码器（默认 SigLIP-Base），在机器人本地实时运行。
   - 输入：当前观测 o_t → 输出实时视觉特征 z_t = vψ(o_t)。
   - 训练时**冻结**，利用预训练视觉表示。延迟为零，捕捉环境的瞬时状态。

3. **边缘动作头（gϕ，System 1 控制，延迟敏感）**
   - 融合可能过期的云特征 h_{t−k} 与当前边缘视觉特征 z_t，预测动作 τ̂_t = gϕ(h_{t−k}, z_t) ∈ R^(T×A)。
   - 实现：对规划特征按动作维度做均值池化 → 将视觉特征投影到同一隐空间 → 拼接 → 通过残差 MLP 输出动作块。
   - 作用：充当"实时接地层"，将云端的过时高级指令转化为精确的即时动作命令。

### 2.2 配对帧双路径训练（Paired-Frame Dual-Path Training）

- **配对帧提取**：从同一回合中取 W 个连续观测窗口，构造：
  - 当前帧：o_t
  - 延迟帧：o_{t−d}，其中 d ~ Uniform(1, W−1)
- **双前向传播**：两帧都经过云端骨干，分别得到 h_fresh 和 h_stale；两者都不做梯度切断。
- **同一个当前动作目标**：两个特征均与同一实时视觉特征 z_t（来自当前帧 o_t）融合，预测的两个动作均被监督到同一真实动作 a_t。
- **双路径损失**：
  - L = (1−λ)‖â_fresh − a_t‖₁ + λ‖â_stale − a_t‖₁
  - 使用**课程学习**：训练初期 λ=0，随 warmup 步数逐渐增至 λ_max，使骨干先学到强表示，再被"压力"推向延迟不变性。

### 2.3 部署协议（完全异步、非阻塞）

- 边缘每步捕获观测 o_t 并异步发送到云。
- 云端返回时，**无条件更新** h_received（无论其年龄）。
- 边缘立刻用 h_received + z_t（当前本地视觉）计算动作并执行。
- 机器人**从不等待**特定云响应；始终使用最新已到达的云端特征与当前边缘视觉。

### 2.4 涌现表示特化（Emergent Representational Specialization）

- 随机延迟 d 使仅依赖瞬时状态的云特征对预测 a_t 不可靠，而任务身份、目标和粗略进度相对稳定。
- 该目标**鼓励（但不保证）**表示对时间位移的不变性（关联 Achille & Soatto 关于不变性与解耦表示的框架）。
- 同时保留边缘实时特征 z_t 编码状态敏感信息——形成两侧互补的鲁棒性。

## 6. 主要结论与发现

- **主结果（仿真）**：在 d_max=40 均匀延迟下，CloudEdgeVLA 在四个 LIBERO 套件保持 76.4 / 75.6 / 78.0 / 63.8% 成功率（Spatial / Object / Goal / Long），而 VLASH 最高仅 6.4%，单路径基线最高仅 3.0%。
- **延迟-保留汇总指标**：CloudEdgeVLA 的归一化延迟 AUC 为 90.8%（VLASH 为 32.4%）；在 d_max=40 保留同步成功率的 76.5%（VLASH 仅 1.8%）。该结果表明"中等延迟有少量收益 ≠ 对长期陈旧性有容忍度"。
- **机制归属（离线诊断）**：
  - 在第 d=20 步时，骨干漂移 Dₕ 从 0.391 降至 0.160（降低 59.2%）；
  - 陈旧传递增益 κ 从 1.082 降至 0.295（降低 72.7%）；
  - 动作漂移降低 88.9%，演示 MAE 降低 88.5%（从 0.421→0.048），且**不是**通过"输出不敏感"的退化方式实现（MAE 与漂移同步下降）。
  - **反事实审计的关键发现**：该 120k 检查点的鲁棒性主要来自**更稳定的骨干 + 动作头对残余漂移的衰减**，而非当前边缘视觉直接、大幅地修正陈旧云特征（边缘救援率仅 0.03%，修正方向与真实需要的修正余弦对齐度仅 0.030）。这约束了机制主张的表述边界。
- **真实机器人**：500ms 级 RTT 下 CE-VLA 保持 80/70%（静态/动态）成功率，VLASH 降至 0/0%。
- **总论点**：延迟容忍可通过配对帧训练成为云-边接口的**可学习属性**，而非仅靠推理调度。

## 7. 优点

- **问题定义的转化**：将工程性的调度/同步问题转化为表示学习问题，概念上新颖且清晰。
- **接口简洁、部署友好**：边缘永不阻塞，无需时钟对齐、频率比率或延迟元数据，天然适配真实网络环境中的可变延迟。
- **训练方法轻巧有效**：配对帧双路径损失 + 课程学习（λ 渐变）无显式不变性约束，但能引导表示涌现延迟不敏感特性。
- **机制分析严谨**：不止报告任务成功率，还用 Dₕ、κ、逐任务 MAE、动作块（7 维×8 步）热图、二维反事实年龄面等从多个角度定位鲁棒性来源；特别诚实地报告了"边缘视觉直接修复贡献极小"这一反直觉结论。
- **消融设计清晰**：解耦了"有无实时视觉"、"编码器规模"和"两个损失路径各自贡献"，关键结论明确（实时视觉接地为主，延迟暴露训练次之，两者联合最优）。
- **小规模真实机器人验证**：虽然是可行性检查，但涵盖静态/动态场景和不同 RTT 等级，增强了仿真结果的可信度。
- **写作品质**：对局限性的讨论明确而具体，包括分布外延迟、双骨干前向开销、冻结 RGB 编码器可能缺失模态信号等。

## 8. 不足与局限

- **延迟覆盖范围有限**：仅测试 d_max ≤ 40 步的均匀分布；论文明确声明不支持无界延迟或云断连场景，需时间戳特征和本地回退策略（但未实现）。
- **训练开销**：配对帧训练需两次骨干前向传播，成本高于单路径训练；训练资源和耗时未报告。
- **缺失模态**：冻结的 RGB 编码器可能缺少深度、力/触觉等对精细操作重要的信号；未评估多模态扩展。
- **机制主张需谨慎**：反事实诊断表明该检查点中边缘视觉**并未**如架构直觉所期望那样直接修正陈旧云特征——若机制目标是通过"边缘修正"实现鲁棒性，则当前 120k 检查点尚未达成该机制层面的预期，虽然端到端效果依然出色。
- **真实硬件实验的局限性**：仅一个平台（Franka）、单任务类型（拾放）、10 次/条件，且是工作站级边缘设备——与嵌入式/低功耗移动机器人的差距较大。
- **基线对比不对称**：基线报告为点估计，无方差；VLASH 在真实机器人测试中的底层实现细节未说明（存在不公平比较的潜在风险）。
- **离线诊断统计有限**：每任务仅 1 条示范、8 个时刻；且因架构和训练目标不同，比较刻画的是整个系统差异，而非单一因素。
- **未涉及**：真实网络（如 5G/WiFi）非稳态延迟分布、云断连处理、多机器人共享云端资源等实际部署问题。
