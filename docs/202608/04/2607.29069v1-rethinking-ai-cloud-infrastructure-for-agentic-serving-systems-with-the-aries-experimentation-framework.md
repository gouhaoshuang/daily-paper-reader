## 摘要
自主智能体通过将重复推理与持久上下文和沙箱工具执行相结合，对传统LLM服务提出了挑战。我们提出了Aries，一个全栈实验框架，它将任务语义与执行配置分离，重建跨组件智能体轨迹并关联系统遥测，并通过统一接口在不同异构沙箱子系统上暴露有状态工具执行。我们使用Aries在开放智能体框架和基准测试上进行可复现的实验。我们通过来自商业平台的生产轨迹补充这些实验，将底层系统研究建立在观察到的生产行为之上。我们的结果表明：(1) 以token为中心的指标忽略了非推理瓶颈；(2) 保留额外上下文带来的准确率提升递减，同时降低服务容量；(3) 工具沙箱在长时间空闲和短时资源突发之间交替，而当前基于快照的状态管理使得激进挂起成本高昂。进一步的安全分析还强调需要减少沙箱攻击面。随后，我们讨论了面向智能体原生服务系统的愿景，该系统围绕轨迹级指标、自适应上下文管理、弹性沙箱资源管理以及攻击面最小化的沙箱进行设计。

## Abstract
Autonomous agents challenge conventional LLM serving by coupling repeated inference with persistent context and sandboxed tool execution. We present Aries, a full-stack experimentation framework that separates task semantics from execution configurations, reconstructs cross-component agent trajectories with correlated system telemetry, and exposes stateful tool execution through a consistent interface across heterogeneous sandbox substrates. We use Aries to conduct reproducible experiments on open agent harnesses and benchmarks. We complement these experiments with production traces from a commercial platform, grounding low-level systems research in observed production behavior. Our results show that (1) token-centric metrics miss non-inference bottlenecks, (2) retaining additional context yields diminishing accuracy benefits while reducing serving capacity, and (3) tool sandboxes alternate between long idle periods and short resource bursts, while current snapshot-based state management makes aggressive suspension costly. A complementary security analysis further highlights the need to reduce the sandbox attack surface. We then discuss the vision for agent-native serving systems designed around trajectory-level metrics, adaptive context management, elastic sandbox resource management, and sandboxes with minimized attack surface.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：大语言模型（LLM）正从单纯的提示响应器演变为自主智能体（Agent），如 OpenClaw、Hermes 等开源智能体在数月内获得超过五十万 GitHub Star，Claude、Codex 等商业智能体被数百万人使用。智能体将模型置于反馈循环中：观察状态→选择动作→执行工具→利用结果继续任务，形成一个端到端的「智能体轨迹」（Agent Trajectory）。
- **核心问题**：传统 LLM 服务系统围绕单个模型请求（request-centric）进行优化，其调度、内存管理和指标（TTFT、TPOT、token 吞吐量）均以单次请求为粒度。但智能体服务不再以生成 token 为终点，每次模型响应只是执行循环中的一步，端到端进展还取决于持久上下文、工具执行和沙箱管理。现有评估体系存在「测量鸿沟」：能力评估基准（如 SWE-Bench）将执行路径视为黑盒，系统基准（如 MLPerf）以孤立请求或事务为单位，两者都无法将任务进度与跨层运行时行为关联起来。
- **研究意义**：论文提出，智能体服务需要全栈（full-stack）系统设计，从模型调用粒度提升到轨迹粒度，重新思考云 AI 基础设施的度量方式、上下文管理、沙箱弹性与安全架构。

## 2. 论文提出的方法论：核心思想、关键技术细节

**核心思想**：以「智能体轨迹」为第一公民（first-class citizen）的观测单元，构建 Aries 全栈实验框架，弥合语义任务结果与跨层系统行为之间的测量鸿沟。

**Aries 框架的三大关键设计**：

1. **分离任务语义与执行配置**：任务规范（task specification）捕获工作负载及其成功语义；执行规范（execution specification）选择 harness、模型后端、沙箱和遥测栈。专用加载器分别验证两类规范，LLM 后端适配器和沙箱适配器将规范绑定到具体执行栈，无需任务级改动。这使得跨配置的受控比较成为可能。

2. **重建跨组件轨迹**：Aries 在模型和工具边界传播轨迹标识符与事件标识符，在统一事件模式下记录因果和排序元数据。遥测收集器将组件指标与这些事件关联，从多个独立管理的组件中重建完整轨迹，揭示延迟和资源压力在轨迹中的位置。

3. **标准化有状态工具执行**：工具调用在持久环境中运行，状态会影响后续步骤；不同沙箱基板暴露不同的生命周期和遥测接口。Aries 标准化环境设置、工具调用、状态连续性、结果收集和遥测钩子，借助沙箱适配器映射到具体基板，使工具执行成为轨迹中可观测的一等阶段。

## 6. 论文的主要结论与发现

- **发现 1：Harness 和工具执行的重要性不亚于模型推理**。工具执行占总延迟的 13%~48%（Hermes Agent × Terminal-Bench 2 达到 48%），Harness 编排占高达 9%；工具调用存在横跨多个数量级的严重长尾延迟。单纯优化 token 生成不能解决 agent 瓶颈。
- **发现 2：上下文保留存在「准确率-容量」权衡**。生产轨迹中 agent 上下文比传统对话请求大得多，导致同一 25GB KV 预算下驻留请求从 176 降至 40（4.4× 缩减）。受控实验表明：任务成功率随上下文增大先升后平台（如 DeepResearch 在 160K 达 95%），超过阈值后无额外收益；大型上下文使 KV 池利用率峰值达 97%，p95 排队延迟达 7.9 秒。
- **发现 3：工具沙箱「大部分空闲但有突发」**。CPU 和内存超过 80%/50% 时间处于空闲，但工具调用期间资源利用率急剧上升。当前基于快照的 scale-to-zero 机制使总成本高达持久沙箱的 4.9×；理想系统可降低 3× 成本。
- **发现 4：工具沙箱面临持续攻击威胁**。AI 工具发现的 Linux 内核漏洞占比在 2026 年 Q2 急剧上升，自主 exploit 开发成本已降至数美元，需设计最小攻击面的沙箱。
