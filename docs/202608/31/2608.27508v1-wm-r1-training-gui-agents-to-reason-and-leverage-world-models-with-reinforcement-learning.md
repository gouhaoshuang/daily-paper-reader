## 摘要
基于强化学习（RL）训练的GUI智能体在移动平台上展现出了强大的环境学习能力。然而，强化学习通常需要大量的真实环境交互，导致高昂的资源成本和训练不稳定性，尤其是在GUI场景中。为解决这些问题，我们提出了WM-R1，这是首个利用世界模型而非真实环境来训练移动GUI智能体的强化学习框架。具体而言，世界模型在所有轨迹生成过程中充当状态转移的来源，在训练循环中取代了真实的Android环境。WM-R1还将世界模型直接嵌入到推理过程中，使智能体在确定最终动作之前，能够推理候选动作的后果。关键在于，WM-R1无需真实环境交互，支持基于世界模型的、大规模并行且步骤级细粒度的轨迹生成，并引入了一种多维度的基于规则的奖励机制，共同优化任务成功率、轨迹效率以及世界模型的利用率。为高效训练，我们精心构建了一个包含2000个具有挑战性任务的高质量数据集。在Android移动端基准测试上的实验表明，经WM-R1训练的智能体显著优于仅使用GRPO的基线方法以及推理时模拟方法。代码可在 https://github.com/genalyu/WM-R1 获取。

## Abstract
GUI agents trained with reinforcement learning (RL) have showcased strong environment learning capabilities on mobile platforms. However, RL typically demands extensive real-environment interactions, leading to high resource costs and instability, especially in GUI scenarios. To address these, we propose WM-R1, the first reinforcement learning framework that trains mobile GUI agents with world models instead of real environments. Specifically, world models serve as the source of state transitions during all rollouts, replacing the real Android environment within the training loop. WM-R1 also embeds world models directly into the thinking process, enabling agents to reason about the consequences of candidate actions before committing to the final action. Crucially, WM-R1 eliminates the need for real-environment interaction, supports massively parallelized and step-level granularized trajectory generation grounded in world models, and introduces a multi-dimensional rule-based reward that jointly optimizes task success, trajectory efficiency, and world model utilization. For efficient training, we curate a high-quality dataset of 2000 challenging tasks. Experiments on Android mobile benchmarks demonstrate that WM-R1-trained agents significantly outperform GRPO-only baselines and inference-time simulation methods. Code is available at https://github.com/genalyu/WM-R1 .

- **整体含义**：作者提出WM-R1，**首次将世界模型作为RL训练的环境本身**，在完全模拟的环境中训练GUI智能体，兼具“大规模并行化”“步骤级细粒度”“零真实环境依赖”等优势，为移动GUI智能体的高效训练提供新范式。

### 二、论文提出的方法论

#### 核心思想
- 用**世界模型W**（Code2World-8B，冻结）替代真实Android环境，作为所有状态转移的来源：
  \[
  \hat{\phi}_{t+1} \sim W(\cdot | \hat{\phi}_t, a_t)
  \]
- 将世界模型嵌入智能体的**思维链（CoT）**中，通过 `<call_wm>` 机制让智能体在执行最终动作前，预览候选动作的后果并据此修正决策，即“先思考再行动”。

#### 关键技术细节
1. **推理与模拟的深度融合**：
   - 智能体在思考过程中调用 `<call_wm>(action)`，世界模型返回模拟截图作为System (WM)观察，智能体在同一thinking块内继续推理；
   - 系统提示词要求输出 `thinking` 与 `answer` 标签，并明确允许使用 `<call_wm>`。

2. **轨迹生成流程**：
   - 循环执行“观察 → 思考（可选调用世界模型模拟）→ 模拟并继续 → 动作输出”，直至终止或达到最大长度 \( T_{max} \)；
   - 整个轨迹 \(\tau_{i,j}\) 完全由模拟状态构成。

3. **多维规则奖励设计**：
   \[
   R = \alpha \cdot R_{success} + \beta \cdot R_L + \gamma \cdot R_{WM}
   \]
   - **\( R_{success} \)**：LLM-as-a-judge（GPT-4o）依据参考轨迹判断任务是否成功（0/1）；
   - **\( R_L \)**：长度奖励，基于参考轨迹长度与最大长度混合的DAST预算，鼓励高效轨迹；
   - **\( R_{WM} \)**：世界模型调用数量奖励，相对组均值归一化，过用/少用均惩罚；
   - 权重 \(\alpha=1.0, \beta=0.5, \gamma=0.1\)。

4. **训练框架**：
   - 沿用GRPO（组相对策略优化）计算优势并更新策略；
   - 训练数据为2000个中等难度任务（筛掉零样本成功率>80%或<5%的样本）。

#### 算法流程（文字说明）
- 使用策略模型 \(\pi_\theta\) 与世界模型W迭代交互，为每个任务生成G条轨迹；
- 对所有轨迹计算复合奖励 → 按GRPO公式计算组相对优势 → 更新策略参数；
- 完整伪代码见Algorithm 1（附录）。

### 六、论文的主要结论与发现

1. **WM-R1显著优于现有基线**：
   - WM-R1-7B在AndroidWorld上达39.8%，比UI-R1-7B（30.8%）高9.0点，比UI-TARS 1.5-7B（34.2%）高5.6点；

2. **世界模型模拟训练优于推理时模拟**：
   - 在AndroidWorld上，3B规模比Qwen2.5-VL+CW提升约8.9点，7B规模提升约11.1点。

3. **OOD泛化能力更强**：

4. **策略熵与探索**：
   - WM-R1在训练过程中保持更高熵（3.2 vs 2.6），表明无噪环境支持持续探索，避免过早收敛。

5. **世界模型利用呈现三阶段演进**：

### 七、优点

1. **范式创新**：首次将世界模型作为RL训练的“环境本体”，完全替代真实环境，打破现有方法的资源瓶颈；
2. **推理与模拟深度融合**：`<call_wm>` 机制使世界模型成为思维链的内部工具，实现“先模拟、后行动”，这是一种可学习、可迁移的推理策略而非记忆映射；
3. **奖励设计细致**：复合奖励（成功+效率+WM使用均衡）三个维度各司其职，消融研究验证了其互补性；
4. **可大规模并行**：全模拟轨迹生成支持步骤级细粒度并行，在单张H200上即可完成训练（11.2小时），计算成本透明合理；
5. **实验体系完整**：从主实验、消融、动态分析、敏感性、泛化到成本对比，多方面论证有效性和鲁棒性；
6. **评估严谨**：对LLM评估器做了人类标注校准和程序化验证，统一评估配置，尽力避免评估偏差。

### 八、不足与局限

1. **严重依赖世界模型保真度**：
   - 训练信号完全来自Code2World的模拟状态转移；对动态UI元素（动画、实时数据、第三方组件）保真度不足时，可能误导智能体学到次优甚至错误的策略。

2. **仅支持离散动作空间**：
   - 当前框架适用于点击坐标、文本输入、滚动方向等离散动作；扩展到自由拖动、连续光标移动等连续控制需要修改世界模型和奖励设计。

3. **评估主观性残留**：
   - 任务成功依赖LLM-judge判断（尽管经校准），在部分语义边界模糊的任务上仍存在偏差风险；
   - 与程序化判定在AndroidWorld上的一致率为97.0%而非完美，说明仍有部分错误判定。

4. **数据筛选引入分布偏差**：
   - 2000个训练任务均经过难度筛选（排除过易/过难），可能使训练分布偏向“中等复杂度”任务，对极端场景的覆盖不足；
   - 三个数据源（AndroidCode、GUI-Odyssey、GUI-R1）相对于评估基准可能存在非对称重叠。

5. **缺少真实环境部署验证**：
   - 所有表现均基于模拟环境或离线评估；从模拟训练到真实Android环境中执行是否存在“sim-to-real gap”尚未直接验证。

6. **对比基线有限性**：
   - 主实验未包含更多在线环境RL方法（如仅将MobileGUI-RL置于7B表，3B未对比其3B版本）；
   - 长程任务Hard子集的数量与具体任务构成未做详细说明（例如Hard到底多少任务，随机性是否影响结论）。

7. **代码/数据公开细节有限**：
   - 论文声称开源代码和数据，但具体数据构建脚本、评估prompt模板等细节需在仓库中进一步确认。
