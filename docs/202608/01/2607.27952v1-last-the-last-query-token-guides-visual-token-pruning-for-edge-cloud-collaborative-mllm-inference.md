## 摘要
多模态基础模型正在将边缘-云视觉智能从任务特定的特征流水线重塑为基于令牌的接口，其中边缘设备将视觉输入编码为令牌，供通用云多模态大语言模型使用。然而，密集的视觉令牌序列增加了云侧推理成本。现有的剪枝方法主要针对集中式推理：视觉驱动的方法可以在云执行之前运行，但通常与查询无关，而查询引导的方法通常依赖于目标多模态大语言模型的内部状态，无法在传输前确定令牌相关性。紧凑的引导模型提供了一种替代方案，但现有设计可能需要昂贵的注意力聚合或辅助生成。我们提出了LAST，一个无需训练、用于边缘-云协同多模态大语言模型推理中查询相关视觉令牌剪枝的框架。LAST使用紧凑的边缘侧视觉语言模型作为引导代理，并从最后查询令牌对视觉令牌的注意力中导出轻量级重要性信号。在因果注意力下，最后查询令牌可以关注完整的视觉序列和整个查询上下文，从而实现了无需云模型访问、自回归生成或多个查询位置上的昂贵聚合的查询感知剪枝。然后，LAST在固定的令牌预算下保留一组多样化的查询相关视觉令牌。我们在11个多模态基准上，在多种令牌预算下，针对具有不同引导策略的剪枝方法评估了LAST。实验表明，LAST始终取得最强性能，在仅保留12.5%视觉令牌的情况下，保留了全令牌准确率的95.4%，并且边缘侧选择开销低，云侧计算量减少。

## Abstract
Multimodal foundation models are reshaping edge-cloud visual intelligence from task-specific feature pipelines into token-based interfaces, where edge devices encode visual inputs into tokens for a general-purpose cloud MLLM. However, dense visual-token sequences increase cloud-side inference costs. Existing pruning methods mainly target centralized inference: vision-driven methods can operate before cloud execution but are typically query-agnostic, whereas query-guided methods often rely on internal states of the target MLLM and cannot determine token relevance before transmission. Compact guidance models offer an alternative, but existing designs may require costly attention aggregation or auxiliary generation. We propose LAST, a training-free framework for query-dependent visual token pruning in edge-cloud collaborative MLLM inference. LAST uses a compact edge-side VLM as a guidance proxy and derives a lightweight importance signal from the last query token's attention to visual tokens. Under causal attention, the last query token can attend to the full visual sequence and the entire query context, enabling query-aware pruning without cloud-model access, autoregressive generation, or costly aggregation over multiple query positions. LAST then retains a diverse set of query-relevant visual tokens under a fixed token budget. We evaluate LAST on 11 multimodal benchmarks under multiple token budgets against pruning methods with different guidance strategies. Experiments show that LAST consistently achieves the strongest performance, preserving 95.4% of the full-token accuracy while retaining only 12.5% of the visual tokens, with low edge-side selection overhead and reduced cloud-side computation.

**研究背景：**
- 边缘-云视觉智能正从“任务特定的特征流水线”范式，演化为“基于令牌（Token）的通用接口”范式：边缘设备将视觉输入编码为视觉token，传输给云端的通用多模态大语言模型（MLLM）进行推理。
- 这种范式带来新的效率瓶颈：视觉编码器通常保留密集的、逐 patch 的表示，其中大量token在视觉上冗余，或与当前查询（query）弱相关；密集的视觉token序列会显著增加云侧的计算与通信成本。

**核心问题：**
- 在边缘-云协同推理场景中，边缘设备必须在**云模型观察完整序列之前**决定保留哪些视觉证据——这与传统集中式推理中的token剪枝有本质区别。
- 现有方法存在以下不足：
  - **视觉驱动方法**（如VisionZip、VisPruner）：可在云执行前运行，但**与查询无关**，可能丢弃视觉上不显眼但回答关键的区域。
  - **查询引导方法**（如FastV、SparseVLM）：依赖目标MLLM的内部状态，**无法在传输前获取相关信号**。
  - **紧凑引导模型方法**（如SGP、IF-Prune）：现有设计可能需要对多个查询位置做注意力聚合、自回归生成或重复视觉编码，引入额外边缘计算开销。

**研究意义：** 论文提出一种**无需训练、无需访问云模型内部状态、无需自回归生成**的查询感知视觉token预传输剪枝框架，在显著降低通信与云侧计算成本的同时，保持较强的下游任务性能。

## 2. 论文提出的方法论

**核心思想：** 利用边缘端紧凑VLM（作为引导代理）的**最后一个查询token**对视觉token的注意力，作为查询条件化视觉重要性信号，在固定token预算下保留“既相关又多样化”的视觉token子集。

**关键技术细节与公式：**

1. **边缘-云Token接口设计：**
   - 边缘和云模型共享同一个视觉编码器参数 E，但使用各自的 token 级连接器（ϕe 和 ϕc）。
   - 图像 I 经共享编码器得到 N 个视觉token：X = E(I) = [x₁, ..., xₙ]。
   - 边缘选中的token子集 X_S 可直接被云连接器消费，无需特征对齐或重新编码图像。

2. **最后查询Token注意力评分（Last-Query-Token Attention Scoring）：**
   - 边缘VLM执行一次**无需解码的 prefill 前向传播**。
   - 关键观察：在**因果注意力掩码**下，最后一个查询token可以 attend 到完整的视觉前缀和全部前面的查询文本上下文。
   - 将最后一个查询位置在**所有层、所有注意力头**上对每个视觉token的注意力权重求和：
     - sᵢ = Σ_ℓ Σ_h A^(ℓ,h)[p⋆, pᵢ]
   - 再对视觉序列做归一化得到重要性分布 w̃。
   - 相比对 M 个查询位置做聚合（复杂度 O(LHM N)），仅用一个位置只需 O(LH N) 的聚合开销。

3. **预传输Token选择（重要性加权 k-center 选择）：**
   - 直接保留 Top-K 最高分token可能导致预算集中在视觉相似区域。论文提出**重要性加权贪心 k-center 选择**：
     - 将特征归一化后，先选最重要token作为起点。
     - 每轮迭代中，未选token的覆盖距离定义为与已选集的最小距离：δᵢ = minⱼ(1 − x̄ᵢᵀx̄ⱼ)。
     - 每轮选择最大化 **query相关性与覆盖增益的乘积** 的token：jₜ = argmax w̃ᵢ · δᵢ。
   - 该乘法目标同时抑制“与查询不相关”和“与已选token冗余”的token。
   - 计算复杂度为 O(K N d_v)，避免构造 N×N 距离矩阵。
   - 动态平铺输入时，所有局部tile和缩略图的token在同一全局预算下竞争；文本token永不剪枝。
