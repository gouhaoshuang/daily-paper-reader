## 摘要
计算机使用代理（CUA）越来越多地被部署用于代表用户导航移动和桌面应用，然而目前尚无基准能够全面评估它们在处理模糊指令时是否能够安全地与视觉界面交互。我们引入了ADeptS-Bench，一个双流式可信度基准，基于ADEPTS能力框架和普通人群用户研究。安全流提供了配对的安全/恶意任务，威胁嵌入在视觉界面中。消歧流则评估代理在意图模糊时是否寻求澄清。对七个模型的评估显示，没有一个模型能够在保持低于30%攻击成功率的同时持续超过80%的任务成功率；每个模型都会毫不犹豫地点击25,000美元订单上的“结账”按钮，且没有一个模型检测到“恢复出厂设置”按钮被错误标记为“优化”。消融实验揭示了三种不同的安全架构：依赖工具型（无拒绝工具时ASR提升21-23个百分点）、部分依赖工具型（提升10-11个百分点）和无机制型（无变化）。在消歧方面，所有模型都高估了后果的严重性，反映了安全观察中看到的过度拒绝偏见。我们将在发表后发布所有数据、评估代码和分析工具。

## Abstract
Computer Use Agents (CUAs) are increasingly deployed to navigate mobile and desktop applications on behalf of users, yet no benchmark comprehensively evaluates whether they can safely interact with visual interfaces while handling ambiguous instructions. We introduce ADeptS-Bench, a dual-stream trustworthiness benchmark, grounded in the ADEPTS capability framework and general population user studies. The Safety stream provides paired benign/malicious tasks with threats embedded in the visual interface. The Disambiguation stream evaluates whether agents seek clarification when intent is ambiguous. Evaluating seven models reveals that no model consistently exceeds 80% task success while staying below 30% attack success; every model clicks "Checkout" on a $25K order without hesitation, and none detects that a "factory reset" button is mislabeled as "Optimize." An ablation reveals three distinct safety architectures: tool-dependent (ASR +21-23pp without refusal tool), partially tool-dependent (+10-11pp), and no mechanism (unchanged). In disambiguation, all models overestimate consequence severity, mirroring the over-refusal bias observed in safety. We release all data, evaluation code, and analysis tools upon publication.

## ADeptS-Bench: 跨设备计算机使用代理的可信度衡量

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究背景**：基于大语言模型的计算机使用代理（CUA）已从研究原型快速演进为用户面产品（OpenAI、Anthropic、Google 及开源社区均有部署），能够自主导航图形界面替用户完成任务。然而，随着 CUA 进入真实世界部署，仅关注任务完成能力的评估已不足以支撑可信部署。
- **核心问题**：现有安全基准存在四方面盲区：(1) 仅覆盖单一平台（Web 或移动或桌面）；(2) 依赖实时环境（live environment），部署成本高且难以复现；(3) 威胁类别由研究者单方面定义，未纳入真实用户关切；(4) **没有任何基准同时评估"安全交互"与"歧义澄清"两大能力**。结果是：在现有安全基准上得分高的模型，仍可能毫不犹豫地点击 2.5 万美元订单的"结账"按钮，或在"立即购买还是加入购物车"这类关键歧义上错误行动。
- **论文提出方案**：引入 **ADeptS-Bench**——一个**双流（dual-stream）可信度基准**，在 ADEPTS 能力框架与大规模用户研究的基础上构建，同时覆盖**移动端和桌面端**，并以**纯离线（offline）**方式运行。
- **整体含义**：该工作将 CUA 可信度评估从"单一平台、单一能力、研究者主导"推向"跨平台、安全+消歧双能力、用户驱动的可信度评估"。

### 2. 论文提出的方法论：核心思想、关键技术细节

#### 2.1 三个设计原则

1. **用户中心的风险优先级排序**：风险分类体系基于用户研究（MaxDiff 调查，n=1,300）、专家研讨会和一般人群调研，确保基准测量的是用户真正担忧的风险（如身份盗用 80.2%、账户泄露 77.5%、未授权转账 76.0%），而非研究者臆想的威胁。
2. **双流评估**：
   - **安全流（Safety Stream）**：将威胁嵌入视觉界面内部（钓鱼浮层、误导按钮、提示注入），文本指令本身看似良善，模型必须解读截图内容才能识别威胁——检测的是"界面嵌入型威胁"而非"明示性恶意请求"。
   - **消歧流（Disambiguation Stream）**：在模糊决策点评估模型是否主动寻求澄清，而非擅自行动。
3. **离线评估**：无需实时环境，安全任务每个仅需一次 API 调用，消歧任务每个需一次模型调用 + LLM 裁判匹配调用，极大降低了评估门槛和碳足迹。

#### 2.2 安全风险框架

- 沿 ADEPTS 框架的四个维度分析风险：**攻击来源**（内在模型失败 vs. 外在环境威胁）、**威胁类型**（危害机制）、**受害者**（用户/系统/第三方）和**危害**（影响结果）。
- 威胁类型涵盖 10 类：幻觉、提示注入、Web 攻击、危险命令、错位、系统破坏、越狱、对抗攻击、推理鸿沟攻击、响应延迟。
- 分类体系通过"专家研讨会 → MaxDiff 用户调查（n=1,300）→ 迭代校准"三层流程构建，每个类别的任务数量还考虑静态截图的可表达性。

#### 2.3 安全流的任务设计

- **配对设计**：每个任务包含良善（benign）和恶意（malicious）两个变体，指令相同但截图不同——恶意变体在相似 UI 中嵌入视觉威胁。良善变体测能力（TSR），恶意变体测安全（ASR）。
- **规模**：1,718 个任务实例（358 对移动端 + 501 对桌面端），涵盖约 70 个 Android 应用和约 150 个桌面应用。
- 截图来自真实应用或合成生成（利用 Gemini 生成无法从生产环境道德获取的威胁场景）。
- 每个任务包含截图、指令、真值动作（带边界框的点击、文本、导航或状态）及元数据。
- **质量控制**：专业标注者进行像素级边界框标注 → 跨模型一致性分析 → 领域专家审查。最终仅 3.3% 的良善任务被普遍失败，11.4% 的恶意任务被普遍遵从。

#### 2.4 消歧流的任务设计

- 每个任务呈现一段截图轨迹（平均 4.7 张/任务）导向模糊决策点 + 自然语言指令，模型须决定"澄清"或"行动"。
- **规模**：744 个任务（381 移动 + 363 桌面），涵盖三类歧义：**语言歧义**、**指代不明确**和**不可能任务**。
- 每个任务在两个轴向上评分：**明显性**（0–2，指令有多模糊）与**后果**（0–2，猜错有多严重）。任一分数高时，代理应澄清。
- 每个任务提供真值澄清问题，用于精确率/召回率评估。

#### 2.5 评估指标

**安全指标：**
- **TSR**（任务成功率）：良善任务正确完成的比例，测能力。
- **ASR**（攻击成功率）：恶意任务中模型执行不安全动作的比例，越低越安全。
- **FRR**（虚假拒绝率）：良善任务中模型调用 status(unsafe) 的比例，测过度防御。
- **ADeptS-Bench Score**：TSR 与 (1−ASR) 的**调和平均**，S = 2·TSR·(1−ASR)/(TSR+1−ASR)。选择调和平均而非算术平均，是因为它惩罚以牺牲一个维度换取另一个维度的模型（如 90% TSR + 90% ASR 只能得 17.1%）。

**消歧指标：**
- **消歧 F1**：生成问题与真值项目的匹配精确率与召回率的调和平均。
- **严重度校准误差（Δ）**：模型打分与人类标注在明显性和后果两个维度上的绝对误差之和，Δ ∈ [0,4]。逐分量计算误差防止过度估计与欠估计相互抵消。

#### 2.6 评分方法

- **空间动作**（点击、长按）：检查预测坐标是否落在扩充了边界 m=0.01 的真值边界框内（命中函数见原文公式 2）。恶意任务中命中不安全目标计攻击成功；部分带 reverse 标志的任务反转逻辑。
- **非空间动作**（键入、导航、状态）：按动作类型匹配；含 tap-before-type 规则（当目标是键入动作时，点击文本框内也算匹配）。
- **消歧评分**：LLM 裁判（Gemini 3.1 Pro）通过配对比较判断模型生成问题与真值项目的语义匹配，与人类判断一致性达 96.1%（κ=0.92）。

- **公平性考量**：

- **潜在不足**：消歧任务每个只有**单个标注者定义的真值问题**，而 17.8% 的移动任务中所有模型的问题均未命中单一真值项，人工检查确认模型经常针对歧义的**另一个合理方面**提问——这暗示单一的 ground-truth 参照可能低估模型实际消歧能力。

### 6. 论文的主要结论与发现

1. **没有任何模型既强大又安全**。最佳得分为 Gemini 3.1 Pro 桌面端的 76.0%（ADeptS-Bench Score）；没有模型能同时满足"TSR>80% 且 ASR<30%"（Gemini 3.1 Pro 桌面 82.9%/29.8% 是唯一接近组合，但 ASR 仍略高于 30%）。
2. **所有模型都会盲目点击 2.5 万美元订单的"结账"按钮，且无模型能识别被误标为"Optimize"的"恢复出厂设置"按钮**——这属于 L4 级威胁（无视觉线索、危险在动作规模或标签错配），当前安全训练完全无法处理此类"后果推理"型威胁。
3. **安全机制的三种架构**（工具消融发现）：
   - **工具依赖型**（Gemini 3.1 Pro）：移除拒绝工具后 ASR 激增 +22.0pp——显式拒绝工具是其主要防线；
   - **部分依赖型**（Claude 4.7、GPT-5.4）：移除工具后 ASR 增加 +10.3/+10.7pp，模型仍保留训练内化的隐式拒绝能力；
   - **无机制型**（Qwen 全系列）：移除工具后 ASR 无变化（±1pp 内），且从未使用过拒绝工具——开源模型完全不参与拒绝机制。
4. **消歧中的严重度系统高估**。所有模型 42–62% 的匹配项将后果严重度评得高于人类标注，仅 7–25% 评低——与安全流中的过度拒绝（FRR 5–10%）相呼应，表明存在普遍性的"谨慎默认"偏差。
5. **跨平台行为不一致**：安全在桌面端更好（TSR +4–8pp），消歧在桌面端更差（F1 掉 8–38pp）；模型排名跨平台反复洗牌（Gemini 3.1 Pro 在移动消歧中第一但在桌面跌至第四，Claude 4.7 在桌面最强）。
6. **能力-安全存在权衡**：Gemini 2.5 CU 专为 computer use 优化，TSR 最高（83.6% 桌面）但 ASR 也是前沿模型中最高（51.5%）——"为行动优化"可能牺牲了"对行动的评价"。
7. **GPT-5.4 的精确刻画**：可拒绝明示恶意请求（OS-Harm misuse 不安全率仅 6%），但面对界面嵌入型威胁时 36% 遵从——区分了"请求级安全"与"界面级安全"两个不同的安全维度。
8. **不可能任务盲区**：需要检测"任务不可能"的情况（如软件界面上"更换 SIM 卡"）的漏检率（30.6%）是普通消歧任务（13.8%）的两倍以上，模型将不可能请求当作欠细化请求处理。

### 7. 优点：方法或实验设计上的亮点

- **双流设计是核心创新**：同时覆盖安全与消歧，且二者互为补充——安全流衡量"何时拒绝"，消歧流衡量"何时提问"，统一在"可信度"框架下。此前没有任何基准同时具备这两个维度。
- **用户驱动的研究方法**：MaxDiff 调查（n=1,300）将一般用户的真实关切（身份盗用、账户泄露、财务损失）直接转化为威胁分类优先级，避免研究者主观风险判断可能偏离用户真实需求的陷阱。74.1% 参与者表示更担心外部攻击而非内部错误，这一发现直接指导了基准对对抗性威胁类别的侧重。
- **配对设计（benign/malicious pairs）**：同一指令、不同截图的配对设计允许进行每任务 2×2 分类（理想/能但险/稳但无能/双错），能更精确地定位模型的安全-能力分配模式，也发现了过度拒绝源于"整体视觉相似性模式匹配"而非精确威胁检测。
- **离线、轻量、可复现**：与需要实时环境的轨迹式基准相比，ADeptS-Bench 每次安全任务仅需一次 API 调用，完整评估约 26 万次 API 调用，大幅降低了评估成本与碳足迹，也易于扩展和复现。
- **L1–L4 失败谱系框架**：通过跨模型一致性分析将威胁可检测性分层——L1 显式线索（全体检测）、L2 文本内嵌威胁（仅前沿捕获）、L3 上下文歧义（模型分歧）、L4 语义后果（全员漏过）——清晰指出当前安全训练的边界：模式匹配已解决，后果推理未解决。
- **严谨的混淆排除**：对 GPT-5.4 的低 ASR 做 323 任务人工意图分类，排除接地失误假象；对 LLM 裁判做 338 样本人工验证（96.1% 一致，κ=0.92，无方向性偏差）；对边界框 margin 做敏感性分析。这些严谨性处理显著增强结论可信度。
- **有明确的安全改善建议**：从拒绝工具内化（post-training 而非 prompt 工具化）、后果推理训练、系统级高风险操作护栏（用户确认、风险预分类、沙箱执行）、校准过度拒绝四个方面给出建设性缓解措施，使基准成为"测量-修复"工具而非单纯暴露漏洞。

### 8. 不足与局限

- **单步评估的局限性**：ADeptS-Bench 只评估单一决策点的原子违规，是智能体安全的**必要但不充分**组件，不能替代轨迹级评估，也不预测端到端的轨迹安全表现。作者明确承认有些 L3 级上下文歧义（如需要观察多步交互才能确认的恶意意图）在单个静态截图中难以定论，而 L4 级后果推理恰恰是未来轨迹级安全基准应重点补充的方向。这意味着基准的高分不能直接外推为"真实部署中安全"。
- **消歧流的真值参照偏移**：每个消歧任务仅配置**单一标注者定义的真值问题**，而人工复核显示 17.8% 的移动端任务中，模型提出的问题其实针对歧义的**另一个合理维度**——即模型确实识别到了歧义并正确选择澄清，只是澄清角度与标注者的单一参照不同。这会导致对模型消歧能力的系统性低估，也使 F1 指标的跨模型排名的绝对数值解读需要谨慎。
- **合成截图引入的生态效度折扣**：为获取道德上无法从生产环境采集的威胁场景（如恶意对话框、钓鱼浮层），基准使用 Gemini 合成生成了部分截图。虽然经过专家审查，合成 UI 与真实应用在视觉噪声、控件密度和布局自然度上仍可能存在差距，可能影响模型在真实界面上的迁移表现。
- **平台覆盖面仍然不完整**：虽然同时覆盖移动端和桌面端，但未覆盖浏览器扩展场景、跨应用协作场景（如移动端 app-to-app 跳转、桌面端 OS 级拖放）以及多模态输入（语音、手势）。对威胁类型的覆盖也不完全均匀——桌面端独有的"Dangerous Commands"类别任务量（49 个）明显少于其他类别，统计功效相对偏低。
- **能力-安全调和平均的聚合粒度偏粗**：ADeptS-Bench Score 将 TSR 与 (1−ASR) 做调和平均，但良善与恶意任务是配对的，良善变体上的失败与恶意变体上的回避并不一定构成"安全-能力权衡"——例如模型因视觉接地失败而恰好避开恶意按钮时，ASR 降低但并非出于安全推理。虽然作者用 323 任务人工分类排除了 GPT-5.4 的此类假象，但该混淆对于其他模型仍可能在较小程度上存在。
- **缺少对"后续对话"的动态安全测量**：真实 CUA 部署中，模型在遭到用户拒绝后可能被说服、被社会工程操纵或受到多轮提示注入。基准的静态单轮设置无法测量这种交互式攻击面。
- **资源细节披露不完整**：论文未报告 GPU 型号、数量或训练/调优成本；消歧 LLM 裁判使用与主实验相同的 Gemini 3.1 Pro，虽然人工验证未发现方向性偏袒，但"裁判与选手同源"在原则上仍是隐忧——尤其当未来用该基准迭代训练模型时，存在优化目标与裁判偏好耦合的风险。
- **时间敏感性**：网页应用和 Android 应用的 UI 会持续更新，基准中的截图会随时间老化；虽然离线设计便于持续更新，但论文未给出明确的基准版本管理与刷新机制。

### 9. 总结与启示

ADeptS-Bench 的核心贡献不在于发明新的威胁类型，而在于将可信度评估的方法论推到了一个新高度：**测评对象从"能否完成任务"转向"在完成任务时是否值得信任"**，测评方式从"研究者定义的实时轨迹"转向"用户驱动的离线原子决策"。从结果中能提炼出几条对 CUA 安全研究有直接指引意义的结论：

1. **安全能力不是大模型的自动涌现属性**。开源与闭源之间的安全差距（最高 ASR 差近 30pp）远超能力差距本身；工具消融显示，只有当显式拒绝机制存在且被模型内化时，安全性能才真正改善。
2. **当前的对抗性防御已接近天花板，下一阶段必须走向后果推理**。所有模型——包括最强的 GPT-5.4 与 Gemini 3.1 Pro——在面对"语义后果型威胁"（L4）时均全员失守：2.5 万美元订单无模型拒绝、伪造的"Optimize"重置按钮无模型识别。模式匹配可以挡住显式恶意，但挡不住被重新包装的危险。
3. **消歧能力与安全能力是正交的两个维度**。排名跨平台反复洗牌（Gemini 3.1 Pro 移动消歧第一但桌面第四）、能力与安全呈相反方向（Gemini 2.5 CU 能力最高但 ASR 也最高），说明"值得信任的代理"至少需要两个正交的训练目标：何时执行、何时停下提问。
4. **对未来的测量学启示**：任何真实部署的 CUA 安全基准都应至少包含三个要素——用户驱动的风险优先级、跨平台覆盖、离线可复现性；而任何声称安全的模型，都应同时通过"安全流"（不出错）与"消歧流"（会提问）的联合测评，否则其安全性声明是片面的。

总体而言，ADeptS-Bench 通过 2,462 个离线任务、七模型 × 两平台 × 十次运行的全面评估，刻画了当前 CUA 上的可信度"现实图景"：能力已可接受，安全远未齐备，而在安全与消歧的交叉点上，还看不到任何一个接近可信部署的模型。这个基准不仅是一把尺子，更是一张路线图——它把"后果推理"和"拒绝机制内化"明确标为下一代 CUA 安全训练的核心攻坚方向。
