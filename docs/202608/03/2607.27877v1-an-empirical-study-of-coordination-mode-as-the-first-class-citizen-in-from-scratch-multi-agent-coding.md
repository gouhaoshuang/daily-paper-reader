## 摘要
多智能体氛围编码有望加速软件开发，然而现有基准依赖合成环境，忽略了实际时间和货币成本，将推理与通信混为一谈，并且只奖励表面的完成。我们引入了多智能体从零开始评估基准 MSEval，用于在真实世界任务上评估多智能体编码。MSEval 基于 10 个领域中的 10 个真实全栈项目，使用分层需求和确定性评分标准对性能进行评分。其执行引擎 LegoGent 测试了 10 种协作拓扑，其中智能体通过周期性同步间隔进行协调，并通过原生 CI/CD 流水线部署。同时，自动评分器 TAgent 动态探测实现，以联合测量功能成功、延迟和前缀缓存 token 成本。在 100 次运行中，MSEval 揭示在塑造速度-成本-质量权衡方面，组织拓扑与模型能力不相上下。对于相同的任务和模型，改变拓扑会使分数变化超过 30 分，并使实际时间加倍。结构化流水线以最高质量最快收敛，而沉重的管理监督则会降低性能。最终，MSEval 为衡量多智能体团队实际构建软件的方式建立了严谨、可复现的标准。该基准已在 https://github.com/robinren03/MSEval 发布。

## Abstract
Multi-agent vibe coding promises to accelerate software development, yet existing benchmarks rely on synthetic environments that ignore practical time and monetary costs, conflate reasoning with communication, and reward only superficial completion. We introduce multi-agent from-scratch evaluation benchmark, MSEval, evaluating multi-agent coding on real-world tasks. Grounded in 10 authentic, full-stack projects across 10 domains, MSEval scores performance using hierarchical requirements and deterministic rubrics.   Its execution engine, LegoGent, tests 10 collaboration topologies where agents coordinate via periodic sync intervals and deploy through native CI/CD pipelines. Concurrently, the automated grader TAgent dynamically probes implementations to jointly measure functional success, latency, and prefix-cached token cost. Across 100 runs, MSEval reveals that organizational topology rivals model capability in shaping the speed--cost--quality trade-off. For identical tasks and models, varying the topology shifts scores by over 30 points and doubles wall-clock time. Structured pipelines converge fastest with the highest quality, whereas heavy managerial oversight degrades performance. Ultimately, MSEval establishes a rigorous, reproducible standard for measuring how multi-agent teams actually build software. The benchmark is released at https://github.com/robinren03/MSEval.

### 2. 论文提出的方法论

#### 核心思想

通过控制项目、模型、部署路径和评分标准不变，**仅改变协作拓扑**，从而可归因地测量协作模式对质量、时间和 token 成本的影响。提出了一个三维一体的基准框架：

- **MSEval**（多智能体从零开始评估基准）：10 个真实全栈项目 + 10 种协作模式，形成 100 个团队配置的评测网格。
- **LegoGent**（多智能体执行引擎）：将协作模式实例化为可执行的团队，负责同步、协调、部署和回合控制。

#### 关键技术细节

1. **流水线结构（三阶段）**：

2. **LegoGent 的协作机制**：
   - **被动同步通道**：每约 4 分钟广播一次合并后的团队状态快照（每个智能体汇报：完成工作、测试证据、阻塞项、后续步骤）。

   - **步骤 1——评分标准编译**：将需求文档解析为结构化的加权 YAML 评分标准（如 P00 即时通讯项目包含 56 个检查项：7 系统级、46 功能级、3 文档级）。

   - **步骤 3——三类评测器**：

   - **步骤 5——反馈生成**：产生条目级证据（观察到的 UI 状态、API 响应、代码位置、失败的先决条件、受影响的权重），作为下一轮的排序修复议程，优先处理高权重根本原因。

- 成本计算采用价格加权求和公式：

### 6. 论文的主要结论与发现

1. **拓扑与模型能力同样重要**：对于相同任务和模型，改变拓扑可使分数波动超过 30 分，耗时翻倍。例如 DeepSeek v4 Pro 在即时通讯项目上从 pipeline 模式下的 89.9 分骤降至 open-source review 模式下的 43.0 分。
2. **结构化流水线收敛最快且质量最高**：Pipeline、QA-first 和 Feature Squad 在多数项目中表现最佳；QA-first 和 Rotation 并列全网格平均最高（83.3），Open-Source Review 最低（73.5）。
3. **重型管理监督适得其反**：PM Oversight 在部分项目中有效（如 P00 的 83.7），但总体上并未超越更轻量的结构化模式，反而增加了开销。
4. **提前检查优于事后修正**：QA-first 将需求转化为验收目标后实现，效果优于后期评审（Open-Source Review 需要调和已分化的修改）。
5. **成本前沿与得分前沿不一致**：GLM-5.2 达到最高全网格平均分，但时间和成本远高于 DeepSeek 模型（约 2.6 倍墙钟、8 倍成本）；GPT-5.5 以低得多的成本逼近 Claude Opus 4.8 的得分。
6. **功能缺失而非崩溃主导失败模式**：不完整逻辑/边界情况（32.2%）和缺失功能（23.8%）合计占失败检查项的一半以上，团队几乎总是交付可运行但不完整的系统。
7. **先决条件级联是多智能体特有的失败模式**：单个断裂的先决条件（如登录失败）可能自动跳过最多 14 个下游检查，出现在 39% 的运行中，跨智能体契约破损静默零化他人的正确工作。

### 7. 优点

- **四重组合创新**：将真实从零开始项目、多种协作模式、部署为基的评测和成本感知反馈集于同一受控环境，在现有基准中是少见的组合。
- **协作拓扑作为独立变量**：通过固定项目、模型和部署路径，仅改变组织策略，使拓扑的影响可归因而非附带。
- **部署为基的评测**：通过原生 CI/CD 路径（GitLab + SonarQube）构建并服务产物，故障部署本身成为测量的一部分，而非仅检查代码文本。
- **迭代反馈回路**：TAgent 输出条目级、加权、可操作的修复议程，使逐轮改进可解释而非偶然。
- **细粒度成本核算**：区分四种 token 计费字段，使基准能够区分原始 token 用量和真实预算压力（缓存读比新输入便宜数十倍）。
- **真实项目规模和防污染设计**：每个端到端产物通常需要生成 2000+ 行 Python 代码，降低了 LLM 数据污染的敏感性。
- **失败模式分类学**：对 1,440 个失败检查项按根本原因分类，提供了基准瓶颈的系统性解释。

- **随机性与规模有限**：LLM 的随机性仅通过即时通讯项目的 3 次平行试验缓解，其他项目仅在异常时重跑；高频测试预算限制了更大规模的统计验证。
- **TAgent 覆盖范围有限**：无法捕获某些边缘缺陷，且评分集中于 Web 应用，未覆盖其他软件形态（如移动端、桌面端、嵌入式等）。
