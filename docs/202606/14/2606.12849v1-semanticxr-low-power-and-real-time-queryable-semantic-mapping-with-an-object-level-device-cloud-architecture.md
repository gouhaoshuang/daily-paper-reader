## 摘要
语义映射是新兴扩展现实（XR）应用（如AI助手和空间对象搜索）中实现具身交互的核心服务。在移动XR设备上部署此能力需要系统具备开放词汇、实时和低功耗特性。现有方法计算密集且假设服务器级资源。云卸载提供了一条实用路径，但现有系统均未在设备-云边界上拆分语义映射或管理其通信、执行和内存占用。我们提出SemanticXR，这是首个在XR功率、带宽和内存约束下实现实时、开放词汇语义映射和查询的设备-云系统。我们的关键洞察是将语义可识别对象提升为跨设备和服务器的一级通信、执行和内存单元。在服务器端，对象级并行和几何下采样改善了映射延迟，而对象级深度映射协同设计降低了上行带宽。在设备端，具有增量更新和更新优先级的对象级稀疏局部地图实现了网络鲁棒性查询，且内存和下行带宽有界。对象级可配置资源使用与质量权衡允许应用和系统分别根据应用需求和运行条件调整映射。与使用相同感知模型的设备-云基线相比，对象级组织在同等语义质量下将服务器端映射延迟提升了2.2倍。深度映射协同设计将上行带宽维持在2.5 Mbps以下。在设备端，SemanticXR即使在网络中断时也能对多达10,000个对象维持低于100毫秒的查询延迟，在500 MB内支持数万个对象，并将下行带宽随地图变化而非场景总大小扩展。该系统在正常运行期间仅增加2%的设备功耗。

## Abstract
Semantic mapping is a core service that enables grounded interactions in emerging Extended Reality (XR) applications such as AI assistants and spatial object search. Deploying this capability on mobile XR devices requires a system that is open-vocabulary, real-time, and low-power. Existing approaches are compute-intensive and assume server-class resources. Cloud offloading offers a practical path, but no existing system splits semantic mapping across the device-cloud boundary or manages its communication, execution, and memory footprint.   We present SemanticXR, the first device-cloud system for real-time, open-vocabulary semantic mapping and querying under XR power, bandwidth, and memory constraints. Our key insight is to elevate semantically identifiable objects to first-class units of communication, execution, and memory across the device and server. On the server, object-level parallelism and geometry downsampling improve mapping latency, while object-level depth-mapping co-design reduces upstream bandwidth. On the device, an object-level sparse local map with incremental updates and update prioritization enables network-robust querying with bounded memory and downstream bandwidth. Object-level configurable resource usage vs. quality trade-offs let applications and the system adapt mapping to application requirements and operating conditions, respectively.   Against a device-cloud baseline with the same perception models, object-level organization improves server-side mapping latency by 2.2X at equal semantic quality. Depth-mapping co-design maintains upstream bandwidth under 2.5 Mbps. On the device, SemanticXR sustains sub-100 ms query latency for up to 10,000 objects even under network drops, supports tens of thousands of objects within 500 MB, and scales downstream bandwidth with map changes, not total scene size. The system adds only 2% device power during normal operation.

## 1. 论文的核心问题与整体含义
- **研究动机**：扩展现实（XR）设备需要实时、开放词汇、低功耗的语义映射服务，以支持空间对象搜索、AI助手等应用。现有语义映射方法（如ConceptFusion、ConceptGraphs）计算密集，假设服务器级GPU，无法在移动XR功耗预算内运行。云卸载虽能利用服务器算力，但现有系统未在设备-云边界上有效拆分语义映射，无法满足XR对通信、执行和内存占用的约束（如网络中断下的查询可用性、有限带宽、设备内存）。
- **整体含义**：SemanticXR首次提出一种设备-云架构，通过将“对象”提升为跨设备-云的一级系统单元（通信、执行、内存管理），在XR功率、带宽和内存约束下实现实时、开放词汇的语义映射与查询。

## 2. 方法论
- **核心思想**：以语义可识别对象作为系统设计的一级抽象。每个地图对象具有稳定ID、语义嵌入、类别标签和3D点云。所有操作（通信、并行、降采样、更新、优先级、配置）均以对象粒度进行。
- **关键技术细节**：
  - **服务器端**：
    - **对象级并行**：对每帧检测到的对象独立执行分割和视觉语言特征提取，提升GPU利用率。
    - **对象级几何下采样**：对每对象点云数量设上限（默认2000点），因对象关联依赖空间邻近性而非高保真几何，降低计算开销且不损语义质量。
  - **设备端**：
    - **对象级稀疏局部地图**：设备存储对象级条目（嵌入+下采样点云），内存与对象总数成正比而非场景复杂度。
    - **增量更新**：服务器只传输新创建或修改的对象，下行带宽与变化量成正比。
    - **更新优先级**：基于语义相关性、空间邻近性和应用声明类别，限制设备上保留的对象数，支持驱逐策略。
    - **查询模式切换**：网络正常时用服务器查询（Server Query，低功耗）；网络中断或高延迟时切换为本地查询（Local Query），延迟稳定。
  - **上行带宽优化**：
    - **对象级深度-映射协同设计**：深度帧下采样（分辨率降至1/5×1/5）后传输，服务器端对投影面积小的对象延迟整合（直至多帧确认），减少带宽约90%而语义质量损失微小（F-mIoU从48.29降至45.81）。
  - **可配置资源-质量权衡**：暴露多个系统旋钮（几何细节、更新频率、最小对象面积、深度下采样率等），允许应用和系统在不修改感知管线的前提下调整映射行为。

## 3. 实验设计
- **数据集**：Replica数据集（8个室内场景：房间、办公室），提供同步RGB-D、姿态和地面真实语义标签。
- **Benchmark**：自建设备-云基线（使用相同感知模型和映射管线，但无对象级系统组织），对比方法包括ConceptFusion、ConceptGraphs、OpenMask3D、Clio（batch/online）。
- **评估指标**：
  - 语义质量：mAcc（平均类别召回）、F-mIoU（频率加权交并比）
  - 映射延迟（每帧处理时间）
  - 查询延迟（服务器/本地，不同网络条件）
  - 设备内存和查询延迟随对象数缩放（合成地图80~50000对象）
  - 下行带宽（增量vs全量更新）
  - 上行带宽（不同深度下采样率与质量权衡）
  - 设备功耗（本地映射、服务器映射+本地查询、连续查询等模式）

## 4. 资源与算力
- **服务器**：AMD Ryzen Threadripper 7960X CPU + NVIDIA RTX 6000 Ada GPU（云级配置）。
- **客户端设备**：NVIDIA Jetson Orin（低功耗模式，20W功率上限，模拟现代XR头显）。未明确提及训练时长，所有实验均为推理阶段；无模型训练过程。
- **网络条件**：低延迟（~20ms RTT）、高延迟（~66ms RTT）、完全中断。

## 6. 主要结论与发现
- 对象级系统组织将服务器端映射延迟降低2.2倍（570ms→260ms），语义质量不变（mAcc 37.0→37.6，F-mIoU 47.23→48.29）。
- 上行带宽通过5×5深度下采样降至2.5 Mbps以下（原来26.4 Mbps），质量仅轻微下降（F-mIoU 48.29→45.81）。
- 本地查询在10,000对象内保持<100ms延迟，内存<500MB支持数万对象。
- 下行带宽与地图变化量成正比而非场景大小。
- 正常运行时设备功耗仅比空闲增加2%（8.6W→8.7W），网络中断下本地查询功耗约9.8W（增量1.2W），峰值13.23W。
- 首个在XR约束下实现实时、开放词汇可查询语义映射的系统。

## 7. 优点
- **创新系统抽象**：将对象作为跨设备-云的一级单元，统一通信、执行和内存管理，区别于以往仅关注算法质量的管线。
- **轻量级协同设计**：深度下采样+基于面积的延迟整合策略，几乎零设备开销即可大幅降低上行带宽。
- **网络鲁棒性**：增量更新+优先级+本地稀疏地图保证网络中断下查询仍可运行，且设备内存和带宽有界。
- **可配置性**：通过暴露系统旋钮允许应用和系统动态调整资源-质量权衡，适应多样化场景。
- **实验设计严谨**：与自建基线进行受控对比，消融实验清晰，评估维度全面（延迟、质量、带宽、内存、功耗）。

## 8. 不足与局限
- **实验覆盖有限**：仅使用Replica室内数据集，未在真实室外环境或动态场景中评估；结论泛化性需进一步验证。
- **依赖对象级后端**：仅适用于产生离散对象表示的管线，不兼容场景级融合表示（如体积映射）；需后端先暴露对象实体。
- **未考虑动态物体**：当前假设静态环境；涉及运动物体时，关联和更新策略需额外扩展。
- **隐私与安全**：设备-云传输RGB-D数据存在隐私风险，论文提及但未深入解决。
- **未与真实商用头显直接对比**：因当前商用头显（如Apple Vision Pro）未暴露原始传感器流，使用iPad作为原型而非头显进行端到端演示；功率测量基于Jetson Orin模拟，与真实头显功耗特性有差异。
- **可扩展性**：仅评估单设备-单服务器，多用户并发或大型环境下的服务器扩展性未讨论。
