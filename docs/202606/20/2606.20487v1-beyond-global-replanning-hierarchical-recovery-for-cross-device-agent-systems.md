## 摘要
现实世界中的计算机使用任务通常跨越多个应用程序和设备，需要智能体在动态运行时故障下协调异构环境。现有的多设备智能体系统支持任务分解和跨设备分配，但恢复机制大多粗粒度：当执行失败时，它们通常重试相同策略、重新分配子任务或修改全局计划，而未系统性地建模设备局部策略空间。这限制了它们区分可在当前设备内修复的故障与需要跨设备重规划的故障的能力。我们提出**H-RePlan**，一种适用于多设备智能体（统一API-CLI-GUI执行）的分层重规划框架。H-RePlan为每个设备配备可互换的执行策略，并通过紧凑的跨层故障抽象将设备局部策略恢复与编排器级全局重规划分离。为评估这一能力，我们引入**HeraBench**，一个注入故障的基准测试，它在Linux和Android设备上构建跨设备工作流，并注入策略级和设备级故障。实验表明，H-RePlan显著优于单策略和粗粒度多设备基线，实现了更高的完成率、指令遵循率和完美通过率，同时降低了实现可靠端到端成功所需的token成本。这些结果表明，范围感知的分层恢复对于鲁棒的多设备智能体执行至关重要。

## Abstract
Real-world computer-use tasks often span multiple applications and devices, requiring agents to coordinate heterogeneous environments under dynamic runtime failures. Existing multi-device agent systems support task decomposition and cross-device assignment, but recovery remains largely coarse-grained: when execution fails, they typically retry the same strategy, reassign the subtask, or revise the global plan, without systematically modeling the device-local strategy space. This limits their ability to distinguish failures that can be repaired within the current device from those that require cross-device replanning. We propose \textbf{H-RePlan}, a hierarchical replanning framework for multi-device agents with unified API--CLI--GUI execution. H-RePlan equips each device with interchangeable execution strategies and separates device-local strategy recovery from orchestrator-level global replanning through a compact cross-layer failure abstraction. To evaluate this capability, we introduce \textbf{HeraBench}, a fault-injected benchmark that constructs cross-device workflows over Linux and Android devices and injects strategy- and device-level failures. Experiments show that H-RePlan substantially outperforms single-strategy and coarse-grained multi-device baselines, achieving higher completion, instruction adherence, and perfect-pass rates while reducing the token cost required for reliable end-to-end success. These results demonstrate that scope-aware hierarchical recovery is essential for robust multi-device agent execution.

- **核心意义**：提出**范围感知的分层恢复**是构建鲁棒跨设备智能体的关键。本文通过显式分离设备内策略恢复与系统级跨设备重规划，弥补了该研究空白。

## 2. 方法论：核心思想、关键技术细节
- **核心思想**：H-RePlan框架采用双层分层结构，将故障恢复按范围解耦：
  - **设备层（Strategy Planner）**：负责子任务在单个设备内的执行策略选择与局部恢复。当某策略失败时，尝试在该设备内切换到其他可用策略（API/CLI/GUI），仅当确信无法本地解决时才升级给编排器。
  - **系统层（Orchestrator）**：维护全局任务链，处理设备级失败，通过全局重规划（重新分配、插入恢复子任务、部分结果复用等）恢复。
- **关键技术细节**：
  1. **统一策略控制抽象**：每个设备用动态能力剖面 Φ(d) = (OS, App, Cap, Πd) 描述，其中 Πd 表示该设备支持的API/CLI/GUI策略集，实现平台无关。
  2. **Orchestrator（编排器）**：维护有序子任务链 P = ⟨q₁,...q_k⟩。三种模式：
     - 任务创建 O_create：根据指令和设备剖面分解为顺序子任务。
     - 信息追加 O_append：子任务成功后，将其结果注入后续依赖子任务。
     - 全局重规划 O_replan：收到跨层故障事件（CLFE）后，改写剩余子任务链，可重试、重分配、增加恢复步骤或声明失败。
  3. **Strategy Planner（策略规划器）**：设备内规划器，状态机包括CREATE、PROGRESS CHECK、REPLAN。输出三种决策：EXECUTE(策略π, 指令x)、DONE(结果y)、ESCALATE(故障证据c_j)。CREATE阶段选择初始策略；PROGRESS CHECK阶段检查进度并决定继续或完成；REPLAN阶段在本地失败后尝试其他策略或升级。
  4. **跨层故障事件（CLFE）**：紧凑的规划导向故障抽象，包含失败子任务ID、源设备、故障类型分类、本地已尝试策略及观察、升级理由。为编排器提供可诊断的证据，同时避免全量低级痕迹。
  5. **策略执行代理**：每个策略对应一个执行代理（API Agent、CLI Agent、GUI Agent），接收局部指令，返回状态、结果和执行证据。

## 3. 实验设计
- **数据集/场景**：构建**HeraBench**基准，由23个种子任务扩展为**174个评估变体**。运行环境包含4台设备（2台Linux、2台Android），使用真实服务和本地文件。故意只暴露部分服务API，以迫使智能体动态探索API-CLI-GUI策略空间。
- **故障注入类型**：
  - **局部故障**：禁用特定策略但保留同设备其他策略。
  - **全局故障**：移除设备完成该步骤的所有路径，要求分配到同类型其他设备。
  - **混合故障**：局部+全局组合。
  - **无故障基线**。
- **对比方法**：
  - CRAB（GUI和API版本）
  - UFO 3（GUI和API版本）
  - 所有方法共享30分钟超时、相同执行管道。文本操作使用DeepSeek-V4-Pro；GUI执行使用Kimi K2.5（除CRAB-GUI用GPT-4o）。

## 6. 主要结论与发现
- H-RePlan在**完成率（75.84%）、指令遵循率（77.72%）、完美通过率（36.78%）**上显著优于所有基线，最强基线UFO 3-GUI的PP率仅为13.79%。
- **token成本效率突出**：预期每完美通过成本（Tok./PP）降至1,932,765，较UFO 3-GUI（10,512,553）降低约5.4倍。
- **分层恢复的价值**：局部故障大部分在设备内通过策略切换解决（94%的API→GUI转换），规避了不必要的全局重规划。全局故障则根据CLFE证据合理升级：相同设备重启成功率（91.7%）远高于跨设备（62.7%）。
- 消融实验证实，移除全局重规划或策略规划器均导致性能急剧下降，CLFE也显著改善了编排器对故障范围的诊断。

## 7. 优点
1. **创新性**：首次系统提出跨设备智能体的分层恢复架构，明确分离设备局部与系统全局故障范围，弥补了现有粗粒度方法的空白。
2. **平台无关抽象**：统一API-CLI-GUI策略控制，使框架可灵活适配不同操作系统，无需依赖特定平台机制。
3. **紧凑故障传递（CLFE）**：既提供足够证据指导全局重规划，又避免信息过载，设计巧妙。
4. **专用基准**：HeraBench通过注入可控的多层次故障，为评估分层恢复能力提供了标准测试环境，填补了评估缺失。
5. **深入分析**：通过多种Scope-level分析和策略转换热图，直观展示了分层恢复的行为与收益。

## 8. 不足与局限
1. **设备覆盖有限**：实验仅涉及Linux和Android设备，未验证在Windows、macOS、iOS等实际常见平台上的效果。
2. **任务规模有限**：种子任务23个，总变体174个，仍属小规模基准；任务类型（文件处理、跨设备传输等）不够多样，可能遗漏网络配置、复杂身份认证、长耗时操作等场景。
