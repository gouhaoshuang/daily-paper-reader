## 摘要
AI代理通过代理路由基础设施（ARI）越来越多地访问外部模型、工具和服务，以管理异构接口和碎片化订阅的开销。然而，ARI的架构引入了根本性的信任风险：它获取代理查询和服务响应的明文访问，同时使代理无法验证其查询是否被路由到预期的服务提供商，或者请求和响应是否保持不被篡改。为了解决这个问题，我们提出了TrustedARI，这是首个用于自主AI的原生可信代理路由基础设施。在架构上，TrustedARI基于三项核心创新构建：（i）一种适应ARI的三方TLS握手，通过角色特定的TLS密钥材料分配，使代理和ARI能够联合认证服务提供商；（ii）一种隐私保护的查询构建协议，允许代理和ARI协作构建格式良好的查询，而无需暴露各自的私有输入；（iii）一种可验证的计费协议，支持基于使用量的公平结算，同时保护服务响应的完整性和机密性。我们实现并广泛评估了TrustedARI的原型，以验证其性能。实验证实TrustedARI非常高效：与现有的三方TLS握手相比，我们的ARI适配握手协议将通信开销降低了39.34%。此外，隐私保护的查询构建协议带来的开销可以忽略不计——平均计算时间0.19秒，通信成本0.58 MB——而可验证的计费协议将证明生成速度提高了28.20倍。关键的是，TrustedARI无需对服务提供商进行任何修改即可轻松部署。

## Abstract
AI agents increasingly access external models, tools, and services through Agentic Routing Infrastructure (ARI) to manage the overhead of heterogeneous interfaces and fragmented subscriptions. Yet, the architecture of ARI introduces fundamental trust risks: it obtains plaintext access to agent queries and service responses, while leaving agents unable to verify that their queries are routed to intended service providers or that requests and responses remain untampered. To address this problem, we present TrustedARI, the first trust-native agentic routing infrastructure for agentic AI. Architecturally, TrustedARI is built upon three core innovations: (i) an ARI-adapted three-party TLS handshake that enables the agent and ARI to jointly authenticate the service provider through role-specific distribution of TLS key materials; (ii) a privacy-preserving query-construction protocol that allows the agent and ARI to collaboratively construct well-formed queries without exposing their respective private inputs; and (iii) a verifiable billing protocol that supports fair usage-based settlement while preserving the integrity and confidentiality of service responses.   We implemented and extensively evaluated a prototype of TrustedARI to validate its performance. Experiments confirm that TrustedARI is highly efficient: our ARI-adapted handshake protocol reduces communication overhead by 39.34% compared to the existing three-party TLS handshake. Furthermore, the privacy-preserving query-construction protocol imposes negligible overhead-averaging 0.19 seconds in computation time and 0.58 MB in communication costs-while the verifiable billing protocol speeds up proof generation by 28.20x. Crucially, TrustedARI is readily deployable without any modification to the service providers.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **研究动机**：AI 代理（Agent）越来越多地通过 **代理路由基础设施（Agentic Routing Infrastructure, ARI）** 访问外部模型、工具和服务（如 OpenRouter、LiteLLM、Pipedream、Zapier），以屏蔽异构接口、简化 API 维护并聚合订阅成本。然而，ARI 的架构引入了两类 **根本性的信任风险**：
  - **隐私泄露**：ARI 能够以明文形式获取代理的完整查询和服务的响应结果。
  - **完整性缺失**：代理无法验证 (a) ARI 是否将查询路由到了预期的服务提供商（防止端点误绑定），(b) 查询和响应内容在传递过程中是否被篡改。
- **整体含义**：现有 ARI 缺乏端到端的加密保证和可验证性，无法在不可信的中间基础设施上建立可信的代理‑服务交互。TrustedARI 旨在为自主 AI 提供“原生可信”的代理路由基础设施，在不修改服务提供商的前提下同时保障隐私、完整性和公平计费。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：**解耦 ARI 参与请求构建和转发的能力，与其观察或单方控制调用的能力**。通过安全多方计算（MPC），让代理和 ARI 共同作为一个“虚拟客户端”与下游服务提供商建立标准的 TLS 1.3 会话。联合执行保证请求加密（隐私），同时产生直接绑定到下游服务的密码学证据（完整性）。

- **三大核心协议**：

  - **(i) ARI-适配的三方 TLS 握手（§4）**：代理和 ARI 利用 MPC (ECtF、2PC) 联合模拟 TLS 客户端，与服务提供商完成 ECDHE 密钥交换和身份认证。**角色特定的密钥材料分配**：
    - 握手秘密（HS）向代理释放，使其能独立认证服务提供商证书，防止误路由。
    - 客户端应用密钥 (`tk_capp`) 在代理和 ARI 之间秘密共享，使得只有双方协作才能加密请求。
    - 服务端应用密钥 (`tk_sapp`) 先秘密共享，然后 ARI 在代理提交承诺后释放其份额给代理，使代理能解密完整响应，而 ARI 仅能获取与计费相关的字段视图（通过 ZKP）。
  - **(ii) 隐私保护的查询构建协议（§5）**：基于**公开模板 + 安全段组装**。模板 `T` 定义语句段类型（公开、代理拥有、ARI 拥有、共享）及填充长度。私有字段内容用秘密共享表示，真假长度（`g`）和填充（`h`）隐藏结构信息。采用两种拼接原语：
    - **局部确定拼接 (LDC)**：当左段有公开长度时，本地计算即可。
    - **结构隐藏拼接 (SHC)**：当左段长度秘密时，通过盲旋转协议（`ΠSHC`）在 2PC 中消除填充零字节，合并真实内容。还包含**最优化拼接规划**（动态规划最小化 SHC 调用成本），以及处理协议元数据（如 Content-Length）的 MPC 辅助生成。
  - **(iii) 可验证计费协议（§6）**：代理必须向 ARI 报告指定计费字段（如 token_usage），并提供零知识证明（NIZK，基于 Plonk）。**核心电路（Ckt）** 仅处理边界锚定的局部 JSON 窗口（自适应选择前向或后向窗口），而非整个响应，从而大幅降低证明开销。电路验证 (a) 结构隔离（计费字段在 JSON 中的预期深度）；(b) 密码学绑定（字段值来自 TLS 响应解密，并绑定到已承诺的服务端密钥 `tk_sapp`）。

## 7. 优点

- **原生信任设计**：将信任机制直接嵌入路由基础设施，而非事后审计或启发式检查。
- **角色感知的密钥分发**：通过巧妙的三方 TLS 密钥调度，精确赋予代理和 ARI 所需的最小权限（代理解密完整响应、ARI 仅计费视图），避免了昂贵的通用 MPC 或 ZKP。
- **结构隐藏拼接**：首创针对 ARI 场景的隐私查询组装，不仅能隐藏字段值，还能隐藏字段长度，并通过最优化规划最小化开销。
- **局部化计费证明**：仅证明包含计费字段的 JSON 窗口（边界锚定），而非整个响应，大幅降低证明成本，且与响应总长度解耦。
- **易部署性**：完全兼容标准 TLS 1.3，无需服务端修改；提供适配器（skill）使现有 LLM 代理可直接生成 TrustedARI 兼容请求。

## 8. 不足与局限

- **实验覆盖**：
  - 未在恶意安全模型下进行实验（仅讨论扩展方向）。
  - 计费证明的异步批处理场景未在评估中体现实际延迟。
  - 仅测试了 10 个 API，样本量较小；若包含更多变长、深层嵌套 JSON 响应，可能暴露开销变化。
- **潜在偏差**：
  - 手握手协议对比 DiStefano 时，假设对手方预计算可异步进行，实际网络拥塞可能影响结果。
  - 计费证明优化假设计费字段靠近响应边界，若字段位于中间且响应极长，窗口仍会增大开销（但比全解析仍好）。
- **应用限制**：
  - 目前仅考虑半诚实敌手；扩展至恶意安全需要额外开销（如 garbled-then-prove 范式、输入验证）。

  - 需假设服务提供商诚实（工具投毒、间接提示注入等攻击范围外）。
  - 模板和计划需预先协商，对动态、自由格式的协议（如未见过的 REST API 变体）适应成本较高。
