## 摘要
检索增强生成（RAG）已成为一种在推理时通过整合外部知识来改进语言模型的关键技术。随着设备-云协同推理使得在边缘设备上部署小型语言模型成为可能，一种新的场景随之出现：私有文档保留在设备端，公共知识位于云端。隐私和政策约束通常禁止原始文档交换，从而形成了文档隔离的双端RAG设置。然而，现有方法依赖于频繁的远程同步和密集的证据传输，在实际延迟和带宽条件下限制了吞吐量。为解决此问题，我们提出了CONCORD，一种用于文档隔离下双端RAG的异步稀疏聚合框架。CONCORD将云端视为异步到达的证据源，而不是持续同步的协同生成器。具体地，我们引入了等待债务控制，根据等待的观察回报来决定每个解码步骤是否应继续等待远程参与。我们还设计了一种证书引导的最小补充机制，仅请求确定当前贪婪决策所需的远程证据。咨询云端的步骤保留了与密集双端聚合相同的贪婪令牌，而其余步骤则在本地提交而无需远程证据。在Natural Questions和WikiText-2上的实验表明，CONCORD将端到端吞吐量分别比基线提高了1.66倍和2.15倍，同时将每个令牌的通信量减少了两个数量级以上，并保持了相当的答案质量和困惑度。

## Abstract
Retrieval-augmented generation (RAG) has emerged as a pivotal technique for improving language models by incorporating external knowledge at inference time. As device-cloud collaborative inference makes it feasible to deploy small language models on edge devices, a new setting arises in which private documents remain on the device and public knowledge resides in the cloud. Privacy and policy constraints often forbid raw document exchange, creating a document-isolated dual-end RAG setting. However, existing methods rely on frequent remote synchronization and dense evidence transfer, limiting throughput under realistic latency and bandwidth conditions. To address this issue, we propose CONCORD, an asynchronous sparse aggregation framework for dual-end RAG under document isolation. CONCORD treats the cloud as an asynchronously arriving evidence source rather than a continuously synchronized co-generator. Specifically, we introduce waiting debt control to decide whether each decoding step should continue waiting for remote participation based on the observed return of waiting. We also design a certificate-guided minimal supplementation mechanism that requests only the remote evidence needed to determine the current greedy decision. Steps that consult the cloud preserve the same greedy token as dense dual-end aggregation, while the remaining steps commit locally without remote evidence. Experiments on Natural Questions and WikiText-2 show that CONCORD improves end-to-end throughput over baselines by $1.66\times$ and $2.15\times$, respectively, while reducing per-token communication by over two orders of magnitude and maintaining comparable answer quality and perplexity.

### 2. 论文提出的方法论

#### 核心思想
以 **等待债务控制** 决定“是否等云端”，以 **证书引导的最小补充机制** 决定“等资源后要多少证据”，两者耦合实现异步稀疏聚合。

#### 关键技术细节

1. **等待债务控制**  
   - 维护一个债务队列 \( q_{t+1} = \min(Q_{\max}, \max(0, q_t + \xi_t - \rho_a \alpha_t)) \)。  
   - \(\xi_t = 1\) 表示超时或等待无效，\(\alpha_t = 1\) 表示远程证据被有效吸收，\(\rho_a\) 为偿还率。  
   - 当债务 \( q_t \geq Q \) 时，缩短等待预算 \(\tau_t = \min(\tau_{\text{base}}, \tau_{\text{short}}(q_t))\)；否则使用基准预算 \(\tau_{\text{base}}\)。  
   - **效果**：高债务（频繁无效等待）时主动让设备前进，低债务（远程有用）时恢复等待。

2. **证书引导的最小补充机制**  
   - 对于每次咨询云端的步骤，设备端已有一部分已知的远程证据 \( K_t \) 和尾界 \( b_t \)。  
   - 计算当前揭示候选的最大值 \( M_t \)，对未揭示候选计算乐观上界 \( U_t(v) \)。若 \( M_t > \max_{v \notin K_t} U_t(v) + \delta \)，则当前贪婪决策被认证，无需更多远程证据。  
   - 否则形成模糊集 \( A_t = \{v \notin K_t : U_t(v) \geq M_t - \delta\} \)，按本地概率质量排序，选择最小补充集 \( S^*_t \) 覆盖 \( 1-\epsilon \) 的本地质量。  
   - **通信**：只请求模糊集中的 token ID 或稀疏块，而非全词汇表。

#### 统一目标函数
\[
\min_{\{\tau_t, S^*_t\}} \frac{1}{T}\sum_{t=1}^T \mathbb{E}[\lambda_1 \text{Latency}_t(\tau_t) + \lambda_2 |S^*_t| + \lambda_3 \text{Fallback}_t]
\]
约束长期净债务非正。

### 3. 实验设计

- **数据集**：  
  - **Natural Questions（NQ）**：500 个采样，每个生成 10 个 token，评估 F1 和 EM。  
  - **WikiText‑2**：100 个样本，前 64 token 为前缀，后 48 token 为目标，评估 teacher-forcing PPL。

- **基准方法**：  
  - **CRCG**：仅用设备端文档的集中式 RAG。  
  - **DRCG**：将双端文档合并到设备端上下文。  
  - **DRDG/TW**：逐 token 同步的分布式输出聚合。  
  - **DRDG/SW**：序列级同步。  
  - **DRAGON**：基于推测调度的双端输出聚合（最直接对比）。  
  - **CONCORD-NoSystem**：移除等待控制，保留补充通信。  
  - **CONCORD-NoComm**：移除通信控制，保留等待控制。

- **评估维度**：答案质量（F1, EM, PPL）、吞吐量（QPS 或 tok/s）、每 token 通信量（bytes/token）。

### 6. 论文的主要结论与发现

1. **质量保持**：CONCORD 的 F1 和 PPL 与 DRAGON 完全相同（F1 0.267 vs 0.268，PPL 17.016），说明稀疏聚合不损害贪婪解码的决策正确性。
2. **吞吐量大幅提升**：NQ 上 QPS 提升 1.66 倍（0.782 → 1.295），WikiText‑2 上 tok/s 提升 2.15 倍（9.29 → 20.00）。
3. **通信量剧降**：每 token 通信量在两个数据集上均降低约 **99.9%**（从 ~250k 降至 ~200-300 bytes）。
4. **两个组件缺一不可**：单独使用等待控制或通信控制只能恢复部分增益，联合使用效果最优。
5. **鲁棒性**：双机部署和链路变化下优势仍然显著。
