## 摘要
三维计算连续体（统一边缘、云和空间）中的应用需要将多个AI任务（如目标检测、时间序列分析和自然语言处理）组合成复合AI系统。这些系统必须满足关于准确性、延迟和成本的严格服务等级目标（SLO）。维持复合AI系统SLO合规的关键机制是运行时模型选择，即为每个工作流任务动态切换AI模型。然而，现有的分布式和复合AI框架并不原生支持运行时模型选择。我们提出了PLAIground，这是一个支持复合AI系统运行时模型选择的框架。PLAIground引入了可复合AI模型（CAIM）抽象，通过任务和数据契约将任务语义与AI模型实现解耦，从而无需更改工作流即可切换模型。此外，PLAIground引入了Pixie，一种SLO驱动的运行时模型选择算法，可在执行期间动态选择最合适的模型。我们在两个真实的复合AI工作流上的评估表明，Pixie在保持SLO合规的同时实现了高达91.3%的准确性，而固定模型策略要么违反成本和延迟预算高达21倍，要么错过准确性目标4%。

## Abstract
Applications in the 3D Computing Continuum, which unifies edge, cloud, and space, require combining multiple AI tasks such as object detection, time-series analytics, and natural language processing into Compound AI systems. These systems must satisfy stringent Service Level Objectives (SLOs) on accuracy, latency, and cost. A key mechanism for maintaining SLO compliance of Compound AI systems is runtime model selection, where AI models are dynamically switched for each workflow task. However, existing distributed and compound AI frameworks do not natively support runtime model selection. We present PLAIground, a framework that enables runtime model selection for Compound AI systems. PLAIground introduces Compoundable AI Model (CAIM) abstraction, which decouples task semantics from AI model implementations via Task and Data Contracts, enabling model switching without workflow changes. Additionally, PLAIground introduces Pixie, an SLO-driven runtime model selection algorithm, which dynamically selects the most suitable model for each task during execution. Our evaluation on two realistic Compound AI workflows demonstrates that Pixie achieves up to 91.3% accuracy while maintaining SLO compliance where fixed-model strategies either violate cost and latency budgets up to 21x or miss accuracy targets by 4%.

- **核心问题**：在运行时，环境条件（如卫星覆盖、带宽、能量预算）持续变化，需要为每个工作流任务动态切换最合适的AI模型（即运行时模型选择）以维持SLO合规。然而，现有复合AI框架（如LangChain、DSPy）将工作流逻辑与具体AI模型紧耦合，导致模型切换需要修改应用代码，无法实现运行时自适应。
- **研究目标**：设计一种框架，通过新型抽象和运行时算法，在不需要开发者介入的情况下实现SLO驱动的运行时模型选择。

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 2.1 核心思想
- 提出**CAIM（Compoundable AI Model）** 抽象，将任务语义与AI模型实现解耦。
- 设计**Pixie**算法，在运行时根据SLO监测数据动态选择每个任务的最优模型。

### 2.2 CAIM抽象
由三个契约组成：
- **任务契约（Task Contract）**：声明功能要求（如目标检测、文本生成）和非功能要求（SLO，包括任务SLO如最小准确率，系统SLO如最大延迟/成本/能耗）。
- **数据契约（Data Contract）**：定义严格的输入/输出数据格式，使得不同模型输出可统一为相同接口，下游任务无需关心具体模型。
- **系统契约（System Contract）**：由平台提供，包含候选模型列表及其性能画像（准确率、延迟、成本等），用于运行时选择。

开发者只需定义任务契约和数据契约，系统契约由平台自动生成。工作流由多个CAIM通过数据流连接组成，模型切换不影响工作流逻辑。

### 2.3 Pixie算法（算法1文字描述）
- **输入**：有序候选模型集合（按资源消耗排序）、系统SLO、窗口大小`k`、阈值`τ_low`和`τ_high`。
- **初始化**：贪心选择在SLO内准确率最高的模型。
- **运行时循环**：
  1. 每处理一个请求后，更新滑动平均窗口（记录观测到的资源指标）。
  2. 当窗口收集了`k`个观测后，计算所有系统SLO的**归一化差距**，取最小值对应的最受限资源。
  3. 若该差距低于`τ_low`（SLO受压），则**降级**到资源消耗更少的模型；若差距高于`τ_high`（SLO有较多余量），则**升级**到准确率更高的模型；否则保持当前模型。
  4. 执行模型切换后重置窗口并进入冷却期（跳过`k`个观测），避免振荡。
- **工作流级SLO分解**：累积资源（如总成本、端到端延迟）按候选模型平均资源消耗比例分解到各CAIM。

Pixie假设复合AI系统具有单调性（提升单个步骤的准确率不降低端到端准确率），因此独立为每个CAIM最大化准确率是充分的。
