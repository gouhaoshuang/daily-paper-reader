## 摘要
LLM代理可以共享的不仅仅是文本。在某些系统中，一个代理可以发送一条简短的可见消息，同时将其完整的KV缓存状态传递给另一个模型。这种隐藏状态有助于最终模型综合多个代理的证据，但也难以检查。即使隐藏状态被更改，可见消息可能看起来无害。我们在多智能体问答设置中研究这个问题。每个专家看到部分证据，发送简短承诺，并将完整的KV缓存状态传递给协调器。在干净运行中，这种潜在协作优于匹配的纯文本版本。在转换后的HiddenBench上使用Qwen3-4B，其EM/F1达到0.338/0.486，而文本协作则为0.231/0.369。Qwen3-8B和HotPotQA运行显示了相同的改进方向。当某个专家是恶意的时，问题就会出现。一些虚假的可见承诺可以引导答案。更严重的是，即使可见承诺看起来仍然合理，更改隐藏的KV状态也可能导致性能崩溃。仅检查文本的验证器会遗漏这种失败模式。简单的幅度检查可以捕捉到一些明显的篡改，但自适应攻击可以避开这些检查，同时仍然损害最终答案。我们找到的最可靠的修复方法不是猜测隐藏状态是否正常，而是在传输过程中保护它。我们实现了一个HMAC-SHA256清单，将专家、会话、模型、可见承诺、张量元数据和负载摘要绑定在一起。它接受了所有774个真实的重放负载，并拒绝了所有295个记录的篡改负载。主要教训是，全KV潜在记忆可能有用，但应将其视为安全敏感对象，而不是普通的模型内部状态。

## Abstract
LLM agents can share more than text. In some systems, an agent can send a short visible message while also passing its full KV-cache state to another model. This hidden state can help the final model combine evidence from several agents, but it is also hard to inspect. A visible message may look harmless even if the hidden state has been changed.   We study this problem in a multi-agent question-answering setup. Specialists each see part of the evidence, send a short commitment, and pass full KV-cache state to a coordinator. In clean runs, this latent collaboration improves over a matched text-only version. On transformed HiddenBench with Qwen3-4B, it reaches EM/F1 of 0.338/0.486, compared with 0.231/0.369 for text collaboration. Qwen3-8B and HotPotQA runs show the same direction of improvement.   The problem appears when one specialist is malicious. Some false visible commitments can steer answers. More seriously, changing the hidden KV state can collapse performance even when the visible commitment still looks plausible. A verifier that checks only text misses this failure mode. Simple magnitude checks catch some obvious corruptions, but adaptive attacks can evade them while still damaging the final answer.   The most reliable fix we find is not to guess whether hidden state looks normal, but to protect it in transport. We implement an HMAC-SHA256 manifest that binds the specialist, session, model, visible commitment, tensor metadata, and payload digest. It accepts all 774 honest replayed payloads and rejects all 295 recorded tampered payloads. The main lesson is that full-KV latent memory can be useful, but it should be treated as a security-sensitive object, not as ordinary internal model state.

# 论文《When Latent Agents Lie: KV-Cache Integrity in Multi-Agent LLM Collaboration》详细总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：多智能体LLM系统中，专家可以共享完整的KV缓存状态（全KV潜在记忆）作为隐藏通信通道，这比纯文本通信能携带更丰富的证据，提升协同推理能力。现代LLM服务架构（如Disaggregated Serving）已将KV缓存作为可管理的系统对象，使得跨组件传输KV状态变得可行。
- **核心问题**：这种隐藏状态是“不透明的”——普通文本检查无法审计其内容。恶意专家可以在保持可见承诺（visible commitment）看起来合理的同时，替换、缩放或优化隐藏的KV状态，从而欺骗协调器（coordinator）输出错误答案。作者将其定义为“KV传输完整性”问题：当专家传递隐藏状态对象时，如何确保该对象在传输后仍然可信？
- **整体含义**：全KV潜在协作带来性能增益，但引入了新的攻击面，且传统的文本级审计或简单后处理滤波无法充分防御。论文通过系统的攻击-防御实验，论证了传输层完整性保护（如HMAC-SHA256）比内容级异常检测更可靠，并给出了具体的安全边界。

## 2. 论文提出的方法论：核心思想、关键技术细节

- **核心思想**：采用**规划者-专家-验证者-协调者**四角色顺序协议。每个专家持有私有证据分区，输出两样东西：1）简短可见承诺（供验证者审计）；2）完整的KV缓存状态（包括提示词KV和生成的潜在思考KV）传递给协调者。匹配的文本基线用可见承诺替换隐藏KV。防御分为三类：
  - **可见验证过滤**：验证者根据承诺内容评分并拒绝部分专家。
  - **潜在状态隔离（Magnitude Quarantine）**：对每个专家的潜在思考KV进行后处理统计，拒绝key幅度偏离中位数超过阈值（1.25倍）的专家。
  - **传输层完整性（HMAC-SHA256清单）**：在专家生成KV后、传输前计算哈希，传输后由协调者验证。清单绑定专家身份、会话ID、模型名称、可见承诺哈希、张量元数据、负载摘要。密钥不泄露。
- **关键技术细节**：
  - 攻击能力分级：A级（仅控制可见文本）、B级（可读写隐藏KV但无梯度）、C级（白盒梯度优化）。
  - 协议实现：Qwen3模型，隐藏大小2560，5个潜在思考步骤，身份归一化至输入嵌入平均范数。
  - 验证者：基于可见承诺的自动评分（可配置），不接受隐藏KV内容。
  - 隔离规则：最多拒绝1个专家（与恶意专家数匹配），拒绝后重建潜在路径。
  - 传输MAC：对序列化KV负载计算SHA-256摘要，再与元数据拼接后计算HMAC-SHA256，协调者解密并比对。

## 6. 论文的主要结论与发现

- **清洁效用**：全KV潜在协作在EM/F1上一致优于文本协作（HiddenBench: 0.338/0.486 vs 0.231/0.369；HotPotQA: 0.450/0.625 vs 0.244/0.397），统计上F1改进更显著（置信区间不包含0），EM改进方向为正但p值接近0.14。
- **攻击效能**：
  - 语义定向攻击：可诱导目标答案，但整体EM下降约0.09，非全面崩溃。
  - 随机潜在思考和尺度8攻击：使EM降至接近0，每例正确答案均被翻转。
  - 符号翻转：因保留幅度，攻击效果弱（与清洁相近）。
  - 白盒范数匹配攻击：保持幅度正常，但大幅降低性能（EM从0.323降至0.077），逃避幅度隔离。
- **防御局限性**：
  - 可见验证过滤：无法检测隐藏KV损坏，且产生大量诚实误报。
  - 幅度隔离：能检测随机/尺度8攻击（65/65拒绝），但自适应攻击完全绕过（0/65拒绝）。
  - 学习式消毒器：在检测器感知攻击下甚至不如随机预算丢弃，被证明为边界。
- **传输MAC成功**：HMAC-SHA256清单接受所有774诚实重放，拒绝所有295篡改负载；检测失败后执行fail-closed丢弃或降级，恢复绝大部分实用价值（如HiddenBench上丢弃后EM/F1恢复至0.338/0.476，远高于攻击后的0.000）。
- **核心启示**：全KV潜在记忆有用但脆弱；最可靠的完整性保证来自传输层认证，而非内容检查；MAC边界覆盖传输后替换，但端点自身签名恶意KV不在保护范围。

## 7. 优点
